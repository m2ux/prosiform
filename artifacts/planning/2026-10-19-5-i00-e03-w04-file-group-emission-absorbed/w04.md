## Overview

What a file group emits: the order its regions appear in, and the source title its file heading absorbs.

## Problem

A file heading names the document, and 37 of this workspace's 38 skill documents open with an H1 restating that same name, so emitting both puts the name twice at the head of almost every group and twice in every destination into it. The one document whose H1 differs carries a title the path does not, so dropping every H1 would lose it.

Separately, nothing states the order a file group's regions appear in. Selections arrive in discovery order, and emitting them that way would break outline reconstruction and the bytes the bundle promises for one selection.

## Proposal

A file heading absorbs the source's first heading when that heading is the document's only H1 and its slug equals the slug of the final segment of the file heading's path. An absorbed title is not emitted, contributes no destination segment and is not a target. Its group keeps its source heading levels, the file heading having taken the level the shift makes room for. A source whose H1 differs keeps it and shifts by one as usual.

A file group emits its selected regions in their original source order, so a document's preamble sits after its file heading and before its first retained heading, and two sections the source separates reach the bundle in the order the source wrote them whatever order the command line named them in.

## The Comparison Both Sides Are Slugged By

AC7 holds that a source whose only H1 slugifies to the final segment of its file heading has that heading absorbed. The contract states the comparison exactly: the heading's slug equals **the slug of** the final path segment, both sides slugged, so the capitalization and spacing a filesystem carries decide nothing. Its own example is a document named `My Note.md` titled `My Note`, which absorbs as one named `my-note.md` does.

`bundle.absorbed` slugs the title and compares it against the raw segment, so any capitalised filename fails to absorb and the bundle heads the document twice. That is [#63](https://github.com/m2ux/prosiform/issues/63), and it is this row's to fix: the criterion is the behaviour, and the title-absorption fixtures that show AC7 must carry the contract's example among them.

The comparison slugs the path segment as it already slugs the title. One expression changes, and the sides it compares become the two the contract names.

## What the Corpus Already Holds

Three fixtures exercised absorption before this row, and each names a lowercase path — `guide.md`, `artifacts/repository-labels.md`, `references/design-flow.md`. A lowercase single-word segment is its own slug, so each of them passes under the defective comparison and under the corrected one alike. None of them was asserting the defect, and none needs its expected bytes rewritten. The two copied sources whose filenames carry capitals are both `SKILL.md`, whose titles slug to neither `skill` nor anything near it, so they are unabsorbed before and after.

What the corpus did not hold was the case the contract names. Every absorbed path it carried was one where slugging the segment changes nothing, so the comparison's second side was never observed.

## Source Order Is Already What the Build Emits

`bundle.group` walks `source.regions` in document order and emits the subset the run selected, so the order a region reaches the bundle in follows from the document rather than from the reference that selected it. Two fragments naming one document in reverse order therefore produce one group in source order, and a whole-document selection puts the preamble after the file heading because the preamble is the document's first region.

AC6 names fixtures as its instrument, and the corpus had none that observes either half as its subject: no fixture selects two regions the source separates, and the preamble is shown only inside fixtures whose subject is something else. The behaviour is delivered; the evidence is what this row adds.
