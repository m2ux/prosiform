**Component:** `fixtures/reference`

## Overview

This task makes the corpus state what the run owes a reference it is responsible for. A local Markdown reference resolving under the allowed source root that names no document, or names a document but no such heading in it, fails with `E_TARGET_NOT_FOUND` and the run publishes nothing.

Position is what makes the run responsible. [W01](https://github.com/m2ux/prosiform/pull/138) moved classification onto where a reference resolves, so a reference under the root is one the bundle must carry, and a reference it cannot follow is a defect in the source rather than a mention the bundle passes through. The reference family is where that is stated, because the criterion is read from the reference fixtures.

## Problem

The corpus states this failure only in passing, and it states it under families whose subject is something else.

- **The failure is declared by families that are about other clauses.**
  `delivery/a-failing-run-publishes-no-bundle` declares that a failing run leaves standard output empty, `extraction/a-heading-only-in-a-code-example` that heading-like text in a code example is no heading, `identity/an-ordinal-names-no-source-heading` that an ordinal names no heading, and `validation-scope/the-sibling-once-closure-includes-it` that a defect enters scope with the closure. Each raises `E_TARGET_NOT_FOUND` on the way to its own subject, and none of them is the clause.

- **The reference family says what resolves and not what fails to.**
  `reference/a-document-under-the-root-is-a-dependency` and `reference/a-document-outside-the-root-is-text` state the two halves of classification. A reference under the root that resolves nowhere is the case classification creates and neither fixture covers it, so the contract asserts a rule the corpus does not read back.

- **The catalogue names the wrong declaring section.**
  `fixtures/README.md` attributes `E_TARGET_NOT_FOUND` to the validation and failure contract. [D59](https://github.com/m2ux/prosiform/blob/engineering/artifacts/planning/2026-10-17-prosiform-v1/decisions.md) put the rule in link classification, under the clause that says position makes the run responsible, so the table points a reader at a section that no longer states it.

## Proposal

The build already fails both shapes, because position alone decides what the run opens and the mark gates nothing here. What is missing is the corpus declaring it as the reference contract it now is.

- **Two fixtures in the reference family, one per shape.**
  `a-reference-under-the-root-naming-no-document` cites a document the root does not carry; `a-reference-under-the-root-naming-no-heading` cites a document the root carries, naming a heading it does not. Each declares exit status 1, an empty bundle and the `E_TARGET_NOT_FOUND` diagnostic with the reference, the source location and the chain the run followed to the link.

- **No mark is written in either source.**
  The sources carry ordinary links. The run is responsible for them because of where they resolve, and a fixture that wrote a mark would state the rule the mark used to carry rather than the rule position now carries.

- **The catalogue row names the clause that declares it.**
  The `E_TARGET_NOT_FOUND` row of `fixtures/README.md` names link classification and the two shapes the design's clause names, so a reader following the table reaches the text that states the rule.

- **The deferred half waits on `W02`.**
  The criterion reads *whether it is compiled or deferred*, and this build has no deferral: the mark is inert after `W01`, so a marked reference is a compiled one and a fixture writing a mark would observe the compiled path under a deferred name. `W02` gives the mark its deferring meaning and the design requires a deferred link's target to exist, so the deferred shape is stated once that rule is in the build. `W08` integrates the criterion.

- **Nothing in the command changes.**
  `cli.read_source` raises `E_TARGET_NOT_FOUND` for a document the root does not carry and `cli.selection` for a fragment naming no heading, and neither reads the mark. The row adds the observation rather than the behaviour.
