## Overview

Classification of a reference as a direct self-reference or as an ancestor reference.

## Problem

A section linking to itself is a defect while a nested section linking back to an including ancestor is ordinary, and both are a link whose target is already present.

## Proposal

Identity is compared after canonical path and fragment resolution, not by comparing link strings. A link from a section to that same canonical section fails. A link to an including ancestor resolves to the existing destination without expansion. Each link is owned by the innermost eligible section containing its position, a document's preamble belongs to the document node, and ownership is stored separately from inclusion so consolidation cannot change the classification.

## A Marked Resource Is Refused

A mark means bundle this, and a resource is never bundled, so marking one asks for something the tool will not do. The contract contradicted itself here: the mark is dropped by the rewrite, a resource is never rewritten, so a marked resource would carry authoring syntax into a published bundle while [D32](https://github.com/m2ux/prosiform/blob/engineering/artifacts/planning/2026-10-17-prosiform-v1/decisions.md) holds that a mark never reaches one. [D40](https://github.com/m2ux/prosiform/blob/engineering/artifacts/planning/2026-10-17-prosiform-v1/decisions.md) settles it as a refusal.

This row carries it under AC17, because the refusal is a classification and classification is what the row already does.

**It adds an error code, which is the two-branch window.** The clause in `design.md` lives on `engineering` and the catalogue in `fixtures/manifest.schema.json` lives on this branch, and `checks/tests/test_catalogue.py` asserts the two agree — reading the design from `origin/engineering`. Adding one side alone turns CI red on every branch of the repository. Land both within seconds of each other and say so when reporting.

The corpus states both outcomes: a marked resource refused, and an unmarked image, web URL and non-Markdown reference emitted as authored beside a marked local link that bundles. [W03](https://github.com/m2ux/prosiform/pull/77) deliberately left both unasserted on finding the collision, so nothing in the corpus has to be unpicked.

## The Code a Direct Self-Reference Reports

The contract holds that a link from section A to the same canonical section A is a compile error, and it named no code for the failure. A diagnostic reports a code and there was none to report, so AC4 was as undeliverable as AC7 was, one clause further on. Measuring the build found it: a marked self-link exits 0 today and publishes the section whole.

[D42](https://github.com/m2ux/prosiform/blob/engineering/artifacts/planning/2026-10-17-prosiform-v1/decisions.md) settles it as `E_SELF_REFERENCE`, a code of its own rather than a widening of one already there. The target exists and the reference resolves; what fails is the relationship between the reference and the node that wrote it, and the remedy is to drop the mark or name another node.

**The window therefore carries three codes rather than two.** The error catalogue stood at twenty and ends at twenty-three; with the two warning codes beside it, the two catalogues hold twenty-five.

## What the Measurement Found

The half of AC4 about an ancestor reference holds on the base: the traversal's identity set already makes a reference to a destination the run carries add nothing, whether the ancestor was selected first or reached through its child. The other half, and the whole of AC13, need the ownership model, and one implementation serves both — the owner of a link decides the classification, and the owner is read from the document's structure rather than from what a run selected, so AC13 follows from AC4's implementation rather than needing one of its own.
