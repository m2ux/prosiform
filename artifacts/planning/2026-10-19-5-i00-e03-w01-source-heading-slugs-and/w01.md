## Overview

Source heading fragments that match the ones a GitHub renderer generates, and the per-document index that holds them.

## Problem

The fragment reaching a heading is renderer-defined, so a lookup that invents its own spelling resolves to the wrong heading or to none. Every row that follows reads this index: section extraction resolves a fragment against it, the shift keeps the visible text it records, and destination identity is generated from the slug it produces.

Three facts about the build as it stands decide what this row has to do.

- **The slug rule lives beside the bundle rather than beside the source.** `bundle.py` carries the slug, the ordinal walk and the heading-text derivation. They are properties of a source document and of the renderer that reads one, and the bundle is one caller of them. A second caller — a fragment resolving against a source — would either import them from the bundle or spell them again.
- **The ordinal walk can hand two headings one fragment.** It counts occurrences of a slug and appends the count, so a document carrying `## Run`, `## Run-1` and `## Run` gives the first and third headings the fragments `run` and `run-1`, and the second already carries `run-1`. A link to it reaches whichever the reader's renderer indexed first.
- **There is no index.** The bundle derives heading text for the headings it emits, keyed by token identity, and keeps nothing about the headings it does not. The design requires every heading the profile recognizes, container-nested ones included, because a heading left out of the enumeration changes the fragment of every later heading that shares its slug.

## Proposal

The source model owns the headings one document carries, as it already owns that document's content and coordinates.

Visible heading text is derived from the parser's events: text and code content, the label a link shows and the character an entity decodes to are text a reader reads; a line break is the control character it is; a formatting delimiter, a raw HTML tag and an image each direct what is read without being read. The slug is the visible text lowered, with the characters a renderer discards removed and each remaining space a hyphen. Headings are enumerated in source order, container-nested ones included, and a slug already taken is numbered apart, counting from one and passing over every ordinal something already carries, so two headings never share a fragment. The counts are kept per complete source document.

The bundle reads those four functions rather than carrying its own. Its destination walk is the same renderer rule applied over the headings it emits, so the two cannot disagree about what a renderer does.

Each rule is measured rather than assumed. The headings of every fixture this row adds were rendered by GitHub and the anchors it generated are the fragments the corpus declares, which is recorded in [validation.md](validation.md).

### What the Index Holds

| Field | Holds |
| --- | --- |
| `level` | The level the heading opens at, whatever syntax wrote it |
| `text` | The text a reader sees, derived from the event stream |
| `fragment` | The fragment a renderer generates, carrying its ordinal where an earlier heading took the slug |
| `line` | The line of the content the heading opens on, which the source's own shift turns into a line of the file |

A heading's fragment and its ambiguity as a lookup key are two facts, not one. The renderer numbers two headings of one text apart, and the index records what the renderer does. A source fragment requiring one of them identifies neither, and that refusal belongs to lookup rather than to the index — the index is what the refusal is read from.

### How the Criterion Is Observed

AC5 names a fixture, and a source heading's fragment is not something the corpus can read directly: this build publishes a bundle, and the only fragments the bundle spells are the destinations of its entry line, one per file group.

The collision between the two is what makes the fragment observable. Destinations are assigned over every emitted heading in bundle order, so a file group whose own heading produces a slug an earlier source heading already took carries that slug's ordinal. A document whose path is the slug under test therefore states, in the bytes the bundle publishes, what the source heading before it slugged to:

| Heading in the first document | Slug it produces | Document named for it | Destination that document takes |
| --- | --- | --- | --- |
| `## What's new: v1.0!` | `whats-new-v10` | `whats-new-v10.md` | `#whats-new-v10-1` |
| ``## The `code` span and **bold** text`` | `the-code-span-and-bold-text` | `the-code-span-and-bold-text.md` | `#the-code-span-and-bold-text-1` |
| `## Café Münster` | `café-münster` | `café-münster.md` | `#café-münster-1` |
| `## Notes`, twice | `notes`, `notes-1` | `notes.md` | `#notes-2` |

The duplicate pair carries two facts in one destination: `#notes-2` holds only if both headings slugged to `notes` and the renderer's ordinal counted both.

### The Boundaries

Three of the row's boundary cases turn out to be observable through the same collision, so each is a fixture that holds rather than one declared ahead.

| Fixture | States |
| --- | --- |
| `headings/collision-with-a-natural-suffix` | A heading whose own text spells an ordinal keeps it, and the heading that would have been numbered into it takes the next free ordinal |
| `headings/an-entity-in-a-heading` | A heading carrying an entity takes the fragment the character it decodes to produces |
| `headings/image-alternative-text` | A heading carrying an image takes the fragment the words beside it produce, the space the image stood in remaining |
| `headings/a-heading-with-no-visible-text` | A heading a renderer discards entirely names nothing and leaves every heading after it nameable — `awaiting = "I00:E10"` |

The fourth stays declared ahead because no destination this build emits can express it: GitHub generates no anchor at all for such a heading, while still counting it against the next heading of that slug, so what it does is visible only to a lookup, and a fragment selects nothing until extraction lands.

### Where the Design and the Renderer Disagree

The design derives visible heading text from "text/code content, link labels, image alternative text, decoded entities, and normalized line-break spacing". Two of those five the renderer does not do, which the measurement shows: an image contributes no text to the anchor GitHub generates, and a line break is discarded rather than spaced. The criterion names the renderer, so the build follows the renderer and the design's wording is raised as a finding.

#### What Was Rejected

- **Spelling the slug rule a second time in the source model and leaving the bundle's copy.** It touches one file. It was rejected because two copies of a renderer's rule drift, and the drift is invisible: each passes its own tests while the bundle's destination and the source's fragment name different headings.
- **Following the design's wording for the image and the line break.** It is the contract as written. It was rejected because AC5 binds the fragment to the one a GitHub renderer generates, and the renderer was asked: a build that followed the wording would fail the criterion it was written to satisfy.
- **Refusing a heading whose visible text is empty.** A destination that names nothing is a defect worth a diagnostic. It was rejected because no code in the catalogue names it, and adding one changes the design on `engineering` and the schema on `main` within one window for a case no row needs yet.
