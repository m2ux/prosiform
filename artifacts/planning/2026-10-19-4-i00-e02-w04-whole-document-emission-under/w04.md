## Overview

Whole-document emission beneath a generated heading naming the source file.

## Problem

Parsed content has no output form, and without a per-file heading two sources would share one outline.

## Proposal

A contributing source is emitted beneath one generated top-level heading whose visible text is its normalized root-relative path with the Markdown extension removed, escaped so punctuation in that path cannot create a link, an image or inline HTML. The document's own content follows, with its preamble before its first retained heading.

A group is assembled from the maximal regions the parse found, in source order, each carried as the bytes its source wrote and separated from the next by one blank line. The bundle opens with its entry line, then each group in root-relative path order.

- **One region, one slice.** Every top-level block the parse recognizes is emitted as the source lines it occupies. Nothing between two regions is source content, so an author's indentation, trailing spaces and inner blank lines survive inside a region while the separation between regions is generated.
- **A file heading that cannot be read as markup.** The path is escaped as literal heading text: a backslash precedes each character that can open an inline construct under the profile, so a path carrying brackets, an underscore, a backtick, an angle bracket, an ampersand or a tilde names a file rather than a link, an image, emphasis, code, raw HTML, an entity or a strikethrough.
- **One heading per source, distinguishable by path.** Two documents sharing a basename in different directories carry their directories in their headings. Two whose paths differ only by Markdown extension produce one heading text twice and fail with `E_AMBIGUOUS_FILE_GROUP`.
- **A title the path already carries is absorbed.** The file heading absorbs the source's first heading when that heading is the document's only H1 and its slug equals the final segment of the path. The group then keeps its source levels; every other group moves each emitted heading down one level, the file heading taking the level that makes room.

### The Entry Line

The bundle opens with the generated line `design.md` declares at `### Entry line`, naming each entry reference by the visible text of the heading its destination names and linking to that destination. For a whole-document reference that heading is the file heading, which is the first heading the bundle emits and therefore carries its slug without an ordinal.

**The criterion that names the entry line is `I00:E05:AC7`, three epics after the fixtures that require it.** `coverage.md` maps the `Input and output contract — Entry line` and `Entry line` clauses to `I00:E05:AC7`, delivered by `E05:W02`; `D28` records the decision the clause rests on. No criterion of `E02` or `E03` names it. Every expected bundle the corpus carries declares it, `identity/whole-document` among them, so the first row that emits a bundle emits the line or no success fixture in the corpus can pass. It is delivered here in the one form this row can produce — one whole-document entry, one file heading, no destination map — and `E05:AC7` keeps the rest: a destination taken from the bundle's map with its ordinal, a grouped entry resolving to an overview subsection, and the entry-line integrity invariant.

### Boundary Whitespace Is Generated, Not Preserved

Two fixtures authored ahead of this row turn on the same question, and the contract answers both in one clause.

- **`profile/task-markers-protected-from-definitions`** declares that removing a reference definition leaves no trailing blank line. **The fixture states the contract.** A definition is a node the parse consumes and emission removes whole; the blank line that separated it from the region above it is separation between regions, not content of either. `Validation and failure contract — Preservation` lists boundary whitespace among the declared transformations rather than among the bytes preserved, and `Block boundaries` states that blank-line separation is *inserted* between maximal emitted regions. A bundle that carried the blank line would be carrying the removed definition's own separation, which no region owns.
- **`frontmatter/leading-blank-line`, `indented-delimiter`, `delimiter-with-trailing-spaces` and `toml-fence`** each declare a leading preamble appearing after the file heading with its leading blank line collapsed. **The fixtures state the contract**, by the same clause: the blank line above the document's first region is outside every region, and the separation the bundle emits between the file heading and that region is one blank line, inserted. The bytes the same fixtures do preserve are inside a region — ` ---`'s indentation, `---  `'s trailing spaces, the TOML fence's three lines — and each reaches the bundle as written.

The rule is one rule: a region is emitted as its source bytes, and what lies between two regions is the bundle's own.

### What This Row Takes from E03

A bundle whose source document keeps its own H1 needs that H1 beneath the file heading, so this row takes the part of the shift a whole-document emission cannot do without.

- **Taken.** The per-group shift decision, the title absorption that selects it, and the level edit on a document-level ATX heading. The depth guard that refuses a shift placing a heading beyond H6 comes with it, because a seventh level is not a heading and emitting one would publish a bundle the contract's depth-safety invariant forbids.
- **Left.** Setext conversion, whose multiline form is an open question `I00:E03:AC4` is chartered to settle; the shift inside a retained container; and the depth-overflow fixtures, which are `I00:E03:AC6`'s. A shifted group carrying a Setext heading or a container-nested heading is the gap those rows close, and no fixture asserts otherwise.

### Selection Is Not This Build's

A reference carrying a nonempty fragment names a section, and section extraction is `E03`. Such a run reaches no bundling stage and returns the unexpected-internal-error status, which says the build cannot carry the request out. A reference with no fragment or an empty one selects the whole document and bundles. A referring document named by `--from` is read under the profile like any other source and contributes no group, because an entry reference names the procedure rather than the routing document the caller read to find it.

## Expected Bundles Authored Ahead of This Row

Fixtures declaring a successful bundling exist before anything emits one, so each states a bundle this row is the first to produce. Where a fixture and this emission disagree, which of the two states the contract is a question this row settles and records; a fixture is not evidence merely by predating the emitter, and the emitter is not correct merely by existing.

Thirteen of the corpus's twenty-six fixtures declare a successful bundling, and every one of them was authored before an emitter existed. Each was read against the contract before the emitter was written, and every one of the thirteen states the contract: the entry line, the file heading, the absorbed title, the preserved region bytes and the generated separation between regions are each a clause of `design.md`, and no fixture was edited to meet what the emitter produced.

`profile/task-markers-protected-from-definitions` carries the sharpest case, and the four frontmatter fixtures declaring a collapsed leading blank line carry the same one. Both are settled above, under *Boundary Whitespace Is Generated, Not Preserved*, on what the preservation invariant requires of the surrounding text: it requires nothing, because the text surrounding a region belongs to no region.
