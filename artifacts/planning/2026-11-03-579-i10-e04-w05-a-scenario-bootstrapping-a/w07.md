**Component:** main:evals/diagram-following/workflows/preset-deferral/scenarios.toml

## Overview

A `staged` workflow whose deferring step heading and target heading select one preset with a `subst` stand-in, so the activated content is the stand-in's and the path follows it.

## Problem

- **A deferral's presets are a build rule.**
  The run refuses a mismatch; nothing shows an agent following the stand-in a matched deferral activates.

## Proposal

**The scene.** A workflow is a directory under `workflows/`, its forms beside a `scenarios.toml` naming each scenario's inputs, the path a correct session walks, the sub-agents it starts and the `pf` runs it makes. A `staged` session receives the compiled bundle set with the build under test as `pf` on its path; the scenario passes when the session's path is the one its bundle states.

- **One preset on both headings.**
  `Mirror` defers `reference/fetch.md#read-mirror`, so both headings select `fetch.md`'s `mirror` preset, whose `subst` puts `cache.md` in place of `net.md`.
- **The transition is deferred.**
  `Mirror`'s document writes no transition paragraph; the section the run on its line composes states "Take the transition labelled `<label>`.", `stored` from the stand-in and `live` from the real target.
- **The path is the stand-in's.**
  `stand-in-followed` runs `pf reference/fetch.md#read-mirror` and walks `Solicit`, `Mirror`, `Restore`; a session following the real target goes to `Serve` and diverges.
- **The corpus reads a deferred transition.**
  A section deferring its transition is walked only through the staged walk, since the sources state its edge only through the run activating it.
