## Overview

Outline and closure completion finishes the structure a bundle presents and settles the output budget against a real measurement. Heading-only ancestors restore the outline a partial selection skipped, a depth beyond the sixth level fails rather than flattening, a grouping rule merges one part of the tree, the configured output budget is set from a bundling that was measured rather than assumed, and the design's usage examples name a tree the repository owns.

## Problem

A tool in use carries the structure its first users did without.

- **A selected child without its parents reads as a top-level topic.**
  Selecting a third-level section and emitting it alone discards the relationship that placed it under its parent.

- **A shift has a ceiling.**
  Markdown carries six heading levels, so a deep selection beneath a generated file heading can require a seventh, which has no heading spelling.

- **One document's sections are read beside another's.**
  Twenty documents in one closure carry an `Operations` section, and a bundle grouped by document puts each in a different place, so comparing them means reading twenty groups.

- **A budget nobody measured is a guess with a number on it.**
  An output limit set from an assumed figure either refuses bundlings that would have been fine or admits ones no caller can hold.

- **An example the repository cannot run is prose.**
  The design's usage examples name a tree that lives in another repository. No check reads them, no run executes them, and nothing notices when one stops being a valid invocation.

## Proposal

- **Ancestors appear as structural ancestors.**
  A selected section's unselected eligible ancestors are emitted as headings with escaped literal text and no body, siblings or other descendants. Structural ancestry is recorded separately from selected content and is not traversed for dependencies.

- **Overflow fails.**
  A bundling needing a heading beyond the sixth level fails rather than flattening, clamping or emitting heading-like text.

- **A group merges one part of the tree.**
  A group names a directory slug and a heading level, and every document beneath a directory of that slug is merged at that level, beneath one heading carrying the slug. A document no group names keeps its own group. A merged section carrying body text from more than one document splits into variants by document, since a procedure is its mode's own rather than a container of named items. A merged heading keeps its source text where that text occurs once; where several documents contribute one text, it is emitted once with each document's content beneath a variant heading naming that document, so the variants of a name sit together.

- **One budget is set by measurement.**
  The closure the proposal measured is bundled and its output size recorded against the configured budget, so the output limit rests on a real bundling rather than on an assumed figure.

- **The repository owns the tree its examples name.**
  A small example tree, taken from the closure of one real procedure and renamed, carries its references marked where the material is required and unmarked where it is cited, so it shows both halves of the rule in one place. The corpus bundles it, so an example that stops working fails a run rather than going quietly stale.

## Acceptance Criteria

- [ ] **AC1.** A selected section's unselected eligible ancestors are emitted as headings carrying no body, sibling or descendant content, as the structural ancestor fixtures show.
- [ ] **AC2.** A bundling that would place a heading beyond the sixth level fails with its declared error code and publishes nothing, as the depth-overflow fixtures show.
- [ ] **AC3.** One entry bundled with and without a group selects the same content, reports the same entry destinations on the diagnostic stream, and differs only in how it is arranged, with each group emitting one heading carrying its slug in title case, a merged section emitted once however many member documents contribute to it, and a document no group names keeping its own group, as the grouping fixtures show.
- [ ] **AC4.** A merged heading occurring once in its group is emitted with its source text alone, while one drawn from several documents is emitted once with each document's content beneath a variant heading naming that document, and a merged section carrying body text from more than one document splits into variants by document, and a member's preamble is emitted under the group's overview section as a subsection named by that document's stem in title case less a trailing word the section states, which is where a whole-document reference to the member resolves, as the grouping fixtures show.
- [ ] **AC5.** A grouping rule whose depth falls outside the supported heading levels, whose slug names no directory under the root, or whose slug is given twice is refused with its declared error code and exit status, while a rule matching no document in the closure warns and arranges nothing, as the grouping fixtures show.
- [ ] **AC6.** Under a grouping rule, a reference to a source heading at the grouping depth resolves to the variant heading carrying the document it named, and to the merged heading itself where that name occurs once, as the grouping fixtures show.
- [ ] **AC7.** The bundled size of the closure the proposal measured is recorded against the configured output budget, as the measurement fixture shows.
- [ ] **AC8.** Each usage example the design publishes runs against a tree the repository carries, and that tree shows a reference marked as required beside one left as a citation, as the example-tree fixtures show.

- [ ] **AC9.** A link to a section present only as a heading-only ancestor expands closure to include that section's selected body, as the ancestor-promotion fixtures show.
