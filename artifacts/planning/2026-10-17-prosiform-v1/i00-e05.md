## Overview

Destination identity makes the bundle navigable by name. Every included document and section takes as its destination the fragment the declared renderer generates for its bundled heading, every rewritten reference points at one, resolved reference-style links become inline links with their definitions removed, and a relative resource reference is carried as authored under a warning.

## Problem

Links that resolved in their source documents resolve to nothing once those documents are one document.

- **A heading slug is not unique across files.**
  Two documents can each hold a section whose heading produces the same slug, so a name derived from heading text alone cannot tell them apart.

- **A definition has file scope and the bundle has none.**
  A reference-style link resolves against its own document's definitions, so moving the use without its definition breaks it, and moving every definition into one document makes labels from different files compete.

- **An unresolved bracket is not a link.**
  Text one document leaves as literal brackets would become a link if another document's definition were in scope, which changes what the source said.

- **A relative resource path is relative to its source.**
  An image path that resolved from its source directory resolves from somewhere else once the content is published at a different location.

## Proposal

- **A destination is the fragment the renderer generates.**
  It is the bundled heading's slug, carrying the renderer's ordinal where two bundled headings share one, so every internal link resolves in a renderer, an editor preview and an agent reading the document whole. Nothing is emitted at the destination; the heading the renderer already indexes is the target.

- **A destination is scoped to the bundle.**
  The bundle is one document, so a section whose slug is unique in it needs no qualification and a cross-file reference is spelled like a same-file one. Two documents whose paths differ only by Markdown extension produce two file headings a reader cannot tell apart, and are refused.

- **The ordinal is safe because the bundle is generated.**
  In a source document an edit elsewhere would change how many similar headings precede a target and silently repoint a stored link. A bundle is written in one pass, validated against the map that produced it, never hand-edited and refused as input to a later run.

- **Every internal link points at its destination.**
  A local Markdown link and a fragment-only link in selected content are rewritten through the same map that produced the destination. A bundle whose destinations are right and whose links still name source paths is the failure this guards against.

- **Nothing is emitted at a destination.**
  The bundle carries Markdown and nothing else. A destination names a place in the document; it is not an element in it.

- **References resolve in their own source.**
  Reference-style uses are resolved against their own document's definition environment, converted to inline form with visible content and titles preserved, and every original definition node is removed, unused definitions included.

- **Literal brackets stay literal.**
  Text a source parser did not resolve as a link is emitted as literal text and cannot acquire a destination from another document's definitions.

- **A resource is text.**
  A relative image or other non-Markdown reference is emitted byte-identical to its source and never opened, rebased or resolved. Where a bundle will be read from is the caller's question, so the run warns that resource portability is not guaranteed rather than inventing a destination.

## Acceptance Criteria

- [ ] **AC1.** Each included document and section carries as its destination the fragment the declared renderer generates for its bundled heading, taking the renderer's ordinal where two bundled headings share a slug, as the destination fixtures show.
- [ ] **AC2.** Two headings in one source sharing a slug fail as ambiguous when a source fragment requires one of them, and two source paths differing only by Markdown extension fail as ambiguous, as the ambiguity fixtures show.
- [ ] **AC3.** Each local Markdown link and fragment-only link in selected content is rewritten to the destination of the target it resolved to, and every destination in the published bundle resolves to exactly one heading in it, as the rewriting fixtures show.
- [ ] **AC4.** A resolved reference-style link or image in selected content is published inline with its visible content and title preserved, and no original definition node is present, as the reference fixtures show.
- [ ] **AC5.** Bracketed text a source parser left unresolved is published as literal text, as the literal-bracket fixtures show.
- [ ] **AC6.** The bundle opens with a line naming each entry reference, linked by the visible text of the heading its destination names and resolving to that destination, stating that the remainder is material those entries reference, carrying no execution verb and counting toward no source's coverage, as the entry-line fixtures show.
- [ ] **AC7.** A relative image or other non-Markdown reference is emitted byte-identical to its source, with a warning on the diagnostic stream that resource portability is not guaranteed, as the resource fixtures show.
- [ ] **AC8.** A reference naming a source heading the file heading absorbed resolves to that file heading's destination, as the absorbed-title fixtures show.
