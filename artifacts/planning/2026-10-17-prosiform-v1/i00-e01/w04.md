## Overview

The checks that hold the repository's documentation to what the project declares and to the files it points at.

## Problem

`prototype/README.md` enumerates the build's dev dependencies and the repository's check commands in two tables, and nothing compares either with its source. A dependency added to `pyproject.toml` and a target added to the `Makefile` both leave the README stating a set the project no longer has, and every check passes. The tables went stale on the first change that touched them, and a reading by hand is what caught it.

The link check reads the root README alone, so the references in `fixtures/README.md`, `checks/README.md` and `prototype/README.md` resolve only as long as someone reads them. Each tree's README gained links as that tree gained content, and none of them is checked.

A reader installs from a README and invokes what it names, so a stale table or a dead link is a wrong instruction rather than an untidy one.

## Proposal

A check reads the dev dependency group from `prototype/pyproject.toml` and the targets from the `Makefile`, reads the two tables from `prototype/README.md`, and fails when either set differs in both directions: a declared item the README omits, and a README row the project does not declare. It names the item and the side it is missing from.

The link check reads every README the repository owns, found rather than listed, so a tree added later is covered without the check being edited. A reference that resolves for the root README resolves the same way for any other: the rules for a local path, a repository tree URL and an authenticated tracker read are the ones already in place.

Both checks run from the named commands, so continuous integration enforces them on every change. Widening the link check may report references that were never checked before; each is a defect this row fixes, not a reason to narrow the check.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The two tables and their sources, how each row corresponds to a declared item, and every README the repository owns |
| Plan | The comparison, its failure message, how the link check discovers the documents it reads, and the commands both run from |
| Implementation | The table check, the widened link check and their named commands |
| Review | Confirmed that the comparison fails in both directions rather than only on an omission, and that a README added later is read without editing the check |
| Test | The table check run against a dependency the README omits, against a README row the project does not declare, and against the clean tree; the link check run against an unresolvable reference in a README other than the root |
