## Overview

The check that holds the build README's dependency and command tables to what the project declares.

## Problem

`prototype/README.md` enumerates the build's dev dependencies and the repository's check commands in two tables, and nothing compares either with its source. A dependency added to `pyproject.toml` and a target added to the `Makefile` both leave the README stating a set the project no longer has, and every check passes. The tables went stale on the first change that touched them, and a reading by hand is what caught it.

A reader installs from that README and invokes what it names, so a stale table is a wrong instruction rather than an untidy one.

## Proposal

A check reads the dev dependency group from `prototype/pyproject.toml` and the targets from the `Makefile`, reads the two tables from `prototype/README.md`, and fails when either set differs in both directions: a declared item the README omits, and a README row the project does not declare. It names the item and the side it is missing from.

The check joins the named commands and runs with the others, so continuous integration enforces it on every change. The documentation this check holds true is already correct, having been brought up to date by the pull request that made it stale.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The two tables, their sources, and how each row corresponds to a declared item |
| Plan | The comparison, its failure message, and the command it runs from |
| Implementation | The check and its named command |
| Review | Confirmed that the comparison fails in both directions rather than only on an omission |
| Test | The check run against a dependency the README omits, against a README row the project does not declare, and against the clean tree |
