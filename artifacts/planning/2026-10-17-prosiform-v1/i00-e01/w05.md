## Overview

The manifest schema and its catalogue extended to the warnings a run emits alongside success.

## Problem

A fixture declares the diagnostics its run produces, and the schema closes that declaration over the twelve error codes the design names. The design also describes two warnings — a grouping rule that arranges nothing, and a bundle whose resource references may not resolve where it is read — and a run emits them on a successful compilation. No fixture can declare either, so the corpus states nothing about a run's output on stderr when the run succeeds.

A diagnostic carries a stable code, and the catalogue test holds the schema to the codes the design declares. It reads the error codes alone, so a warning code the design names is invisible to it and the schema may omit one without failing.

## Proposal

The schema admits a warning diagnostic beside an error one, and its code comes from a catalogue of the warning codes the design declares. A manifest naming a warning code outside that catalogue fails validation, as one naming an unknown error code does.

The catalogue test reads both prefixes from the design, so a code the design names and the schema omits fails the check whichever kind it is. The two catalogues stay distinct, because a warning accompanies a successful run and an error decides a failing one: a fixture that declares a warning where an error belongs is a fixture that has stated the wrong contract.
