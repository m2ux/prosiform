## Overview

The validation gate completes what candidate validation began. Region boundaries are proven safe, sources are rechecked for change, a generated document is refused as input, every failure produces a diagnostic a calling agent can act on, and validation follows the selection rather than the file. The tool is in use while this lands, so each row closes a way a bundle can be wrong that first use has already exposed or could.

## Problem

Provenance agreement is not the whole of correctness.

- **A boundary can swallow what follows it.**
  Two regions joined without safe separation can place later content inside an earlier code fence, HTML block, list or quote, which changes meaning without producing invalid Markdown.

- **A source can change mid-compilation.**
  Files are read during discovery and published after validation, so a source edited in between would be published from the bytes discovery captured rather than the bytes on disk.

- **Output read back as input compounds.**
  A published bundle already carries generated file headings and rewritten links, so bundling it again would rewrite generated structure as if it were source.

- **A failure the agent cannot explain is a failure twice.**
  Without a code, a location, the offending reference and the chain that reached it, a calling agent can report only that bundling failed.

- **A sound section is unreachable through an unsound document.**
  A check applied to a whole file refuses a run that selected one good section of it, so the defect of a region nobody asked for decides the outcome.

## Proposal

- **Boundaries are proven safe.**
  Emitted regions are separated and the result reparsed. A boundary that absorbs content into an unintended container fails with its declared code, naming the source regions and the conflicting boundary.

- **Sources are rechecked before publication.**
  Each source is compared against its captured content hash and canonical identity. A changed, removed or relocated source fails with a retry message.

- **A generated document is refused as input.**
  A source opening on a file heading is rejected, recognized by a document-level H1 whose text names a document under the root once a Markdown extension is appended, while a heading-like line inside code is not a heading and is not detection.

- **Diagnostics carry a stable shape.**
  Each carries an error code, the referring source location, the original reference, the resolved identity where one exists, the inclusion chain and a remedy where one can be stated accurately. A selected JSON format emits one object per line with no prose on that stream.

- **Validation follows the selection, not the file.**
  Link resolution, self-reference and syntax checks apply within the selected dependency closure. Parsing a whole file to index it does not make its unselected sections dependencies, so a broken or self-referential link in one of them does not fail a run that did not select it. If closure later includes that section, its links become subject to validation like any other.

- **An indexing failure is not a dependency.**
  A file-wide parsing-safety limit exceeded by an unselected construct fails as an inability to index that source safely, diagnosed as such rather than as a dependency on the construct that exceeded it.

## Acceptance Criteria

- [x] **AC1.** A region boundary that would place content inside an unintended container fails with its declared error code, naming the source regions and the conflicting boundary, as the boundary fixtures show.
- [x] **AC2.** Each source's content hash and canonical path identity are captured at discovery and rechecked before anything publishes; a source that changed, disappeared or resolved elsewhere fails with a retry diagnostic and publishes nothing, as the consistency tests show. A fixture declares a static source tree, so the corpus states the capture and the recheck rather than a source changing mid-run.
- [x] **AC3.** A source opening on a file heading, whose text names a document under the root other than itself once a Markdown extension is appended, is rejected, while a document titled with its own name and a heading-like example in code are both bundled, as the generated-input fixtures show.
- [x] **AC4.** Each diagnostic carries a stable error code, and the referring source location, the original reference, the resolved identity and the inclusion chain wherever the defect it reports has them, as the diagnostic fixtures show.
- [x] **AC5.** Selecting the JSON diagnostic format emits one JSON object per line on the diagnostic stream and no prose on that stream, as the JSON diagnostic fixtures show.
- [x] **AC6.** A broken or self-referential link in an unselected section does not fail a run that did not select it, as the validation-scope fixtures show.
- [x] **AC7.** A file-wide parsing-safety limit exceeded by an unselected construct fails as an inability to index that source, as the file-wide safety fixtures show.

- [x] **AC8.** A profile refusal in a section no reference selected does not fail a run that did not select it, in a document the closure reached as in one the command line named, as the validation-scope fixtures show.
- [x] **AC9.** A link-reference definition whose destination or title the author spelled across two lines is published inline carrying both as authored, and its definition is removed, as the reference fixtures show.
