## Overview

Python retirement leaves one delivered build. The prototype's install path as `pf` is removed, it runs in continuous integration only as the differential oracle, and the documentation names the production binary as the command and the prototype as the oracle.

## Problem

After cut-over the prototype is still a second product.

- **Two builds install as one command.**
  While the Python package still installs as `pf`, a caller can reach either build, and a defect report names neither.

- **Maintenance spreads across both.**
  Checks and jobs that run the prototype beyond the differential comparison keep its delivery path alive.

- **The documentation describes two tools.**
  Installation and usage pages that still present the prototype as a way to run `pf` direct callers back to it.

## Proposal

- **The prototype loses its command.**
  The Python package declares no `pf` command, and no documented install path delivers it.

- **The oracle keeps running.**
  The prototype runs in the differential job and nowhere else in continuous integration.

- **The documentation names one build.**
  The repository documents the production binary as the command and the prototype as the oracle.
