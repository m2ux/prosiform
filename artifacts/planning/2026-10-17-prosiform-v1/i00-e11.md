## Overview

This epic holds the technical debt the prototype initiative's delivery defers. A unit that finds debt while validating its work fixes it when it blocks the unit's own criteria or needs no work item of its own, and defers it here when it blocks nothing and would warrant a work item. The epic runs after every other epic of the initiative, so the clear-up competes with none of them, and each deferred item is one row covering the criterion that states what fixing it makes true.

## Problem

Debt found during delivery has nowhere to go that is neither a widened epic nor an orphan.

- **Widening the epic in hand changes what it was planned to be.**
  A unit that absorbs every defect it notices delivers something other than the work the epic scoped, and the criteria it was measured against stop describing it.

- **A standalone issue with no home is a decision postponed, not taken.**
  An orphan waits for a later pass to find it a place, and until then nothing says when it is fixed or what fixing it makes true.

- **Nothing records that the initiative is carrying debt.**
  An initiative whose epics are all closed reads as complete even when its delivery left known defects behind, because no row and no criterion names them.

## Proposal

- **One epic takes the whole of it.**
  Each item a unit defers becomes a row here, and the initiative stays open while any row is undelivered, so the debt is visible as outstanding work rather than as prose in a planning record.

- **Each row carries the criterion its fix makes true.**
  The statement is what the fix establishes, not the defect it removes, so the row is verified the same way any other row is.

- **The clear-up absorbs what it uncovers.**
  Debt a unit of this epic finds in resolving its own row becomes a further row here, so fixing one item cannot quietly widen another epic.

- **It is raised when the first item is deferred and grows as delivery proceeds.**
  Its rows are not planned ahead of the work that finds them.

## Acceptance Criteria

- [ ] **AC1.** The link check's heading-slug rule is held to the anchor GitHub generates by a check that runs with the others, as that check's run against a heading whose slug the rule would get wrong shows.
- [ ] **AC2.** Each standalone check's parsing is held by tests that run with the others, as those tests' run against a document the parser would read wrongly shows.
- [ ] **AC3.** Each warning the design declares is stated by a corpus fixture that carries it, as the corpus run shows.
- [ ] **AC4.** A run whose standard output legitimately differs between builds is stated by a corpus fixture comparing the shape of that output rather than its bytes, as that fixture's run against a response the comparison must accept and one it must refuse shows.
- [ ] **AC5.** A fixture states the outcome of an allowed source root that names no directory, as that fixture's run against a build that reports it and one that does not shows.
- [ ] **AC6.** The fixtures awaiting one named piece of work are reported from the corpus on request, as that report's run against a corpus carrying fixtures awaiting two different pieces of work shows.
- [ ] **AC7.** A source path carrying a number sign is either nameable by an entry reference and emitted with that character in its file heading, or refused with the code the contract names, as the fixtures for whichever the contract states show.
- [x] **AC8.** A remote reference whose host does not answer is reported as an unreachable host rather than as an unresolved reference, under the verdict `checks/README.md` states for one, as the check's run against a host returning `5xx` and one returning a missing page shows.
- [x] **AC9.** A marked image is refused with the error code a marked resource takes, so no published bundle carries the mark, as the marked-resource fixtures show.
- [ ] **AC11.** A link written inside an image's alternative content is read as the reference it is, so a marked one is bundled and rewritten and no published bundle carries its mark, as the reference fixtures show.
- [x] **AC12.** A remote address whose host answers 403 to both methods is either counted as unreachable or held to that answer, under whichever `checks/README.md` states, as that check's run against a host refusing both shows.
- [ ] **AC13.** A fixture declares text a diagnostic's message carries, so two faults sharing one error code are told apart, as that fixture's run against a build reporting each of them shows.
- [ ] **AC14.** A remote address whose host answers 401 or 405 to both methods is either counted as unreachable or held to that answer, under whichever `checks/README.md` states, as that check's run against a host refusing both shows.
- [ ] **AC15.** A parser resource limit that suppresses a reference lookup is reported with the code the contract declares for it, so a bundle is never published from a lookup the parser silently abandoned, as the parser-limit fixtures show.
- [ ] **AC16.** A grouping rule that arranges no source is reported with the warning code the contract declares for it, as the grouping fixtures show. `fixtures/grouping/a-rule-matching-no-document-in-the-closure` declares the warning and awaits this row; I00:E09:AC5 carries the arranging half and this criterion the warning, so neither epic waits on the other.
- [x] **AC17.** The dependency check reports no problem against I00, and each initiative gate that differs from the one the task graph derives is recorded in the planning record with why, as the check's run over the initiative and every epic body shows.
