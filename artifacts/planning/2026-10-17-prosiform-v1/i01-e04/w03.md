## Overview

Records, for the freeze tag, the build revision and the fixture bytes the freeze check was run against, so the tag names evidence a later build can be compared with.

## Problem

The freeze check refuses a tag over an unexamined ledger, but a tag alone names a revision and not the run that judged it. Without the build revision and the fixture bytes the check read, a production build cannot tell whether the corpus it targets is the one the freeze accepted.

## Proposal

A reader opens the freeze record and finds the tag, the build revision the freeze check ran, and a digest of each fixture's bytes at that revision. The freeze check writes the record when it applies the tag and refuses a record whose revision or digests do not match the tagged tree.
