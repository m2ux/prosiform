## Overview

Source-change detection before publication, and rejection of a generated document as input.

## Problem

Files are read during discovery and published after validation, so a source edited in between would be published from the bytes discovery captured; and a published bundle read back as input would have its generated structure rewritten as source.

## Proposal

Each source's canonical identity and content hash are captured at discovery and rechecked before publication; a changed, removed or relocated source fails with a retry message. A source whose first heading is a document-level H1 naming a document under the root, once a Markdown extension is appended, is rejected with its declared error code, while a heading-like line inside code is not a heading and is not detection. A bundle's own links are ordinary fragments, so the file heading is the only signal and the diagnostic says so.
