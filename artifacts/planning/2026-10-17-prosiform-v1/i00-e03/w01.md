## Overview

Source heading fragments that match the ones a GitHub renderer generates.

## Problem

The fragment reaching a heading is renderer-defined, so a lookup that invents its own spelling resolves to the wrong heading or to none.

## Proposal

Visible heading text is derived from the event stream: text and code content, link labels, image alternative text and decoded entities, with formatting delimiters and HTML tags excluded and line-break spacing normalized. Headings are enumerated in source order with duplicate numbering applied, and fresh state is kept per complete source document.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The renderer's documented formatting removal and duplicate numbering |
| Plan | The text derivation, the slug transformation and the duplicate state |
| Implementation | The slugger and its per-document state |
| Review | Collisions between a naturally suffixed heading and a generated suffix confirmed handled |
| Test | Compatibility fixtures covering punctuation, repeated spaces, inline markup, Unicode, duplicates and suffix collisions |
