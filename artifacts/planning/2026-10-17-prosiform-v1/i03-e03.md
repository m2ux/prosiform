## Overview

Caller cut-over moves every caller of `pf` to the production binary at one recorded release. Each caller is listed with how it resolves the command, each is pointed at the released binary, and an agent following the skill bootstrap proves the switch end to end.

## Problem

The production build is released, and nothing invokes it.

- **Callers are not listed.**
  The skill bootstrap, dispatch, the delivery wrapper and the evaluation harnesses each reach `pf` their own way, and no record says which.

- **Resolution follows the install.**
  A caller that runs whatever `pf` is on its path keeps running the prototype until that path changes.

- **A silent switch has no date.**
  Without a recorded release at which callers moved, a behaviour change cannot be placed before or after the cut-over.

## Proposal

- **An inventory first.**
  Every caller in the repository and the skill tree is listed with how it resolves the command.

- **Every caller resolves to the binary.**
  Each listed caller reaches the production binary through the documented install path.

- **The switch is recorded.**
  The release from which callers resolve to the production binary is named in that release's notes.

- **An agent proves it.**
  A smoke run of an agent following the skill bootstrap compiles and follows a bundle with the production binary.
