## Overview

Source-change detection before publication, and rejection of a generated document as input.

## Problem

Files are read during discovery and published after validation, so a source edited in between would be published from the bytes discovery captured; and a published bundle read back as input would have its generated structure rewritten as source.

## Proposal

Each source's canonical identity and content hash are captured at discovery and rechecked before publication; a changed, removed or relocated source fails with a retry message. A source whose first heading is a document-level H1 naming a document under the root, once a Markdown extension is appended, is rejected with its declared error code, while a heading-like line inside code is not a heading and is not detection. A bundle's own links are ordinary fragments, so the file heading is the only signal and the diagnostic says so.

## The Document a Title Points At

Detection rests on the first heading naming a document under the root **other than the one being read**. A bundle's first file heading names its first contributing source, which is never the bundle itself, so output still identifies itself. An authored document titled with its own name points at itself and bundles.

Without that condition the rule collides with the absorbed title's worked example: a document at `My Note.md` headed `# My Note` has a first heading whose text plus a Markdown extension names a document under the root, and the absorbed-title clause requires it to bundle. `identity/a-title-the-path-spells-with-a-space` is in the corpus and passing, so building the refusal without the condition turns it red.

The collision was found while delivering I00:E03:W04 and the contract was corrected then; this row builds the rule as corrected, and its fixtures state both sides — a real bundle refused, and a self-naming authored document bundled.
