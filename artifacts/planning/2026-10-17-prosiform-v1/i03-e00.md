## Overview

Differential conformance makes the two builds check each other. Both bundle every corpus input in continuous integration, their outputs are compared, and every dependency takes an exact pinned version, so the production build is proven against the prototype before any caller moves to it.

## Problem

Two implementations of one contract diverge quietly unless something compares them.

- **A corpus tests what it declares.**
  A behaviour no fixture declares can differ between the builds without any fixture failing.

- **An unpinned dependency changes the contract.**
  Parser behaviour on duplicate definitions, offsets and option-controlled extensions is what the profile rests on, so an unpinned upgrade can change how existing source is interpreted.

- **A fixture rewritten to pass hides a defect.**
  Changing an expectation so the production build passes converts a defect into a contract change, without a record that the contract changed.

## Proposal

- **Both builds run every input.**
  The differential run bundles each corpus input with both builds and compares the results byte for byte, so a divergence outside the declared expectations is still a failure.

- **Pins come after the fixtures pass.**
  Exact versions are chosen once the corpus holds against them, and the lockfile is what the run uses.

- **A fixture change is a decision.**
  An expectation changing to accommodate the production build is recorded with its reasoning before the change lands.

- **The prototype stays.**
  It is maintained as the oracle rather than removed once the production build passes.
