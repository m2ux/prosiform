## Overview

The freeze check and the tagged revision the production build targets.

## Problem

A build that targets the branch tip follows later refinement rather than the specification it was reviewed against.

## Proposal

A check refuses the freeze while any ledger entry is neither resolved nor deferred. Once it passes, the design and the corpus take one tagged revision. That tag is what the production build names as its target, and adopting a later revision is a recorded decision rather than a drift.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | What the tag must cover for the production build to target one revision |
| Plan | The check, the tagging and where the target revision is recorded |
| Implementation | The freeze check and the tag |
| Review | The tagged revision confirmed to cover both the design and the corpus |
| Test | The check refuses a tag while an entry is unresolved and undeferred, and accepts it once every entry carries a state |
