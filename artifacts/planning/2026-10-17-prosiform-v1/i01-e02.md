## Overview

Grouping is requested by name rather than inferred from a path. A caller names the sections to gather, the folders to gather, or both, and a name given to both reaches one output section. This epic replaces the single directory-and-depth option with those two, so the arrangement a bundle takes is the arrangement its caller asked for.

## Problem

One option carries two selections, so neither can be asked for alone.

- **Directory and depth travel together.**
  `--group SLUG:DEPTH` names a directory and a source-heading depth in one argument, so a caller wanting sections gathered by name has to accept the folder selection that comes with it.

- **A name a caller means twice has one destination it cannot reach.**
  Sections called `rules` and files under a folder called `rules` belong in one Rules section, and no argument asks for both.

- **Automatic folder grouping arrives uninvited.**
  Selecting by depth brings the folder arrangement whether or not the caller wanted it, so the default arrangement cannot be kept alongside a section gathering.

- **A collapsed wrapper has no rule.**
  Where a gathered section already carries the group's name, nothing states whether the result is one Rules section or Rules nested inside Rules.

## Proposal

- **A section group selects by heading name.**
  `--section-group rules` gathers the Rules sections the participating documents carry beneath one generated Rules section, wherever in the tree those documents sit.

- **A folder group selects by folder name.**
  `--folder-group rules` gathers the contributing documents under a matching rules folder beneath a generated Rules section, each a subsection titled from its filename stem.

- **One name reaches one destination.**
  Naming `rules` to both options merges the section and folder contributions into a single Rules section. A region both reach is emitted once, and a wrapper carrying the group's own name collapses into it rather than nesting beneath it.

- **Grouping is asked for, never assumed.**
  A run naming neither option takes the default document arrangement. Each option is repeated for each further group name.

- **Grouping arranges what was selected.**
  Membership is the selected documents and the non-deferred dependencies they reach, so a grouped run carries no unselected file and no deferred target's content. Entry and internal links resolve against the headings the arrangement emits.

- **The retired option leaves.**
  `--group` goes from the command, its help and its documentation, with no alias standing in for it.

## Acceptance Criteria

- [ ] **AC1.** A section carrying a grouped name is gathered under that group wherever its folder sits, as the fixtures covering matching and non-matching sections across directories show.
- [ ] **AC2.** A folder carrying a grouped name yields one parent section whose member subsections are titled from their filename stems, as the fixtures for heading-free and headed files show.
- [ ] **AC3.** One name given to both options yields one parent carrying each source region once and no same-named wrapper beneath it, as the overlapping section-and-folder fixtures show.
- [ ] **AC4.** A run naming neither option arranges its documents in the default arrangement, as the baseline fixtures show.
- [ ] **AC5.** A grouped run emits no file its selection did not reach and no deferred target's content, as the closure and harness-selection fixtures show.
- [ ] **AC6.** An entry link and an internal link resolve to the heading the grouped bundle emits, as the destination and collision tests show.
- [ ] **AC7.** The command takes the two grouping options and refuses the retired one, as the command-line tests and the help output show.
- [ ] **AC8.** The documented commands and the diagrams beside them carry the headings a run of them emits, as running those commands and comparing their output shows.

## Open Questions

- What matches a section name: its case, the inline formatting it carries, a name repeated in one document, and a heading at a depth other than the one its siblings take.
- What matches a folder name under nesting and repetition, and the order contributions take where a section and a folder both reach one group.
