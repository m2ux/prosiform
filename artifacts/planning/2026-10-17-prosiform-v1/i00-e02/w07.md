## Overview

An error code for every failing outcome the contract names, so the corpus can declare each one.

## Problem

The contract declares twelve error codes, each naming a defect in a source document or in the closure drawn from it. It names none for a fault in the command line itself other than a grouping rule, and none for an unexpected internal error, although it declares an exit status for both.

A diagnostic carries the stable code of the defect it reports. A failing outcome the contract names no code for therefore emits a diagnostic carrying a severity and a message and no code, since a code is the name of a defect the contract declares and inventing one puts a name in the tool that the contract does not carry.

A fixture's manifest requires a catalogued code for every diagnostic it declares. So the outcomes with no code are outcomes the corpus cannot state: a missing allowed source root, an unknown diagnostic format, an output path naming an input source, a fragment-only reference with no referring document, and an internal failure are each reachable, each declared an exit status, and each outside the corpus. The contract has behaviour its own conformance instrument structurally cannot reach.

## Proposal

The contract declares a code for each failing outcome it names, and the manifest schema's catalogue carries them, so the corpus can declare any outcome the contract declares.

The two documents are held in exact agreement by the catalogue test, which reads the design from the engineering branch and the catalogue from the schema. They therefore change as one piece of work: the design gains the codes, the schema's catalogue gains the same codes, and the fixtures that could not exist before are written against them.

A usage failure takes a code naming the fault in the command line, not the document the command line mentions, so a caller reading the code is not sent to look at its sources. An internal failure takes one code of its own, which the contract already forbids being reported as a source-document defect.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The failing outcomes the contract names, the code each one lacks, and which of them a fixture could declare once it has one |
| Plan | The codes, their names and the clause each is declared under; the order the design and the schema change in, so the window where they disagree is bounded |
| Implementation | The design's codes, the schema's catalogue, and a fixture for each usage failure that now has a code |
| Review | Every failing outcome the contract names carries a code, no code names a defect the contract does not declare, and the catalogue test holds both directions |
| Test | The catalogue test against the changed design and schema; a fixture declaring a usage failure by its code; a manifest naming a code the catalogue does not carry failing validation |
