## Overview

Regeneration of the clause-to-fixture mapping with each revision.

## Problem

A design clause added during refinement has no fixture and produces no failure, so the gap presents as a passing corpus.

## Proposal

The conformance report's mapping is regenerated whenever the design or the corpus changes, so a clause added without a fixture appears in the uncovered list on the revision that added it rather than at the end of the stage.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The report's existing mapping against a design that changes under it |
| Plan | When regeneration runs and what a changed uncovered list reports |
| Implementation | The regeneration and its reporting |
| Review | A revision adding a clause confirmed to surface it as uncovered |
| Test | A revision that adds an unfixtured clause produces that clause in the uncovered list, and one that adds a fixtured clause does not |
