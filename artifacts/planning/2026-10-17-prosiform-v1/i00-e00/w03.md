## Overview

The commands that run the tests and the static checks, and the term inventory the vocabulary check measures the shipped glossary against.

## Problem

Every later epic carries tests, and nothing states how they are discovered, how they are run, or what reports a failure.

The three checks W01 brought with it are standalone scripts outside that scheme, and one of them rests on a source that is leaving. `checks/vocabulary.py` reads its term inventory from the glossary in the planning record at a hard-coded dated path, so the check reports a term is defined only because a second, unshipped glossary also defines it. The shipped glossary is the one copy the design calls for, and a check that measures it against itself establishes nothing.

## Proposal

Tests, lint, format and type checks are each a named command with a declared configuration: test discovery and reporting, a linter, a formatter in check mode, and a type checker. Each returns a nonzero status when it fails, so one runner can drive them all and a failure is attributable to the check that produced it. The layout, link and vocabulary checks join that scheme as named commands.

The vocabulary check takes its term inventory from the sources the contract is stated in — the design and the acceptance criteria — rather than from a second glossary, so `docs/glossary.md` is the one glossary the repository holds and the check compares it with the usage it must cover. The planning record's glossary then ends as a planning artifact with no runtime consumer. No path to a dated planning folder survives in a check, so superseding that folder breaks nothing.
