## Overview

The commands that run the tests and the static checks.

## Problem

Every later epic carries tests, and nothing states how they are discovered, how they are run, or what reports a failure.

## Proposal

Tests, lint, format and type checks are each a named command with a declared configuration: test discovery and reporting, a linter, a formatter in check mode, and a type checker. Each returns a nonzero status when it fails, so one runner can drive them all and a failure is attributable to the check that produced it.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The check tools that fit the declared Python version and the build's shape |
| Plan | The command names, their configuration and their failure behaviour |
| Implementation | The configurations and the commands |
| Review | Each command confirmed to fail with a nonzero status and to name the check that failed |
| Test | Each command run against a deliberate violation of the rule it enforces, and against the clean tree |
