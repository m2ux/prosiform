## Overview

Continuous integration running the same commands a developer runs.

## Problem

A check that exists only locally passes silently when it is skipped, and one that exists only remotely cannot be reproduced before a change is pushed.

## Proposal

A continuous-integration job installs the environment from the lockfile and runs the documented check commands, failing the change when one of them fails. It invokes those commands rather than reimplementing them, so a local run and a remote run exercise the same configuration.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The job environment and how it obtains the locked dependencies |
| Plan | The job's steps, each naming a documented command |
| Implementation | The job and its wiring to the lockfile and the commands |
| Review | Confirmed that the job runs the documented commands rather than its own variants |
| Test | A deliberate violation of each check fails the job, and the clean tree passes it |
