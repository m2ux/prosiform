## Overview

The check that the corpus and its report bind behaviour rather than an implementation.

## Problem

A fixture naming a module, a flag spelling or an error-message wording specific to one implementation binds that implementation rather than the contract.

## Proposal

The corpus and the report are scanned for references to an implementation language, module path, internal identifier or internal error wording. A hit fails the check and names the fixture and the term. Declared error codes and the command's own documented options are not implementation references.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | What distinguishes a declared interface term from an implementation term |
| Plan | The term list, the scan and its exclusions |
| Implementation | The independence check |
| Review | The exclusions confirmed to admit no implementation term |
| Test | The check fails on a fixture carrying an implementation module name and passes on the corpus as it stands |
