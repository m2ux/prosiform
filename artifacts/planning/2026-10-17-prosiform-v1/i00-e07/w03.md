## Overview

Documentation of the invocation, checked against the command's own help.

## Problem

Each caller invents its own arguments, so a bundling that fails for one caller is not reproducible for another.

## Proposal

The repository documents the entry point's options, their defaults, the exit statuses and the profile identifier. A check compares that documentation with the command's own help output, so the two cannot drift apart.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The option and status surface the command exposes |
| Plan | The documentation's location and the comparison the check performs |
| Implementation | The documentation and the check |
| Review | Each documented option confirmed present in the help output and each help option documented |
| Test | The check fails on a documented option the command does not expose and passes on the current surface |

## The Supported Environment This Row Declares

The build reads every source through rooted, no-follow access, which rests on POSIX open flags. `access.py` raises on a platform that lacks them, so the build refuses to run rather than following a link it cannot refuse — which is the failing half of the contract's requirement that a platform unable to enforce the policy "fail or declare a narrower supported environment".

The declaring half is this row's. The documented invocation states which platforms the build supports and that the support rests on no-follow access, so a caller on another platform reads the limit rather than discovering it as an import failure. It is carried here because this is the document a caller reads for the entry point's options, defaults and exit statuses, and the supported environment is the same kind of fact.
