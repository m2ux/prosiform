## Overview

Distribution makes the production build something a caller can install. A tagged release publishes a versioned Rust binary, one documented install path places it as `pf`, and the invocation documentation is held to that binary's own help.

## Problem

A build that passes the corpus still reaches no caller.

- **No release carries the binary.**
  The Rust build produces an artifact only inside a developer's checkout.

- **The install path delivers the prototype.**
  The documented installation places the Python package's entry point as `pf`.

- **The documentation describes the prototype.**
  The invocation reference is checked against the Python command's help, so options, defaults and exit statuses the binary states differently go unnoticed.

## Proposal

- **A tag builds the release.**
  A release workflow builds a Linux x86_64 binary from the pinned lockfile on a version tag and attaches it to that release as a release asset. A further platform is added when a caller needs it.

- **One install path.**
  The documentation states one command that installs the released binary as `pf`, and a smoke run installs it that way.

- **The documentation is held to the binary.**
  The invocation check compares the reference against the production binary's help output.
