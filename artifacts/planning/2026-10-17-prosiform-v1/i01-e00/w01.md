**Component:** ledger

## Overview

The ledger that holds what use reveals, and the triage states an entry moves through.

## Problem

A surprise met mid-task competes with the task, so without a cheap place to record it the cheapest action is a local workaround.

## Proposal

The ledger is a folder at the root of `main`, beside the schema check that reads it, so one revision of the repository carries both. Each entry carries its date, the invocation, the source identities it bundled, the observed result and the result expected, and one triage state among design change, corpus gap, build defect and no change, with a reason. A schema check validates every entry.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | What a later reader needs to reproduce an entry without the original session |
| Plan | The entry fields, the triage states and the schema |
| Implementation | The ledger folder on `main`, its schema, the declared exposure set, and the check run by `make check` |
| Review | An entry confirmed reproducible from its recorded fields alone |
| Test | The schema check rejects an entry missing each required field in turn and accepts the recorded entries |
