**Component:** ledger

## Overview

Enters the demonstration's measurements in the ledger, so the first runs and findings it holds are the ones already taken rather than ones waiting for new use.

## Problem

The demonstration bundled every mode of the worked example on a tagged revision and measured two findings along the way — the Understand Mode dispatch saving and the route that pushed `modes/deliver-mode.md` past the default budget. Those figures sit in planning prose beside the work that met them, so neither counts as a run or can be reduced to a fixture.

## Proposal

A reader opens the ledger and finds a run record for each mode bundle the demonstration published, taken on `demo/i02`, and an entry for each measurement the demonstration recorded, citing that revision and the planning record that measured it. Each entry carries its triage state, so a finding already resolved by the demonstration reads as resolved.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The demonstration's mode bundles and every measurement its planning records hold |
| Plan | The run record and entry for each, and the triage state each takes |
| Implementation | The records and entries written to the ledger |
| Review | Each entry read against the planning record it cites |
| Test | The ledger's schema check over the new records |
