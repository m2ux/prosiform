## Overview

The ledger is where what use reveals is kept, and the capture tool is what makes an entry something that can be re-run. Together they turn a surprise met while bundling into evidence a revision can be judged against.

## Problem

A finding met mid-task competes with the task, and a finding stated in words cannot be re-run.

- **The cheapest action is a local workaround.**
  The agent is carrying out a procedure, so without a recorded place for a surprise the surprise is absorbed and the design keeps its original claim.

- **Prose is not reproducible.**
  A finding described in sentences cannot establish whether a later change fixed it, so the question becomes a matter of opinion.

- **An untriaged entry is a backlog item.**
  An entry nobody classifies never reaches the design, the corpus or the build, and accumulates instead.

- **A real source tree is not a fixture.**
  The skill tree that triggered a surprise is too large to serve as a fixture and carries content the finding does not need.

## Proposal

- **The ledger is a file in the planning record.**
  Each entry carries its date, the invocation, the source identities it bundled, the observed result and the result expected.

- **Triage is part of the entry.**
  One state among design change, corpus gap, build defect and no change, with the reason for it. A schema check validates every entry.

- **A capture tool reduces an entry to a fixture.**
  It takes the invocation and the source closure the entry reached and emits the smallest fixture directory and manifest that still reproduces the observed result.

- **The ledger records runs, not only surprises.**
  Each bundling run is recorded with the source identities it bundled and its outcome, and a surprise entry cites the run it came from. A ledger holding only surprises cannot show whether the tool was used.

- **A run records whether the entry was found.**
  The bundle names what it was built for in its entry line, and whether that is enough is a question about agent behaviour that no reading of the design settles. Each run records whether the entry's content was acted on from the bundle alone, so the arrangement has evidence rather than argument behind it.

- **A run is measured against what it replaces.**
  Each run record carries the bundled output size and the total size of the same sources read whole, so the retrieval cost the proposal measured has a bundled figure to sit beside.

- **The exposure set is declared once.**
  It names the real sources the tool must have bundled before the specification can be called settled, and it is written down at the start of the stage rather than chosen at its end.

- **A reduced fixture waits with its entry.**
  It enters the corpus with the revision that resolves the entry, so the corpus never carries a fixture declared to fail.
