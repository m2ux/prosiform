**Component:** example/work-planner

## Overview

Every rule of the example states once and every consumer links it. Each file the authoring check's size report names holds one subject, recorded with the reason it is not split.

## Problem

The example repeats shared rules inside operations rather than linking a home:

- The command-result rule — read the preceding command's exit code and output, and return an execution error or refusal before continuing — is written out in 61 steps across five artifact files.
- The body-writing helper's result rule is written out in six steps across two files.
- The rule that a board read can lag a write, so the same write and the item read repeat, appears in four places.
- The dispatch rules stated in `rules.md` are restated in the guidelines' Modes section.

## Proposal

- **One home per shared rule.**
  State the command-result rule and the body-writing helper's result rule in `conventions.md`, add the lagging board read to its Write confirmation entry, and replace each restatement with a link naming that anchor. Move the dispatch condition the guidelines add alone into `rules.md` Execution, and link it from the guidelines' Modes section.
- **Conditions survive the link.**
  Keep every operative condition each replaced sentence carried; a condition specific to a step stays in that step.
- **Subject review.**
  Read each file the size report names for operations that share no contract and apply nothing across a possible cut. Record the subject found and the reason no split follows; split only where a second subject genuinely exists.
- **Bundles follow.**
  Regenerate every usage-example bundle whose bytes the edited files reach, with the corpus tooling rather than by hand.
