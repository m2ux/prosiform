**Component:** evals/diagram-following/baseline.json

## Overview

One baseline over the hardened corpus, carrying every form the matrix runs: the four the eval already knew and the dispatch scenarios' compiled and authored forms beside them. This is the first measured pass rate the dispatch scenarios have, and it is the reference later runs compare against.

## Problem

- **The baseline carries three of the forms the matrix runs.**
  `baseline.json` holds 150 sessions over `bundle`, `tree` and `prose`, so every `linked` cell of a report reads `new`.
- **The dispatch forms have no baseline at all.**
  The compiled and authored forms are newer than the committed baseline, so a dispatch scenario's pass rate has nothing to be compared with.
- **One file holds one baseline.**
  `report.py` writes the baseline whole, so a dispatch run and a corpus run cannot each commit one: the second replaces the first. The forms and the dispatch scenarios therefore share one run.

## Proposal

- **Cost first.**
  The run's estimate is put to the user before it starts, and the run starts only on their approval.
- **One run over the default matrix.**
  `make eval-diagrams` over the hardened corpus, every form each workflow is written in, both dispatch forms among them, the default models and five repetitions.
- **Review.**
  Every failing session is read: a failure caused by an ambiguous scenario or an unclear protocol is a corpus defect, fixed and the affected cells re-run before the baseline is taken.
- **Record.**
  The baseline file and the run's report are committed, and the eval's README states the measured cost of the matrix it covers.
