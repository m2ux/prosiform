**Component:** evals/diagram-following/workflows

## Overview

The eval's scenarios are easy enough that every cell of the committed baseline is 5 of 5. This task raises the corpus's difficulty until a plausible misreading produces each failure class the scorer defines, so a run's failures say which way an agent departed rather than only that it stumbled.

## Problem

- **Every cell is saturated.**
  The committed baseline holds 30 cells, every one 5 passed of 5, with zero recorded failures of any class.
- **Five scenarios cannot reach eight classes.**
  The corpus holds five scenarios over three workflows: `straight-through`, `high-severity`, `low-severity`, `no-rework` and `two-rounds`. A linear three-state workflow offers nothing to mis-branch at, and a two-round loop is short enough to miscount by luck rather than by error.
- **Nothing tests that a class is reachable.**
  The scorer holds seven classes beside `errored`, and no test asserts each has a scenario that can produce it, so a class could become dead without a failure.

## Proposal

- **Difficulty comes from the scenarios.**
  Each class gets at least one scenario a plausible misreading fails: a second decision, a longer loop with a counted bound, a state reachable only through a link, and a distractor state no edge leads to.
- **Every class is held reachable.**
  The corpus test asserts that each of the seven classes and `errored` has a scenario able to produce it, and names any class no scenario reaches.
- **The diagrams, prose and linked forms stay consistent.**
  A new scenario's path is still the walk of its workflow's diagram from the start state to a terminal one, so the corpus test continues to hold the three forms to one statement of the edges.
- **The result is measured by the baseline.**
  Success is a committed default-matrix run carrying a cell below 1.0. A harder corpus that still saturates is reported as not separating the forms rather than accepted.
