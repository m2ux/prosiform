**Component:** fixtures

## Overview

Every corpus family that described a declared root states declaration instead: its fixture names, descriptions, clause cases and source prose speak of the declaring target and the invocation working directory, and `make corpus` passes with every expected bundle unchanged except the lines whose prose this rewrite touches.

## Problem

[W01](https://github.com/m2ux/prosiform/pull/487) withdrew `root` from every fixture and [W03](https://github.com/m2ux/prosiform/pull/493) declared every target the run compiles, so the corpus runs the new rule. Its words still state the old one.

- **Families are named for the root.** Twenty fixtures carry `the-root`, `allowed-source-root` or `root-escape` in their path, though no source declares a root and the run's only bound is the invocation working directory.
- **A fixture proves the opposite of its name.** `reference/a-document-outside-the-root-is-text` puts its target above the working directory, which no run opens whatever it declares, so it shows nothing about a silent target.
- **Descriptions and prose state a root.** Forty-six manifest descriptions say "under the allowed source root", two clause cases name the root as the confinement boundary, and a dozen source documents say "the document the root holds" or "above the root".
- **The copied-source rule contradicts its copies.** The `real-source/` family states a copy is never edited, while each of its six sources carries a `prosiform` declaration its upstream original lacks.
- **The corpus README describes a root.** Its tree example, `invocation.cwd` row, `-r` fault row and code catalogue name a root, and one row says `E_INVALID_FRONTMATTER` covers an invalid root.

## Proposal

**The scene.** A fixture is a directory with `manifest.toml`, `source/` and `expected/`, run from the `cwd` its manifest names. A link inside a source resolves from its file; it is compiled when its target declares `prosiform`, is text when the target declares nothing, and is text when it normalizes above the working directory, which bounds every source the run reads.

**The design.**

- **Fixtures are named for what they prove.** A fixture about a path above or below the run's bound says "working directory"; one about a compiled target says "declaring". `extraction/a-setext-heading-as-a-root`, the `root-relative` fixtures and `inclusion/a-declared-root-is-refused` keep their names: each names a section root, a URL form or the refused field.
- **The silent-target fixture states its rule.** `reference/a-silent-target-above-the-writing-directory-is-text` writes its link from `source/notes/guide.md` to `source/guidelines.md`, inside the working directory and above the writing document, and the target carries raw HTML the profile refuses, so the run publishing shows the declaration decided it.
- **Descriptions, clause cases and prose name the working directory.** No description says "allowed source root"; the two clause cases name the invocation working directory; source prose naming a root is rewritten and its expected bundle re-derived from the build.
- **A copy adds its declaration and nothing else.** The `real-source/` statement admits the `prosiform: {}` each copy opens with, and holds the copy to its original with that declaration removed. The build reads a declaration from the document alone, so a fixture-supplied setting would state a rule the design does not carry.
- **The corpus README states declaration.** Its rows name the working directory, the `-r` row links the renamed fixture, and the Declarations section states that a target is compiled when it declares.
