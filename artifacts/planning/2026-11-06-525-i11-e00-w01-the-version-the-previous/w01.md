## Overview

The release record states the `contract/v0.15.0` corpus's result against the release build and the version that result selects, so the bump is a measured fact rather than a judgement.

## Problem

- **The bump is read, not chosen.**
  `docs/versioning.md` settles it by running the previous revision's corpus against the new build, and `main` already declares a version no tag carries.
- **The tag messages cite the result.**
  The `contract/` tag states the previous corpus's result, so the run is recorded before the tags.

## Proposal

**The scene.** `contract/v0.15.0`'s corpus is the fixtures at that tag; `make corpus` runs a corpus against the build `PROSIFORM_BUILD` names.

- **The previous corpus against the release build.**
  Run the `contract/v0.15.0` fixtures against the build at `origin/main` and record each failure.
- **The version follows the rule.**
  Any failure is incompatible, which below 1.0 bumps the minor; a fixture added and none failing is a minor change; neither failing nor added is a patch. The record states the version selected.
