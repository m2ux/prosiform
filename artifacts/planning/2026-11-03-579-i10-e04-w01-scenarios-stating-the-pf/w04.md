**Component:** main:evals/diagram-following/harness.py

## Overview

Each harness reports every sub-agent's starts and shell commands at every dispatch depth its stream carries, filed under the section the sub-agent followed, so a scenario can state what a sub-agent three hops down did.

## Problem

- **A sub-agent's calls are unattributed.**
  `starts` lists every start in one sequence and `commands` reads the session's shell calls; nothing says which sub-agent made a start or ran a command.
- **Depth was assumed.**
  The opencode harness declares that a sub-agent's own calls reach the session's stream, which no recorded transcript showed.

## Proposal

**The scene.** A workflow is a directory under `workflows/`, its forms beside a `scenarios.toml` naming each scenario's inputs, the path a correct session walks, the sub-agents it starts and the `pf` runs it makes. A `staged` session receives the compiled bundle set with the build under test as `pf` on its path; the scenario passes when the session's path is the one its bundle states.

- **Calls are attributed.**
  Each start names `parent`, the index of the start whose sub-agent made it, and `commands`, the shell commands that sub-agent ran; `subagents.json` holds the session's own `commands` beside its starts.
- **Depth is read, not assumed.**
  `sub_agent_calls` declares whether a sub-agent's own tool calls reach the session's stream. Claude's stream carries them, each message naming its `parent_tool_use_id`; Cursor's reports a sub-agent's text and no tool call it made; opencode's run command prints only the parts of the session it started, so it is declared as carrying none.
