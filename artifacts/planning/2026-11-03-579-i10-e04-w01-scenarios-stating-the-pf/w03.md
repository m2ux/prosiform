**Component:** main:evals/diagram-following/score.py

## Overview

The scorer holds a session that walked its path to the `pf` runs its scenario states, so compiling too little, too much or out of order is a named failure.

## Problem

- **Compiling is one boolean.**
  `compiled_by` asks only whether any command began with `pf`, so a session that compiled a line its path never reached passes.

## Proposal

**The scene.** A workflow is a directory under `workflows/`, its forms beside a `scenarios.toml` naming each scenario's inputs, the path a correct session walks, the sub-agents it starts and the `pf` runs it makes. A `staged` session receives the compiled bundle set with the build under test as `pf` on its path; the scenario passes when the session's path is the one its bundle states.

- **A run record is a check after the path.**
  Read after the path, the actions and the dispatch checks, against the commands the session record holds for the session and for each sub-agent, wherever the harness reports commands at all.
- **A run is read from a command.**
  A command is split at `;`, `&&`, `||` and `|`; a segment whose first word is `pf`, or a path ending `/pf`, is a run, and its references are its words other than options and their values. A reference matches a stated one when equal to it or ending `/<stated>`, so a run from the workspace root names the same document as one from the skill's directory.
- **Three departures fail.**
  `uncompiled`: a stated run was not made. `overcompiled`: a run naming a reference matched no stated run, as one on a deferred line the path did not reach is. `misordered_compile`: an agent made its stated runs in another order. A bare `pf` beyond those stated is no departure.
- **Each class joins the rubric.**
  The three classes reach `RUNBOOK.md`'s triage rubric with I10:E05 W00, which is not on this unit's base; that entry is a further task.
