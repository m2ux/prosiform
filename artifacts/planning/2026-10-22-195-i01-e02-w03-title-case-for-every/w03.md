**Component:** [src/prosiform/bundle.py](https://github.com/m2ux/prosiform/blob/main/src/prosiform/bundle.py)

## Overview

One title-casing convention over every heading the compiler generates.

## Problem

The group construction title-cases the name it carries and the document arrangement emits the path it derived, so one run produces `# Rules` beside `# procedure` and `# rules/codex`. The rendered diagrams carry both spellings, so the mixed output reads as the intended output.

## Proposal

The casing the group construction applies becomes the convention every generated heading takes, path structure preserved. A heading an author wrote and a filesystem path a run names keep the spelling their source gave them, so the convention reaches what the compiler wrote and nothing else.

- **The convention is stated once.** `title_cased` capitalizes each word of a name and keeps every separator the name carries, so a nested path keeps its slashes and a hyphenated name keeps its hyphens with each part capitalized. The file heading is the path the convention is applied to.
- **The boundary is the compiler's own writing.** An authored heading is emitted as its author spelled it; a deferred link's destination, a diagnostic's reference and the manifest a run names a source in carry the spelling the filesystem holds.
- **A file heading still names its document.** Two documents whose paths differ only by the capitalization of their letters now head one file group text, which is the ambiguity `E_AMBIGUOUS_FILE_GROUP` already refuses. Generated-input detection reads a file heading as written and in lower case, since the convention raises a word's first letter and changes nothing else.
