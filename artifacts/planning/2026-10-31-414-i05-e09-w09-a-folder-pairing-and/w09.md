**Component:** src/prosiform/cli.py

## Overview

A mapping side ending in a separator makes its entry a **folder pairing**. The key folder matches every reference whose normalised path sits under it, the substitute folder takes the same remainder, the reference keeps the section it named, and exact keys answer before folder keys — with the longer of two matching folders winning.

## Problem

The mapping holds one kind of key, and a folder of stand-ins costs one entry per file.

- **`cli.mock` reads each side as one document.** It partitions on `SUBSTITUTION_PAIR` and calls `entry` on each side, so a side is a reference to a document or a section and nothing else.
- **A trailing separator is normalised away.** `closure.normalized` drops an empty path segment, so `rules/` and `rules` normalise to one path and the separator that would state the folder is gone before anything can read it.
- **The Markdown-suffix test would refuse a folder.** W12 (`AC24`) refuses a value whose path names no Markdown document, and `rules/` names none, so a folder side tested as a document would fail the refusal that protects every document pairing.
- **The lookup knows two keys.** `Substitution.key` asks `(path, fragment)` then `(path, None)`. A reference under a folder matches neither, so a folder key has nowhere to answer.
- **`rules/visual/` and `rules/` both hold one reference.** The answer cannot be whichever a dictionary happens to yield, so the precedence between folders is a decision rather than an accident.

## Proposal

**The scene.** `mock(value)` partitions the pair, reads the folder marker from each side before the reference grammar sees it, and `substitution(options)` folds the pairs into a `Substitution` holding document keys and folder keys alike. `Substitution.substitute(found)` asks one lookup and returns the reference the mapping names.

**The design.**

- **The separator is read before normalisation.** `cli.marked` reads the path component of each side and reports whether it ends in a separator. `mock` states the marker on the `Pairing` it returns and reads the side through `entry` whole, so `rules/` and `rules` stay one path identity for matching while stating two different kinds. Reading the marker from the path component alone means `rules/#checks` is a folder side carrying a section rather than a side whose text happens to end in `#checks`.
- **Both sides agree or the pair is refused.** One folder side and one document side fails the grammar with `E_INVALID_USAGE`, exit status `2`, naming the pair as the author wrote it. A folder and a file state different questions and one entry cannot ask both.
- **A folder side is read by the reference grammar.** Percent decoding, control-character refusal and `..` normalisation all apply, and the Markdown-suffix test is applied to the path each reference resolves to under the substitute folder rather than to the folder, so a folder key is not refused for naming no document.
- **A folder side carries no fragment.** A side marked a folder whose text carries `#` is refused, because a folder names no section. A substitute side carrying one is refused on the same ground.
- **The lookup answers exact first, then the longest folder.** `Substitution.answering` asks `(path, fragment)`, then `(path, None)`, then each folder key whose prefix holds the path, longest first, and returns the key with the substitute it names in one answer so the lookup and the redirect record cannot disagree about which of two keys holds.
- **The remainder is appended and the section is the reference's.** A folder key `k` answering for path `p` yields `substitute_path + p[len(k):]`, and `substitute` keeps `found.fragment`, so `rules/red.md#checks` redirects to `stubs/red.md#checks`.
- **A folder key that answered nothing warns once.** `unserved` reads document keys and folder keys alike, so `W_MOCK_UNUSED` names `rules/` as written.
- **A redirect is recorded per substituted document.** `Redirects` keys its records by the served key and the substitute's path rather than by the key alone, so a document key serving a document and one of its sections states one substitution, and a folder key answering two references states one per document it answered. `AC7` requires one `W_MOCK_SUBSTITUTED` per target, and a folder key's targets are several.
- **A folder needs a declaring substitute once inclusion is by declaration.** A substitute is read because it declares, so a stub folder carries `prosiform` in every stub. That rule is [I05:E11](https://github.com/m2ux/prosiform/issues/434)'s and this row states it rather than depending on it: the mechanism here is buildable and testable before that epic lands. Every document of each fixture declares from the first, so no fixture changes with that epic. On this branch the declaration bounds inclusion no further than the writing source's root already does — each fixture was run with and without it and expects the same bundle, and only the link's line moved, which the frontmatter shifts.

## Additions from review

| Addition | What it states |
| --- | --- |
| The redirect record is kept per substituted document | `AC7` states one warning per redirected target, and a folder key has one target per document it answers. A record kept under the key alone collapses them into the first, which a folder pairing makes routine rather than incidental. |
| The marker is read from the path component, not the whole side | A side is `ORIGINAL` and `ORIGINAL` may carry a query or a section. Reading `text.endswith("/")` would refuse `rules/#checks` as a document rather than as a folder carrying a section, and would read `rules/?q` as neither. |
| The fixtures declare from the first | `fixtures.md`'s stub-declaration rule is [I05:E11](https://github.com/m2ux/prosiform/issues/434)'s, and the epic record states the fixtures declare from the first so neither changes when that epic lands.
