## Overview

The checks page lists every check and states that continuous integration runs the same names. This task states on it which changes run the checks and what a pull request reports when its change runs none.

## Problem

- **The rule lives in a workflow comment.**
  The checks page says continuous integration runs `make check`, and says nothing about which changes start it. The trigger is described only in the comments of `.github/workflows/checks.yml`.

## Proposal

**The scene.** A reader judging a merge reads the checks page, not the workflow file.

- **The page states the rule.**
  It names the paths whose change runs the checks and the events that start them, matching the workflow's own statement.
- **The page states the skip.**
  It says what a pull request changing none of those paths reports, so a reader of a merge record knows how an unchecked change reads.
