**Component:** checks/render.py, fixtures/

## Overview

A Gantt diagram's link is proven in a running page: `make render` loads each Gantt fixture's bundle, clicks each clickable task and holds the URL each click opens to the group heading the bundle carries.

## Problem

Mermaid 11.16.0 draws a Gantt task's link as no anchor. `setLink` binds a click handler calling `window.open(link, "_self")` once the page runs, so a static render of the bundle carries no destination to read ([W05–W08 validation, T10](../2026-10-27-339-i05-e02-w05-link-forms-as-mermaid/validation.md#t10-every-diagram-link-form-rendered)).

## Proposal

- **mermaid-cli drives no click.**
  Its `renderMermaid` inserts the SVG and never calls the `bindFunctions` the render returns, so its page carries no handler.
- **The page driver.**
  `checks/click.mjs` resolves the puppeteer and the Mermaid that mermaid-cli ships from its `mmdc`, renders each diagram in a headless page, binds the handlers, replaces `window.open` with a recorder, clicks each `.task.clickable` bar and reports the URLs each click received. It runs offline: the page is set from a string and Mermaid is added as an inline script.
- **The check.**
  `checks/render.py` lists the Gantt fixture under `CLICKED`, runs the driver as `node` under the words of `MERMAID_CLI` before `mmdc`, and holds the opened URLs to the fixture's list and to the bundle's headings, as it holds rendered anchors. A click opening anything but one URL fails.
- **No new dependency.**
  Node, puppeteer and Chromium are those mermaid-cli already needs.
