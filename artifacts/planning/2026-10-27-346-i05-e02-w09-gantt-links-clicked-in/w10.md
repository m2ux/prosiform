**Component:** src/prosiform/source.py, src/prosiform/profile.py

## Overview

A Kanban ticket's link and an HTML anchor in a node label naming a local Markdown document end the run in `E_UNSUPPORTED_CONSTRUCT` naming the line. One naming a remote address is carried as written.

## Problem

Under Mermaid 11.16.0 both render followable anchors: `ticketBaseUrl: 'people/#TICKET#.md'` with a ticket `user` draws `<a class="kanban-ticket-link" xlink:href="people/user.md">`, and a label `<a href='people/user.md'>` draws `<a href="people/user.md">`. Neither is a use, so a bundle ships a link to a file it does not hold and the run exits `0` ([#347](https://github.com/m2ux/prosiform/issues/347)).

## Proposal

- **The read.**
  `read_diagram` holds each unfollowed link beside its clicks. In a `kanban` diagram, a node whose `@{…}` metadata names a `ticket` renders the `ticketBaseUrl` the fence's front matter `config` or an `init` directive sets, its first `#TICKET#` replaced by the ticket. On any diagram line but a comment, an `<a … href=…>` renders its `href`.
- **The refusal.**
  `profile.diagram_refusals` refuses each unfollowed link whose path, before its query or fragment, carries no scheme, no authority and a Markdown suffix, under `E_UNSUPPORTED_CONSTRUCT` naming its line. The scheme and authority test moves to `source.py`, so the profile and the resolution share one.
- **The boundary fixture.**
  `reference/diagram-links-outside-the-forms-read` keeps the C4 `$link` and the pie chart; the refused forms move to fixtures of their own.
