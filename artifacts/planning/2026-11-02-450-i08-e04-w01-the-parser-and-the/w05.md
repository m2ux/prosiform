**Component:** main:fixtures/source-consistency/a-source-that-changes-during-compilation/manifest.toml

## Overview

The three existing fault fixtures pass unchanged through the new channel, which shows the mechanism moved and the behaviour did not.

## Problem

The three fixtures are the evidence the faults still work.

- **`a-source-that-changes-during-compilation` exercises the recheck.** It is the only fixture of the mechanism that keeps a run from publishing bytes it no longer reads.
- **`a-run-that-fails-in-itself` exercises exit status `4`.** Nothing in a well-formed tree produces an internal error.
- **`an-earlier-set-the-run-cannot-remove-warns` exercises the retention warning.** A directory the run cannot remove is unreachable from a tree.
- **Their manifests already declare a field, not a flag.** A changed expected result would show the behaviour moved when only the channel should.

## Proposal

**The scene.** Each manifest declares `fault = "<name>"` and its expected result, and the runner asks the build for that fault.

**The design.**

- **No fixture changes.** The three manifests keep their declarations and expected results.
- **A diff proves it.** `git diff origin/i08/e04/main` over the three fixture directories is empty.
- **The refusal has its own fixture.** `cli/an-unknown-fault-is-invalid-usage` is W01's.
