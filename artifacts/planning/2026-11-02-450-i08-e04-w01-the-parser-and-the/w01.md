**Component:** main:src/prosiform/cli.py

## Overview

The parser declares no fault option, the run reads `PROSIFORM_FAULT` once where the option's value was read, and a value outside the three is invalid usage.

## Problem

The fault arrives through a shipped flag and the run reads it from the parsed options.

- **`parser()` declares it.** `-x` takes a choice of the three names with `dest="fault"`, so the grammar admits it like any other option.
- **`execute` reads `options.fault` at three points.** Once before `rewrite_sources`, once to raise `Faulted`, and once as `publication`'s `retained` argument.
- **`diagnostic_format` walks its value.** That function steps over the value of every option that takes one, so its set names `x`.
- **An unknown value has no path.** A grammar choice cannot meet one; a variable can, and the run has to refuse it.

## Proposal

**The scene.** `main` parses the command line, `execute` runs the compilation, and `publication` takes a `retained` flag.

**The design.**

- **The option is removed.** `parser()` declares no `-x`, and `diagnostic_format`'s set of value-taking options omits it.
- **One read of the environment.** `conformance_fault(environment)` reads `PROSIFORM_FAULT` once, after the informational responses and before any reference is resolved, and returns the fault or `None`. The three sites compare that one value.
- **An unrecognized value is invalid usage.** A value outside the three, the empty string among them, fails with `E_INVALID_USAGE` and exit status `2`, naming the value and the three admitted.
- **An absent variable is no fault.** Every run a caller starts performs exactly what it performed before.
