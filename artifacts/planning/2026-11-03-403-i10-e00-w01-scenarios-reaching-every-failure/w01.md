## Overview

The eval's scenarios are easy enough that every cell of the committed baseline is 5 of 5. This task raises the corpus's difficulty until a plausible misreading produces each failure class the scorer defines, so a run's failures say which way an agent departed rather than only that it stumbled.

## Problem

- **Every cell is saturated.**
  The committed baseline holds 30 cells, every one 5 passed of 5, with no recorded failure of any class. The proof's shakedown passed 30 of 30 feature sessions on `claude-haiku-5-5`, so the present workflows do not separate even the default matrix's model.
- **The diagram workflows cannot reach every class.**
  `linear`, `branching` and `looping` carry five scenarios. A linear workflow offers nothing to mis-branch at, and a two-round loop is short enough to miscount by luck rather than by error.
- **Nothing tests that a class is reachable.**
  The scorer defines eleven classes beside `errored`, and no test asserts each has a scenario that can produce it, so a class can go dead without a failure.

## Proposal

**The scene.** `make harness` bundles every form of every workflow, holds each scenario's path to the walk of its diagram, and scores stub runs against it. A scenario is what makes a mistake possible; the workflow's diagram, prose and linked forms are the product under test.

- **Difficulty comes from the scenarios.**
  Two workflows, each in the `bundle`, `tree`, `prose` and `linked` forms, carry the misreadings `claude-haiku-5-5` makes:
  - `pricing` puts a second decision after the first, each read from its own input, so a branch carried from the first decision is `wrong_branch`. It also draws `Refund`, linked from the terminal `Invoice`'s section, with no edge leading to it, so following the link is `invalid_transition`.
  - `rework` runs a four-round loop whose bound counts `Retest`, a state no click names and `Rework`'s section links, so a miscount is `loop_miscount` and passing over the linked state is `skipped_state`.
- **Every class is held reachable.**
  The corpus test scores each scenario's path departed from once at every point (an action undone, the last state left out, a state the diagram does not hold, any diagram state entered at any index or after the end, an uncompiled bootstrap, a dispatch record missing, split or answered in a sub-agent's place) and an errored session, and names any class no scenario produces.
- **The forms stay one statement of the edges.**
  A new scenario's path is the walk of its workflow's diagram from the start state to a terminal one, held by the existing corpus test to every form's sections and to the diagram bundle's own walk.
- **A new linked form meets the entry rule.**
  Each document a linked form links declares `prosiform`, so `pf` follows every link into the bundle; the corpus test names a link the bundle leaves as written.
- **The matrix grows by the new cells.**
  Four scenarios in four forms add 16 cells: 74 cells, 740 sessions at two models, and `EVAL_BUDGET_TOKENS` covers 44 400 000 at the 60 000-token session cap.
