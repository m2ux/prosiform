**Component:** `checks/restate.py`, `checks/README.md`

## Overview

A restatement that writes the build's current output into every fixture a red run names turns the build's behaviour into the corpus's truth. Restatement here is dry by default, and when written it changes exactly two things: the declared output, and the `[expected]` block of the manifest.

## Problem

A rewrite driven from a red run's verdict writes whatever the build produced, and a re-rendered manifest changes more than the expectation.

- **The manifest around the block is re-rendered.**
  Re-rendering from parsed TOML escaped every em dash in 177 manifests, which is churn that hides the line a reviewer needed to see.

- **A fault is recorded as the expectation.**
  A fixture whose run reports an internal error looks like a fixture that failed, so a regeneration driven from that verdict writes the crash into the corpus.

- **The tools reach no documented place.**
  Both scripts are the same tool, and neither is named where the corpus maintains itself, so the next red run writes another.

## Proposal

- **Restatement is dry by default.**
  Without `--write` a fixture is named and left alone, so the set is read before any of it is written.

- **When written, two things change.**
  The declared output file and the `[expected]` block of the manifest. The manifest around that block is copied through byte for byte.

- **A fault is refused rather than recorded.**
  A fixture whose run reports an internal error is named and skipped and the exit status is nonzero, so a pipeline that regenerates on a red build cannot write a crash into the corpus.

- **The tool lives where the corpus maintains itself.**
  It joins `checks/`, imports the corpus's own `runner.py` and `manifests.py`, and is named in `checks/README.md`.

- **Scope boundary.**
  Restatement rewrites expectations; it adjudicates nothing.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Read the manifest schema, the `[expected]` block's position, and the two script copies |
| Plan | Declare the dry-run default, the two files written, and the refusal |
| Implementation | The restatement command over the manifest's block and the declared output |
| Review | Confirm a non-ASCII clause and a second declaration survive byte for byte |
| Test | A stale fixture, a manifest with an em dash, and a crashing fixture |

## Acceptance Criteria

- [ ] **AC1.** Restatement without `--write` leaves the working tree unmodified and names every fixture it would rewrite, as `git status` after a run over a corpus with one stale fixture shows.
- [ ] **AC2.** Restatement with `--write` replaces only the declared output and the `[expected]` block, as a manifest carrying a non-ASCII clause and a second declaration compared before and after shows.
- [ ] **AC3.** Both commands are reachable from the corpus guide and import the corpus's own runner rather than a copy of it, as the repository's file check and a read of the imports show.
