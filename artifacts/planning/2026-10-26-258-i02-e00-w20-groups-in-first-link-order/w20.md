## Overview

A bundle carries its sources in placement order, the order in which links first reach them from the entry.

## Problem

- **Path order buried the binding material.**
  Groups sorted by path (parent first) put `Artifacts`, `Conventions`, other modes, `Protocols` and `References` ahead of `Rules` in every mode bundle; members inside a merged group (artifacts, protocols) were alphabetical.

## Proposal

- **Placement order.** `cli.placement`: seed with the entry references in command-line order (a fragment-only entry names the `-f` document), then read each placed document's final selection in placement order, each in source order, through `required`; a document is placed at the first link naming it.
- **Groups and members.** `assembled` reads documents in that order and sorts groups by their first document's placement; `grouping.merged` passes members in placement order and names the group by its first-placed member.
- **Kept.** Parent's own contribution leads a merged group (its sections in its order, then sections other members add by first appearance in member order; within a section the parent's variant first, then member order). Content inside one document in source order. Declaration conflicts (`group-depth`, `group-heading`) and member-name ambiguity read in path order. The traversal itself still reads documents in path order per round.
