**Component:** `src/prosiform/cli.py`

## Overview

The warning a grouping rule takes when the closure carries no document it arranges. The code is declared by the design and by the fixture catalogue, the corpus fixture awaits this row, and no run raises it.

## Problem

A rule that arranged nothing is indistinguishable from a rule that worked. The run succeeds, the bundle is published, and the caller reads nothing that tells a directory name wrong by one character from a directory the closure legitimately left out.

- **The code exists on paper alone.**
  `W_EMPTY_GROUP_RULE` sits in the manifest schema and the fixture catalogue, `fixtures/README.md` names the design clause it comes from, and the three refusals `E_INVALID_GROUP_RULE` covers are the only grouping diagnostics the build raises.

- **The fixture declares it and waits.**
  `fixtures/grouping/a-rule-matching-no-document-in-the-closure` carries `awaiting = "I00:E11:W14"`, so the corpus reports it as awaited rather than failing on it, and the marker goes when the behaviour lands.

## Proposal

A grouping rule names a directory slug, and the run already refuses one naming no directory under the allowed source root. What it does not report is a rule whose slug names a directory from which the closure carries no document: the arrangement is empty, the bundle is the one the closure makes without it, and the run succeeds.

- **The closure decides it.**
  Membership is read from the closure's own documents rather than from the source tree, so a directory holding documents the traversal never reached is as idle as an empty one. The test reuses the membership rule the arrangement itself applies, which means a rule an inner rule out-ranks on every document it could have taken is reported idle, because it arranges nothing.

- **One warning per idle rule, in declaration order.**
  Each carries the declared code and names the slug, so a caller reading diagnostics as data has the rule that did nothing.

- **It accompanies a published bundle.**
  The warning is emitted once the bundle is published and ahead of the entry destinations, which is where the contract's successful-run diagnostics sit.
