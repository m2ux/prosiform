**Component:** [`src/prosiform/profile.py`](https://github.com/m2ux/prosiform/blob/main/src/prosiform/profile.py)

## Overview

The Parser exhaustion family stated by the corpus: suppression reached with every declared budget at its default, a failure that names the reference whose lookup was suppressed, and a budget spent on its last valid reference that claims no omission.

## Problem

The code is raised and the detection holds, and the condition the design's family names is stated by nothing. The corpus reaches `E_PARSER_REFERENCE_LIMIT` through two fixtures that declare `--max-nesting 1`, so the ceiling they reach is one the invocation lowered.

- **The family is named by no fixture.**
  A clause maps to the fixtures that name it, and no manifest carries the Parser exhaustion clause. The listing epic [#9](https://github.com/m2ux/prosiform/issues/9) reads that mapping for its own criterion, so the family reads as uncovered whatever the build does.

- **The declared condition is narrower than the one covered.**
  The family requires suppression below the tool's public input and output limits. An invocation that sets a budget to 1 demonstrates the detection, not the condition: a reader cannot tell from it whether an author writing an ordinary command line can reach the ceiling at all.

- **The failure names the source rather than the reference.**
  The diagnostic carries the path it could not index. An author reading it learns which document failed and not which dependency went unresolved, and the criterion the task issue states requires the reference.

## Proposal

The profile owns the parser's configuration and the watch over its label scan, so it is where the abandoned scan is read for what it was reading. The ceiling sits a fixed headroom above the declared nesting budget and counts inline nesting, which no budget counts, so a source inside every default budget reaches it with 85 open brackets.

- **Name the reference from the scan that abandoned it.**
  The watch records the span the declined scan stopped in, which runs from inside the label the parser had opened to the end of that inline content. Reading that span under the profile's own parser, with the source's definition environment, yields the destination the construct names, and the failure carries it as the reference.

- **Fall back to the source where the span names nothing.**
  A span carrying no destination leaves the reference unnamed, and the diagnostic names the source it could not index, as it does for every declined lookup whose construct the span does not complete.

- **State the family at the default budgets.**
  Two fixtures invoke the build with the entry reference alone. One opens 85 brackets and fails with the code, naming the reference and publishing nothing; one opens 84, resolves that last valid reference and bundles what it names, reporting no omission.

- **Leave the gate fixtures on the gate clause.**
  The fixtures reaching a lowered ceiling state observable suppression, which is a different claim, so they keep the clause they declare and the family clause sits on the two that meet its condition.
