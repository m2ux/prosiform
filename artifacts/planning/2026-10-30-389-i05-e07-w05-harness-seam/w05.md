**Component:** evals/diagram-following/harness.py

## Overview

The seam between the eval and the agent CLI it drives, and a second harness across it, so one measurement serves any CLI whose stream can be read.

## Problem

The eval named one CLI in five places, and every one of them was a property of that CLI rather than of the measurement.

- **The command line** carried `--tools`, `--strict-mcp-config`, `--disable-slash-commands`, `--permission-mode` and `--max-budget-usd`, none of which another CLI need offer.
- **The environment** scrubbed `CLAUDE*` and `ANTHROPIC*` and set `CLAUDE_CONFIG_DIR`; the preflight required `.credentials.json` and refused a config that installed or enabled a plugin.
- **The transcript reader** sought `tool_use` blocks named `Task`, took togetherness from one assistant message, and read returns from `tool_result`.
- **The budget** was dollars from `total_cost_usd`, which a CLI may not report.
- **The stub** printed that one stream's shape, so every harness test measured one CLI's format.

A second CLI could not be run at all, and adding one would have meant a second runner.

## Proposal

- **A harness is the whole of what a CLI differs in.**
  `argv()`, `environment()`, `preflight()`, `starts()`, `result()`, `tokens()` and `cost()`. The runner keeps the matrix, the workspaces, the timeout, the budget guard and the scoring call, and asks the harness for the rest.
- **A start is the same value whichever stream states it.**
  `Start(target, returned, together)` is read by each harness from its own stream, and `score.py` reads only the record written from it, so the scorer above is unaware of the CLI.
- **The budget is tokens.**
  Both CLIs report tokens and only one reports a cost, so the run is held to the measure both state. Cost remains a figure a harness records where it has one.
- **Cursor is read from what it prints.**
  A start is a `taskToolCall` in a `tool_call` event; two starts in one message share a `model_call_id`; a return is the text of the completed call's `conversationSteps`; usage is `inputTokens`, `outputTokens`, `cacheWriteTokens` and `cacheReadTokens`.
- **Isolation is declared rather than assumed.**
  A harness states what confines its sessions. Cursor has no configuration directory, no MCP switch, no slash-command switch and no session spend cap, so its preflight refuses an unusable config path and the run's own guard is the whole budget, rather than a boundary claimed and not drawn.

### Test

The unit's one duty is that either harness can be driven and read. The Test part names the per-harness checks, the suite that runs the seam, and the tree.

| Reading | Test |
| --- | --- |
