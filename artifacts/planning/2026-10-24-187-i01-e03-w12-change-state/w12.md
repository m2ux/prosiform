**Component:** `.github/workflows/checks.yml`, `Makefile`, `checks/runner.py`

## Overview

One command states whether a tree is sound, and every failing target is named in one run rather than one at a time.

## Problem

Three mechanisms each report part of whether a change is sound, and none reports the whole of it. A branch name decides whether CI runs, so a pull request merged from outside the naming pattern is never checked. A failing suite stops at its first failure, so the target it names is one of however many are broken. A run that failed in itself is one boolean beside a run whose output merely moved.

`main` stayed red through six commits, each naming a different problem: `links`, then `corpus`, then `test`, while all three were failing underneath. The pull request that broke it, [#236](https://github.com/m2ux/prosiform/pull/236), carried a branch outside the CI trigger pattern and has no workflow run at all.

## Proposal

- Trigger on `pull_request` for every branch, keeping `push` on `main` as confirmation that the merged state stands.
- Add a `check-all` target running the same sixteen checks under `make -k`, naming each failure and exiting nonzero when any fails.
- Give a fixture's verdict three states, so a run that failed in itself is distinguishable from one whose output drifted.
- Make restatement refuse a fixture whose run failed in itself, naming it.
