**Component:** `main:Makefile`, `main:checks/runner.py`

## Overview

One command states whether a tree is sound, and every failing target is named in one run rather than one at a time.

## Problem

Two mechanisms each report part of whether a change is sound, and neither reports the whole of it. A failing suite stops at its first failure, so the target it names is one of however many are broken. A run that failed in itself is one boolean beside a run whose output merely moved.

`main` stayed red through six commits, each naming a different problem: `links`, then `corpus`, then `test`, while all three were failing underneath.

## Proposal

- Add a `check-all` target running the same sixteen checks under `make -k`, naming each failure and exiting nonzero when any fails.
- Give a fixture's verdict three states, so a run that failed in itself is distinguishable from one whose output drifted.
