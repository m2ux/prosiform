**Component:** src/prosiform/source.py

## Overview

A class diagram's `link` line is read as a diagram use, and every diagram link keyword is matched in any letter case, so the link forms Mermaid renders for flowchart, state, Gantt and class diagrams are all bundled and rewritten.

## Problem

[`CLICK`](https://github.com/m2ux/prosiform/blob/ad2e7338c65259e546a97be83b0964e705d64bc5/src/prosiform/source.py#L147-L150) is a case-sensitive pattern for a line opening with `click`. A class diagram's `link <class> "<destination>"`, and a `click` line written `Click` or `HREF`, both render as links in Mermaid 11.16.0 and are carried by prosiform as text.

## Proposal

A class diagram may write `link Cls "states/open.md" "Open"` beside its `click` lines. Mermaid feeds both to one handler, and `Click Cls HREF "states/open.md"` reaches it too.

- **One pattern for the quoted forms.**
  The pattern accepts `click` or `link` as the keyword, `href` optional after `click` only, then the quoted destination, an optional quoted tooltip and an optional target.
- **Case-insensitive.**
  The pattern compiles with `re.IGNORECASE`, so the keyword, `href` and the target match in any case. Mermaid 11.16.0's state, Gantt and sequence lexers read these keywords in any case; its flowchart and class lexers read them in lowercase alone, so a mixed-case line there is one Mermaid fails to parse and opens no link.
- **Nothing downstream changes.**
  `clicks` yields the same `Click` for the new lines, so discovery, the budget, emission and candidate validation take them without change.
