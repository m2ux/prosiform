## Overview

Corpus fixtures for a validation-only run, which publishes nothing to either stream and writes no file.

## Problem

A validation-only run discovers, bundles and validates its entry references and publishes none of the result. No fixture declares such a run, so the corpus states nothing about it and the criterion naming it rests on the build's own tests.

The gap was structural when the command was first delivered: nothing bundled, so a validation-only run validated nothing and a fixture for it would have declared an absent stage. Emission exists now, and the run it names is reachable and produces the result the criterion describes — an exit status of zero with both streams empty — so the criterion's instrument is a fixture nobody has written rather than a fixture nobody can write.

The manifest states a run's standard output, its exit status and its diagnostics. It states nothing about the filesystem the run leaves behind, so the half of the criterion that concerns a named output file has no declaration to carry it.

A generated file heading escapes each character that can open an inline construct, and `#` is not among them. A path whose final segment ends in a space and a number sign closes the heading as an ATX closing sequence, and the character leaves the visible text without a diagnostic.

## Proposal

A fixture declares a validation-only run over a source the corpus already carries, and a second declares the same run with an output file named. Each expects an exit status of zero, standard output holding nothing, and no diagnostic. The second names the output path as one the run must leave absent, which is the half of the criterion a stream comparison cannot reach.

The escape set gains `#`, so a path segment carrying one reaches the file heading as text. The heading's visible text is the path, and a path that silently loses a character names a document the bundle does not carry.

### What a Manifest Can State About a File the Run Must Not Create

The first half of the criterion — nothing published to either stream — the manifest already states: `exit_status = 0`, `stdout` naming a file holding nothing, `diagnostics = []`. The second half it does not. `expected` requires `exit_status`, `stdout` and `diagnostics`, and `additionalProperties` is false throughout, so there is no field in which a fixture can name a path that must not exist when the run completes.

Two facts about the runner decide how reachable the second half is without a schema change.

- **A run's working directory is the fixture's own.** The runner passes `cwd=fixture`, so an `--output` path written in `arguments` resolves inside the fixture directory. A published file would therefore land among the fixture's own files, where it is observable.
- **The runner reads the fixture directory only for the paths the manifest names.** `invocation.root` must be a directory and `expected.stdout` must be a file, and both are checked before the run. Nothing is read afterwards, and no file set is captured, so the directory a run leaves behind is not part of any comparison.

So the second half is observable in principle and unobserved in fact. The decision is what observes it.

**The manifest declares the paths the run must leave absent, and the runner checks them after the run.** `expected.absent` is an optional array of fixture-relative paths. A fixture that already holds one of them is malformed, reported like a missing `stdout` file and before the build is invoked, because a declaration the directory contradicts before the run says nothing about the run. After the run each named path is checked, a path the run created is a difference naming the bytes it carries, and the runner removes it, so a corpus run leaves the tree as it found it whatever the build did.

This states the invariant the criterion states — this path does not exist after the run — in the corpus, in the same language-neutral form as the three expectations beside it, and it binds every implementation of the contract rather than this build's test suite.

#### What Was Rejected

- **Holding the second half in the build's own tests, with a test-plan row naming it and an empty Test cell.** The mechanism exists and costs nothing. It was rejected because this row exists to state AC10 in the corpus, and a row whose whole purpose is that, closing with the criterion still half-stated by the corpus and half-stated by one implementation's unit tests, delivers the smaller thing. The prototype's tests keep covering the behaviour; they are not what the criterion names.
- **Naming an output path whose parent directory does not exist.** A `--check` run that wrongly published would then fail its write, exit 3 and emit `E_PUBLICATION_FAILED`, which the manifest's declared status and empty diagnostic list already catch. It needs no schema change. It was rejected because it states a different fact: that a write to that path fails, not that the run does not attempt one. A build that created the missing parent, or wrote through a different path, would satisfy the fixture while creating the file the criterion forbids. A fixture must mean what it says.
- **Naming `expected/stdout.md` as the output path, so a wrongly published bundle overwrites the bytes the comparison then reads.** The runner reads that file after the run, so the fixture would indeed fail. It was rejected because it works by letting the build overwrite a committed fixture file: the corpus would mutate itself on a red run, and the failure would be reported as a standard-output difference rather than as the created file it is.
- **Capturing the fixture's whole file set before and after the run and comparing them.** It needs no per-fixture declaration. It was rejected because it states nothing about what the run was supposed to do: every fixture would carry the assertion, a build writing a temporary file it later removes would be indistinguishable from one that published, and the fixture that cares about an output path would not say so.

### The Fixtures

| Fixture | Invocation | Declares |
| --- | --- | --- |
| `cli/validation-only-run` | `--check guide.md` | Exit 0, standard output holding nothing, no diagnostic |
| `cli/validation-only-run-with-an-output-file` | `--check --output bundle.md guide.md` | The same, and `bundle.md` absent after the run |

Both run over a copy of the source `identity/whole-document` already carries, because the invocation is what each fixture establishes and the document is the part that must not distract from it. Neither carries `awaiting`: both pass against the build as it stands, and a marked fixture that meets its manifest fails the corpus run.

### The Escaping Has No Fixture, Because No Run Reaches It

The escaping fixture was planned as a third, modelled on `identity/path-needing-escaping`: one source at `notes/draft #.md`, whose file heading's visible text is `notes/draft #` with the trailing number sign where an ATX closing sequence would take it. No run of this build reaches that heading.

An entry reference is a document and an optional fragment, and the fragment opens at the first number sign. A reference spelling `notes/draft #.md` therefore names the document `notes/draft ` and the fragment `.md`, and fails with `E_UNSUPPORTED_ENTRY_SUFFIX` before anything is bundled. The same split applies to `--from`, so no form of the command line names such a document.

Nothing else puts a document into the bundle here. Each file group comes from a document an entry reference names: dependency traversal, which would discover a document without naming it, is `I00:E04`, and grouping bundles nothing in this build. So the path cannot reach a file heading, and a manifest declaring the bundle it would produce would declare behaviour the contract nowhere states — how a reference spells a path carrying a number sign is undesigned, and a fixture is not the place to decide it.

The escaping is therefore carried by the build's own tests, which hold `escaped` to escaping the number sign and hold `group` to emitting `# notes/draft \#` for that path. The reachability gap is an arising issue rather than a fixture with a marker on it: `awaiting` names the work that delivers the behaviour a fixture declares, and no planned row makes such a path nameable.
