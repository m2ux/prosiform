# W03 Carry Every Click and Every Link Element

> Work item · 2026-11-01

## Overview

Three diagram faults in the diagram link reader, where a link Mermaid renders was bundled as nothing, or refused where Mermaid draws no link. The reader is `read_diagram` and the functions it calls in `src/prosiform/source.py`; the refusal it feeds is worded in `src/prosiform/profile.py`.

## Problem

- **A `links` array escapes the run.** `links Server: ["a.md", "b.md"]` decodes to a list, which the reader treated as naming nothing. Mermaid draws a live menu entry for each element, so the bundle shipped two links to documents it never compiled, and the run exited 0.
- **Every anchor on a fence line was refused.** Any `<a href>` naming a local document was refused as a node label, including one in a `click` tooltip, a pie label and a sequence note, none of which Mermaid draws as an anchor.
- **A second `click` on a line hid both.** `click A "one.md"; click B "two.md"` matched the one-statement click pattern for neither, so both destinations published as source paths.

The faults are findings 19, 20 and 25 in the [merged-epic review](../2026-10-31-merged-epic-review/findings.md).

## Proposal

**The scene.** Each defect was found by the review of fifteen merged epics and has a case that reproduces it. The task repairs the diagram link reader and carries those cases, so a regression fails a target rather than waiting for another review.

**The design.**

- **A `links` array is refused.** A non-empty array in the object's place is a listed menu. The profile refuses it under `E_UNSUPPORTED_CONSTRUCT`, naming its line, with the remedy of writing the value as an object naming each entry. Mermaid labels an array's entries by their positions, so the array names no menu the author wrote. An empty array draws no menu and is carried.
- **An anchor is refused only where Mermaid draws one.** Rendering each diagram type with mermaid-cli 11.16.0 settles where an anchor in label text becomes an SVG `<a>`:
  - Drawn: flowchart and graph labels, edge labels and subgraph titles, class, state, mindmap, ER, block, Kanban and requirement diagrams.
  - Shown as text: sequence, pie, timeline, journey, Gantt, quadrant, Git, XY, Sankey, packet, radar, treemap and C4 diagrams.
  - A `click` tooltip, and a class diagram's `link` or `callback` tooltip, is an attribute Mermaid shows on hover in a box that takes no pointer, so an anchor there opens nothing.

  The reader skips anchors in a text-drawing diagram and in a click or class link statement. Every other diagram type is held to draw one, so a type not yet verified still refuses an anchor rather than shipping it unbundled.
- **Every statement of a line is read.** Mermaid ends a flowchart statement at a `;` outside a double-quoted string. The reader splits each line into those statements and matches each click or class link statement on its own, so every destination is followed and rewritten in place. The anchor rule uses the same split, so a node label beside a click on one line still refuses its anchor.
- **The case ships with the fix.** Unit cases in the source and profile tests, run cases in the CLI tests, corpus fixtures for each finding, and render-check entries proving which anchors Mermaid draws in the bundled fixtures.

### Departure from the epic plan

The epic record's work item proposed reading a `links` array as a destination set and bundling both documents. The epic's criterion states the array is refused with a named code, so the criterion decides it. The epic record names `src/prosiform/diagram.py` as the component. No such module exists: the diagram link reader is in `src/prosiform/source.py`, which this file declares.
