## Overview

An agent-pick workflow puts the pick in front of a headless agent: a workflow reaches a kind router through a `?` link, the session compiles it with `pf`, reads the alternatives, and continues with the one its input calls for. The eval scores the path, the runs and the files read, so a session that picks the wrong kind, never reruns the listing or reads a source fails.

## Problem

- **No agent makes a pick.**
  The router fixtures show `pf` printing the listing and each pick's bundle, and the bare-command test shows the guide stating `?`; neither shows an agent resolving one.
- **The scorer cannot see a source read.**
  A session's record holds its commands and its sub-agent starts; a file it opened with a read tool reaches no check, so a session that reads the router's source beside compiling it passes.

## Proposal

**The scene.** The diagram-following eval's `compiled` form gives a session the entry's bundle, a shell limited to `pf` and the sources to compile from; its deferral workflows already hold a session to compiling what a bundle defers, and the corpus test walks each scenario by running `pf` as a session does.

- **The workflow.**
  `agent-pick`, written in the `compiled` form alone and run with the edge workflows: `Classify` defers a kind router's `Route` section with `¬↳` and `?`; the router's alternatives `initiative`, `epic`, `task` and `other` each route the section's link to a document stating the transition into that kind's state.
- **The scenarios.**
  One per alternative, each with `inputs/work.txt` describing the work in the words of one choice line and naming no alternative; the `other` scenario's input matches no choice line, and its path ends at `Hold`, the state the router names for any other work. Each states the listing run and the rerun with the pick.
- **The walk.**
  The corpus walk runs the `?` line, reads the listing, and reruns with the alternative whose choice line an input holds, or the one declared last where none does.
- **The read check.**
  Each harness reports the files its read tool opened; the record holds them as `reads`, and a shell-form session that opened a document of its form's sources fails `read_source`, after the run checks.
- **The README.**
  The workflow joins the deferral scenarios; Run checks and the runbook's rubric state `read_source`.
