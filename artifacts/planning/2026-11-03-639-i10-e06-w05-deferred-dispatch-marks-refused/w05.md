## Overview

`¬⇉` and `¬⫽` are refused: a link opening with either fails, so dispatch has one form, compiled up front.

## Problem

- **Deferred dispatch is a second way to dispatch.**
  `closure.py` admits `¬⇉` and `¬⫽` as one compilation on two counts, published with their marks removed, so a reader cannot tell one from a citation and a deferred set member falls out of its set.
- **A `⫽` link in a heading reads its set before the set is known.**
  A heading carrying the only `⫽` link of a set of one publishes as a `⇉` dispatch, yet its text was read as one of a set of several, so the published heading differs from the one provenance records.

## Proposal

**The scene.** `closure.py` reads operator marks and the groups of marks one link may state; `dispatch.py`, `candidate.py` and `bundle.py` each carry a branch for a deferred dispatch; `bundle.py` reads a heading's shown text.

- **The combined marks are refused.** (User, 2026-11-03.)
  A link opening with `¬⇉` or `¬⫽` fails with `E_UNSUPPORTED_CONSTRUCT`, naming the link, and the run publishes nothing.
- **Code that served them goes.**
  The deferred-dispatch branches in `dispatch.py`, `candidate.py` and `bundle.py` are removed, and the deferred-dispatch fixtures become refusals.
- **A heading reads its set.**
  A heading's shown text is read with whether its section's `⫽` links name one distinct target, so a set of one shows the `⇉` mark the heading publishes with.
- **The design names what a bundle carries.**
  The clauses *The Prosiform section* and *Dispatch sub-sections*, the fixture group *Prosiform section* and the glossary terms for them become *The run-pf line*, *Dispatch links* and *Run-pf line*, and the terms go; the manifests cite the new titles and the design pin moves to the commit holding them.
