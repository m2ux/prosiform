**Component:** main:checks/corpus.py

## Overview

Every corpus source declares its settings in a preset, every expected bundle is unchanged, and the corpus run fails a fixture whose source declares a setting outside one, so the migration's completeness is something `make corpus` observes.

## Problem

The corpus states the preset shape by convention alone.

- **The migration has already landed.**
  Earlier epics rewrote each fixture source: every key of every corpus `prosiform` names a preset and maps it to that preset's settings, so a search finds nothing left to move.
- **Nothing holds the corpus to that shape.**
  A fixture source declaring `group` or `subst` outside a preset is refused by the build, and a fixture expecting a refusal of another kind would pass over it, so a regression in the corpus's own declarations has no check of its own.
- **The design still states usage examples over a specimen tree.**
  The design's *Usage examples* clause runs worked commands over `work-planner/`, the removed example tree, so conformance reports it uncovered with no fixture able to cover it.

## Proposal

**The scene.** `make corpus` walks every fixture, runs each through the build and compares its bundles and diagnostics with the manifest.

**The design.**

- **Every corpus source declares in a preset.**
  A search of every fixture source's frontmatter finds each `prosiform` key naming a preset; the two that do not sit in fixtures whose subject is that refusal.
- **The corpus run reads fixture sources.**
  `corpus.py` reads each fixture source's `prosiform`; a key naming a setting (`group`, `subst` or the refused `root`) or holding anything but a mapping fails the fixture, naming the source and key, whatever the build answers.
- **A refusal fixture is its own subject.**
  A fixture expecting `E_INVALID_CONVERSION_METADATA` declares the refusal of such a key, so its sources are not read.
- **No expected bundle changes.**
  This task's commits touch no file under `fixtures/`.
- **The Usage examples clause is retired.**
  The design drops the clause, and the README's design pin moves to the revision carrying that removal, so conformance reports no clause about the removed tree.
