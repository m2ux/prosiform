**Component:** [`src/prosiform/profile.py`](https://github.com/m2ux/prosiform/blob/main/src/prosiform/profile.py)

## Overview

The detection behind `E_PARSER_REFERENCE_LIMIT`: where the parser's own resource limit suppresses a reference lookup, how the run observes it, and the two fixtures that separate a suppressed lookup from a budget merely spent.

## Problem

The contract declares the code and the fixture catalogue lists it, and nothing in the build raises it. The code appears in `src/prosiform/limits.py` only inside a docstring, distinguishing it from `E_RESOURCE_LIMIT`.

- **The gate is a claim.**
  The design requires a run to detect when an internal parser resource limit prevents a reference lookup and to fail, naming the first affected source span where one is available. No module defines the code as a constant, no call site passes it, and no fixture expects it.

- **The failure it closes is silent.**
  A marked dependency whose lookup the parser declined is read as literal text. Nothing in the run distinguishes that from an author writing brackets, so the bundle omits the document the reference named and reports a success.

- **The budget already declared is a different thing.**
  `--max-nesting` counts container blocks and refuses a source that crosses it. The parser's ceiling counts inline nesting, which no budget is declared over, so a source well inside every declared budget can still reach it.

## Proposal

`skill-markdown-v1` configures the parser, so the profile is where its ceiling is answered for. The parser's ceiling sits `HEADROOM` above the declared nesting budget, which keeps a container-nested source refused rather than reinterpreted; inline nesting is counted into the same ceiling and reaches it on a source the nesting budget never notices.

- **Watch the scan rather than compare two parses.**
  `markdown_it` abandons a link-label scan to the end of the paragraph once its nesting ceiling is reached, and that abandonment is the suppression signal the design asks for. A `Watched` inline parser notes it, carrying the content it was reading, so the profile's `parse` raises `Suppressed` instead of returning a token stream the parser did not resolve in full. An event stream that omits a suppressed reference agrees with a second parse that omits it too, which is why the comparison is not the instrument.

- **Tell a declined lookup from the brackets it leaves behind.**
  The abandoned scan is an event, not an inference over the source text. A preflight counting brackets cannot separate the literal bracketed text the suppression produces from the reference it suppressed; the scan itself is only entered where a label was being read.

- **Report it where a source is indexed.**
  The CLI reads and parses each source of the closure. A `Suppressed` raised there becomes an input failure carrying `E_PARSER_REFERENCE_LIMIT`, the source, the chain that reached it, and the line of the inline content the parser was reading, which is the first affected span.

- **A consumed ceiling is not an omitted reference.**
  Nothing is reported unless a scan was abandoned. A source whose deepest reference sits exactly at the ceiling resolves it, bundles what it names, and succeeds.
