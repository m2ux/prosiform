## Overview

The plus-one heading shift for a file group, inside retained containers as elsewhere, and the Setext conversion the shift requires.

## Problem

A Setext heading writes its level as an underline rather than as a prefix, so a uniform level shift cannot be applied to it by the means an ATX heading admits. A heading a container carries is written where the container holds it, so an edit that reads only the first line of a region reaches the region's own heading and no other.

## Proposal

Every emitted source heading in a file group moves down exactly one level, a heading a retained container carries included, preserving visible text, relative depth and the container's own structure. Heading-like text inside code is untouched, because it is content rather than a heading.

A shifted group emits a Setext heading as the ATX heading of the same level, carrying the inline source its content lines hold joined into the one line an ATX heading is, each line break reading as the space it already read as, and the number-sign run that would be read as a closing sequence escaped so the text keeps the characters it showed. A group whose title the file heading absorbed shifts by nothing, has no level to write, and emits a Setext heading as the Setext heading its source wrote.

An emitted heading the shift would place beyond the sixth level is the overflow the group refuses, whatever region carries it.

## What the Plan Got Wrong

The brief and this row's stub both held that publishing a container-nested heading at a correct level needs a group shift of zero, which needs an absorbed title, which needs the whole document selected, and that a whole-document selection has no boundary to demonstrate. The fixture W02 wrote disproves it: `extraction/a-heading-a-blockquote-carries` selects one section of `guide.md` by fragment, shifts by one, and shows both the boundary and the container-nested heading in the same bytes. What blocked AC1 was that the container shift did not exist, not that the two halves were mutually exclusive in one invocation.
