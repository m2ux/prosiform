**Component:** src/prosiform/cli.py

## Overview

`-o` names a folder, every bundle a run publishes is written there under its derived name, and a run of several entries takes one name joining each entry's. A run that will publish a bundle per dispatched target needs a folder and a naming scheme that covers every bundle, and standard output can carry only one.

## Problem

- **`-o` names one file or standard output.**
  [`-o`](https://github.com/m2ux/prosiform/blob/9851615028ea489c48f6b3fa5ddbe0d917438cf2/src/prosiform/cli.py#L388-L391) takes an exact file or `-`, and the corpus runner [passes `-o -`](https://github.com/m2ux/prosiform/blob/9851615028ea489c48f6b3fa5ddbe0d917438cf2/checks/runner.py#L451-L459) to every fixture, so all 308 expected bundles are declared as `expected/stdout.md`.
- **Several entries have no derived name.**
  [`derived_output`](https://github.com/m2ux/prosiform/blob/9851615028ea489c48f6b3fa5ddbe0d917438cf2/src/prosiform/cli.py#L1800-L1818) refuses more than one distinct selection and asks for `-o`.
- **The delivery wrapper reads standard output.**
  [`delivery.py`](https://github.com/m2ux/prosiform/blob/9851615028ea489c48f6b3fa5ddbe0d917438cf2/src/prosiform/delivery.py) buffers a bundle from standard output and holds it against a transport limit; only its own test calls it.

## Proposal

A caller runs `pf -o build/ modes/plan-mode.md rules.md` and finds `build/modes_plan-mode+rules.bundle.md`.

- **`-o DIR` names the output folder.**
  The default is the working directory. The folder must exist; a bundle path naming a captured source is refused as it is today.
- **Joined derived names.**
  Each entry's derived name (path with `/` as `_`, `__<fragment>` for a section) is joined with `+` in entry order, then `.bundle.md`.
- **Standard output carries no bundle.**
  `-o -` is invalid usage. Help, version and code listings stay on standard output.
- **The corpus reads the folder.**
  The runner gives each fixture a fresh output folder and compares every file the run writes there with the fixture's `expected/` files by name; the manifest schema, `fixtures/README.md` and each fixture's expected file move to the derived name. `checks/render.py` reads the renamed bundles, and `checks/smoke.py`, which today [expects a directory destination to fail](https://github.com/m2ux/prosiform/blob/9851615028ea489c48f6b3fa5ddbe0d917438cf2/checks/smoke.py#L226), expects it to hold the bundle.
- **The delivery wrapper is removed.**
  With no bundle on standard output it has nothing to deliver; `delivery.py`, its test and the prose describing it go.
- **The contract moves with the build.**
  The design's Invocation and Publication clauses, the README's design pin and the `-o` row of `invocation.md` state the folder, so `make conformance` and `make invocation` hold on this revision.
