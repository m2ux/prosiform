**Component:** src/prosiform/cli.py

## Overview

A bare `pf` prints what an agent needs before it compiles anything, so a skill's bootstrap is one instruction: run `pf` and follow it. The example's bootstrap document is retired, and the documentation states the output folder, the bundle set, the dispatch and parallel sub-sections, the Prosiform section and the guide.

## Problem

- **A bare `pf` is a usage error.**
  [`execute()`](https://github.com/m2ux/prosiform/blob/c285144f4c993c714e2151052b147a913dd0b4b5/src/prosiform/cli.py#L2024) refuses a command line naming no entry reference with `E_INVALID_USAGE`, so an agent meeting `pf` learns nothing from it.
- **Every corpus restates how to use pf.**
  The example's [`bootstrap.md`](https://github.com/m2ux/prosiform/blob/c285144f4c993c714e2151052b147a913dd0b4b5/example/work-planner/bootstrap.md) carries a compile command writing `-o <scratch>/<name>.bundle.md`, and symbol rows for `⇉` and `⫽` that describe a compile-at-run-time dispatch and a run-set of parallel tool calls. `SKILL.md`, `rules.md` and `guidelines.md` link it.
- **The documents describe a bundle opening on its first group.**
  `invocation.md`'s Output section and the design's Clean Markdown rule state that a bundle opens on its first group's content, which a bundle carrying a Prosiform section does not.
- **The corpus cannot state a bare invocation.**
  The runner adds `-d json` to every fixture's command line, and the manifest schema requires at least one argument.

## Proposal

A skill's `SKILL.md` says: run `pf` and follow it. The agent runs `pf`, reads the compile step, compiles the mode a `↳` link names into `<folder>/<name>.bundles/`, and follows the entry bundle from its Prosiform section when it opens with one.

- **`pf` with no arguments.**
  Prints the guide to standard output and exits `0`: the compile step (`pf -o <folder> <destination>` from the skill directory; a non-zero exit stops the run and reports diagnostics), the `↳` inline-target rule, and that a bundle opening with a Prosiform section is followed from there. A command line holding any argument and no entry reference stays a usage error. No option prints the guide; `pf -h` states that a bare `pf` does.
- **The guide is pf's text.**
  It is a constant of the build beside the parser. The design states the bare invocation under the CLI contract as *guide*, the glossary defines it, and `invocation.md` states it, held by `make invocation`.
- **A bare fixture.**
  A manifest declaring no argument and no fault is the bare command: the runner invokes the build with nothing added, and the schema admits an empty argument list. `fixtures/cli/informational-guide-response` observes the guide.
- **Bootstrap retired.**
  `example/work-planner/bootstrap.md` is removed. `SKILL.md` states the one instruction; `rules.md` and `guidelines.md` link nothing to it and describe dispatch and parallel dispatch as the build publishes them, with the protocols in the bundle's Prosiform section. The usage-example fixtures take the bundles the rewrite compiles to.
- **Documentation.**
  `invocation.md`, `docs/glossary.md` and `README.md` state the output folder, the bundle set, the dispatch sub-sections, the parallel set, the Prosiform section and the guide. The design's Clean Markdown rule and `invocation.md`'s Output section state that a dispatching bundle opens with its Prosiform section.
