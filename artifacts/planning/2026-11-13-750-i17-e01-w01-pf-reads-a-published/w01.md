## Overview

`pf` takes a link exactly as a bundle publishes it — a Markdown link, a Mermaid `click` line or a class diagram `link` line — reads its destination and title with the readers that classify authored links, and compiles the destination under the presets the title selects. `--pick` resolves a `?` deferral, and `--presets` leaves the build, so an agent runs the link it meets without converting it into a command.

## Problem

- **The entry refuses a link.**
  The build takes `<document>#<section>` and a `--presets` value, and refuses a complete Markdown link as its entry, so an agent splits every link it meets into a command.
- **A click's tooltip is passed with its marks.**
  An agent passing a tooltip such as `¬ Epic` as the preset list selects no preset and loops on `E_ALTERNATIVE_UNRESOLVED`.
- **A pick edits the link.**
  The guide and the listing's remedy have the agent rewrite the title with `?` replaced.

## Proposal

An agent meets a link in a bundle and runs `pf -o <folder> '<link>'`. The build:

- **Reads the link with the existing readers.**
  The Markdown parser reads a Markdown link's destination and title; the diagram line reader reads a `click` or class diagram `link` line's destination and tooltip, and the tooltip reader sets its opening marks aside. A text that is neither is a plain path, selecting no named preset.
- **Ignores operator marks.**
  Marks opening the link text or the tooltip are never checked, so any combination compiles the destination alike.
- **Takes `--pick`.**
  Beside an entry whose title carries `?`, the pick stands where `?` stands; anywhere else, repeated or without an entry, it is invalid usage. The listing's remedy names `--pick`.
- **Holds no `--presets`.**
  The option, its usage, help and guide text leave; `invocation.md` states the link entry and `--pick`.
