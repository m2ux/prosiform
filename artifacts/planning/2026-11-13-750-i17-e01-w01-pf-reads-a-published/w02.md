## Overview

The conformance corpus states the link entry: each fixture that selected presets through `--presets` runs a published link, and new fixtures pin a link opening with operator marks, a diagram link entry, a first-run pick, a pick after the listing and a stray pick. The corpus is the build-independent statement of the contract, so it moves with the build.

## Problem

- **The corpus pins the removed option.**
  Twenty-one manifests pass `--presets`, two of them pinning its usage errors, so the corpus fails once the option leaves.
- **The link entry has no fixture.**
  Nothing in the corpus states a link or diagram line entry, operator marks on it, or `--pick`.

## Proposal

A conformance run reads each manifest's arguments and compares the outcome. The corpus:

- **Selects presets through links.**
  A fixture selecting presets passes the link that selects them, as a bundle publishes it; the informational fixtures state the new usage and guide text.
- **Retires the option's usage fixtures.**
  The fixtures pinning `--presets` usage errors become `--pick` usage fixtures: a stray pick, a repeated pick and a pick without an entry.
- **Adds link entry fixtures.**
  A Markdown link opening with operator marks, malformed combinations included; a `click` line and a class diagram `link` line; a first-run pick; a pick after the listing.
