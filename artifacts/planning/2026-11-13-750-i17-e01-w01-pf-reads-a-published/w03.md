## Overview

The smoke check and the diagram-following eval harness invoke `pf` on links as written and `--pick`, and recognise those invocations in a session's commands, so both keep exercising the build once `--presets` leaves it.

## Problem

- **The checks invoke the removed option.**
  The smoke check, the runner and authoring tests, the example script and the eval harness's scenario commands pass `--presets`, so they fail once the option leaves.
- **The scorer reads commands by the old grammar.**
  The eval scorer recognises a session's `pf` runs by their `--presets` value, so a run on a link as written scores as no run.

## Proposal

A check or an eval scenario runs `pf` the way an agent following the guide runs it. The harnesses:

- **Run links as written.**
  The smoke check, the runner tests and the example script pass a published link where they selected presets; the eval harness states a scenario's run as the link and any `--pick`.
- **Score link runs.**
  The scorer reads a session's `pf` command as a link entry with its title tags, or a plain path, plus any `--pick`.
- **Name no `--presets`.**
  The harness README, runbook and recorded pick evidence state the link invocation.
