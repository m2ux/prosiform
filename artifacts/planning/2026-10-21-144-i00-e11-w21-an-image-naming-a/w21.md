**Component:** `src/prosiform/cli.py`

## Overview

This task asks the portability question of a reference as its author wrote it. An image names a resource whatever file its destination spells, because image syntax embeds rather than links, so a bundle whose only resource is an image naming a Markdown document warns once with `W_RESOURCE_PORTABILITY`. A bundle naming no resource still warns not at all.

The classification the warning applies becomes the one discovery already applies, so a single run gives one answer about the same reference whichever question is asked of it.

## Problem

- **The predicate reads the destination and nothing else.**
  `cli.resource()` takes a destination string, answers "not a resource" for every path the profile reads as Markdown, and is never told which syntax named it. `cli.resourced()` walks the published bundle's inline events, where the image token sits in front of it, and throws that fact away by asking only about the destination.

- **Two definitions of resource are in force at once.**
  `source.uses()` marks every image `resource=True`, and `cli.required()` passes over it on that mark, so `![the rules](rules.md)` is never opened and never bundled. The warning disagrees with that classification, so one run reads the same reference two ways.

- **The silence is the failure mode the warning exists to prevent.**
  A reader opening such a bundle from another directory may not find `rules.md`. That is what `W_RESOURCE_PORTABILITY` is for, and a bundle whose text names no resource is meant to be the only one that says nothing.

- **The published corpus records the gap as the rule.**
  `fixtures/resource/an-image-naming-a-document-under-the-root` declares the run's present diagnostics, so its manifest is what states the rule once the predicate is whole.

## Proposal

- **The use decides, with where it points.**
  The portability predicate takes the reference as written: whether its destination is one the directory the bundle is read from decides, and whether the use embeds. A local destination names a resource when the use is an image, whatever the destination spells, or when the use is a link naming no Markdown document. A destination carrying a scheme, an authority or a drive letter, and a bare fragment, name nothing that directory decides and are no resource under either use.

- **One walk over the bundle's references.**
  `cli.resourced()` reads the published bundle through `source.uses()`, the same walk discovery reads a source through, so an image's alternative content is descended into where it sits and the emission and the warning count the same uses.

- **The warning stays once per bundle and stays a warning.**
  A bundle naming one resource or twenty warns once, and the run still exits 0, because portability is the caller's question rather than a defect in the source.

- **The corpus states both edges.**
  `resource/an-image-naming-a-document-under-the-root` records the warning, and `resource/a-bundle-naming-no-resource-does-not-warn` still records none, so the rule is published rather than left to the build's own tests.

| Analysis | Where the warning is decided — `cli.resource()` and `cli.resourced()`, against `source.uses()` and `cli.required()`, which already classify an image as a resource.
