**Component:** src/prosiform/cli.py

## Overview

The three mapping shapes that state nothing and must be refused, with the fixtures that show each refusal and the run it leaves unpublishing. Two keys normalizing to one identity, a key and value normalizing to one identity, and a key of the form `#section` that names no document to redirect.

## Problem

A repeatable option admits values the grammar cannot tell apart by shape. Two keys normalizing to one identity means the second silently wins, and a key whose sides normalize to one identity is a substitution that changed nothing while reading as one that took effect. A key carrying no document is resolved against an empty path and redirects nothing. None is visible in a bundle, and none fails any other check.

All three are absent from the build at this branch's base, `164a5200`, which W01's change list records from the other side: `-m rules.md=a.md -m ./rules.md=b.md` exits `0`, and so does `-m rules.md=./rules.md`.

## Proposal

**The scene.** A value the grammar cannot admit becomes a `Failure` carrying `E_INVALID_USAGE` and exit status 2, which is the outcome the contract gives a command line it refuses. The refusals are decided where the whole mapping is known, which is after every entry has been parsed rather than per value.

**The design.**

- **One place decides the three.** `cli.substitution` reads `options.mock`, which the grammar left as the parsed pairs, and holds the set of identities the mapping has claimed. Every entry is added to it, so a shape that states nothing is refused at the point the whole mapping is visible.
- **Duplicate keys.** Each entry contributes `(path, fragment)` — the identity `closure.identity` names — to the set. A second entry naming one already there is refused, and the message carries both spellings the author wrote, kept beside the set for that purpose, so it says which two options to edit rather than which one identity they share.
- **A self-mock.** An entry whose key and value name one identity is refused, because the redirect is what the option states and it states none.
- **A fragment-only key.** A key whose `path` is empty names no document, so it is refused rather than resolved against a referrer the option does not name.
- **Each refusal names its own fault.** All three carry `E_INVALID_USAGE` and the reference the author wrote. Two of the three share the code by design — the contract gives every malformed command line one code so a caller has one remedy — and the message tells them apart.
- **Nothing is published.** The refusals are raised in `execute` before `entry` resolves the positional references and before `root` is read, so a refused run opens nothing and writes nothing.
- **A document key and a section key of that document are two keys.** The identity includes the fragment, so `rules.md` and `rules.md#escalation` may both be given.
- **The row is not divisible further.** All three are decided from one loop over one set, and a pull request carrying one without the others leaves a mapping shape that silently wins. They land together.

Each manifest names four clauses: the mapping's own clause, the `CLI contract` heading whose prose declares the usage failure, the option's row, and the exit status the contract gives it. The mapping's clause carries the refusal in prose; the other three are what the run reaches when it refuses.

## Additions from review

| Addition | What it states |

| The spelling is kept beside the identity set | A set of identities alone can say that a second entry repeats one, but not which two options to edit. The mapping is small, so the authored text is kept with the key it normalized to and the message is written from both. |
| A fragment-only key is refused ahead of the self-mock comparison | A key carrying no document would otherwise be compared to its substitute as an identity of `""` or of a bare fragment, which reports a self-mock for a pair that names no document at all.
