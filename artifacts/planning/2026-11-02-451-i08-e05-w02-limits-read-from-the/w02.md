**Component:** main:src/prosiform/limits.py

## Overview

`in_force` builds the budgets in force from the entries a command line named, so the rule that an unnamed budget stands at its default is stated once, in the module that declares the defaults, and `src/tests/test_limits.py` observes it.

## Problem

The default rule lives outside the table that declares the defaults.

- **`cli.budgets` fills the defaults.** It walks `BUDGETS` and reads `budget.default` for each one the command line did not name, so the command-line module states a rule of `limits.py`.
- **Every other caller restates it.** Eight test sites build `Limits({b: b.default for b in BUDGETS})`, or the same comprehension with one figure swapped in, so the rule is written once per caller.
- **No test observes `limits.py` itself.** There is no `src/tests/test_limits.py`; the defaults are observed only through the parser in `test_cli.py`.

## Proposal

**The scene.** `limits.py` declares `BUDGETS` and holds the `Limits` value a run counts against; `cli.budgets(options)` returns the `Limits` in force from the parsed `--budget` entries.

**The design.**

- **`in_force(named)` builds the budgets in force.** It takes a mapping from `Budget` to figure and returns a `Limits` holding one entry per `Budget` in `BUDGETS`: the named figure where one is given, the declared default otherwise.
- **`cli.budgets` reads the parsed entries.** It returns `in_force(options.budgets)`, so the command-line module translates options and nothing more.
- **Callers name only the figures they change.** A test holding defaults writes `in_force({})`; one raising a single budget writes `in_force({FILE_BYTES: figure})`, and a test reading only the nesting default reads `NESTING.default`.
- **`src/tests/test_limits.py` observes the rule.** A `Limits` read from no entries holds every budget at its default; one read from a single entry holds that figure and every other budget at its default; each holds exactly one entry per `Budget`.
