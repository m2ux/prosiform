**Component:** `checks/conformance.py` — the conformance report.

## Overview

The installation claims the smoke run cannot observe stand in the conformance report's declared-surface listing, each beside the exit statuses and codes already listed as unfixturable, carrying the reason it is unreachable and what would have to change for a run to reach it.

## Problem

The smoke run builds the distribution, installs it into a throwaway environment and invokes the command by name from a directory unrelated to the repository. Three claims about installation sit outside what that run can observe: another platform, whose command wrapper and path resolution are a different mechanism; a machine that never held the repository, which is on disk throughout the run and merely unreachable by path, working directory and environment; and the installation command the documentation gives a reader, where the run installs an artefact it built rather than running that command line.

None of the three is a corpus fixture. A fixture declares a source tree and the bytes a run must return for it, and the corpus reaches the build under test through configuration, so an installation is not a thing a fixture can name. Today the three live only in the I00:E07:W01 planning record, a dated folder nothing re-reads, and the conformance report — the one place a reader asks what the contract's surface is covered by — says nothing about them. The corpus therefore reads as covering installation whole.

## Proposal

- **An installation claim is an entry of the declared surface.**
  The report already lists each name the contract declares against the fixtures reaching it, and names one only an awaiting fixture declares as unfixturable with the work it awaits. A claim about installation is the same kind of statement about the same surface — something the contract says that no run of the corpus observes — so it is listed there rather than in a second report or a planning document.

- **Each claim carries the reason it is unreachable and what would make it observable.**
  The reason says why the smoke run as it stands cannot reach the claim; the second line says what a run would have to do to reach it. A reader of the report then knows both what is uncovered and what covering it would take, which is what the exit-status entries already give for the work they await.

- **The listing is generated, so a claim that becomes observable leaves it.**
  The claims are declared beside the surface the report renders and are printed by running the report, so the report is where the statement lives and a run that comes to observe a claim removes its entry at the one place it is written.

- **The entries state the behaviour, not the machinery.**
  The independence check scans the report as it renders, so a claim is worded in the terms the contract uses — a platform, a machine, a documented command line — rather than in the words a build's packaging uses for them.

- **The report's summary counts them.**
  The closing line already counts the declared names reached and those unfixturable; it gains the number of installation claims no run reaches, so the figure a reader takes from one line is the whole of what the surface listing holds.
