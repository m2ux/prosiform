## Overview

The diagram-following eval gains corpus, scorer and harness support for checking how agents follow compiled bundles through composition, deferral and deep dispatch. Scenarios state each agent's ordered `pf` runs, and session traces are checked against those runs and the expected path. The edge-run shakedown, live edge measurements and measured-results documentation are scoped to [I14 Evaluation Refinement](https://github.com/m2ux/prosiform/issues/660), in [Composition Measurements](https://github.com/m2ux/prosiform/issues/661).

## Changes

The eval observed only whether a bootstrapping session ran `pf` at all, so no scenario could say which deferred line a session compiles, and no form gave a session a bundle and the build together.

### Stated Runs

- **A scenario states its `pf` runs.**
  A `[[scenario.compile]]` table names each run's agent and references, in walk order, each held to the sources by the corpus test.

### Compiled Form

- **A compiled session receives a `pf` run's output.**
  The compiled sources, the entry's bundle set in `pf`'s folder, and the build as `pf` with a shell limited to it.

### Run Checks

- **The scorer holds a session to its stated runs.**
  `uncompiled`, `overcompiled` and `misordered_compile` follow the dispatch checks wherever a harness reports commands.

### Sub-agent Calls

- **The session record files each call under its sub-agent.**
  Each start names its parent start and its sub-agent's commands, at the depth each harness declares its stream carries.

### Bootstrap and Deferral

- **A skill's undeclared entry hands over one `↳` line.**
  `inline-bootstrap` states bare `pf`, then `pf` on the line, and the walk of the bundle it writes; a session that ran no `pf` fails `uncompiled`.
- **A compiled walk runs `pf` on each `↳` line a step reaches.**
  `deferred-composition` reaches and passes a conditional and a nested deferral, and `preset-deferral` follows the transition its preset's stand-in states.

### Composition

- **A bundle walk enters a state where a `↳` title or a footnote leads.**
  `conditional-composition` composes a state beneath a conditional step, entered only where the step holds; `directive-labels` reads a `↳` composition in place, opens a footnote's target as a document, and composes a section of its own document under `W_COMPOSE_SELF`.

### Deferred and Deep Dispatch

- **A deferred section that dispatches is compiled where its step reaches it.**
  `deferred-dispatch` states `pf` on the `↳` line and the sub-agents its run's bundle dispatches; the dispatch walk records each start's depth.
- **Chains run three hops below the session.**
  `dispatch-depth` states a chain, a set at the second hop and a question relayed from the third, with no `W_DISPATCH_DEPTH`.
- **A sub-agent's `pf` run is stated and shown by its action.**
  `subagent-first-run` states each sub-agent's run and the files only a deferred line's material names, at the first, second and third hop; one undone fails `missing_action`.

### Claude Compiled Session

- **A compiled Claude session carries a shell.**
  `Bash`, approved for `pf` alone, reaches the `compiled` and `bootstrap` sessions, so the nested-dispatch scenarios take a Claude cell scored on each start's runs.

### Guide Bundles

- **The corpus test reads the guide's bundles.**
  Each dispatched bundle carries the run-pf instruction before its source content, each `⇉` link names a file its run wrote, and no source writes a retired mark.

### Triage Rubric

- **The rubric decides each run class.**
  `uncompiled`, `overcompiled` and `misordered_compile` each take a `miss`, `defect` and `unclear` reading in `RUNBOOK.md`, which holds no row for a class the scorer does not give.
