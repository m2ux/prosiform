## Overview

The run's entry declares the stubs of a trial, and their `subst` pairs redirect the links of every document the run compiles, so a shim holds a test's whole configuration and the stages it tests hold only what a live run reads.

## Problem

- **A stub redirects only its own document's links.**
  A shim's stand-in for a stage two dispatches below it substitutes nothing, so trial material sits in the stages under test.

## Proposal

- **The run's mapping carries the entry's stubs.**
  `Substitution` holds the entry's path and the pairs of the stubs its title selects, keys resolved from the entry. Each lookup asks them before the writer's pairs, exact section then whole document, so the entry's pair holds for one key and a document's section key still holds over an entry's document key. A redirect it serves is recorded under the entry, so it warns once across the run.
- **The entry's bundle reads the stubs; dispatched bundles inherit them.**
  `staked` reads them once the entry is read; `Compiled.substitution` hands the mapping to every dispatched bundle.
- **A stub below the entry fails.**
  `stub_off_entry` refuses a `stub` preset in any compiled document other than the entry with `E_STUB_OFF_ENTRY`. A deferred target is no document this run compiles, so it may declare stubs for the run that compiles it.
- **A deferral carries names alone.**
  The user chose this: the later run's entry is the deferred target, so the names select its stubs, and this run's pairs stay with this run.
