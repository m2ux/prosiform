**Component:** `checks/manifests.py`

## Overview

Every warning the design declares is stated by a fixture of the corpus, and a check of the corpus's own harness holds that true.

## Problem

A warning code the contract declares and no manifest carries is a claim about standard error that nothing exercises.

- **A catalogue entry is not a conformance.**
  The schema enumerates the warning codes and holds each manifest to them, so a code in the catalogue can never be mistyped. Nothing requires the corpus to reach one, so a declared warning can sit in the catalogue with no run stating what it accompanies.

- **Coverage that no check holds drifts in silence.**
  The corpus grows one clause at a time, and a warning arrives in the catalogue with the clause that declares it. The fixture that states it arrives with whichever row the clause falls to, and nothing reports the interval between them.

## Proposal

The corpus already reads every manifest to validate it, so the codes the fixtures reach are a fact the harness can take from the same pass. The gap is that nothing collects them.

- **The corpus reader reports the codes the fixtures declare.**
  `declared_codes` walks the corpus and returns the codes its manifests carry at one severity, read from the manifests rather than from a list beside them, so a fixture added anywhere is counted by being a fixture.

- **A warning the catalogue holds and no fixture states fails the harness.**
  The assertion sits beside the test that holds each catalogue to the design's own text, so the two statements a catalogue is held to — that it is the design's codes, and that the corpus reaches its warnings — are read together. A warning code added to the design fails the harness until a fixture states it.

- **A fixture awaiting later work counts.**
  A fixture states its diagnostics whatever the build currently produces, so the declaration is the corpus's the moment the manifest carries it. Requiring a passing run instead would make this row wait on the rows that deliver the warnings, and each of those already carries its own criterion.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The warning codes the design declares, and the manifests that state each one, measured over the corpus |
| Plan | Where the coverage is read, where it is asserted, and what a fixture awaiting later work counts for |
| Implementation | The declared-code reading in the corpus reader, and the statement of the invariant in the checks and corpus documentation |
| Review | Confirmed the reading takes a code from a manifest alone, and that the error catalogue's own coverage is left to the rows that carry it |
| Test | A harness test requiring every warning code of the catalogue to be declared by a fixture, run with `make harness`, alongside the corpus run and the repository's full check suite |
