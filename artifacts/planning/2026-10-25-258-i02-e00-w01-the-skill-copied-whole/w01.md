**Component:** example/work-planner/

## Overview

The example carries the work-planner skill under the name it holds, so the tree a demonstration compiles is the one its users write rather than a four-file reduction of it. This row copies every Markdown file the skill holds into `example/work-planner`, and gives each a root that resolves from the example directory.

## Problem

The example states a shape its users do not write, and nothing in it can be compiled into a tree of the size the demonstration needs.

- **Four files stand for a skill of forty-nine.**
  `example/work-tracker` holds one routing document, one mode and two artifacts. The skill it reduces holds a routing document, ten modes, six protocols, thirty artifacts and one reference.

- **No link in the tree reaches a protocol or a second mode.**
  A tree that small has no folder holding more than two members, so a bundle of it can show neither a grouped folder nor a mode a routing document selects.

- **The declarations the copy needs do not exist yet.**
  `example/work-tracker` declares `root: "."` on its routing document and nothing on its members, so a member's link to a sibling resolves under the invocation directory rather than under the source root.

## Proposal

- **The copy is the skill's Markdown, whole and unaltered.**
  Every `.md` file under `skills/work-planner` is written to the same relative path under `example/work-planner`, with the file's content unchanged. The scripts and tests are not copied, because the example states what a bundle of a skill reads and not what a skill runs.

- **Each member declares the root it resolves from.**
  Every file under `artifacts/`, `protocols/` and `references/` declares `root: ".."`, and each mode declares `root: ".."`, so a link to a sibling or to the routing document resolves from the example directory.

- **The routing document keeps the root it states.**
  `SKILL.md` declares `root: "."`, which is what makes it the entry a bundle starts from rather than a member of the folders beneath it.

- **The example is named for the skill it carries.**
  The directory is `example/work-planner`, matching the skill's own `name`.

- **The row is read by the checks the repository already runs.**
  The link check resolves every reference the copied files write, and `make layout` confirms the tree is tracked rather than an untracked directory a fresh checkout cannot see.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Read the skill's file inventory from `git ls-tree` on the branch the copy is taken from, and read `invocation.md` for the root rules a member's link resolves under. |
| Plan | Decide the root each file declares by the directory it sits in, and confirm the routing document is the only file declaring `root: "."`. |
| Implementation | Write every Markdown file of the skill to `example/work-planner`, with its frontmatter carrying the declared root. |
| Review | Compare the two trees by file count and by path, and confirm no file's content beyond its frontmatter differs from the skill's. |
| Test | Run `make links` and `make layout`, and bundle the copied `SKILL.md` to confirm the tree resolves. |
