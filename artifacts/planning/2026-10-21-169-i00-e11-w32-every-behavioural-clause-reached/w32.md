**Component:** `fixtures/`

## Overview

Every behavioural clause of the design is reached by a fixture or recorded with the reason no fixture can reach it, and the design's own non-behavioural sections are told apart from the gaps, so the conformance report's uncovered figure reads as the corpus's reach.

## Problem

The report reads 253 clauses from the design and lists 64 reached by no fixture.

- **Eleven are the design's own non-behavioural sections.**
  `Design status`, `Implementation verification and residual policy detail` and `Upstream follow-up reference`, with their bullets, state what the project decided rather than an outcome a run can produce, and are listed for the same reason a genuine gap is.

- **Thirty-three are clauses the corpus already exercises.**
  A fixture establishes the clause and names another, so the report understates the corpus's reach.

- **Four are clauses no fixture reaches.**
  The usage response, the profile's core syntax, a raw HTML link naming a local document, and a title the file heading absorbed standing as a structural ancestor.

- **Sixteen state something one run against one source tree cannot produce.**
  Two headings carry no rule of their own, six bind how a build identifies and edits spans, four state what a project does rather than a run, and three bind the caller's wrapper.

## Proposal

- **A section stating no behaviour is told apart from a gap.**
  The report names the design's non-behavioural sections with the reason each states no behaviour a run can produce, and their clauses leave the uncovered list.

- **A clause no source tree can state is recorded where it is read.**
  It takes the entry shape the declared surface already uses for an installation claim no run observes: its name, the reason, and what a run would have to do to reach it.

- **Every remaining clause is named by the fixture that establishes it.**
  A clause the corpus already exercises gains its declaration; one nothing exercises gains a fixture.
