## Overview

Restatement refuses each fixture whose difference a reader must decide, so a fault or a behaviour change never becomes a fixture's expectation.

## Problem

A rewrite driven from a failing run's verdict writes whatever the build produced.

- **A fault is recorded as the expectation.**
  A fixture whose run reports an internal error reads as one that failed, so restating it writes the crash into the corpus.
- **A behaviour change hides behind a bundle rewrite.**
  A fixture whose exit status or diagnostics moved also differs in its bundles, and restating those leaves the real change unread.
- **An added or lost bundle is accepted unseen.**
  A run writing more or fewer bundles than declared changes what the fixture states, not how it is spelled.

## Proposal

A red corpus run names forty fixtures, and three of them differ for a reason the change did not intend.

- **A failed run is refused.**
  Restatement reads the runner's verdict. A fixture whose run failed in itself is named and skipped.
- **A contract difference is refused.**
  A fixture whose exit status or diagnostics differ from its manifest is named and skipped.
- **A change in the number of bundles is refused.**
  A rename keeps the count. A different count is a hand edit.
- **A refusal fails the run.**
  The exit status is nonzero when any fixture is refused, so a pipeline restating on a red build cannot pass over one.
