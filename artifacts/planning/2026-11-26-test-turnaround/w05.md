## Overview

The overlap table lists every command-line test beside the fixtures that hold the same assertion, so the user decides which tests leave from a record, not from a guess. The task removes nothing.

## Problem

Nothing says which command-line tests a fixture already holds.

- **Two suites run the command end to end.**
  [The command-line tests](https://github.com/m2ux/prosiform/blob/b0eb7a2335436f2ce9c35546d3bfd2e39f7ae3be/src/tests/test_cli.py#L233-L260) invoke the build as [a fixture run](https://github.com/m2ux/prosiform/blob/b0eb7a2335436f2ce9c35546d3bfd2e39f7ae3be/checks/runner.py#L535-L595) does.
- **A test names no clause.**
  A fixture declares the clauses it exercises and a test declares none, so the conformance report cannot pair them.

## Proposal

A change to one behaviour fails a fixture and a command-line test that assert the same thing.

- **Line containment shortlists.**
  The build's tests run under coverage with a context per test, and the corpus under subprocess coverage with a context per fixture. A fixture whose lines contain a test's is a candidate.
- **Reading decides.**
  Each candidate pair is read, and the table records whether the fixture asserts what the test asserts.
- **Every test has a row.**
  A test no fixture holds is recorded as held by none, so the table accounts for the whole file.
- **Coverage stays outside the lockfile.**
  It runs through `uv run --with`, so the build's dependencies do not change.
- **The user's verdict is a column.**
  Each row a fixture holds carries the user's approval or refusal of its removal.
