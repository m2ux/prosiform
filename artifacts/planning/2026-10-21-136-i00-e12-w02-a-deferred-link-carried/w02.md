**Component:** `src/prosiform/closure.py`

## Overview

This task makes the mark defer a compilation. A link whose text opens with `¬` is not compiled by this run: the document it names is not opened through that reference, its content does not enter the bundle, and the link reaches the output with the mark exactly as its author wrote it, so an agent reading the bundle compiles what it marks in a run of its own.

It matters because the mark is the only thing an author writes to say that material belongs to a bundle's context without belonging to its body. Without it a bundle is all of its context or none of it: linking material carries it, and moving it outside the root puts it beyond the agent holding the bundle. The deferral is what lets a bundle state its immediate context now and its deeper context on demand.

## Problem

Position decides what the bundle compiles, and the mark decides nothing. A marked link under the allowed source root is compiled like any other, and the rewrite takes the mark off the text it published.

- **The deferral has no subject.**
  An author who writes the mark on a reference under the root gets the compilation they were asking the run not to perform, so there is no way to state that material is reached in a run of its own.

- **The rewrite destroys the instruction.**
  Three paths take the mark off a compiled link — the span edit in `rewrite.edits()`, `rewrite.unmarked()` behind `bundle.emitted_visible()`, and `rewrite.unmarked()` behind `candidate.intended()` — so the one byte an agent would read the deferral from is the byte the bundle removes.

- **A heading is slugged twice because of that removal.**
  `bundle.shown_text()` derives the text a heading shows after the rewrite and `bundle.source_fragments()` derives the fragment it answered to before it. The two differ only where the rewrite dropped a mark from a heading's link, so one removal is carried through every emission and every candidate comparison.

## Proposal

The mark is content rather than a selector. It overrides position in one direction only: it withholds a compilation that position would have granted, and it changes nothing about a reference position already leaves as text.

- **The classifier holds the whole rule.**
  `closure.bundled()` answers whether the bundle compiles one link, and it now reads the literal text that link opens with alongside the destination. A marked link is no dependency, so discovery, emission and candidate validation give the same answer without any of them restating the rule.

- **Discovery defers rather than opens.**
  A marked reference resolving to a Markdown document under the root is passed over in `cli.dependencies()`: no identity is yielded for it, so the document is not read, not parsed and not bundled through that reference.

- **Nothing strips the mark.**
  The mark span is no longer an edit the emission makes, and `rewrite.unmarked()` goes with it. A link the bundle compiles carries no mark, and a link it does not compile is published with the bytes its author wrote.

- **One heading text, read from the source.**
  With no rewrite to the text a heading shows, the text the bundle emits is the text the source wrote, so `bundle.emitted_visible()` and `bundle.compiled()` have nothing left to compute and the two heading maps are the visible text and its slug.

- **A deferral survives another author's reference.**
  Whether a marked link is compiled is read from that link, never from its target, so a document another source carried into the bundle leaves a deferred link to it untouched.

- **A rule a later row owns keeps the behaviour the build has.**
  A marked resource and a marked direct self-reference are still refused, which `W04` and `W05` retire. A deferred reference naming no document or no heading is not resolved further and does not fail, which `W03` states with `E_TARGET_NOT_FOUND`. A deferred link's destination stays as the author wrote it, which `W07` rebases to the target's root-relative path.
