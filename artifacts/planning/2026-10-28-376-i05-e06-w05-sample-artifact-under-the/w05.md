**Component:** example/work-planner/artifacts/placement.md

## Overview

One artifact file, `example/work-planner/artifacts/placement.md`, is brought to every authoring rule, so each structural rule is seen on a real file and approved before W06–W09 apply it across the example. The pull request is the approval: a rule changed in review is changed in `example/work-planner/guidelines.md` on this row.

## Problem

`make authoring` over the branch base (`8440ab31`) reports 13 findings for the file:

| Kind | Count | Where |
| --- | --- | --- |
| Inputs and Outputs | 10 | Each of the five operations has a prose **Inputs:** line and no **Outputs:** line |
| Commands section | 1 | `## Commands` |
| Command placement | 2 | The List Orphans command and its example sit outside a step |
| File-relative links | 0 | |

Inspection finds what the check does not read:

- **Operation names.** Each operation heading carries an emphasised verb: `### *Draft* Issue Placement`.
- **Contracts.** Fields mixes a bullet list of conditions (Source, Destination, Disposition, Draft bodies, Links, Preservation) with five `###` sections; the orphan, the candidate destinations and the draft bodies have no contract of their own.
- **One home per rule.** The disposition rule is stated in five places in the file: the Fields Disposition bullet, the Placement Record table, Disposition Conditions, the last sentence of Destination Work, and Draft Issue Placement step 3.
- **Conditions in contracts.** Preservation (the original-body comment before a rewrite) is a condition on a step, stated in Fields.
- **Conventions.** Subsume Orphan Work prepares a comment file without linking the Bodies convention in `conventions.md`.

## Proposal

### Operations

| Operation | Inputs | Outputs |
| --- | --- | --- |
| Draft Issue Placement | Orphan, Candidate destinations | Placement options, Draft bodies |
| Find Placement Candidates | Repository issues (`issue.md#fields`) | Candidate issues, Candidate destinations |
| Apply Issue Placement | Confirmed placement, Orphan, Destination, Initiative body, Epic body, Body paths | Populated bodies, Destination, Disposition |
| Rewrite Orphan Issue | Orphan, Destination | Rewritten orphan |
| Subsume Orphan Work | Orphan, Destination | Closed orphan |

Each heading is verb first with no emphasis; steps stay `#### N. Action`. Each **Inputs:** and **Outputs:** line is a paragraph of its own.

### Contracts

Fields holds one `###` contract per value: Orphan, Candidate Issues, Candidate Destinations, Placement Record, Destination, Disposition, Draft Bodies and Original Body. Destination absorbs Destination Work; Disposition absorbs Disposition Conditions and is the one home of the disposition rule; Draft Bodies absorbs the Draft bodies and Links bullets. Preservation moves into Rewrite Orphan Issue step 1 and Subsume Orphan Work step 2.

### Commands

List Orphans moves into Find Placement Candidates step 1 with its "Runs as Helper invocation states." line and its labelled example; step 2 reads the helper's exit code and output. `## Commands` goes.

### Guidelines

- **W11 de-duplication, applied here.** One home per rule and Commands in steps link the shared rules and keep only what the work-planner adds.
- **Inputs and Outputs.** "one line each" becomes "each a paragraph of one line", since two adjacent lines render as one paragraph.
