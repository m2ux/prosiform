**Component:** main:src/prosiform/metadata.py

## Overview

A preset holds its division pairs and `subst`, and nothing else. The `exclude` entry W03 built named sections a whole-document reference withheld; the design no longer states it, so the reader, its value, its tests, its fixtures and its page rows go, and an `exclude` key is refused as any unknown preset key is.

## Problem

The design states a preset of two keys, and the tree still carries a third.

- **The reader admits `exclude`.** `metadata.FIELDS` lists it, `metadata._exclusion` reads its entries into `Exclusion` values, and `Preset.exclusions` holds them, though nothing reads them.
- **Tests and fixtures state it.** `src/tests/test_metadata.py` reads and refuses `exclude` entries, and two corpus fixtures cite the design's *`exclude` holds names* clause.
- **Pages state it.** `docs/sources.md` lists the key and its example; the design's Conversion metadata and Presets clauses describe what it withholds and how selected presets combine it.

## Proposal

**The design.**

- **A preset admits two keys.** `FIELDS` holds the division pairs (`group-depth`) and `subst`; any other key, `exclude` among them, meets the unknown-field refusal `E_INVALID_CONVERSION_METADATA` that already exists.
- **The retired key is removed, not refused.** No refusal code, message or fixture names `exclude`.
- **The shared single-entry reader stays.** `_pair`, `_level` and `_single_line` serve the division pairs and `subst`.
- **The design and the source page state two keys.** The design's example, field table, *An entry is one string key with an integer value*, *`default` always applies*, *Selected presets union*, *What a selection governs*, *A preset nothing selected warns*, the metadata failure table and the rejected-metadata row drop `exclude`; *`exclude` holds names* is removed. The README design pin moves to that commit.
