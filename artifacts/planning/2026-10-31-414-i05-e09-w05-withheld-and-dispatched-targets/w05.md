**Component:** src/prosiform/cli.py

## Overview

Withheld references redirected: the deferred and dispatched targets a run resolves without compiling, the destinations a bundle publishes for them, and the fixture that shows a deferred destination naming the substitute. A withheld link's target is redirected like any other, and the destination the bundle publishes for it is the substitute's working-directory-relative path, because a later run follows the path the bundle published and must therefore find the stand-in there.

## Problem

A deferral and a dispatch withhold a compilation but not the resolution. `withheld` yields each target, the run confirms the document and its heading exist, and `rebased` publishes the target's working-directory-relative path for a later run to follow. A mapping applied only to compiled dependencies would leave those destinations naming material the mock never touched, and the later run would compile the real document out of a bundle built to avoid it. `bundle.target` reads the same resolution while rewriting the link, and `candidate` reads it again while comparing the emitted text, so a mapping that reached only one of them would report a destination the bundle invented.

The published destination is the one place the resolution is written down rather than read, so it is where a redirect can be lost without any stage disagreeing. `rebased` publishes the fragment its author wrote, and a section key redirects that fragment to a different section of the substitute: the run confirms the substitute carries the section it resolves to, then publishes the section the author named, which the substitute need not carry at all. A later run follows that destination and fails with `E_TARGET_NOT_FOUND` on a bundle this run declared sound. The contract's rule is the resolved fragment — *retain the resolved fragment when present* — so the defect is the code reading the authored spelling where the rule names the resolved one.

## Proposal

**The scene.** `withholding_target` resolves through `resolvable` for both operators. `bundle.target` reads it while rewriting, `candidate` reads it while comparing, and `dispatches` reads it for the dispatch analysis of both the dispatch operator and the parallel dispatch mark.

**The design.**

- **The seam covers them already.** `withholding_target` takes the mapping, so both operators resolve to the substitute and everything downstream reads it: the existence check, the heading check, `rebased` and the chain a diagnostic carries.
- **`rebased` publishes the substitute's path.** It reads `found.path`, which is the substitute's. Its fragment is the one the target resolved to, so a section key's substitute publishes the section the substitution names, and a document key — which keeps the reference's own section — publishes the section the author named, having confirmed the substitute carries it. A reference resolving to no section publishes the fragment its author wrote, which an empty one spells as the bare delimiter.
- **Dispatch analysis follows the substitute.** `onward` compiles a dispatched target as an entry, and it compiles the substitute, because the hop it is given is the redirected reference. A substitution inside a dispatched closure raises its own warnings there.
- **The heading check is asked of the substitute,** because that is the document the later run reads.
- **The candidate comparison reads one answer.** A run that resolved without the mapping would report the published destination as one the bundle invented.
