## Overview

The pull request artifact owns the head, target and publication rules protocols restate. Create Pull Request Worktree owns its freshness retry. Measure Repository Change owns its stale-index retry. Checking a work item's tests against its criteria is one operation. Retargeting a pull request to its delivery base is one operation. Merge Task Pull Requests changes one object.

## Problem

- Epic Integration checks head and target itself (epic-integration step 1) and restates readiness and refusal handling (steps 2-3). Review Pull Request holds its publication condition (step 3).
- Change Overview step 1 repeats Read Pull Request State and Create Pull Request Worktree on a changed head.
- Change Overview step 1 repeats Measure Repository Change after an index update.
- Run Delivery Session checks the test row against Coverage inline (deliver-mode.md:100-102).
- Align holds the base rules and the update-on-unmergeable step inline (align-mode.md:251-259), and Plan retargets with Publish Pull Request (plan-mode.md:85).
- Merge Task Pull Requests also updates the epic base and task branch, a second object.

## Proposal

- Fetch Merge Readiness checks head and target; the State field holds the publication condition and the ready mark.
- Create Pull Request Worktree re-reads the head and retries before returning a changed-head finding.
- Measure Repository Change updates the index and measures again before returning.
- Check Test Coverage returns each criterion with no test.
- Align Pull Request Base retargets to the epic base or long-lived branch, applies Update Task Branch when not mergeable, and reports the rest; the base rules sit in Scope and Other Pull Requests.
- The branch update moves to Task Merge, which applies Update Task Branch.
