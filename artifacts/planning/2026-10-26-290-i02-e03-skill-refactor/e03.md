## Overview

The example skill follows its own layering. Each mode is orchestration alone, each object the modes act on is an artifact owning the operations that change it, and each protocol is a procedure built only of applied operations and followed protocols, so a call always goes down the stack. The example then demonstrates the structure its rules prescribe, and every mode bundle stays clean and within budget.

## Problem

The example's modes do much of the work their artifacts and protocols should own.

- **Modes transform artifacts inline.**
  Sync [verifies, ticks and saves criteria step by step](https://github.com/m2ux/prosiform/blob/2ff72d16f43b6620e55fd7a43a4f747d36f45f78/example/work-planner/modes/sync-mode.md#L93-L104), and Align writes the [same sequence again](https://github.com/m2ux/prosiform/blob/2ff72d16f43b6620e55fd7a43a4f747d36f45f78/example/work-planner/modes/align-mode.md#L216-L244).
- **Sequences are copied between modes.**
  Verify Selected Criteria is linked on seven lines across Sync, Align and Issue Delivery, and Read Board State on six lines across Advance, Deliver and Standup.
- **Protocols hold rules their artifacts should state.**
  Epic Integration [checks head and target itself](https://github.com/m2ux/prosiform/blob/2ff72d16f43b6620e55fd7a43a4f747d36f45f78/example/work-planner/protocols/epic-integration.md#L21), and Change Overview [names its record folder](https://github.com/m2ux/prosiform/blob/2ff72d16f43b6620e55fd7a43a4f747d36f45f78/example/work-planner/protocols/change-overview.md#L28-L29).
- **Some operations change two objects.**
  [Merge Task Pull Requests](https://github.com/m2ux/prosiform/blob/2ff72d16f43b6620e55fd7a43a4f747d36f45f78/example/work-planner/artifacts/pull-request.md#L144-L161) also updates the epic base and task branch, and Apply Issue Placement saves several issues.
- **Technical debt has no artifact.**
  Deliver [classifies the debt a unit finds inline](https://github.com/m2ux/prosiform/blob/2ff72d16f43b6620e55fd7a43a4f747d36f45f78/example/work-planner/modes/deliver-mode.md#L123-L131).

## Proposal

- **Modes orchestrate.**
  A mode's Procedure selects scope, applies operations, follows protocols and modes, and routes returned findings and decisions.
- **Artifacts own their operations.**
  Each object is an artifact with Operations, one `###` per operation opening with its purpose and an **Inputs:** line, beside its Fields, Guidance and Commands.
- **Protocols compose.**
  A protocol names no artifact's rule: it applies operations and follows protocols, and a mode reaches an operation directly only where no protocol owns the change.
- **Technical debt becomes an artifact.**
  The classes Blocking, Trivial and Non-trivial and the classification of an item sit in their own artifact.
- **Each row keeps the build green.**
  A row re-records the usage fixtures its change moves, so `make corpus` passes and each mode bundles cleanly on the epic base between rows.
- **What stays.**
  Generic heading names, Run Delivery Session's place in Deliver, parallel dispatch wording and script paths are left as they are.
