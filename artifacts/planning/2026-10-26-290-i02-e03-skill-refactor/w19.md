**Component:** `example/work-planner`

## Overview

Every operation and protocol has a caller. The worked examples quote what the refactored tree holds. The refactored tree bundles cleanly and its fixtures describe what they record.

## Problem

- Operations whose callers moved to protocols or new operations, such as Locate Project Board, Publish Planning Record, Apply Issue Placement and Subsume Orphan Work, stay in the tree with nothing reaching them.
- `example/README.md` quotes Plan Mode's publish step and states the tree's document counts, and the refactor changes both.
- Every row re-records the usage fixtures it moves, and a description written for the tree before the refactor can name a heading, count or section its bundle no longer holds.

## Proposal

- Each uncalled operation leaves its artifact, with its commands where nothing else runs them.
- Each excerpt and count is re-read from the tree and its bundles.
- Each mode is bundled and its standard error read; each fixture is re-recorded and its description held to its expected output.
