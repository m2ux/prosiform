**Component:** `example/work-planner/artifacts/delivery-evidence.md`

## Overview

Read Delivery Evidence reads; the caller owns any title repair. Plan Available Work resolves the off-board issues it needs. Compose Standup Report resolves the initiatives it reports on. The board's delivery snapshot is read by one operation. Record Board Delivery reads the snapshot through its operation.

## Problem

- Read Delivery Evidence step 3 renames a pull request through Publish Pull Request, a write inside a read; Sync repeats that repair itself (sync-mode.md:35-41).
- Deliver resolves missing issues and repeats Plan Available Work by hand (deliver-mode.md:33-34, 54).
- Standup resolves initiatives and repeats Compose Standup Report by hand (standup-mode.md:33-37).
- The same fetch block of board state, initiative pull requests, issue links, configuration and assignee is copied into Advance, Deliver and Standup (advance-mode.md:21-26; deliver-mode.md:21-27; standup-mode.md:26-30) and Record Board Delivery step 1.
- Record Board Delivery step 1 carries the copied fetch block.

## Proposal

- Step 3 leaves the read, and the Named Delivery field stays the rule the caller's repair meets.
- Plan Available Work applies Read Tracker Issue for each missing issue and re-plans until none is missing or one is unavailable.
- Compose Standup Report applies Locate Initiative Issue and Read Tracker Issue for each unresolved initiative, leaving an unavailable one a reported gap.
- Read Board Delivery Evidence is the board-scoped twin of Read Delivery Evidence.
- Step 1 applies Read Board Delivery Evidence.
