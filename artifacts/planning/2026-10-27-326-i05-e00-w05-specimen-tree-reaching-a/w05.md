**Component:** fixtures/rewriting/a-diagram-reached-through-a-linked-document

## Overview

One end-to-end fixture bundles a tree the way an author writes one: a main document links a document carrying a `mermaid` diagram, and the diagram's clicks link further documents. It shows the diagram carried whole and every link it writes read, bundled and rewritten.

## Problem

Each diagram fixture is a single document whose diagram links one level down. None reaches a diagram through another document's link, mixes the click forms in one diagram, or carries a section destination, a callback and a web address beside the links that compile.

## Proposal

The specimen run on `i05/e00/main` on 2026-10-27 is the source tree and the bundle it published.

- **Source.**
  `guide.md` links `lifecycle.md`. `lifecycle.md` holds a `mermaid` flowchart whose clicks name `states/open.md` (`href` with a tooltip), `states/review.md` (short form with `_blank`), `states/closed.md` (`href` with a trailing `;`), `#notes` (a section of `lifecycle.md`), a callback, and an `https://` address, followed by a `## Notes` section.
- **Expected output.**
  `pf guide.md` exits `0` with no diagnostics. The bundle carries `# Ticket Guide`, `# Lifecycle` with the fence byte for byte except the three state destinations, which read `#open`, `#review` and `#closed`, then `# Open`, `# Review` and `# Closed`. `#notes`, the callback and the address are as written, and the guide's link reads `#lifecycle`.
