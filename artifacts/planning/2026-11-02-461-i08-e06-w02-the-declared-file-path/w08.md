**Component:** main:src/prosiform/closure.py

## Overview

A `subst` side ending in a separator is refused, and the folder lookup, its refusals and its six fixtures are removed. A preset states one pair per entry.

## Problem

The folder form retired with `-m` and survives in the code.

- **The lookup answers for folders.** `Substitution.folders`, the folder branch of `Substitution.answering`, `Substitution.folder`, `Reference.folder` and `Pairing.folder` redirect every document under a key folder.
- **The parser reads the marker.** `cli.marked`, `cli.folderless` and the folder branch of `cli.mock` read a trailing separator before normalisation.
- **A diagnostic names a folder key.** `cli.missing` and the folder remedy in the walk's absent-document refusal report a path a folder key derived.
- **A preset folder side is refused for the wrong reason.** `subst: [{rules/: stubs/}]` fails as invalid usage because the alternative names no Markdown document, not as malformed metadata naming the entry.
- **Six fixtures assert it.** `a-folder-key-redirects-each-reference-under-it`, `an-exact-key-beats-a-folder-key`, `a-folder-substitute-that-is-absent-fails`, `an-unused-folder-key-warns`, `a-half-folder-pair-is-refused` and `a-folder-key-carrying-a-section-is-refused`.

## Proposal

**The scene.** `cli.substs` holds each `subst` side to the reference grammar when the declaring document's metadata is read.

**The design.**

- **A side ending in a separator is refused.** `substs` refuses a side whose path component ends in a separator with `E_INVALID_CONVERSION_METADATA` naming the entry, because a pair names one document or one section.
- **The folder code is removed.** The lookup, the marker, the folder refusals and the folder diagnostic go together, leaving the exact and the document lookups. A `-m` side ending in a separator normalises as any reference does; no refusal is added for it.
- **The six fixtures are withdrawn.** `fixtures/inclusion/a-folder-subst-is-refused` holds the refusal.
