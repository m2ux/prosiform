## Overview

The documentation states the document boundary only as the build computes it. The build has derived no boundary since its last caller went, so the recommended course removes the definition and every use of it.

## Problem

- **Three pages define a boundary nothing derives.**
  `docs/sources.md` gives it a section, the glossary an entry, and the output-budget page a worked derivation, and the build's sources compute none.
- **A reader takes the definition for behaviour.**
  A page that defines a term implies the build uses it, so an implementor may build a derivation nothing reads.

## Proposal

A reader of `docs/sources.md` looks for what confines a run.

- **The working directory confines a run.**
  The page already states it; the boundary section goes and the confinement text stays.
- **Every use goes with the definition.**
  The glossary entry, the output-budget derivation and the docs index's mention are removed or restated without it.
- **The design is checked too.**
  If the design on the engineering branch states the boundary as behaviour, the open question returns to the user before the row lands, since removing behaviour from the contract is the contract's decision.
