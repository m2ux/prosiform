**Component:** src/prosiform/dispatch.py

## Overview

Each target a `⇉` link names is compiled, transitively, to a bundle of its own, and the link points at a `Dispatch <link text>` sub-section that names that bundle. An agent follows a dispatch by handing a bundle that already exists to a sub-agent, rather than compiling at run time from a symbol table. A run's bundles land together in one sub-folder of the output folder, named for its entry and swapped in whole.

## Problem

- **A dispatched target is withheld.**
  A `⇉` link [contributes nothing](https://github.com/m2ux/prosiform/blob/45acf3e1dd6228a3d99ea12406c9926cbfcadd4e/src/prosiform/cli.py#L1054-L1082) to the bundle and publishes its mark and a source path, so the agent must compile the target itself, as the example's [bootstrap](https://github.com/m2ux/prosiform/blob/45acf3e1dd6228a3d99ea12406c9926cbfcadd4e/example/work-planner/bootstrap.md) instructs.
- **A target's closure is computed for warnings alone.**
  [`onward`](https://github.com/m2ux/prosiform/blob/45acf3e1dd6228a3d99ea12406c9926cbfcadd4e/src/prosiform/cli.py#L1944-L1963) traverses each target's would-be closure, and [`analysed`](https://github.com/m2ux/prosiform/blob/45acf3e1dd6228a3d99ea12406c9926cbfcadd4e/src/prosiform/dispatch.py#L202-L247) reports depth and cycles from it; nothing from it is published.
- **A set of bundles shares the folder with every other file.**
  [`publish_files`](https://github.com/m2ux/prosiform/blob/45acf3e1dd6228a3d99ea12406c9926cbfcadd4e/src/prosiform/cli.py#L1798-L1834) renames each bundle onto its own path, so a rename refused part-way leaves a mixture of old and new bundles.

## Proposal

`modes/advance-mode.md` step 2 writes `[⇉ Sync Mode](sync-mode.md)`. `pf -o build modes/advance-mode.md` publishes `build/modes_advance-mode/` holding `modes_advance-mode.bundle.md` and `modes_sync-mode.bundle.md`; in the first, step 2's link reads `[Sync Mode](#dispatch-sync-mode)` and the section ends with `### Dispatch Sync Mode`, whose one line names `modes_sync-mode.bundle.md`.

- **One bundle per distinct target.**
  The run follows dispatches transitively and compiles each distinct document-and-fragment target once, as its own entry; every link naming it points at that bundle. A single-entry run's own selection is the entry bundle.
- **The sub-section.**
  One per target per section, one heading level below the section holding the link, after its own content and before its child sections; a dispatch above the first heading takes that heading's level. Its body is one line: dispatch the bundle file to a sub-agent.
- **The mark is stripped.**
  The published link text carries no operator, and the link's destination is the sub-section's anchor.
- **Per-bundle budgets.**
  `-E` counts hops from each bundle's entry; `-F`, `-T`, `-L`, `-I` and `-O` count what each bundle alone opens, reaches and publishes.
- **The run's sub-folder (user-confirmed design change).**
  `-o DIR` is the root; the whole set is written to `DIR/<entry name>/`, built in a temporary sibling folder and renamed onto it, an older sub-folder renamed aside first and removed after. A failure before the swap leaves `DIR` as it was; everything else under `DIR` is untouched; `-c` writes nothing.
- **The contract moves with the build.**
  The design's Output, Publication and Dispatch clauses, the pin, `invocation.md` and the glossary state the bundle set and the sub-folder, so `make conformance`, `make invocation` and `make vocabulary` hold.
