## Overview

The diagram-following runbook's triage rubric states `overcompiled` as a run of `pf` on a reference no `[[scenario.compile]]` table states, while the scorer also counts a malformed `pf` call. The rubric's row and the README's class line should state each call the scorer counts. The unit also folds #804, the scorer reading a pick beside its `?` token, and #805, the scorer counting an unsplittable command whatever its first word.

## Problem

- **The rubric names one case the scorer counts among several.**
  The `overcompiled` row speaks of `pf` on a reference, while the `dispatch-brief` run's `overcompiled` sessions include `pf -o . 2>/dev/null || true` and `pf .`.
- **A disposition rests on reading past the row.**
  Those sessions were triaged `miss` by inference, since no column of the row covers a call with no entry.
- **The scorer keeps the pick token as a preset.**
  The compiler's entry reader keeps `?` in the tag list beside a pick, so `pf_runs` read a picked run as selecting `?` and `make eval-harness` failed (#804).
- **A malformed command counts whatever its first word.**
  `pf_runs` counted every segment `_commands` could not split as invalid usage, so `ls >` failed a session `overcompiled`; the docstring and README stated the checks and separators more narrowly than the scorer reads them (#805).

## Proposal

- **The row states what the scorer counts.**
  The RUNBOOK row gives `miss`, `defect` and `unclear` conditions for an unstated reference and each malformed `pf` call: options but no entry, an entry or option the compiler refuses, and a `pf` call whose words cannot be split. The README line names the same calls.
- **A pick stands where its token stands.**
  `pf_runs` drops `?` from a picked run's tags, so the token selects nothing; a listing keeps it.
- **Only a `pf` call counts as malformed.**
  A segment that does not split whole counts only when its readable first word names `pf`. A redirect a separator cuts short is a syntax error the shell runs nothing past, so the reading stops there.
- **The docs state the reader.**
  The `score.py` docstring names each case `_held_to` counts, and the README's Run checks section names every separator `_commands` splits at.
