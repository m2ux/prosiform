## Overview

The diagram-following runbook's triage rubric states `overcompiled` as a run of `pf` on a reference no `[[scenario.compile]]` table states, while the scorer also counts a malformed `pf` call: one naming no entry, one the compiler refuses, and a command whose words cannot be split. The rubric's row and the README's class line should state each call the scorer counts.

## Problem

- **The rubric names one case the scorer counts among several.**
  The `overcompiled` row speaks of `pf` on a reference, while the `dispatch-brief` run's `overcompiled` sessions include `pf -o . 2>/dev/null || true` and `pf .`.
- **A disposition rests on reading past the row.**
  Those sessions were triaged `miss` by inference, since no column of the row covers a call with no entry.

## Proposal

- **The row states what the scorer counts.**
  `_held_to` in `score.py` counts a run naming a reference no stated run names, and every run `pf_runs` reads as invalid usage: `pf` with options but no entry, an entry or option the compiler refuses, and a command `_commands` cannot split, whatever its first word. The RUNBOOK row gives each its `miss`, `defect` and `unclear` conditions.
- **The class line names the same calls.**
  The README's `overcompiled` line names the unstated reference and the malformed call, in the intro's word, and exempts a bare `pf` and an informational call the compiler accepts.
