**Component:** main:src/prosiform/cli.py

## Overview

A positional entry compiles the document it names, and the run derives its name from that path. No `subst` pair substitutes it, because no document writes it.

## Problem

The entry is redirected by a mapping no document states.

- **`cli.entry` ends in `substitution.redirect(found)`.** The command line's `-m` mapping redirects the entry before any source is read, and the run name follows the substitute.
- **A preset cannot state it.** A `subst` pair substitutes links its declaring document writes, and an entry reference is written by none. The entry's own presets govern the links the entry writes, not the entry.
- **A fixture asserts the retired behaviour.** `fixtures/mock/a-redirected-entry-derives-its-name-from-the-substitute`, and five `test_mock.py` cases, assert the entry redirect.

## Proposal

**The scene.** `cli.execute` normalises each positional reference through `entry` and derives the run's folder from the selections.

**The design.**

- **`entry` takes no mapping.** It normalises the positional reference and returns it, so the selection and the run name are the path the caller wrote.
- **A record is a link's.** With no entry recorded, every substitution record names the link that made it, and the `Redirect` docs no longer carve out a command-line entry.
- **The retired fixture and tests go.** `a-redirected-entry-derives-its-name-from-the-substitute` and the entry-redirect unit tests are removed; `fixtures/inclusion/an-entry-is-not-substituted` asserts the entry compiles as named.
- **The prose follows.** `invocation.md`, `docs/glossary.md` and `docs/references.md` state that an entry reference is not redirected.
