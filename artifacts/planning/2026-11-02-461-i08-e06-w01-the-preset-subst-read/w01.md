**Component:** main:src/prosiform/cli.py

## Overview

The `subst` pairs a document's governing presets state redirect the links that document writes, beside the command line's `-m` mapping, so a preset states a substitution the option states today and the corpus can move onto presets before the option retires.

## Problem

A preset's `subst` entry is parsed and held to its rules, and then read by nothing.

- **`read_document` validates and drops it.** `substs` holds each side to the reference grammar and `stated_once` holds each preset to stating a key once, but no stage builds a mapping from the pairs, so a document stating `subst: [{rules.md: stub.md}]` compiles `rules.md`.
- **The one mapping is the command line's.** `substitution(options)` folds `-m` into one `Substitution` before any source is read, and `closure.inside` consults it for every link whatever document wrote it.
- **The warnings read only that mapping.** `substituted` and `unused` report the command line's keys, so a preset pair no reference used would state nothing.
- **A pair whose alternative names no Markdown document is admitted.** The design refuses it within one preset, as the option refuses it, and `stated_once` does not.

## Proposal

**The scene.** `traverse` reads each carried document's selected content round by round, `compose` reads it again to emit the bundle, and every link either stage resolves goes through `closure.inside` with the document that wrote it.

**The design.**

- **A document's governing pairs are read where its references are known.** `governing` reads, for each document the run carries, its `default` pairs and the pairs of every preset a reference reaching it selects, the selected presets' pairs holding over `default`'s for one key. Each side resolves from the declaring document's directory, as `subst_identity` already reads it for the preset rules.
- **The mapping answers per writing document.** `Substitution` carries the run's per-document table, and `closure.inside` reads the mapping in force for the document a link is written in: the command line's keys with that document's pairs above them. Every stage resolving a link already passes that document, so one change point covers discovery, emission, candidate validation and dispatch placement.
- **The table follows the traversal.** Each round builds the table from the references found so far, so a link is resolved under the presets its document's references selected; `compiled` builds it once more from the closure and composes under it.
- **The record is the run's.** A derived mapping shares the run's `Redirects`, so `W_SUBST_USED` reports a preset pair as it reports a command-line key. `Compiled` carries each document's pairs, and a pair no reference served raises `W_SUBST_UNUSED` naming its key as written and its declaring document.
- **Selected presets agree across references.** Two presets selected for one document, by one title or by two, mapping one key to two alternatives are refused as invalid usage naming both, since the union would leave nothing saying which takes effect.
- **A value naming no Markdown document is refused.** `stated_once` refuses it at the entry, as the design states for a rule within one preset.
