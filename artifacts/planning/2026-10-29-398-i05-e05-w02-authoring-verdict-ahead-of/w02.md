**Component:** Makefile

## Overview

The authoring check runs last in `make check`, so a rule break in a file any usage-example fixture reaches fails the corpus first, as a byte difference in a bundle. This task moves the check ahead of the corpus, so a broken tree reports the rule it broke rather than the bundle that moved.

## Problem

- **A rule break in a reached file is reported as a byte difference.**
  Breaking the Inputs rule in `example/work-planner/artifacts/board.md` makes `make corpus` fail with `expected.bundles: modes_advance-mode.bundle.md: the bytes differ`, naming the bundle rather than the file the rule was broken in and the rule.
- **The authoring check runs after the corpus.**
  `check` names `authoring` last, after `steps`, and a corpus failure stops the run before it.
- **A rule break in an unreached file is reported by the rule.**
  `example/work-planner/protocols/task-merge.md` is reached by no fixture, so a `## Commands` section written into it fails `make check` with the file, the line and the rule.

## Proposal

- **The authoring check runs before the corpus.**
  It reads the example on its own, needs no build and takes under a second, so a rule break fails with the rule named and the corpus reports only what the authoring rules permit.
- **The corpus's byte comparison stays as it is.**
  It is the stronger statement: a change that breaks no authoring rule but alters a bundle still fails there. Only the order changes.
- **The order is held by a test.**
  `checks/tests/test_check_order.py` reads `check`'s prerequisite list and fails unless `authoring` is named ahead of `corpus`.

## Validation

The demonstration is run against `example/work-planner/artifacts/board.md`, whose Inputs line is rewritten from contract links to prose. Three targets are run over that tree, and the file is restored before the passing run.

- **Before, `make corpus`.** The broken tree fails at `corpus` with `usage-example/a-mode-and-the-board-reads-it-steps-through: fail — expected.bundles: modes_advance-mode.bundle.md: the bytes differ`, `77174 bytes expected, 77143 produced`, first difference at byte 8469, line 152. It names the bundle and the byte window, never the file or the rule.
- **Before, `make check`.** The same failure is what the run reports, and it stops at `corpus`, fifth, so `authoring` never runs.
- **After, `make check`.** The run stops at `authoring`, which reports `example/work-planner/artifacts/board.md:17 — Inputs and Outputs: operation 'Select Project Board' Inputs is not None or a comma-separated list of links to contract sections`, then `authoring check: 1 finding(s)` and `make: *** [Makefile:111: authoring] Error 1`.
- **Restored, `make check`.** A clean run passes every check in `check`'s prerequisite list, so the change alters the order the prerequisites are listed in and nothing a passing run asserts.
- **The guard, `test_check_order.py`.** It passes with `authoring` moved ahead of `corpus` and fails against the old line, so the order cannot drift back without the suite reddening.
