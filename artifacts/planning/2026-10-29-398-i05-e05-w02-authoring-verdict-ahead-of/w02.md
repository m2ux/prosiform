**Component:** Makefile

## Overview

The authoring check runs last in `make check`, so a rule break in a file any usage-example fixture reaches fails the corpus first, as a byte difference in a bundle. This task moves the check ahead of the corpus, so a broken tree reports the rule it broke rather than the bundle that moved.

## Problem

- **A rule break in a reached file is reported as a byte difference.**
  Breaking the Inputs rule in `example/work-planner/artifacts/board.md` makes `make corpus` fail with `expected.bundles: modes_advance-mode.bundle.md: the bytes differ`, naming the bundle rather than the file the rule was broken in and the rule.
- **The authoring check runs after the corpus.**
  `check` names `authoring` last, after `steps`, and a corpus failure stops the run before it.
- **A rule break in an unreached file is reported by the rule.**
  `example/work-planner/protocols/task-merge.md` is reached by no fixture, so a `## Commands` section written into it fails `make check` with the file, the line and the rule.

## Proposal

- **The authoring check runs before the corpus.**
  It reads the example on its own, needs no build and takes under a second, so a rule break fails with the rule named and the corpus reports only what the authoring rules permit.
- **The corpus's byte comparison stays as it is.**
  It is the stronger statement: a change that breaks no authoring rule but alters a bundle still fails there. Only the order changes.
- **The order is held by a test.**
  A check that `check`'s prerequisites name `authoring` ahead of `corpus` keeps the sequence from drifting back.
