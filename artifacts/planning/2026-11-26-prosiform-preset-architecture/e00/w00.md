## Overview

The ledger set shows, as files, what the proposed ledger option writes for two builds the 0.36.0 release already produces.

## Problem

The ledger's fields, its check-mode output and its verification outcomes are described in prose, so no reader can hold a field to the build fact it records.

## Proposal

- Two real 0.36.0 builds anchor the set: the fixed-dispatch control the record already holds, and a run with an entry stub in force, a dispatch leaving its pick open and a deferral.
- Each build has a hand-written YAML ledger. The README maps every 0.36.0 feature to a ledger field or a stated exclusion: capture and hashes, regions, default and selected presets in order, layout groups, substitutions with lexical origins, stand-in use, alternatives and picks, briefs, dispatch and deferral targets, levels and resolved models, bundle hashes and the invocation (entry reference, picks, budgets).
- A proposed JSON Schema accompanies the ledgers, and both ledgers validate against it.
- Hand-written text shows the check-mode output, each verification outcome (unchanged set, changed source, changed bundle, absent ledger) and the refusal that publishes neither ledger nor bundles.

| Part | Description |
