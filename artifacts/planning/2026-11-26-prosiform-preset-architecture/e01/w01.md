## Overview

A deterministic projection serializes an actual build into the contracted ledger.

## Problem

Captured facts need one bounded projection owner, so the ledger is never read back out of rendered Markdown.

## Proposal

- One pure projection and serialization service reads the existing captured build and provenance records.
- It writes YAML through `ruamel-yaml`, the library the build already depends on, each string quoted and the keys in one fixed order.
- It is exercised through real build results. The command line and publication are wired by later work.
- A first checkpoint at sixty minutes returns a smaller replan where the facts would need a broad traversal or data-model rewrite.
