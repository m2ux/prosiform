## Overview

The ledger option publishes the ledger atomically with the bundle set, and a check-mode run writes it to standard output.

## Problem

The ledger must share the existing complete-or-refused publication result, and the corpus cannot yet state a ledger a run must write.

## Proposal

- The delivered serialization service is wired into the ledger option and the existing whole-folder publication.
- A check-mode run with the option writes the ledger to standard output and publishes nothing.
- The options table states the option in the same change, since the invocation check holds the help output and that table to each other.
- The README's design link moves to the contract revision stating the ledger, so the conformance check reads the clauses and codes this build reports.
- The fixture manifest gains the ledger a run must write, the corpus runner compares it, and a published JSON Schema holds each fixture's ledger.
- A first checkpoint at sixty minutes stops for a replan before publication infrastructure is replaced or the output contract widened.
