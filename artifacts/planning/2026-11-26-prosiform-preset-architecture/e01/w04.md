## Overview

One command holds a published bundle set to its ledger and reports each source or bundle that differs.

## Problem

A ledger records hashes, but nothing reads them back, so a set whose sources or bundles changed after publication looks unchanged.

## Proposal

- The verification option names a published folder, re-hashes each source and bundle its ledger names, and reports each differing path.
- An unchanged set exits with success; a differing or absent ledger exits as the accepted specimen shows.
- The build's own reader holds the ledger to its schema before any other file is opened, and refuses one naming a bundle or a source twice. The JSON Schema validator stays a development dependency, and a test holds the reader and the schema to the same cases.
- The folder's bundles are compared with the ledger's list in both directions, each read as a regular file.
- The contract gains the verification clauses and codes in this work, and the README's design link moves to that revision in the same change.
- The public example's published set is the unchanged case the check verifies.
