## Overview

One option writes a checksum file beside the bundles, and the standard checksum tool holds a published set to it.

## Problem

A published set carries nothing a later reader can hold its sources and bundles to, so a set whose bytes changed after publication looks unchanged.

## Proposal

- The checksum option writes one file into the run's folder in the same swap as the bundles, in the format the standard tool writes.
- It lists each other file of the folder, the ledger among them where one is written, then each source the run read, a source written from the folder as a deferred link is.
- The standard tool, run in the folder, passes an unchanged set and reports each changed or missing file. The bundler gains no verifying mode and no code.
- The contract gains the checksum clauses in this work, and the README's design link moves to that revision in the same change.
- The fixture manifest gains the checksum file a run must write, and the corpus runner compares it.
