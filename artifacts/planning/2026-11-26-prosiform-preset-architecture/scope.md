# Confirmed Goal And Boundary

Plan an incremental extension of the Python Prosiform bundler in four stages: specimen sets of every proposed form first, then a build ledger, explicit pure preset imports, and named local exclusive component and test choice groups. An author can reuse narrowly scoped settings and select independent local alternatives, while an operator can inspect the effective sources and configuration of each bundle.

## Goal Clauses

- The requester scrutinises every proposed form as files, and rules on it, before its contract is written.
- An operator can inspect the exact effective configuration behind a build, without publishing it, and can hold a published set to that record.
- An author can reuse narrowly scoped level and substitution settings.
- An author can select independent local component and test alternatives, at a dispatch or at the entry, and can list a document's choices without bundling it.
- Authored policy stays readable and selection outcomes stay observable.

## Boundary

The bundler's released 0.36.0 semantics, at `8cedda4cc06b0486168addc05f057161192a22a6`, are the comparison baseline. New syntax and output are proposals until their implementation and release are delivered. Authored Contracts, operations and governing Rule links remain readable Markdown. Metadata imports carry only levels and substitutions; they carry no body, Rule injection, brief, capability declaration, layout, alternative or stub role. The receiving preset retains its declared scope, the existing explicit entry-stub scope included.

The ledger is one TOML file named for the single word `ledger`. It records build facts and the invocation, and asserts nothing about runtime effort, provider observation, delivery or meaning.

Runtime profiles remain a harness boundary. Structured model and effort values and focused reviewer presets are exploratory follow-up concerns, excluded from implementation here. Permissions, secrets, sessions and capacity do not belong in presets. This work introduces no generic inheritance, automatic global context or inline-brief behavior.

Public sources and specimens use generic synthetic components and tests only. No private application source, names, findings, journals or fixture content is part of the upstream plan.

## Standing

The planning scope is feature-scale and user-approved, so no proposal is required. The order is Design Specimens, Build Ledger, Preset Imports, Local Choice Groups, with epic priorities 4, 3, 2 and 1. Each row carries a lane marking the model class its delivery needs. Implementation has not been authorized.
