Hand-written specimen: pf 0.36.0 offers no --verify option.

Verification holds one published folder to the ledger inside it. Each command
runs in `run/`, where the build ran.

What verification reads

  - The ledger is read first, under the rules a source's frontmatter is read
    by, and held to its schema by the build's own reader. One that does not
    parse, states a schema this build does not read, or names a bundle or a
    source twice, is refused before any other file is opened.
  - A bundle is named by a file name alone, and is read from the folder being
    verified, as a regular file. Every bundle the folder holds is compared with the ledger's
    list, in both directions.
  - A source path resolves from the working directory, as it did for the
    build, and is opened as a build opens a source: a path leaving the working
    directory or carrying a symbolic link is refused with the build's own code.
  - Verification reads a set the caller trusts to be the one published. It
    states nothing about who wrote the ledger.

Not stated by this specimen: what a folder replaced while it is being verified
reports.

1. An unchanged set

$ pf --verify bundles/entry-recorded.bundles

Both streams are empty. Exit status 0.

2. A source changed after the build (the line `One more line.` appended to worker.md)

$ pf --verify bundles/entry-recorded.bundles
E_LEDGER_MISMATCH: the source 'worker.md' differs from the bytes the ledger records
  source: worker.md
  recorded: 717d3abc23f57da755374ec9927b7dde3594f92ec91e5875525618b505b85113
  found: 9b79f6c99f872e43445fbdd17e1ee6cdaafe853ff1a5babf30716cc7e2d930bb
  remedy: rebuild the bundle set, or restore the source the ledger records

Exit status 1. Every differing path is reported, each in a diagnostic of its own.

3. A bundle changed after publication (the line `One more line.` appended to worker-alpha+small.bundle.md)

$ pf --verify bundles/entry-recorded.bundles
E_LEDGER_MISMATCH: the bundle 'worker-alpha+small.bundle.md' differs from the bytes the ledger records
  bundle: bundles/entry-recorded.bundles/worker-alpha+small.bundle.md
  recorded: 33d3c874d0d8e93b281c2cf5b76a34326d6f82fb5295f7fb50def3d5619ecb6d
  found: 2443933a272b496baf56e6dc04b26696b29a699b5bf77ba83c3994c1f8d6bb74
  remedy: rebuild the bundle set

Exit status 1.

4. A source the ledger names is gone (beta.md removed)

$ pf --verify bundles/entry-recorded.bundles
E_LEDGER_MISMATCH: the source 'beta.md' is not where the ledger records it
  source: beta.md
  recorded: f56cb332bd3e9c2390e7fab6be5bea964b71d68a34e093a4a4d63cfa2fcf18a3
  remedy: rebuild the bundle set, or restore the source the ledger records

Exit status 1.

5. A set published without a ledger (run in `../valid-two-bindings/`, whose set was published with no ledger option)

$ pf --verify bundles/entry.bundles
E_LEDGER_NOT_FOUND: the folder 'bundles/entry.bundles' holds no ledger.yaml, so nothing records what it was built from
  remedy: rebuild the bundle set with --ledger

Exit status 1.

6. A bundle the folder holds and the ledger does not name

$ pf --verify bundles/entry-recorded.bundles
E_LEDGER_MISMATCH: the bundle 'worker-gamma+small.bundle.md' is in the folder and the ledger does not record it
  bundle: bundles/entry-recorded.bundles/worker-gamma+small.bundle.md
  remedy: rebuild the bundle set

Exit status 1.

7. A bundle the ledger names is gone (worker-beta+small.bundle.md removed)

$ pf --verify bundles/entry-recorded.bundles
E_LEDGER_MISMATCH: the bundle 'worker-beta+small.bundle.md' is not in the folder the ledger records it in
  bundle: bundles/entry-recorded.bundles/worker-beta+small.bundle.md
  recorded: 4c0feb2da7f4c780bb87651d969ff0d3a58647a1562c21307fc67844542936d5
  remedy: rebuild the bundle set

Exit status 1.

8. A ledger naming one bundle twice

$ pf --verify bundles/entry-recorded.bundles
E_LEDGER_MISMATCH: the ledger 'bundles/entry-recorded.bundles/ledger.yaml' names the bundle 'worker-alpha+small.bundle.md' twice
  remedy: rebuild the bundle set

Exit status 1. No source and no bundle is opened.

A mismatch reports E_LEDGER_MISMATCH, for a source and a bundle alike, and a
folder holding no ledger reports E_LEDGER_NOT_FOUND. E_SOURCE_CHANGED keeps its
one meaning: a source that changed during a build.
