Hand-written specimen: pf 0.36.0 offers no --ledger option.

A check-mode run with the ledger option writes the ledger to standard output
and publishes nothing. Run in `run/`:

$ pf -c --ledger '[Run](entry.md "recorded")'

Standard output: the bytes of `run/bundles/entry-recorded.bundles/ledger.yaml`,
from its `schema: 1` line to its last line.

Standard error: the two warnings the build raises today, as `run/diagnostics.txt`
holds them.

Exit status 0. No bundle and no ledger is written.

$ pf -c --ledger -o bundles '[Run](entry.md "recorded")'

The same ledger, byte for byte. The ledger holds no hash, no file name and no
published link, so it follows from the sources and the options and not from
where the bundles would go. The folder `-o` names is made where it is absent
and left empty, as a check run makes it today.

$ pf -c --ledger --sums '[Run](entry.md "recorded")'

The same ledger, and no checksum: a check run writes no file to take one of.

$ pf -c --ledger entry.md        (run in `../missing-component/`)

Standard output is empty. Standard error holds the refusal, exit status 2: a
build that fails has no ledger.
