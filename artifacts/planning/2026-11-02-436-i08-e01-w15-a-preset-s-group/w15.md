**Component:** main:src/prosiform/metadata.py

## Overview

A preset's `group` holds one division-to-depth pair, `group: {modes: 1}`. The key `group-depth` held a list of pairs, so one link could place a document's content under several divisions of one bundle; the key is renamed `group`, holds one single-entry mapping, and its depth conflict is `E_GROUP_CONFLICT`.

## Problem

The design and the epic record state one pair under `group`, and the tree still carries the list under `group-depth`.

- **The reader admits a list.** `metadata.FIELDS` lists `group-depth`, `Preset.memberships` holds every entry, and a bare `group` key is refused by `_refused_group` with a remedy naming `group-depth`.
- **The run unions pairs within one reference.** `cli.pairs` layers `default`'s pairs beneath the selected presets' pairs group by group, so one link may join a document to several divisions, and `cli.stated_once` refuses a preset naming one group twice.
- **The conflict code names the old key.** `E_GROUP_DEPTH_CONFLICT` is in `cli.CODES`, the schema catalogue, the corpus and the design.
- **About 110 sources write the list.** Fixtures, `example/`, check scenarios, unit tests, `scripts/examples.json` and the rendered SVGs write `group-depth: [{...}]`; three fixtures exist only for the list shape.
- **Pages state the list.** `invocation.md`, `docs/sources.md`, `docs/hierarchy.md`, the glossary and `example/guidelines.md` describe `group-depth` and a document joining several groups through one preset.

## Proposal

**The design.**

- **`group` holds one pair.** `FIELDS` is `group` and `subst`. `_preset` reads `group` through the shared `_pair` reader into `Preset.membership`, absent where the preset states none; `subst` alone must be a list.
- **Retired forms are removed, not refused.** `_refused_group` goes. A list or scalar under `group` is a malformed value under `_pair`, refused as `prosiform.<preset>.group must be a mapping holding one group and its depth`; no fixture names the list form.
- **One reference, one pair.** `cli.pair` returns the first selected preset's pair, or `default`'s where no selected preset states one. `cli.agreed` refuses two selected presets stating different pairs, whether they name two groups or one group at two depths, as `E_INVALID_USAGE` at the first pair's group. The within-preset "group named twice" refusal goes with the list.
- **Two references may still place one document twice.** `cli.joined` collects the pair each reference puts in force, so two links selecting different pairs place the document in each group, as *A document in several groups* states.
- **`E_GROUP_DEPTH_CONFLICT` is `E_GROUP_CONFLICT`.** In `cli.CODES`, the schema catalogue, `fixtures/README.md`, the corpus, the tests and the design.
- **The design states one pair.** `design.md` on `engineering` replaces *`group` is refused* with *`group` holds one pair*, and rewrites the example, the field table, *An entry is one string key with an integer value*, *`default` always applies*, *Selected presets union*, *What a selection governs*, *A document in several groups*, the Grouping clause, the metadata failure table and the rejected-metadata row. The README design pin moves to that commit.
