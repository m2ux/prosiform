## Overview

Dispatch is written `⇉`, must name a Markdown target under the root, and is analysed for depth, cycles, procedure and self-reference, each a warning.

## Problem

- **Unbounded nesting.** A dispatched target's content may dispatch again; nothing reported a chain the user should flatten, or a loop of sub-agents.
- **Silent operator on a non-target.** `¬`/`»` on a URL, resource, image or outside-root document published as authored.
- **Non-procedural and self dispatch.** A dispatched Fields section, or a mode dispatching its own section, passed unremarked.
- **Operator glyph.** The user ruled `⇉` the one dispatch operator.

## Proposal

- **Dispatch depth.** The number of `⇉` hops along a chain from the bundle being compiled. `cli.onward` re-runs `traverse` on a dispatched target as its own entry (same rules: links resolve from the writing file within its root; `¬` contributes nothing; `⇉` is a hop) and returns the dispatches it reads. `dispatch.deepest` follows simple paths in link order and stops at the fourth hop. Analysis never changes the bundle; a target whose own compilation is refused (any `Failure` or `Crossed`) carries no further hop.
- **Cycles.** `dispatch.returning`: DFS with the chain's targets and the entry identities on the path; a hop naming one closes a cycle. Own code `W_DISPATCH_CYCLE`: a cycle is a defect to break, depth an optimisation; a 2-hop cycle is not too deep. Both searches skip targets already on the chain, so termination holds on any graph.
- **Reporting rule.** Each distinct target the bundle dispatches, from the first link naming it, raises at most one warning of each code; `location` is that link, `related` each later hop's link with the target it dispatches, `chain` the entry and every hop's target.
- **Procedures.** `cli.unperformable`: the target's selected content (whole document, or section with subsections) must carry an `ordered_list_open` token; the parser reads none inside code.
- **Self-dispatch.** A hop whose target path is the file writing it warns `W_DISPATCH_SELF`; it is excluded from the cycle search, so it is reported once. It still counts as a depth hop.
- **Operator target.** `refusals_of_operators` refuses `¬`/`⇉` on any use `withholding_target` does not resolve, and on any image.

## Implementation Findings

- **Pass-through fixtures removed.** `resource/a-marked-resource-is-emitted-as-authored` and `citation/a-marked-reference-above-the-root` declared the pass-through now refused; their cases are covered by the new `deferral/` and `dispatch/` refusal fixtures. Six unit tests declaring it were replaced by one parametrized refusal test.
- **Existing dispatch fixtures.** Their targets were prose; they now carry numbered steps so each fixture warns only of what it declares. Bundles unchanged except for the new chain fixtures.
- **Same-file fragment.** `[⇉ X](#x)` counts as a hop (fixture `dispatch/a-dispatched-section-of-the-entry-is-a-hop`, which also warns `W_DISPATCH_SELF`). pf still compiles the entry file whole, so such a section is not withheld; that behaviour is unchanged here.
- **Operator spacing.** The operator is recognised with or without a following blank, as `»` was; documentation writes it followed by a space.
- **Deliver.** W23's `[» Run Delivery Session](#run-delivery-session)` is a self-dispatch; it is linked without the operator and the sub-agent start is stated in prose. `delivery-brief.md` and `guidelines.md` read consistently and were not changed.
- **Remaining `»`.** Two tests use it deliberately to show it is ordinary; the dated W15 planning record keeps its historical text.
