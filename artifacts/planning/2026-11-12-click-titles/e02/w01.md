**Component:** main:src/pyproject.toml, main:src/uv.lock

## Overview

A release carries the click tooltip rule and the link invocation, cut under the project's versioning procedure.

## Problem

- **No tag carries the rule.**
  The latest pair, `contract/v0.24.0` and `python/v0.24.0`, predates both.

## Proposal

**The scene.** Cutting a release in `docs/versioning.md` states every step; the click tooltip rule and the link invocation are on `main`.

- **Branch and declare.**
  `release/vX.Y.Z` from `main`, the unit's only branch, with no epic base; one commit `Declare Python build version X.Y.Z` setting `src/pyproject.toml` and the `prosiform` entry of `src/uv.lock`.
- **Choose the number.**
  The previous contract tag's corpus runs from its own worktree with `PROSIFORM_BUILD` naming the release build's `pf`; any failure is incompatible.
- **Merge, then tag.**
  The release pull request merges into `main`, and annotated `contract/` and `python/` tags name that merge, their messages following the previous pair's.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The previous pair's tag messages and what has merged since it |
| Plan | The number the previous corpus run chooses |
| Implementation | The release branch, version commit, pull request and tags |
| Review | `pf -v` on `main` and each tag's target |
| Test | `make check` on the release branch with `PROSIFORM_BUILD` set, and the previous contract tag's corpus against the release build |
