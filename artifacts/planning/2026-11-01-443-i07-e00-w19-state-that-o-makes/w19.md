**Component:** src/prosiform/cli.py

## Overview

Brings every statement of `-o` into line with what the command does: the folder `-o` names is made when absent. `pf -h` already says so; the pages and the command's own docstring and remedy text say the folder must already exist.

## Problem

`publication` makes the output folder, parents included, when it is absent, and `pf -h` describes `-o` as "made if absent". Four other places state the opposite:

- `README.md` places the run folder "in the existing folder `-o` names".
- `docs/bundles.md` says `-o DIR` "names an existing folder".
- `invocation.md` says the folder `-o DIR` names "must exist".
- `src/prosiform/cli.py` holds the output folder "to existing" in the `publication` docstring, and the publication-failure remedy tells the reader to "name an existing folder the run can write".

A reader who trusts the pages creates folders by hand that the run would make, and a reader who trusts `pf -h` finds the pages wrong.

## Proposal

A reader runs `pf -o out/site entry.md` against a checkout with no `out/` folder, and the pages they read beforehand agree with what happens: the folder is made.

- `README.md`, `docs/bundles.md` and `invocation.md` state that `-o` names the folder the run folder is written into, made if absent.
- The `publication` docstring states that the output folder is made where absent.
- The publication-failure remedy names a folder the run can write, without requiring that it exist.
