**Component:** evals/diagram-following/test_run.py

## Overview

Every dispatch scenario, in both of its forms, classified by the departure a stub agent states, so the scorer's discrimination is held across the corpus rather than by one hand-written case per check.

## Problem

The scorer's four dispatch checks are tested on a scenario each. A check that only ever meets the departure it was written for is not shown to tell one departure from another, and a class that fired for the wrong reason would pass every test the corpus holds.

## Proposal

- **Each departure is a stub script.** `STUB_AGENT_NO_DISPATCH`, `_SEQUENTIAL`, `_ANSWER` and `_STOP` already state the four departures the scramble, and the stub's default states a correct run.
- **Each runs over the whole dispatch corpus.** Four scenarios in two forms, so every scenario is classified by every class it can fail, and the correct run passes each cell.
- **The assertion is per cell.** A cell reads the class its script states and no other, so a class firing for the wrong reason fails where it fires.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Which departure each script states, and the class each must produce. |
| Plan | The matrix the test runs: scripts by scenario by form. |
| Implementation | The test, driving the runner over the dispatch corpus once per script. |
| Review | Each cell's class is the script's, and a passing run stays passing. |
| Test | Stub-agent tests under `make check`, no paid session and no baseline written. |

## Boundaries

The run is a fixture run: the stub agent walks the workflow's own diagram, so its pass rates are correct by construction and are no measured baseline. `baseline.json` is untouched and AC4 stays W03's.
