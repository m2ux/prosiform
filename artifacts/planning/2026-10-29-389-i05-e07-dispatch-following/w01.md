**Component:** evals/diagram-following/workflows

## Overview

Dispatch and parallel-dispatch scenarios in the diagram-following eval, each written in the two forms the report compares: the bundle set `pf` publishes, and the same source tree carrying a dispatch protocol an author wrote.

## Problem

The eval's corpus holds workflows walked from an entry document to a terminal state. None dispatches, so no scenario names a dispatch trace and the report has no form that carries a compiled protocol alongside an authored one.

## Proposal

The scenario set sits beside the workflows the eval already holds, and its forms follow the ones the eval's reader already understands.

- **Scenarios.**
  A dispatch chain, a parallel set, a set beside a dispatch, and a dispatched target returning a question. Each names its inputs and the dispatch trace a correct agent produces: the sub-agents it starts, in what order, and what each returned.
- **The compiled form.**
  The source tree whose links carry `⇉` and `⫽`, bundled by `pf` from the guide a bare `pf` prints, so the protocol an agent reads is the one the profile fixes.
- **The authored-protocol form.**
  The same state documents, with the dispatch protocol written into the corpus as prose instead of compiled in, so the report separates what compilation adds.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | What a scenario names of a dispatch trace, and how the eval's reader declares a form. |
| Plan | The scenario file shape for a bundle set, and the two forms' source trees. |

| Review | Each scenario's expected trace is a walk of the bundle set its source produces. |
