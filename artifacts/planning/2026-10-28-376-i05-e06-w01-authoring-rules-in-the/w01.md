**Component:** example/work-planner/guidelines.md

## Overview

The work-planner example's guidelines state the authoring rules the epic applies, so each later change has one written rule to meet and a reviewer one place to check it against.

## Problem

The guidelines describe operations with a prose Inputs line and a separate Commands section, italicise an operation's leading verb, and say nothing about where a binding, a convention or a rule lives. The shape the example teaches is the one the epic replaces.

## Proposal

A reviewer opens `guidelines.md` beside a changed file and finds each rule that file must meet stated once, with nothing in the guidelines asking for the shape being removed. Each rule sits in the section whose files it binds.

### Rules Stated

- **Titles.**
  - **Operation names.** An operation is named verb first, with no emphasis.
  - **Title headings.** Every file keeps one H1, which is its heading in the bundle: the name `pf` gives the file's section when it groups bundled content.
  - **Action titles.** Names operation and mode procedure titles; command titles go with the Commands sections.
- **Procedure.**
  Step sub-sections and Step anchors stay as I05:E04 stated them.
- **Prose.**
  - **One home per rule.** A rule is stated once; every other file links it, never naming it in code font; its home is the contract or outcome it constrains, the step it binds, Rules or Conventions, or the kind's section.
  - **Bindings.** A deployment or run value is stated once in the configuration document beside the entry point, which the entry point links; a loop or batch limit names the configured value; a helper takes each binding as an argument.
  - **Shared conventions.** How a helper is invoked and how a write is confirmed are stated once in Conventions and linked by each operation applying them.
  - **Index files.** A README says what each file is for and links it, without restating content.
  - **File-relative links.** Every cross-file link is relative to the file holding it.
  - **One subject per file.** Two subjects split along the cut; a file over about 20 KB or 8 operations is reviewed for a second subject.
  - **No spare parts.** A rule, section, field, outcome, operation or protocol that nothing reads or follows is deleted.
- **Operations.**
  - **Inputs and Outputs.** One line each of contract links, or `None`; boundary values only.
  - **Contracts.** Every value has a contract in the file owning its subject; contract prose says what a value is, never who supplies or uses it.
  - **Conditions are steps.** Authority, preconditions, refusals, and null or error returns sit in the step they bind.
  - **Operation structure.** Same-file application by link, shared operations for repeated sequences, and instrument choice as an operation.
  - **Commands in steps.** A command sits in an unindented fenced block in the step that runs it; the step names where it runs and which inputs fill which parameters; the next step reads its result; no file has a Commands section; a helper several operations use is written in each.
  - **One command, Execution, Placed paths, Parameter placeholders, Concrete examples, Local scripts, Bodies.** Kept, bound to the step that runs the command.
- **Modes, Protocols, Artifacts, References.**
  Section orders lose Commands; an artifact operation opens with its Inputs and Outputs lines; Fields subsections are contracts.

### Rules Retired

- **Italicised verb.** `### *Verb* Name`, with its verb-sense table. Converting the operations is W06–W09's work.
- **Input labels.** A prose **Inputs:** description.
- **Spec layout, One home, Direction.** Command specifications under a Commands section, run by heading link.
- **Returned output.** No separate output declaration.
- **Command implementation.** Commands holding specifications beside Operations.
- **Commands in section orders.** In Modes › Sections, Artifacts › Sections, Protocols › Sections and References › Shape.
- **Per-kind No spare parts.** The mode, protocol and artifact variants, which the one Prose rule states.
- **Restated condition placement.** The condition sentences in Artifacts › Fields and Artifacts › Step rules, which Conditions are steps states.

### Outside the Guidelines

- **Process statements.** The Proposal's findings-sample-rollout order, Fixtures follow and Boundary govern the epic's delivery, not how a file is written, so the guidelines carry none of them.
- **Configuration document.** W03 creates it. The Bindings rule names it in words with no link until it exists.
