**Component:** src/prosiform/cli.py

## Overview

The fourth mapping shape the clause states as invalid usage and no row owned: a value whose path names no Markdown document. The three shapes W02 refuses state nothing about the mapping; this one states a substitute the profile cannot carry, so the run treats it as text and the entry reads as a redirect that took effect as nothing.

## Problem

The pinned clause refuses four shapes. `cli.substitution` decides three of them from one identity set before any source is read. A value naming no Markdown document is not among them, so `pf -c -m rules.md=notes.txt guide.md` over a tree whose `guide.md` links `rules.md` exits `0` and reports nothing.

The substitution silently degrades. The mapping redirects `rules.md` to `notes.txt`, `required` then classifies the redirected reference as a text use because its destination names no Markdown document, and the published bundle carries the link exactly as the source wrote it. Neither a publishing run nor a check run fails, which is the defect: a substitute the profile cannot bundle is a command line the run cannot honour.

## Proposal

**The scene.** `cli.substitution` decides the three existing shapes from the parsed pairs. A fourth test over the same set joins them, and the run refuses the command line rather than publishing a bundle in which the entry did nothing.

**The design.**

- **Refused where the others are.** The value's Markdown test is decided with the three existing refusals, before any source is read, carrying `E_INVALID_USAGE` and exit status 2.
- **The test is `profile.is_markdown` over the substitute's path,** because that is the criterion `required`, `resource` and `read_document` already apply to a destination. A substitute failing it is one every stage would treat as text.
- **The message names the entry its author wrote,** as the three existing refusals do, so the remedy is the entry to edit rather than the mapping as a whole.
