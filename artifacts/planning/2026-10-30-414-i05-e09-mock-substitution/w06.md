**Component:** src/prosiform/closure.py

## Overview

Two rules the lookup settles: a section key serving one reference while a document key serves the rest, and a substitute that is itself a key being material rather than another indirection — with the two fixtures that show each. The two-step lookup is W01's; this row settles what the second step means for a section and why the substitution is not reapplied.

## Problem

A key without a fragment covers a document and every fragment of it, which is right when the whole document is being replaced. A caller rehearsing one branch of a procedure wants one section redirected and the document's other sections compiled as they ship, and a whole-document key cannot express that. Separately, a mapping is a lookup table and not a chain: a caller who redirects `a.md` to `b.md` while another key names `b.md` has written something the run must read one way and not the other.

## Proposal

**The scene.** `identity` joins a path and a fragment into the name two spellings of one dependency share, and a fragment on a `Reference` is the decoded section name a later `section` lookup resolves against.

**The design.**

- **A key's fragment is a section name,** decoded as any fragment is and matched against the identity a reference normalized to, so `rules.md#escalation` matches `./rules.md#escalation` and does not match `rules.md#Escalation`.
- **A fragment-only key is refused.** A key of the form `#section` names no document to redirect, and the value parser refuses it rather than resolving it against something the option does not name.
- **A redirected fragment is the substitute's.** Where the substitute carries a fragment, that is the section the bundle selects, because the redirect replaces the reference rather than only its path.
- **A section key beats a document key,** because the lookup W01 lands asks for the exact identity before the document-wide one. This row is what makes that precedence observable for a section, and its fixture is the one that shows it.
- **No chaining.** The substitution is applied once, to the reference the source wrote, and applying it a second time is structurally impossible rather than guarded against: what a substitute's own links resolve to is a fresh `inside` call against the substitute's document, so the mapping sees the link that document wrote and never the path it was reached by.
