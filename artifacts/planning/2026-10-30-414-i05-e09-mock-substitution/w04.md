**Component:** src/prosiform/cli.py

## Overview

The two warnings a substituted run emits, with the fixtures that show each and the exit status both leave.

## Problem

A bundle of stand-in material is the same kind of output as a bundle of the material that ships, so a skill rehearsed against stand-ins reads as a skill validated. The complementary defect is quieter: a fixture whose mapping matched nothing mocks nothing, and whatever it asserts passes for the wrong reason. Neither is observable from the bundle, so the run must state both.

## Proposal

**The scene.** `Diagnostic` carries a severity, a code, a message and the further fields a defect has values for, and `Reporter` writes them in the format the run asked for. A fixture declares a diagnostic by its severity, its code and the fields it carries, so each warning must name what tells one substitution from another.

**The design.**

- **`W_MOCK_SUBSTITUTED`.** One per distinct redirected target, emitted at the first reference that redirects it. `location` is the link's source position, `source` the authored destination, `resolved` the substitute's identity, and the message names the identity the reference would have resolved to.
- **`W_MOCK_UNUSED`.** One per mapping key no reference named, with the key's authored spelling as `source`. It states a fact about the invocation rather than about the sources, so it carries no `location`.
- **Both accompany a published bundle and exit `0`,** which is the rule `W_RESOURCE_PORTABILITY` already follows.
- **An empty mapping raises neither,** because neither has a subject.
- **The records are kept where the lookup is read.** The lookup is the one place that knows a reference was redirected and which key served it, so the mapping records each hit and the run reads the record after traversal rather than inferring it from the bundle.
