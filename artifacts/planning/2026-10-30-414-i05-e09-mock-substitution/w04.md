**Component:** src/prosiform/cli.py

## Overview

The two warnings a substituted run emits: one per redirected target, and one per mapping key that matched nothing.

## Problem

A bundle of stand-in material is the same kind of output as a bundle of the material that ships. Nothing in a run says which documents a bundle carries, so a skill rehearsed against stand-ins reads as a skill validated. The complementary defect is quieter: a fixture whose mapping matched nothing mocks nothing, and whatever it asserts passes for the wrong reason.

## Proposal

**The scene.** `Diagnostic` carries a severity, a code, a message and the further fields a defect has values for, and `Reporter` writes them in the format the run asked for. A fixture asserts a warning by its code and the fields it carries, so each warning must name what a test needs to tell one substitution from another.

**The design.**

- **`W_MOCK_SUBSTITUTED`.** One per distinct redirected target, emitted at the first reference that redirects it. `location` is the link's source position, `source` the authored destination, `resolved` the substitute's identity, and the message names the identity the reference would have resolved to. A target reached twice raises one warning, as `W_DISPATCH_DEPTH` does for a target dispatched twice.
- **`W_MOCK_UNUSED`.** One per mapping key no reference named, with the key's authored spelling as `reference`. It states a fact about the invocation rather than about the sources, so it carries no `location`.
- **Both accompany a published bundle and exit `0`.** A warning neither withholds a bundle nor turns a successful run into a failure, which is the rule `W_RESOURCE_PORTABILITY` already follows.
- **An empty mapping raises neither,** because neither has a subject.
- **The records are kept where the mapping is read.** The lookup is the one place that knows a reference was redirected and which key served it, so the mapping records each hit and the run reads the record after traversal rather than inferring it from the bundle.
