**Component:** invocation.md

## Overview

The `-m, --mock` row in the documented invocation, reproducing the command's help text word for word.

## Problem

`make invocation` compares the documented option table with the command's own help output in both directions. An option the command offers and no table names fails with "the command offers this option and no table names it", and a row whose `Effect` cell differs from the help text by one character fails too. The option cannot be documented before it exists, and it cannot ship before it is documented.

## Proposal

**The scene.** `checks/invocation.py` reads the `Option` and `Effect` cells of `invocation.md`'s table and compares each with the help output the build under test prints, forgiving only runs of whitespace. The same check holds the exit-status table and the profile identifier.

**The design.**

- **One row.** `-m, --mock` with the metavar `ORIGINAL=ALTERNATIVE` and the effect the command prints, taken from the build's help rather than composed for the table.
- **The default is part of the effect.** A default that moves is a row that no longer matches, so the row states the default the grammar declares: none.
- **The row stands with the other options.** It joins the table between `-d` and the budget options, so a caller reading the table meets it where the grammar declares it.
- **Nothing else in the guide changes here.** The bundling rule that states what a mapping does landed with W00, because a fixture's clause must exist before the fixture names it.
