**Component:** src/prosiform/cli.py

## Overview

A mapping side ending in a separator makes its entry a **folder pairing**. The key folder matches every reference under it, the substitute folder takes the same remainder, the reference keeps its section, and exact keys answer before folder keys.

## Problem

The mapping holds one kind of key, and a folder of stand-ins costs one entry per file.

- **`cli.mock` reads each side as one document.** It partitions on `SUBSTITUTION_PAIR` and calls `entry` on each side, so a side is a reference to a document or a section and nothing else.
- **A trailing separator is normalized away.** `closure.normalized` drops an empty path segment, so `rules/` and `rules` normalise to one path and the separator that would state the folder is gone before anything can read it.
- **The Markdown-suffix test would refuse a folder.** W10 refuses a value whose path names no Markdown document, and `rules/` names none, so a folder side tested as a document would fail the refusal that protects every document pairing.
- **The lookup knows two keys.** `Substitution.key` asks `(path, fragment)` then `(path, None)`. A reference under a folder matches neither, so a folder key has nowhere to answer.
- **`rules/visual/` and `rules/` both hold one reference.** The answer cannot be whichever a dictionary happens to yield, so the precedence between folders is a decision rather than an accident.

## Proposal

**The scene.** `mock(value)` partitions the pair, reads each side through `entry`, and `substitution(options)` folds the pairs into a `Substitution` keyed by `(path, fragment)`. `Substitution.substitute(found)` asks `key(found)` and returns the reference the mapping names.

**The design.**

- **The separator is read before normalisation.** `mock` records whether each side ends in `/`, strips it, and reads the remainder through `entry`. The trailing separator is the folder's marker rather than a path segment, so `rules/` and `rules` stay one identity for matching while stating two different kinds.
- **Both sides agree or the pairing is refused.** One folder side and one document side fails with `E_INVALID_USAGE`, exit status `2`, naming the pair as the author wrote it. A folder and a file state different questions and one entry cannot ask both.
- **A folder side is read by the reference grammar.** Percent decoding, control-character refusal and `..` normalisation all apply, and the Markdown-suffix test is applied to the path each reference resolves to under the substitute folder rather than to the folder, so a folder key is not refused for naming no document.
- **A folder side carries no fragment.** A side ending in a separator whose text carries `#` is refused, because a folder names no section. A substitute side carrying one is refused on the same ground.
- **The lookup answers exact first, then the longest folder.** `key` asks `(path, fragment)`, then `(path, None)`, then each folder key whose prefix holds the path, longest first. A document key beats any folder and a narrower folder beats a wider one.
- **The remainder is appended and the section is the reference's.** A folder key `k` answering for path `p` yields `substitute_path + p[len(k):]`, and `substitute` keeps `found.fragment`, so `rules/red.md#Checks` redirects to `stubs/red.md#Checks`.
