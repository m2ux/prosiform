**Component:** fixtures/mock

## Overview

The mechanism applied to its first real consumer: the example work-planner skill bundled against stub artifacts and a fake `gh`, so a mode can be exercised without editing the 79-file tree and without a live GitHub account.

## Problem

Every behavioural test of the example skill needs two things the tree cannot give it. A scenario that varies one artifact means copying the skill and editing it, so the tree under test is not the tree that ships. And 96 `gh api` and `gh project` call sites across seven documents make any run against the real skill depend on a live repository, so on `main` there is no behavioural test at all — the seven `usage-example` fixtures prove the closure is complete, not that the instructions are followable.

## Proposal

**The scene.** `example/work-planner/conventions.md` declares `prosiform.root: "."` and is where the skill states how it reaches GitHub. `modes/plan-mode.md` links the artifacts its publish step reaches. Neither is edited by a scenario.

**The design.**

- **A stub artifact is a mapping entry.** A scenario that needs `artifacts/epic.md` to carry no criteria is `-m artifacts/epic.md=stubs/epic-no-criteria.md` against the real tree. The substitute becomes the target outright, so the bundle the agent receives carries the stub's content under the artifact's place in the graph, and nothing is copied.
- **A stub may name a document that does not exist,** which is what makes an artifact under authoring testable before it lands: the mode can be bundled, and the section it names can be reviewed, while the artifact is still a stub.
- **The environment is a substituted document.** Redirecting `conventions.md` to a stub that names a fake `gh` tells the agent to run the fake while every other instruction stays real. That is the seam between a bundle and its environment, and it is the only way a behavioural test becomes hermetic.
- **The tree is untouched.** A scenario run leaves the skill byte-identical, which `cmp` over a copy of the tree shows.

## Fixtures

| Fixture | What its source tree and manifest declare |
| --- | --- |
| `fixtures/mock/an-example-mode-bundled-against-a-stub` | The fixture's `source` is the example skill's `modes/plan-mode.md` tree, reached by a relative mapping value, and the run is given `-m artifacts/epic.md=../stubs/epic-no-criteria.md`. The bundle carries the stub where the mode links the artifact, the skill tree is byte-identical afterwards, and the same run without `-m` bundles the real artifact. |
| `fixtures/mock/an-example-skill-told-to-use-a-fake-gh` | The run is given `-m conventions.md=../stubs/fake-gh-conventions.md`, and the stub names `./fake-gh` as the command every `gh` call is written with. The bundle carries the stub's Conventions section, so an agent following the bundle is told to use the fake, and no other section of the skill differs from the unmocked bundle. |
