**Component:** checks/mock_scenarios.py

## Overview

The mechanism applied to its first real consumer: the example work-planner skill bundled against stub artifacts and a fake `gh`, so a mode is exercised without editing the 79-file tree and without a live GitHub account. The scenarios run from a temporary copy of the tree made at run time, so there is one source of truth and nothing is checked in twice.

## Problem

Every behavioural test of the example skill needs two things the tree cannot give it. A scenario that varies one artifact means editing the skill, so the tree under test is not the tree that ships. And 96 `gh api` and `gh project` call sites across seven documents make any run against the real skill depend on a live repository, so on `main` there is no behavioural test at all — the seven `usage-example` fixtures prove the closure is complete, not that the instructions are followable.

## Proposal

**The scene.** `example/work-planner/conventions.md` declares `prosiform.root: "."` and states how the skill reaches GitHub. `modes/plan-mode.md` declares `root: ".."` and reaches `artifacts/epic.md` through the shared artifact documents; `epic.md` declares `group: artifacts` at depth `1`, so it is emitted as a member of that merged group under a `## Epic` heading, at line 2718 of the existing `plan-mode` bundle.

**The design.**

- **These are checks, not corpus fixtures, because the corpus cannot express them.** Three facts decide that. A `usage-example` fixture reaches the tree through a `source` symbolic link so the corpus and the published example name one tree; `execute` takes `Path.cwd().resolve()`, so a substitute written relative to a linked `source` resolves beside the link's target; and `access.py` refuses a symbolic link in any traversed component, so a fixture running from its own directory and naming `source/…` fails with `E_SOURCE_SYMLINK`. A corpus fixture therefore has nowhere to put a substitute. A copied `source/` would work and is refused, because a copy per fixture is the drift the symlink exists to prevent.
- **The copy is made at run time, so it cannot drift.** The check copies `example/work-planner` into a temporary directory, writes the scenario's stubs beside the copy, runs `pf -o -` from the copy, and compares. One tree is maintained; the copy lasts for one run.
- **A stub artifact is a mapping entry.** A scenario that needs `artifacts/epic.md` to carry no operations writes `stubs/epic-minimal.md` and passes `-m artifacts/epic.md=../stubs/epic-minimal.md`, taken from the copied tree so the value lands in the temporary directory.
- **A stub may name a document that does not exist,** which is what makes an artifact under authoring testable before it lands.
- **The environment is a substituted document.** Redirecting `conventions.md` to a stub naming a fake `gh` tells the agent to run the fake while every other instruction stays real. That is the seam between a bundle and its environment, and it is the only way a behavioural test becomes hermetic.
- **The check reports the way the corpus does.** Each scenario names itself and its differences, so a red run names which scenario departed, and the target returns nonzero the moment one does.

## Scenarios

| Scenario | What it declares |
| --- | --- |
| An example mode bundled against a stub | `stubs/epic-minimal.md` stands in for `artifacts/epic.md`. The bundle carries the stub's text beneath the `Artifacts` group where `## Epic` stood, exit status `0`, and one `W_MOCK_SUBSTITUTED` naming the substitution. |
| An example skill told to use a fake `gh` | `stubs/fake-gh-conventions.md` stands in for `conventions.md` and names `./fake-gh` as the command every `gh` call is written with. The bundle carries the stub's Conventions group, so an agent following the bundle is told to use the fake, and every other heading the unmocked bundle carries is present and unchanged. |
