**Component:** fixtures/mock

## Overview

The mechanism applied to its first real consumer: the example work-planner skill bundled against stub artifacts and a fake `gh`, so a mode can be exercised without editing the 79-file tree and without a live GitHub account.

## Problem

Every behavioural test of the example skill needs two things the tree cannot give it. A scenario that varies one artifact means copying the skill and editing it, so the tree under test is not the tree that ships. And 96 `gh api` and `gh project` call sites across seven documents make any run against the real skill depend on a live repository, so on `main` there is no behavioural test at all — the seven `usage-example` fixtures prove the closure is complete, not that the instructions are followable.

## Proposal

**The scene.** `example/work-planner/conventions.md` declares `prosiform.root: "."` and is where the skill states how it reaches GitHub. `modes/plan-mode.md` reaches `artifacts/epic.md` through the shared artifact documents, and `epic.md` declares `group: artifacts` at depth `1`, so it is emitted as a member of that merged group under a `## Epic` heading.

**The design.**

- **The fixture copy is the tree, because a symlink cannot be redirected.** Every `usage-example` fixture's `source` is a symbolic link to `example/work-planner`, and `execute` takes `Path.cwd().resolve()`, so a `../stubs` value from a linked tree resolves to `example/stubs` — outside the fixture entirely. A scenario fixture therefore holds a real copy of the skill under `source/`, which is also what lets the substitute sit beside it. The copy is held to the original by `cmp` outside the corpus, as `real-source` fixtures already are.
- **A stub artifact is a mapping entry.** A scenario that needs `artifacts/epic.md` to carry no operations is `-m artifacts/epic.md=../stubs/epic-minimal.md` against the copied tree. The substitute becomes the target outright, so the bundle carries the stub as that group's member, and the skill's own documents are unedited.
- **A stub may name a document that does not exist,** which is what makes an artifact under authoring testable before it lands: the mode can be bundled while the artifact is still a stub.
- **The environment is a substituted document.** Redirecting `conventions.md` to a stub naming a fake `gh` tells the agent to run the fake while every other instruction stays real. That is the seam between a bundle and its environment, and it is the only way a behavioural test becomes hermetic.
- **The run publishes nothing.** `-o -` sends the bundle to standard output, so the only file the fixture holds is the one it declared.

## Fixtures

| Fixture | What its source tree and manifest declare |
| --- | --- |
| `fixtures/mock/an-example-mode-bundled-against-a-stub` | `source/` is a copy of `example/work-planner`, and `stubs/` sits beside it under the fixture. The run is `-o - modes/plan-mode.md` with `-m artifacts/epic.md=../stubs/epic-minimal.md`, taken from `cwd = "source"`. The bundle carries the stub's text beneath the `Artifacts` group where `## Epic` stood, exit status `0`, and one `W_MOCK_SUBSTITUTED` naming the substitution. |
| `fixtures/mock/an-example-skill-told-to-use-a-fake-gh` | The run is `-o -` with `-m conventions.md=../stubs/fake-gh-conventions.md`, and the stub names `./fake-gh` as the command every `gh` call is written with. The bundle carries the stub's Conventions group, so an agent following the bundle is told to use the fake, and every other heading the unmocked bundle carries is present and unchanged. |
