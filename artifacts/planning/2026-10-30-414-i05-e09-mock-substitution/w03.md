**Component:** src/prosiform/cli.py

## Overview

A redirected positional entry and a redirected referrer, and the filename a run derives when either is substituted — with the two fixtures that show each.

## Problem

`derived_output` composes the name from an entry's path relative to the working directory, and `execute` derives it from `requested`, which the mapping changes nothing about. An unmocked name over a mocked bundle publishes a file naming a document it does not carry, and a caller who redirects the entry to rehearse one path cannot tell the two runs' outputs apart. A referrer the run was given with `-f` is resolved before any source is read, so a fragment-only entry against a redirected referrer resolves against the real document.

## Proposal

**The scene.** `execute` normalizes the referrer and the entries, builds the mapping, then traverses and derives the name. Both the referrer and each entry are references the mapping serves, and both are resolved before the closure reads anything.

**The design.**

- **The redirect reaches the entry and the referrer.** Both are resolved through the mapping where `execute` normalizes them, so a fragment-only entry against a substituted referrer names a section of the substitute.
- **The name follows the substitute.** `derived_output` reads the substituted entry, so the name is the name of what the file holds.
- **A section entry keeps the substitute's fragment.** A substitute carrying a fragment contributes that fragment in place of the authored one, so the `__` segment of the name names the section the bundle carries.
- **Two entries naming one substitute collide.** Both derive one name, which `derived_output` already refuses as multiple distinct selections requiring an explicit `-o`. No new refusal.
- **`-o` short-circuits the whole question,** because an explicit destination names the file rather than the selection.
