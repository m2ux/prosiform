**Component:** src/prosiform/cli.py

## Overview

The filename a run derives for its bundle when a positional entry reference is redirected.

## Problem

`derived_output` composes the name from the entry's path relative to the working directory. A redirected entry that kept the authored name would publish a file naming a document the bundle does not carry, while deriving from the substitute alone would leave `pf entry.md` and `pf -m entry.md=mock.md entry.md` writing to one destination and overwriting each other.

## Proposal

**The scene.** `derived_output` reads `requested`, which `execute` has already normalized and which the mapping changes nothing about. The name is therefore derived from the authored reference, and the substitution reaches no further than the closure.

**The design.**

- **The name follows the substitute.** The redirect is total: the bundle carries the substitute's content under the substitute's identity, so the name derived from it is the name of what the file holds.
- **The redirect is applied before the name is derived.** `execute` derives the name from `requested` after the mapping exists, resolving each entry through the mapping first.
- **A section entry keeps the fragment it names.** A substitute carrying a fragment contributes that fragment in place of the authored one, so the `__` segment of the name names the section the bundle carries.
- **Two entries naming one substitute collide.** Both derive one name, which `derived_output` already refuses as multiple distinct selections requiring an explicit `-o`. No new refusal.
