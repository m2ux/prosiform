**Component:** main:evals/diagram-following/README.md

## Overview

The eval page names the feature workflows and states what the proof run proves and what it cost.

## Problem

- **The proof file is unexplained without the page.**
  A reader finds a run record beside the baseline and no statement of what it shows.
- **Its cost is a fact a reader plans by.**
  A rerun spends the same budget.

## Proposal

**The scene.** The page states the forms, the scenarios and the scoring, with tables per workflow family.

**The design.**

- **A table of the feature workflows.**
  Each workflow and the permutations its scenarios cover.
- **A section on the proof.**
  What `mvp-proof.json` proves and its measured cost, read from the file. The managed configuration is named by the page's Isolation section, and the run's method by the runbook.
- **A test holding the page to the file.**
  `test_readme.py` reads the proof file and the workflows' `scenarios.toml` files, so a scenario the proof runs without a row, or a cost the file does not record, fails the harness.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Read `mvp-proof.json` for its matrix, pass rates and cost, and each feature workflow's `scenarios.toml` for its permutations. |
| Plan | Settle the table, one row per scenario, and the proof section. |
| Implementation | Amend the page; add `test_readme.py`. |
| Review | Compare the stated cost with the file. |
| Test | T1 and T2 in `test_readme.py` observe that the table names each scenario the proof runs and each its workflow declares; T3 observes that the stated cost and session count are the file's; T4 `make tables` and T5 `make links`; T6 `make check`. |
