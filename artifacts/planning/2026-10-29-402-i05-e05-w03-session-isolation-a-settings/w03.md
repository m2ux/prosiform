**Component:** evals/diagram-following/run.py

## Overview

A session's config directory cannot deliver a hook the eval did not write. The preflight refuses the two files a plugin reaches a session through, and each session's transcript is read for context the run did not supply. A `settings.json` carrying a `hooks` block reaches a session through neither check, so a directory the eval writes can still deliver a hook before the read that would catch it. This task closes that third path in the preflight, where the refusal costs nothing, and holds it with the tests that state what a settings file may hold.

## Problem

- **The preflight reads two files, and a hook need not be in either.**
  `preflight` refuses `plugins/installed_plugins.json` when it lists a plugin and `remote-settings.json` when its `enabledPlugins` enables one. A `settings.json` carrying a `hooks` block delivers a `SessionStart` hook without installing a plugin, and the preflight never reads that file.
- **The injected-context read catches it, but only after the run.**
  `injected` fails a run one of whose sessions carried a hook response, so the invariant holds. A paid run carrying one spends its sessions' cost before it is refused, where the preflight refusal costs nothing.
- **No test states what a settings file may hold.**
  The four preflight tests plant a plugin in each file and a clean directory. None plants a `settings.json`, so a hook reaching a session through it is not refused and no test says so.

## Proposal

- **The preflight reads the settings file for hooks.**
  `hooking` returns the settings file and the events its `hooks` block declares, in the shape `installing` and `enabling` already take, and `preflight` refuses it beside the two refusals it already makes. The read reuses `record_of`, so a malformed file is refused the same way.
- **The refusal names what it found.**
  The message names the file and each event the block declares, so a directory carrying a hook states which event would reach a session.
- **The tests hold the third file.**
  A test plants `settings.json` with a `SessionStart` hook and asserts the refusal, the empty stub log and the absent `results/`, as the plugin tests do. A second asserts a settings file holding only preferences starts its session, so the refusal does not over-reach.
- **The documentation names the third file.**
  The eval's README lists the settings file among what the preflight refuses, beside the plugin and the remote settings.
