**Component:** example/work-planner/

## Overview

The example states a tree with four folders of skill documents, and a bundle of it must show those folders as groups rather than as a flat sequence of documents. This row declares a group on every file that sits in a folder, so a mode's bundle composes the folders its documents belong to, and the routing document and the guidelines stay ungrouped because they are the entry's peers.

## Problem

A tree with folders, compiled without declarations, produces a bundle with no groups.

- **A folder is a filesystem fact, not a bundle fact.**
  Nothing in a file's path tells a run to compose it with its siblings, so thirty artifacts arrive as thirty documents in link order rather than as one group holding thirty members.

- **Without a depth, a group has no shape.**
  A group's members are its files at one depth, and the depth also decides which of a member's headings sit inside the group and which stay above it.

- **A group heading a reader does not want is not optional by default.**
  A group's name is emitted as a heading unless the declaration says otherwise, and the artifacts folder reads better named by its member headings than by a heading over them.

## Proposal

- **Every artifact declares the artifacts group at depth two.**
  `artifacts/` holds thirty files reached from a mode, and each declares `group: "artifacts"`, `group-depth: 2` and `group-heading: false`, so the group is composed without a heading above its members.

- **Every protocol and the reference declare their group at depth one.**
  `protocols/` holds six files and `references/` one, and each declares `group: "protocols"` or `group: "references"` with `group-depth: 1`, so the group heading names the folder and the members sit beneath it.

- **A mode carries no group.**
  A mode is the entry's peer rather than a member of a folder the entry composes, so a mode declares no group and its bundle shows it above the folder groups.

- **The routing document and the guidelines carry no group.**
  Both sit at the example's top level, which is the entry's own level, so neither is a member of anything.

- **No file declares a `prosiform` key beyond the four this row and its predecessor use.**
  `root` is already declared. This row adds `group`, `group-depth` and `group-heading` where the folder calls for them, and nothing else.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Record each file's folder, and read `invocation.md` on groups: a group's name, its depth, and when its heading is emitted. |
| Plan | Decide the declared name, depth and heading for each folder, and confirm no document sits in two folders or at an ambiguous depth. |
| Implementation | Add the three declarations to each grouped file, leaving each file's content and its existing root untouched. |
| Review | Confirm every file declares only `root`, `group`, `group-depth` and `group-heading` within `prosiform`, and that every member of one group declares the same depth and heading. |
| Test | Bundle each mode and confirm its headings show artifacts at depth two without an artifacts heading, protocols and references at depth one under their named headings, and modes and guidelines ungrouped.
