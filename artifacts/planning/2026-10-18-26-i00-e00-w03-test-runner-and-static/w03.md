## Overview

The named commands that run this repository's tests and static checks, the inventory the vocabulary check measures the shipped glossary against, and the lock check that holds the lockfile to the dependency list it describes.

## Problem

Every later epic carries tests, and nothing states how they are discovered, how they are run, or what reports a failure. A contributor and a continuous-integration job share no command, so a check can hold in one place and be absent in the other.

The three checks W01 wrote stand outside any such scheme: `checks/layout.py`, `checks/links.py` and `checks/vocabulary.py` are invoked by hand, each with its own argument conventions. One of them also rests on a source that is leaving. `checks/vocabulary.py` inventories the contract's terms from the glossary in the planning record at a hard-coded dated path, so its verdict depends on a second, unshipped glossary — a term is measured only because that copy lists it — and the path it names breaks when that folder is superseded.

Nothing holds `prototype/uv.lock` to `prototype/pyproject.toml`. A dependency list edited without relocking passes against a lock that no longer describes it, while the guarantee that a checkout installs the recorded versions appears to hold.

## Proposal

The repository's checks are a set of named commands with declared configuration, each returning a nonzero status when it fails, and one runner that drives them all. A contributor and continuous integration invoke the same names, and a failure is attributable to the check that produced it.

- **One entry point names every check.** A `Makefile` at the repository root carries one target per check — `test`, `lint`, `format-check`, `typecheck`, `lock-check`, `layout`, `links`, `vocabulary` — and `check` runs the set in that order, stopping at the first failure. Make is present wherever the build runs and adds no package to the Python build, so the names are callable from a shell and from a job step without a runner of their own.

- **The tools are declared where the build's dependencies are declared, and locked with them.** `pytest`, `ruff` and `mypy` sit in a development dependency group in `prototype/pyproject.toml` and are recorded in `prototype/uv.lock`, so the versions that run the checks are pinned exactly as the runtime parser is. Each command invokes its tool through `uv run --frozen`, which installs what the lockfile records and resolves nothing. `ruff` supplies both the linter and the formatter, so one declared configuration governs lint rules and formatting.

- **Discovering no test is a failure.** A test command that reports success having found nothing is a hole a job cannot see through: the suite would be absent and the gate green. `pytest` exits 5 when it collects no test, which is nonzero, so the behaviour is the tool's default and needs no configuration. The build therefore carries its first tests, which assert the parser configuration the declared profile rests on: the version the lockfile pins, pipe tables and double-tilde strikethrough enabled, task-list markers preserved as source text, typographic substitution off, and raw HTML emitted as a token of its own so the build can refuse it.

- **The static checks cover every Python file the repository owns.** The linter, the formatter and the type checker read one configuration from `prototype/pyproject.toml` and run over the package, its tests and `checks/`, so the scripts that hold the repository's claims true are held to the same standard as the build.

- **The link check's named command is the online one.** Without `--online` a reference outside this repository counts as unresolved, so an offline run cannot pass on the README as written and reports nothing a reader can act on. The named command supplies the flag, and the environment that runs it needs network access and GitHub credentials, because a private repository answers an unauthenticated request with 404.

- **The vocabulary check's inventory is the contract's own text.** The design marks a contract term with emphasis where it first uses it, and the check reads those marks as the inventory. The shipped glossary must define every term the design marks, and must define no term that neither the design marks nor an acceptance criterion uses. The inventory is then independent of the file under test and of any second glossary: a term the glossary stops defining fails the check, and a term the glossary carries that the contract does not use fails it too.

- **No check holds a path into a dated planning folder.** The vocabulary check locates the design by resolving the README's Design link, and reads each epic's Acceptance Criteria from the design's siblings on the branch that link names. Superseding the planning folder changes the README's link, which the link check already holds to resolving, and the vocabulary check follows it.

- **The lock check holds the lockfile to the dependency list.** `uv lock --check` exits nonzero when `prototype/pyproject.toml` names a dependency set the lockfile does not describe, so a dependency edited without relocking fails at the gate rather than at the next install.
