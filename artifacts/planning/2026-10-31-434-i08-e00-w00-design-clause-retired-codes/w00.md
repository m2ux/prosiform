## Overview

The clause that makes inclusion a property of the target document, the codes the change retires, and the pin that lets a fixture name the clause.

## Problem

`make conformance` reads the design at the revision `README.md` pins and refuses a declaration naming no clause it carries. The clause does not exist, and three pieces of the contract currently state the opposite of what this epic delivers.

- **The root decides a link, and the root is authored twice.**
  The pinned design states at *Link classification and resource handling* that a reference is a dependency when it resolves under its authoring source's effective root, so a link's reach is stated both by the path and by the declaration bounding it.
- **`root` is an admitted key.**
  At *Conversion metadata* the design states that `prosiform` admits `root`, `group` and `group-depth`, and that a key outside them fails with `E_INVALID_CONVERSION_METADATA`.
- **Both clauses are read by fixtures across the corpus.**
  A fixture names a clause exactly, so a clause rewritten in place changes what every fixture naming it proves, and the report fails while a declaration names no clause the pinned revision carries.

## Proposal

**The scene.** The pin names a revision whose design states inclusion by declaration; every fixture the epic lands resolves against it.

**The design.**

- **One clause, stated where the root's clause stands.** The root's three statements are replaced by one clause: a local Markdown link under the invocation working directory is a dependency when its target declares `prosiform`, a target that declares nothing is text, and a document's boundary is the deepest directory holding every local Markdown path its own links name.
- **The key set narrows rather than widens.** `root` leaves the admitted keys and joins the refused ones, carrying the code the unknown-key refusal already carries.
- **The retired code is recorded rather than deleted quietly.** `E_ROOT_NOT_FOUND` leaves the code catalogue, and the clause states the retirement so the comparison `make conformance` makes has a fact to read.
- **`E_SOURCE_OUTSIDE_ROOT` keeps its row.** Its meaning is stated as the path forms no grammar admits, a drive path, an absolute path, or a path normalising above the invocation working directory.
- **`E_TARGET_NOT_FOUND` keeps its row and narrows its reach.** The clause states the two shapes that still reach it, a link an operator marks and a fragment-only link.
- **One pin moves for every clause in this initiative.** Conformance reads the design at the committed revision, so a clause has to exist there before a fixture can name it. This row is the only one that moves the pin; the other six amendments land beside it.
