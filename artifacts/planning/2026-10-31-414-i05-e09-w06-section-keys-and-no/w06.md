**Component:** src/prosiform/closure.py

## Overview

What a section key means, and why the mapping stops after one hop. W01 landed the exact-then-bare lookup; this row states what the fragment on a key decides, and makes both rules observable in the corpus. It writes no second lookup.

## Problem

A key without a fragment covers a document and every fragment of it, which is right when the whole document is being replaced. A caller rehearsing one branch of a procedure wants one section redirected and the document's other sections compiled as they ship, and a whole-document key cannot express that. Separately, a mapping is a lookup table and not a chain: a caller who redirects `a.md` to `b.md` while another key names `b.md` has written something the run must read one way and not the other.

Both rules had no fixture when W01 merged. The lookup's order was asserted in `src/tests/test_mock.py` and proven by nothing in the corpus, so a later change to the order of the two `keys.get` calls would have passed every check.

## Proposal

**The scene.** `identity` joins a path and a fragment into the name two spellings of one dependency share, and a fragment on a `Reference` is the decoded section name a later `section` lookup resolves against.

**The design.**

- **A key's fragment is a section name,** decoded as any fragment is and matched against the identity a reference normalized to, so `rules.md#escalation` matches `./rules.md#escalation` and does not match `rules.md#Escalation`. A key carrying no document is refused by W02, which owns every mapping refusal.
- **A redirected fragment is the substitute's.** Where a section key's substitute carries a fragment, that is the section the bundle selects, because the redirect replaces the reference rather than only its path. Where the substitute carries none, the section the reference named is the one read against the substitute's document.
- **A section key beats a document key,** because the lookup W01 lands asks for the exact identity before the document-wide one. This row makes that precedence observable for a section: with both keys given, each link compiles the substitute its own exact key names and neither real document is bundled.
- **No chaining.** The substitution is applied once, to the reference the source wrote, and applying it a second time is structurally impossible rather than guarded against: what a substitute's own links resolve to is a fresh `inside` call against the substitute's document, so the mapping sees the link that document wrote and never the path it was reached by. The key naming a substitute's own path is therefore reported unused by `W_MOCK_UNUSED`, which is the observable half of the rule.

## Additions from review

| Finding | How the row states it |
| --- | --- |
| The order the two lookups are asked in decides the whole fixture, and no corpus fixture held it. | The precedence is asserted by `a-document-key-and-a-section-key-together`, which fails if the document-wide key is asked first: the escalation link would take `rules-copy.md` and `escalation-copy.md` would be bundled by nothing. |
| A section key's substitute may carry a section of its own, and the row's scene did not say which section wins. | The substitute's section is the one read, stated in the design and covered by `src/tests/test_mock.py::test_a_section_keys_substitute_section_is_the_one_the_run_reads`. |
| "No chaining" reads as a guard, which would invite one. | The design states the structural reason a second application cannot happen, and the unused-key warning is named as its observable half rather than as a test of the guard. |
| A section key whose substitute lacks that section is a defect, not a silent whole-document read. | Left to resolution, which reports `E_TARGET_NOT_FOUND` against the substitute's document. The row asserts it rather than changing it. |
