**Component:** main:src/prosiform/metadata.py

## Overview

`exclude` holds bare section names and single-entry name-to-level mappings in one list, and `path-sub` holds `ORIGINAL=ALTERNATIVE` strings whose sides the reference grammar reads. Each malformed entry is refused at the entry, named by its index.

## Problem

Both fields are checked only as lists, so any entry passes and nothing a later row reads has a shape.

- **An exclusion needs a name and sometimes a level.** A document may carry two headings of one name. A bare name cannot say which one is meant, so the entry needs a form that holds a level, and the two forms belong in one list.
- **A substitution's sides are references.** A mapping key would put a path where a colon collides with YAML's separator, so the pair is one string split at `=`, and each side must be a reference the grammar admits.
- **Shapes YAML admits but no author means.** `{Tests: 3, Draft: 3}`, `{3: 1}` and `{rules.md: stub.md}` decode without complaint and would be read as something.

## Proposal

**The scene.** `metadata._preset` checks each field is a list and reads only `group-depth`, into `Membership` values named `prosiform.<preset>.group-depth[<n>]` when malformed. `path-sub` has no effect until [I08:E06](https://github.com/m2ux/prosiform/issues/461), and the carve that reads `exclude` is [I08:E02](https://github.com/m2ux/prosiform/issues/445)'s.

**The design.**

- **`exclude` entries are `Exclusion` values.** A string entry is a section name with no level; a single-entry mapping is a string key mapped to a heading level from 1 through 6. The name is the heading's text, not a reference, so `#Notes` is a name and nothing is decoded.
- **The single-entry shape is shared.** `_pair` reads a single-entry mapping's string key and value for both `group-depth` and `exclude`, and `_level` reads one integer from 1 through 6 for both, so the two fields refuse one malformed shape with one rule.
- **`path-sub` entries are `PathSub` values.** Each is a string split at its first `=`, both sides nonempty, held as written with the entry's location. Anything else is refused naming the `ORIGINAL=ALTERNATIVE` form.
- **The sides are read by the reference grammar where the document is captured.** `metadata` sits beneath the reference grammar in the import graph (`closure` imports `source`, which imports `metadata`), so `cli.path_subs` reads each side through `closure.resolve` inside the capture's metadata context. A side the grammar refuses, or one carrying a scheme or an authority, fails with `E_INVALID_CONVERSION_METADATA` at the entry, naming the side. The grammar's refusals hold whatever directory a side resolves from, so the declared-file basis, E06's, is not needed to decide them.
- **One separator.** `metadata.SUBSTITUTION` is the `=` both the `-m` option and the entry split at.
