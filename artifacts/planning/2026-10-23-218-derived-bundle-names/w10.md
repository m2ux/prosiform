**Component:** src/tests/test_linked_bootstrap.py

## Overview

An installed-command end-to-end suite exercises the linked documents a skill bundles when invoked and preserves its runs as reference examples.

## Problem

Isolated source and CLI tests do not establish how independently bundled skill links behave across a stack of documents with divergent frontmatter settings.

## Proposal

- Use the preserved bootstrap specimen and executable prototype in [the end-to-end artifacts](e2e/README.md). SKILL.md is read directly by the agent; each of its three or more linked targets is compiled separately with pf, and each resulting bundle is read before its instructions are used.
- Create real source trees with top-level prosiform mappings and varying root, group and group-depth values. Exercise explicit file-relative roots and absent-root defaults from a caller directory distinct from each source directory. Place same-named decoys under incorrect roots.
- Invoke an installed pf executable in subprocesses, using short flags. Verify each target's transitive content, isolation from unrelated targets, grouping boundaries, section selections, stable rewrites and output publication. No mocked compiler or in-process main call supplies end-to-end evidence.
- Include compatible depth differences across distinct groups and conflicting depths within one group. Invalid metadata and conflicts preserve existing output and report original locations. Cover repeated targets and an absent-root shared source reached through parents with different explicit roots.
- Make the suite part of the project's normal verification. Supporting checks accompany this task; a real agent walkthrough of the specimen, if performed, is recorded separately from deterministic command execution.
- Preserve each run beneath the delivery planning record: readable source trees including SKILL.md, invocation working directory, exact commands, compiler revision/version, exit status, diagnostics and resulting Markdown bundles. Keep per-link outputs separate, retain failed-run inputs and diagnostics, and mark missing bundles as not produced. Index artifact links and expected content/grouping so the fixtures and successful outputs can serve as later reference examples.
