**Component:** main:evals/diagram-following/score.py, main:evals/diagram-following/test_score.py

## Overview

The diagram-following scorer reads a session's shell commands as the shell reads them: a duplicated descriptor is its redirect's operand, and a heredoc body is data. A scored run then records the compiles a session made, and none it did not.

## Problem

- **An adjacent redirection invalidates its command.**
  In `pf --entry target.md 2>&1>out`, `SHELL_TOKEN` takes `2>&`, then `1>` as a second redirect where the shell reads `1` as the duplicated descriptor. A redirect following a redirect marks the segment invalid, so the session is scored uncompiled.
- **A heredoc body is read as commands.**
  `<<` is read as two `<` redirects, and each body line after the newline is a command segment. Compiler-looking text inside an unrelated `cat <<'EOF'` body counts as a compile, so the session is scored overcompiled.

## Proposal

A session runs `pf target.md 2>&1>out`, or writes a file through `cat <<'EOF'` whose body quotes a `pf` command, and the scorer reads the record its harness wrote.

- **A duplication takes its descriptor as its operand.**
  `[<>]&` followed by a descriptor or `-`, ending the word, is one complete redirect; a redirect after it starts a new redirect. `[<>]&` followed by anything else still takes the next word as its operand, and one left without an operand still invalidates its segment.
- **A heredoc's body is skipped as data.**
  `<<` and `<<-` take their delimiter word, quoted or not, as their operand. At the next unquoted newline the body lines up to the matching delimiter line, leading tabs stripped for `<<-`, are skipped, each heredoc on the line in turn. No word in them is a command. A body no line closes invalidates the segment that opened it.
- **A here-string is one redirect.**
  `<<<` takes one operand, so it is not read as a heredoc.
- **Nothing is executed.**
  The reading stays lexical: no shell input is evaluated.
