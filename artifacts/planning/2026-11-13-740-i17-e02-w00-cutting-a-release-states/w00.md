**Component:** main:docs/versioning.md

## Overview

Cutting a release states the tag target the project uses: the release pull request merges into `main` first, and the paired tags name that merge.

## Problem

- **The procedure names another commit.**
  Its Tag step names the version commit and its Merge back step follows it, while `contract/v0.24.0` and `python/v0.24.0` name the release merge on `main`, commit `6fc54bbf7`.

## Proposal

**The scene.** Cutting a release in `docs/versioning.md` lists the release steps in order.

- **One merge carries both tags.**
  The section's opening line names the release merge on `main` as what a release is.
- **Merge before tagging.**
  The Merge step precedes the Tag step: the release pull request merges the release branch into `main`, and the annotated tags name that merge.
