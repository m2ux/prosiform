**Component:** src/prosiform/cli.py

## Overview

A folder key that answered a reference at a path the substitute folder does not hold fails the run, and a folder key that answered no compiled reference warns once. Both name the key in the form the author wrote it.

## Problem

Two outcomes turn on a key's reach, and a folder key asks one more question than a document key.

- **An absent substitute is derived rather than written.** A document key names the path the run reads. A folder key derives it from a reference, so the run reads a document nobody named directly and its absence is nobody's obvious mistake.
- **The absence is known where the reference is resolved.** `key` answers a substitute reference and the caller then opens it, so the absence is visible before any source is captured and can be refused as the command-line fault it is.
- **`W_MOCK_UNUSED` names a key no reference named.** A folder key answers many references, and the used set should hold the key once rather than once per reference.
- **A folder matching only text is used by nothing.** Under the inclusion rule a reference whose target declares nothing is text rather than a dependency, so a folder redirecting only silent documents answers no compiled reference.

## Proposal

**The scene.** `compiled` reads `W_MOCK_UNUSED` for each key the run never used, and a substitution's target is opened where the reference is resolved.

**The design.**

- **The absent substitute is refused where the reference is resolved.** When the folder lookup answers and the target at the substitute path is absent, the run fails with `E_TARGET_NOT_FOUND`, exit status `1`, naming three things: the reference as its author wrote it, the folder key, and the path the redirect resolved to.
- **A document key keeps its shape.** A document key naming a path the run does not hold is refused where every other absent target is, so the folder key's message is the only one stated with three parts.
- **The used set holds a folder key once.** It is recorded at the first reference the key answers, so `W_MOCK_UNUSED`'s absence states that the folder was reached and not how often.
- **The warning states the key as written.** A command line carrying both a document key and a folder key is told which one matched nothing, separator included.
- **A folder answering only text references is unused.** It warns, and the warning is the fact the author needs: the folder was never consulted by a compiled reference.

## The reading this row settles

The work item asks whether a folder matching only text is a warning case or a documented non-event. It is a **warning case**, and the warning follows from the mechanism rather than being added to it: `Substitution.redirect` marks a key served only where the substitute it derived is a Markdown document, because a redirect to a resource is a redirect the bundle does not carry out. A folder whose every derived path is a resource therefore answers no compiled reference, and `unserved` reports it as it reports a key no reference named. The alternative — a second notion of "reached" that counts a reference whose target is text — would make `W_MOCK_UNUSED` state that the folder was consulted, which is a weaker fact than the one the author needs, and would need a rule distinguishing a folder that reached only text from one that reached nothing. Both are the same fault to fix: the stand-in folder holds nothing the run reads.

## Additions from review

| Addition | What it states |
| --- | --- |
| `Reference.folder` | The refusal names the key, and by the time `read_document` raises the absence the key is no longer in scope. The reference the lookup derived carries it, which is also the only place the caller's spelling of the key survives to the diagnostic. |
| The redirect takes effect only on a Markdown document | Without it the text case would record a substitution for a redirect the bundle never performs, and `W_MOCK_SUBSTITUTED` would name a substitution the published link does not show. |
| The remedy differs by kind | An author's absent reference is fixed by naming a document the root carries; a derived one is fixed by naming a folder whose documents the remainder reaches. One remedy for both would tell a folder key's author to do something the folder cannot do. |
