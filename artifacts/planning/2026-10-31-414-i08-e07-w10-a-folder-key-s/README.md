## Executive Summary

A folder key derives its substitute from each reference it answers, so the document the run reads is one nobody named directly. That absence is known where the reference resolves, before any source is captured, and is refused as the command-line fault it is. A folder key that answered nothing warns once for the key, not once per reference, and a folder matching only text is used by nothing because a reference whose target declares nothing is text rather than a dependency.
