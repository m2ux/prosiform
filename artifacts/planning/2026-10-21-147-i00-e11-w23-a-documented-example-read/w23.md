**Component:** `checks/documents.py`

## Overview

This task makes the link check read a document the way a renderer does. Literal content — a fenced block, an indented block and a code span — is blanked out of the text the reference patterns are applied to, so a link form written as an example is passed over while a link beside it is resolved.

It matters because the repository's subject is Markdown references, so the documents most likely to spell a link as an example are its own. A check that reads the example as a reference teaches the author to stop writing the example, which costs the reader the one spelling that shows the syntax.

## Problem

`checks/links.py` applies `INLINE_LINK` and `REFERENCE_DEFINITION` to the whole document, with only fenced blocks blanked out first.

- **Two of the three literal forms are text like any other.**
  `strip_code_fences()` blanks fenced blocks. A code span and an indented block survive it, so `` `](path.md)` `` written to show the syntax is indistinguishable from prose linking `path.md`.

- **The check and the product answer differently about the same bytes.**
  `prosiform` masks code spans before it reads inline tokens, and the design's *Examples* clause states the rule for code spans, fenced blocks and other literal example content alike. The check reaches the opposite answer on two of the three.

- **The remedy available today is to stop writing the example.**
  `example/README.md` names the deferral mark in prose and never spells the link that carries it, because spelling it reported a reference the tree does not hold.

- **No test holds the rule.**
  The harness suite covers a fenced reference. Nothing states what the check does with a code span or an indented block, so the behaviour rests on whichever document happens to carry one.

## Proposal

The reading a reference scan does is the renderer's reading, and literal content is what a renderer leaves as text. So the mask belongs beside the reading the checks already share, applied once and used by the scan that resolves.

- **Literal content is blanked where the shared reading lives.**
  `documents.strip_literal()` composes three passes over one document: the fenced blocks `strip_code_fences()` already blanks, then indented blocks, then code spans. Each blanked character becomes a space and every newline survives, so a line-anchored pattern still sees the lines the document has.

- **A code span closes on a backtick run of its own width.**
  `strip_code_spans()` opens at a backtick run and closes at the next run of the same length, which is the rule `prosiform.rewrite.code_spans()` applies. An opener that never closes is the literal backticks it is written as, and the scan carries on past it.

- **An indented block is told from a list's continuation.**
  `strip_indented_blocks()` opens a block at a four-space or tab indent that follows a blank line, and closes it at the first line indented less. A line below an open list marker is that list's content however far it is indented, so a nested bullet carrying a link is read as the link it is.

- **The heading and table readings keep the text they need.**
  `fragments_of()` reduces a code span to its code when it slugs a heading, and a table cell's value is routinely a code span. Both go on reading `strip_code_fences()`, and `references()` alone reads `strip_literal()`.

- **The check's own tests state the rule.**
  A case for a link inside a code span, one inside an indented block, one for a real link beside each, and one for a nested bullet's link, fix the behaviour where the check is tested rather than where a document happens to exercise it.

- **The example tree spells the deferral.**
  `example/README.md` writes `[¬ Routing Document](SKILL.md)` as the code span it is, so the document showing what a deferral looks like shows it.
