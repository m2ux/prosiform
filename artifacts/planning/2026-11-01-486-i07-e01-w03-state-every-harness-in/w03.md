**Component:** evals/diagram-following/harness.py

## Overview

Makes the harness module state every harness it declares, and declare on each harness only the fields some code reads, so a reader of the module learns the harnesses and their schema from what it says.

## Problem

- **The module docstring names two of three harnesses.**
  It says two harnesses are declared and describes `claude` and `cursor`; `HARNESSES` also holds `opencode`, whose stream of `part` events with one `step_finish` per model step is described nowhere at module level.
- **Harnesses declare fields nothing reads.**
  `Opencode.usage` names `cache` twice and is read by nothing, since `Opencode.tokens` sums its own token kinds. `Cursor` and `Opencode` also declare a `config_variable` and an empty `tools` that no code reads, and the module keeps `CLAUDE_USAGE` and `CURSOR_USAGE` tables that duplicate each harness's `usage` and are read by nothing.

## Proposal

A reader opens `harness.py` to learn what an agent CLI differs in. The module docstring lists every harness `HARNESSES` declares, each with the stream it reads, and each harness class carries only the fields its own methods or the runner read.

- The docstring names `claude`, `cursor` and `opencode`, and the stream shape of each.
- `Opencode.usage`, `Opencode.config_variable`, `Opencode.tools`, `Cursor.config_variable` and `Cursor.tools` are removed.
- `Opencode.tokens` sums `TOKEN_KINDS` and `CACHE_KINDS`, so the token kinds the harness sums are stated once.
- `CLAUDE_USAGE` and `CURSOR_USAGE` are removed.
