**Component:** fixtures/usage-example

## Overview

Five `usage-example` fixtures source `example/work-planner`. Two of them describe a bundle their expected output does not hold, and two of them run one invocation. This row gives each fixture an invocation of its own and holds every description to the bundle the fixture records.

## Problem

- **`a-procedure-and-everything-it-reaches` names a section the tree does not carry.**
  Its description says the bundle holds "the two documents its prerequisites reach". `modes/plan-mode.md` carries no `## Prerequisites` section, and the recorded bundle is 203,906 bytes.

- **`every-document-under-a-directory-merged` repeats the procedure fixture.**
  Both run `modes/plan-mode.md` and record byte-identical output, so the merged-group fixture observes nothing the procedure fixture does not.

- **The merged-group description names headings the bundle lacks.**
  It says each merged group is headed by its declared name and carries an Overview section. In the recorded bundle the artifacts group emits no heading (`group-heading: false`), and the `# Protocols` and `# References` groups carry no `## Overview`.

## Proposal

- **The merged-group fixture runs an entry whose closure shows what it describes.**
  Choose an entry under `example/work-planner` whose bundle exercises merged groups, or rewrite the description to the grouping the tree does exercise. The manifest's clause list names only clauses that bundle exercises.

- **Every description names only what its expected output holds.**
  Each count, heading and section named is present in the recorded bundle.

- **Every page citing a changed bundle follows it.**
  `example/README.md` quotes fixture output byte-for-byte; a block citing a re-recorded bundle is re-read from it.

## Implementation Findings

- **No entry yields a group both headed and carrying an Overview.**
  The tree's only headed groups, `protocols` and `references`, declare depth 1, so a member's H1 is a merged heading and nothing sits above the grouping depth. The artifacts group carries `Overview` but declares `group-heading: false`. The merged-group description states that split rather than a group holding both.

- **The merged-group fixture runs `modes/hoist-mode.md`.**
  Its 82,369-byte bundle holds the headless artifacts group (`Overview` with `Epic Issue Body`, then `Operations`, `Fields`, `Commands`) and the headed `References` group. It declares `Grouping — The overview section` beside its existing clauses.

- **`modes/plan-mode.md` names no routing document.**
  The procedure description drops that claim and states the closure the bundle records: three modes reached whole, the grouped material they link, and two deferred links to `guidelines.md`. It declares `Link classification and resource handling — The deferral mark`.

- **The section fixtures were reworded, not re-recorded.**
  `two-selected-sections` names the resolution of the first selection's reference to the second; `validation-without-publication` names the selection whose closure it reaches.

- **The merged-group fixture's directory name still states directory-wide membership.**
  `every-document-under-a-directory-merged` predates per-file declarations; the contract has a declaration discover no files. Renaming changes the fixture's identity and the pages citing it, so it is left as an open question on the pull request.

- **Outside AC11 and AC12.**
  - An artifact document bundled as the entry, such as `artifacts/goal-trace.md`, emits its own above-depth content as an H1 before the group, and the group's `Overview` follows the merged sections holding only the other whole-document member. Whether that departs from *The overview section* is unexamined here.
  - `pf SKILL.md` fails with `E_RESOURCE_LIMIT`: its bundle reaches 298,483 bytes against the default `-O` budget of 262,144.
