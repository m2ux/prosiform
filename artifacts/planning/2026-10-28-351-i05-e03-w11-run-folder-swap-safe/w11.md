**Component:** src/prosiform/cli.py

## Overview

The run folder's swap replaces only what stands at the run folder's own path and reports every state a failed swap leaves. A link at that path is an entry the run replaces, never a folder it follows; a swap whose earlier set cannot be restored names where that set is; and a set that cannot be removed once the new one stands is a warning on a published run.

## Problem

- **The run folder's path is resolved through a link.**
  `execute` resolves `<DIR>/<entry>.bundles` whole, so a link there sends the swap to the folder the link names: that folder is renamed aside and removed, and a dangling link writes the set outside `-o`.
- **A failed restore is an internal error.**
  When the swap is refused and renaming the earlier set back is refused too, the run exits `4` and the earlier set sits under a hidden name nothing reports.
- **A published run can report failure.**
  Removing the earlier set after the new one stands can fail, and the run then exits `3` although its set is published.

## Proposal

The scene: `-o out` with `out/ref.bundles` a link to `../precious`.

- **Resolve the output folder, not the run folder.**
  The run folder is the resolved `-o` folder joined with the run's name, so the swap's renames act on the link itself; the captured-source check is held against that path.
- **A failed restore names the earlier set.**
  The publication failure names the path the earlier set was moved aside to, and its remedy is to rename it back.
- **Cleanup after a stood swap warns.**
  The run publishes, exits `0` and warns with `W_EARLIER_SET_RETAINED`, naming the path that holds the earlier set; the contract's Publication clause and codes table state it.
