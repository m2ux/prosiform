## Overview

A `staged` Claude session carries a shell, so the nested-dispatch scenarios reach a harness that reports every start they state.

## Problem

- **The nested scenarios reach no harness.** ([#635](https://github.com/m2ux/prosiform/issues/635))
  `dispatch-depth` and `subagent-first-run`'s `deep-hop-runs` are written in the `staged` form alone. Claude's stream reports each sub-agent's own starts by `parent_tool_use_id`, but its tool allowlist names no shell, so Claude runs no `staged` session; Cursor and opencode carry a shell but report no sub-agent's calls. The edge run therefore gives these scenarios to no harness.

## Proposal

**The scene.** A run gives a `staged` session only where its harness carries a shell; the scorer reads the session's starts and each start's commands.

- **A shell for a staged session.** (User, 2026-11-03.)
  A Claude session given the `staged` form carries the CLI's shell tool, and only that form does; every other form keeps the allowlist that names no shell, `bootstrap` among them. Each harness answers `shell(form)`, so `runnable()`, `observable()` and the sub-agent record ask it of the session's form. The staged session's shell is approved for `pf` alone (`--allowedTools Bash(pf:*)`), since `acceptEdits` approves no command and a headless session cannot be asked.
- **Each start's commands.**
  A `Bash` call the session makes is its own command; one a sub-agent makes names that sub-agent's `Task` call as `parent_tool_use_id`, so it is that start's command. A session whose form carries no shell records no command list.
- **Each sub-agent's runs stated.**
  `subagent-first-run` states each sub-agent's `pf` run with `by`, and the corpus test holds a trace entry's stated runs to the lines its bundle reaches, so the scorer reading each start's runs holds a correct run to them rather than calling them overcompiled.
- **The nested scenarios on Claude.**
  `make eval-diagrams` gives `three-hop-chain`, `three-hop-set`, `three-hop-question` and `deep-hop-runs` to Claude, and the stub agent, whose shell runs each stated `pf` under the start that makes it, shows each one scored.
