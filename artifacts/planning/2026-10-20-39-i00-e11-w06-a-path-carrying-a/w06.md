**Component:** [fixtures](https://github.com/m2ux/prosiform/tree/main/fixtures)

## Overview

The corpus states what becomes of a source path carrying a number sign: the reference that names such a path, the file heading that carries the character, and the spelling that names another document instead.

## Problem

A number sign is a filename character on every platform the tool supports and a delimiter in every reference that names one, and the corpus says nothing about either half.

- **The escaping is held by one build's own tests.**
  A generated file heading escapes the number sign, because a path ending in a space and a number sign would otherwise close the heading as an ATX closing sequence. The three tests holding that are Python tests of the Python build, so a second implementation inherits no obligation.

- **The clause that makes such a path reachable is uncovered.**
  The resolution sequence splits a reference before decoding it, so `notes%23draft.md` names a filename carrying a number sign. The design's table states that row, and no fixture runs it; the double-encoded row beside it has one.

- **The literal spelling is read as two things and declared as neither.**
  `notes/draft #.md` names the document `notes/draft ` and the fragment `.md`, which fails on the suffix. Nothing records that this is the reading, so a build splitting after decoding would pass the corpus.

## Proposal

The disjunction the criterion offers is settled by the contract rather than by this row: the design's resolution sequence makes the encoded spelling name the file, so such a path is nameable and the fixtures state the naming. The literal spelling is the complement, and it is declared beside it so the split that makes the encoding necessary is itself under test.

Three fixtures, each a run of the corpus against the build under test:

- **`normalization/an-encoded-number-sign`.**
  The design's own row, run: `notes%23draft.md#run` against a source at `notes#draft.md`, which bundles the named section under the file heading `# notes\#draft`.

- **`identity/a-path-ending-in-a-number-sign`.**
  The heading hazard, run: a source at `notes/draft #.md`, named by `notes/draft%20%23.md`, whose file heading keeps the trailing character as `# notes/draft \#` where an ATX closing sequence would take it off.

- **`normalization/an-unencoded-number-sign`.**
  The same tree named literally, which resolves to a document whose suffix the profile does not classify and fails with `E_UNSUPPORTED_ENTRY_SUFFIX`.

The build changes nothing. The behaviour the fixtures declare is the behaviour it has, and this row moves it from one implementation's tests into the language-neutral corpus every implementation runs.
