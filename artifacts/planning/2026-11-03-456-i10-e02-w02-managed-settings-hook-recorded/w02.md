## Overview

Claude Code reads a managed settings file from a system path on every host, whatever the config directory names, and the preflight does not read it. This task makes the run read the host's managed settings file and record any hook it declares in the run record, so a committed run states what its sessions carried.

## Problem

- **Managed settings reach every session.**
  The managed settings file sits at a system path, `/etc/claude-code/managed-settings.json` on Linux, and its `hooks` block reaches a session exactly as one in the config file does. Relocating the config directory leaves it in force.
- **The preflight reads the config directory and the project scopes alone.**
  A hook declared by the host's managed settings therefore reaches every session of every form, and nothing the run commits says so.

## Proposal

**The scene.** The preflight, as widened by W01, reads the config directory's `settings.json` and every project-scope settings file before `run()` starts a session.

- **A managed hook is recorded, not refused.** (User, 2026-11-03.)
  The managed scope belongs to the host's administrator, as the eval login's managed plugin does, so the run reads the managed settings path for the host's platform and records the file and the events its `hooks` block declares in the run record, as it records a managed plugin (E05 W00). The run starts. An absent file records nothing.
- **The path is injectable.**
  The harness holds the managed settings path as a field beside the config directory's file names, so a stub-agent test plants a file at a temporary path in place of the system one.

## Analysis

- **Paths.** Claude Code reads managed settings from `/etc/claude-code/managed-settings.json` on Linux, `/Library/Application Support/ClaudeCode/managed-settings.json` on macOS and `C:/Program Files/ClaudeCode/managed-settings.json` on Windows. The harness selects by platform and holds the choice as a field. A session's own report of the settings it loaded was not read: the run is stub-agent only and starts no paid session.
- **Shape.** `managed` in `run.json` is a mapping whose `hooks` entry lists `{file, events}` for the managed settings file. I10:E05 W00 (#596) records managed plugins under the same `managed` key as `plugins` and `environment`, so the second of the two epics to reach `main` merges the mappings in `Claude.managed` and `run()`.
- **Hook responses.** A managed hook's response is accounted for, as #596 accounts for a managed plugin's: `injected` and `carried_context` take `hooked`, true where `managed.hooks` is non-empty. The merge of the two epics makes it true where either records.
