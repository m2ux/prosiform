**Component:** main:checks.md

## Overview

`checks.md` states every check and `make` target the repository runs as the merged build and the pinned design have it.

## Problem

- **The page was written epic by epic.**
  Each epic amended the parts it touched, so the page as a whole was never read against the merged build.
- **A stale claim reads as current fact.**
  A reader of the MVP takes the page as the contract.

## Proposal

**The scene.** `checks.md` documents every check and `make` target the repository runs.

**The design.**

- **The page is read whole against the build.**
  Each claim is checked against `make tables` and the `Makefile`, and each behaviour of its subject the build has is stated.
- **The evidence is recorded.**
  The pull request lists each claim corrected or added and what showed it.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Read the page against `make tables` and the `Makefile`. |
| Plan | List each claim to correct, add or remove. |
| Implementation | Amend the page. |
| Review | Re-read the page whole against the build. |
| Test | A read of the page whole against `make tables` and the `Makefile`, recorded in the planning record; `make tables`, `make links` and `make vocabulary`. |
