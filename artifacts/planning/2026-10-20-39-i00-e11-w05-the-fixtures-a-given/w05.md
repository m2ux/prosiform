**Component:** `checks/corpus.py`

## Overview

The fixtures awaiting one named piece of work, reported from the corpus on request, so a session starting that work reads what it unblocks before it changes anything.

## Problem

A fixture declares the work it awaits, and the corpus run names that work on the fixture's line. Reading the declaration therefore costs a whole corpus run, and only the question the run happens to answer can be asked.

- **The answer arrives from a red run or from a person.**
  A session starting `I00:E11:W14` learns which fixtures it turns green by running every fixture in the corpus against a build and reading the awaited lines out of the output, or by asking whoever wrote the marker.

- **The run needs a build the question does not.**
  `PROSIFORM_BUILD` must name a build before the corpus produces any line at all, so the declaration a manifest already carries is unreadable until something has been built and every fixture has been executed against it.

- **The markers are the only record, and nothing reads them as a set.**
  The marker lives in the manifest beside the expectation it qualifies, deliberately, because a list held elsewhere drifts. Without a report over those manifests the set they form is never read.

## Proposal

The declaration is already in the corpus; what is missing is a way to ask it a question. `corpus.py --awaiting WORK` reports the fixtures declaring that work and runs nothing.

- **The report reads manifests alone.**
  It needs no build and executes no fixture, so the question is answered before the work starts and in the time it takes to walk the corpus.

- **It names each fixture by its identity and counts them.**
  One line per fixture, its path under the corpus, in path order, then a count beneath them, so the set is readable by eye and the empty answer says so rather than printing nothing.

- **It returns zero whatever it finds.**
  A report is not a verdict. A work item that unblocks no fixture is an answer, not a failure, and the exit status stays with the corpus run.

- **The name is compared as the manifest declares it.**
  Markers are written at the grain the work was known at, so `I00:E11` and `I00:E11:W14` are separate requests and a fixture is found by the identity it was marked with. Matching a prefix would answer a question nobody asked and fold two grains into one.

The documented invocation moves with it: `checks/README.md` states what the request reads and why it returns zero, and `fixtures/README.md` shows the command beside the marker it reads.
