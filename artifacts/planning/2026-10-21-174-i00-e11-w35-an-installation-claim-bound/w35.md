**Component:** `checks/conformance.py` — the `Claim` record, the `CLAIMS` tuple, the report's failures and the declared-surface listing that renders them.

## Overview

Each installation claim the conformance report lists names the smoke-run property that would observe it, and the smoke run declares the properties it observes, so the report reads what is unobserved from the run rather than from a second account of it. A claim naming a property the run observes fails the check instead of printing a line that is now wrong.

## Problem

The declared-surface listing carries three installation claims no run of the corpus observes, each with the reason it is unreachable and a sentence of prose stating what a run would have to do to observe it. That sentence is free text. Nothing compares it with `checks/smoke.py`, which is where the properties of an installation are actually observed, so the agreement between the two is maintained by hand.

- **A claim can outlive what made it true.** The claim that the documented command line is not the one executed becomes false the day the smoke run executes it, and its entry stands until someone deletes it. A stale entry reads as a current limit of the corpus, which is the condition the listing exists to end.
- **The harness holds the shape, not the content.** Its cases hold the entry's two lines, the observability line's position and the closing count. A claim whose wording no longer describes the run passes every one of them.
- **Neither side reads the other.** The run performs the steps and the report prints the claims, and the only thing joining them is prose written at the same time.

## Proposal

The smoke run is the authority on what it observes, so the properties it holds are declared where it performs them and the report reads that declaration.

- **The run declares the properties it observes.**
  `checks/smoke.py` names the three properties of an installed command that its steps establish, under the names the repository README gives them: named on the path, independent of the working directory, independent of this repository. The run's closing summary states them, so the declaration is what the run reports rather than a constant beside it.

- **A claim names the property that would observe it.**
  Each claim carries the property a run would have to observe, written in the run's own terms rather than as prose about what a run might do. The listing renders that property, so a reader of the report sees which property is missing rather than a sentence describing one.

- **A claim naming a property the run observes fails the report.**
  The check compares each claim's property with the properties the run declares. A claim whose property the run has come to observe is a listing that states a limit the corpus no longer has, so it joins the report's failures and leaves the listing, and the closing count counts what is left.

- **The restated claims keep their scope.**
  Each claim's property restates its existing observability line in the run's terms without narrowing what the claim covers: another platform becomes a command named on another platform's path, a machine that never held the repository becomes a command installed on such a machine, and the documented route becomes a command installed by the command line the documentation gives a reader.
