## Overview

One live run of the default matrix over the feature workflows, committed beside the baseline as the MVP's proof.

## Problem

- **Nothing shows the merged surface working for an agent.**
  The corpus holds each feature's bytes; no session has followed a bundle built with them.
- **The baseline belongs to the evaluation work.**
  A proof written into it would move the reference another initiative measures against.

## Proposal

**The scene.** `make eval-diagrams` runs the default matrix within its token budget and writes a run record.

**The design.**

- **Harness and model asked at the start.**
  The session asks the user, one question at a time, which harness the run uses (claude, opencode or cursor; opencode recommended while the eval login carries an org-managed plugin) and, as an open-ended question with no options, which model (any the chosen harness reaches, Anthropic's or another provider's), and passes both explicitly.
- **The runbook is the plan.**
  The run follows the proof's runbook in `RUNBOOK.md` (W00): its command, budget, cost cap and stop rules, then every form the chosen harness runs in the default matrix, on the chosen model.
- **Failures are triaged, not fixed.**
  Each failing session gets the rubric's disposition in the run record; a defect or an unclear session stops the run and is escalated, and the run edits no scenario, harness or scorer.
- **A file of its own.**
  The run is committed as `mvp-proof.json` beside `baseline.json`, which stays untouched.
