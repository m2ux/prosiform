**Component:** [checks/manifests.py](https://github.com/m2ux/prosiform/blob/main/checks/manifests.py)

## Overview

A corpus fixture that states what a run does when its allowed source root names no directory, and the manifest validation that lets such a fixture exist.

## Problem

The contract declares the outcome: a `--root` naming no directory is well formed and names a root that is not there, so it fails with `E_ROOT_NOT_FOUND` and exit status 1. The corpus cannot declare it.

- **A fixture's root is required to be a directory the fixture holds.**
  `missing_files` reports `invocation.root` as a missing path when it is not a directory, so a fixture naming an absent root is refused as malformed before the build is invoked. The outcome under test is the one shape of fixture the validator rejects.

- **The outcome is held by one build's tests alone.**
  `src/tests/test_cli.py` covers it in Python. A caller of any other implementation of the contract has nothing holding that build to the same code and the same status, which is what the corpus exists to do.

## Proposal

A fixture declares the absence of its root the same way it declares every other expectation: by declaring the result. Nothing is added to the schema's shape.

- **The declared outcome decides which rule the root is held to.**
  A manifest whose expected diagnostics name `E_ROOT_NOT_FOUND` has declared that the run cannot find its root. For such a fixture `invocation.root` names a path the fixture must *not* hold, and for every other fixture it names a directory the fixture must hold. One predicate over the declared diagnostics selects between them, so the manifest carries one statement of the fact rather than two that can disagree.

- **The contradiction is refused in both directions.**
  A fixture declaring the outcome while holding the directory states nothing about its run, exactly as a fixture holding a path it declares absent does, so it is reported by `present_files` and the build is never invoked. A fixture declaring any other outcome over an absent root is reported by `missing_files`, unchanged.

- **The code is the contract's name for the outcome, so keying on it keys on the contract.**
  `manifests.py` already draws both catalogues from the schema rather than from a list of its own. A boolean beside `invocation.root` would be a second declaration of what the diagnostic already states, and two declarations of one fact drift.

- **The fixture sits with the other command-line outcomes.**
  `fixtures/cli/` holds the fixtures for faults in the invocation rather than in a source document. The run reads no reference, so the fixture carries no source tree at all and its expected standard output is empty.
