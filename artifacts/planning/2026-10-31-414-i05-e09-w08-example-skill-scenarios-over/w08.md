**Component:** checks/mock_scenarios.py

## Overview

The example work-planner skill bundled against stand-in material, so a mode is exercised behaviourally for the first time. Two scenarios run: the plan mode over a stubbed artifact, and `conventions.md` redirected to a document naming a fake tracker command. Both arrive as a mapping, so neither edits the tree under test and neither needs a live repository.

## Problem

Every behavioural test of the example skill needs two things the tree cannot give it. A scenario that varies one artifact means editing the skill, so the tree under test is not the tree that ships. And 96 `gh api` and `gh project` call sites across seven documents make any run against the real skill depend on a live repository, so on `main` there is no behavioural test at all: the seven `usage-example` fixtures prove the closure is complete, not that the instructions are followable.

## Proposal

**The scene.** `example/work-planner/conventions.md` declares `prosiform.root: "."` and states how the skill reaches GitHub. `modes/plan-mode.md` declares `root: ".."` and reaches `artifacts/epic.md` through the shared artifact documents; `epic.md` declares `group: artifacts` at depth `1`, so it is emitted as a member of that merged group under a `## Epic` heading.

**The scenes this row runs.** The plan mode bundles over `artifacts/epic.md` stubbed, so the stand-in's words stand where the artifact's stood and the `## Epic` heading the group emits still stands. `conventions.md` is redirected to a document naming a fake tracker command, so a bundle read whole tells a session to run the fake while every other heading it reads for the surrounding instructions stays where it was.

**The design.**

- **These are checks, not corpus fixtures, because the corpus cannot express them.** A `usage-example` fixture reaches the tree through a `source` symbolic link so the corpus and the published example name one tree; a run takes the resolved working directory, so a substitute written relative to a linked `source` resolves beside the link's target; and the build refuses a symbolic link in any traversed component, so a fixture running from its own directory and naming a path under `source/` reads nothing. A copied `source/` would work and is refused, because a copy per fixture is the drift the link exists to prevent.
- **The copy is made at run time, so it cannot drift.** The check copies `example/work-planner` into a temporary directory, writes the scenario's stubs beside the copy, runs the build from the copy, and compares. One tree is maintained, nothing is checked in twice, and the copy lasts for the run.
- **Every run publishes outside the trees it reads.** A run that published into the skill directory would be green on its bundle, so both trees are fingerprinted either side of the scenarios and a write is reported as a write.
- **The environment is a substituted document.** Redirecting `conventions.md` to a stub naming a fake tracker tells the session to run the fake while every other instruction stays real. That is the seam between a bundle and its environment, and it is the only way a behavioural test becomes hermetic.
- **A scenario's expectation is the bundle the same tree produces unmocked.** Material that moves moves both sides, so only a difference the substitution makes can be red. A difference is held twice over: every byte outside the section the stand-in occupies is the unmocked bundle's, and inside that section the stand-in's own blocks stand in place of the artifact's.

## Scenarios

| Scenario | What it declares |
| --- | --- |
| An example mode bundled against a stub | `stubs/epic-minimal.md` stands in for `artifacts/epic.md`. The section under `## Epic` carries the stand-in's placeholder text where the artifact's prose stood, every byte outside it is the unmocked bundle's, `example/work-planner` carries no write, and the run states one `W_MOCK_SUBSTITUTED` naming the artifact and the stand-in. |
