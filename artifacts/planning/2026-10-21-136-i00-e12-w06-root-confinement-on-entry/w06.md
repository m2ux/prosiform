**Component:** `src/prosiform/cli.py`

## Overview

This task confines `E_SOURCE_OUTSIDE_ROOT` to the caller's entry references. An entry naming a path the allowed source root cannot contain is work the tool cannot perform, so the run fails before anything is opened; a reference inside a source naming such a path is the author citing material the bundle does not carry, and it reaches the bundle as its author wrote it.

It is the boundary the rest of the epic is written against. [W01](https://github.com/m2ux/prosiform/tree/engineering/artifacts/planning/2026-10-21-136-i00-e12-w01-classification-by-where-a) made position decide what a reference is; this row says whose reference the root binds, so the one refusal that served both cases serves the one case that is left.

## Problem

The refusal is written in two places and the corpus states its two halves for one spelling.

- **One code is raised from two sites.**
  `cli.entry()` refuses an entry the root cannot contain, and `cli.read_document()` maps the access walk's `Outside` to the same code with wording that names either an entry reference or a reference a source carries. The second site is the shape the refusal had while a mark selected dependencies and a source's outward reference was followed.

- **The second site cannot be reached.**
  A reference arrives at `read_document()` carrying the path a normalization produced, and a normalization that walks above its base raises before it returns one. Discovery leaves such a reference as text and `entry()` refuses it, so nothing reaches the walk with a segment the walk refuses. A handler for a case that cannot arrive reads as a case that can.

- **The corpus states the confinement for one spelling.**
  A reference walking above the root with `..` is declared on both sides — refused as an entry, carried inside a source. The positional spellings are declared on the entry side alone: a root-relative path beginning with a slash and a platform-specific drive path each name a local document the root cannot contain, and no fixture says what one inside a source becomes.

## Proposal

The root is the caller's confinement boundary. It binds what the caller asks the tool to carry out, and it does not bind what an author's prose names, so one site raises the refusal and discovery raises nothing.

- **One site raises the code.**
  `cli.entry()` is where an entry reference the root cannot contain is refused: a path that normalizes above the root, a root-relative or drive-path spelling, and a scheme or an authority each fail there with `E_SOURCE_OUTSIDE_ROOT`, named for the entry that asked for them.

- **The read raises what a read can fail on.**
  `cli.read_document()` keeps the refusals a read reaches — a symbolic link below the root, a document that is not there, bytes that are not valid UTF-8 — and carries no handler for a path the root cannot hold. A walk that refuses a segment of a normalized path is an invariant of this tool breaking rather than a defect in a source document, and the command's declared internal-error status is what says so.

- **The corpus states both halves for every positional spelling.**
  The root-confinement family declares the entry that fails beside the source reference that is carried, for the parent segment and for each spelling that names a document positionally.

- **A rule this row does not own keeps the behaviour the build has.**
  A marked resource and a marked direct self-reference are still refused, which `W04` and `W05` retire; a marked link under the root still compiles, which `W02` defers; a reference under the root resolving to nothing still fails as the build fails it, which `W03` states.
