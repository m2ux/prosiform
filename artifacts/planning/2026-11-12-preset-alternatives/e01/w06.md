## Overview

A live run of the agent-pick workflow measures how often an agent resolves a `?` pick from what the bundle and `pf` print, and commits the result as the workflow's baseline.

## Problem

- **The workflow has no measurement.**
  A designed workflow proves the scenarios are well formed; only a live run shows whether agents pick correctly.

## Proposal

**The scene.** `RUNBOOK.md` sets how a live run is planned, run, reviewed and recorded; the user chooses the model and harness for each run.

- **The run.**
  `make eval-diagrams` live for `agent-pick` with the model, harness and session count the user chooses, following `RUNBOOK.md`.
- **The record.**
  The baseline gains the workflow's pass rates; each failing session carries the rubric's disposition.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The sessions and token budget the workflow needs |
| Plan | The run's model, harness, form and arguments, confirmed by the user |
| Implementation | Run `make eval-diagrams` live with those arguments; commit the record |
| Review | Give each failing session the rubric's disposition before committing |
| Test | `make harness` and `make eval-diagrams` |
