## Overview

A live agent-pick run on the skill-entry eval measures whether an agent reaching a `?` pick through a skill keeps to what the bundle and `pf` print. The run commits its own run record, and the epic's bar is that every session passes.

## Problem

- **The measured run was not real use.**
  The earlier agent-pick run started each session from a prompt naming a bundle in a folder of loose sources; every pick was right, and no session of twenty passed.

## Proposal

**The scene.** The skill-entry eval starts every session from a skill the agent's CLI discovers. The real-use shakedown runs one repetition of every cell, agent-pick included, on the harness and model the user names, and records the caps it sets.

- **The runbook section.**
  An Agent-Pick Run section: the shakedown's harness and model, `--workflows agent-pick`, five repetitions, caps from the shakedown's agent-pick cells, and the committed files.
- **The run.**
  `make eval-diagrams` live with those arguments once the user approves the cost cap.
- **The record.**
  The run's report as `agent-pick.json` and `agent-pick.md`, each failing session with the rubric's disposition, and the run's measured cost in the README.

## Work Breakdown

| Part | Description |
