# W07 — Make the Cursor Harness Run and Keep Traces

> Work item · Created 2026-10-31

**Component:** evals/diagram-following/harness

## Overview

The Cursor harness, which crashes on every default run and discards the traces it keeps.

## Problem

`--harness cursor` crashes on every default run: `sections_of` receives a run form where `TRANSITION` is keyed by corpus form, raising `KeyError`. A sub-agent's trace is discarded, because `keep()` globs `trace*` while the instruction tells the sub-agent to write `trace-<section>.log`.

The finding is recorded as findings 1 and 8, one defect from two directions in the [merged-epic review](../../2026-10-31-merged-epic-review/findings.md), with its site and the case that failed.

## Analysis

Two name spaces meet at `sections_of`. The runner names a form by what a session receives — `bundle`, `tree`, `prose`, `linked`, `compiled`, `authored`, `bootstrap`. The corpus names a form by what its tree holds — `diagram`, `prose`, `linked`, `compiled`, `authored`, `bootstrap`. `TRANSITION` is keyed by the corpus names, since it states which form's transition sentences a form's sections are written in. `Workflow.sections` is keyed the same way.

Every other reader crosses the boundary through `FORMS[form]` before it asks the corpus anything: `runnable`, `bundles_of`, `prepare`, `compiled_by` and the prompt table all do. `observable` alone handed the runner's name straight to `sections_of`, and `sections_of` falls back to `TRANSITION[form]` only after finding no such key, so `KeyError: 'bundle'` came out of the run-form name rather than out of any corpus fault.

The crash is reached only where `harness.nested_starts` is false, which is the Cursor harness alone. That is why the Claude matrix runs and the Cursor matrix does not: the guard above the lookup returns early for Claude.

The trace defect is a spelling mismatch with a fixture that hides it. `keep()` globbed `f"{TRACE}*"` — `trace.log*` — which matches `trace.log-review.log` and not `trace-review.log`. The instruction, `instruction-bootstrap.md` and `keep()`'s own docstring all state `trace-<section>.log`, so the file the agent is told to write is the one file the glob cannot match. The test beside it named its fixture `trace.log-review.log`, the spelling the glob happens to accept, so the test passed while the stated behaviour was absent.

## Proposal

- **The repair follows the finding.** `observable` reads the runner's form as the corpus form it carries, once, and passes that name to `sections_of`, `workflow.form` and `dispatched`. `keep` globs `trace*.log`, the pattern the stated name is an instance of, and that pattern is one constant `TRACES` beside `TRACE` in `score.py` so the two cannot drift apart again.
- **The case ships with the fix.** AC15's case builds the default matrix under the Cursor harness and holds that every workflow-form pair the corpus offers is reached; without the repair it raises the recorded `KeyError` before one session is built. AC16's case is a scored run over a dispatching scenario whose stub writes each sub-agent's path under the stated name; without the repair the run keeps one trace where two were written.
- **The stub writes what the instruction asks a session for.** `write_sub_agent_traces` makes the stub agent write one `trace-<section>.log` per start, so a dispatching scenario exercises the stated name rather than a fixture beside it.
- **No other task's area is touched.** The corpus, the scorer's classes, the harnesses' stream readers and the report are unchanged.
