**Component:** work-planner/scripts (new tree on the `skills` orphan branch)

## Overview

The twelve scripts the skill's procedures run, and the seventeen test modules that cover them, arriving on the branch so a procedure runs from the tree it is bundled out of.

## Problem

The example cites `skills/work-planner/scripts/*.py` in thirty-seven places and carries no script. A reader given the example runs nothing, and an agent following a bundled mode reaches a command that does not exist in the tree it was handed.

## Proposal

The scripts are the workspace copy's, arriving with the tests that cover them.

- **Each script arrives at the path its citations name.**
  The branch path is `work-planner/scripts/<name>.py`, which is what the re-rooted citation resolves to.
- **The tests arrive beside them.**
  The test modules keep their `test/` folder under `work-planner/`, because a suite that stays behind is a suite that stops running.
- **The suite runs from the branch root.**
  The branch carries no virtual environment, so the suite runs on the interpreter the caller supplies, and a missing dependency fails the run rather than being skipped.
- **A test that assumed a workspace root is re-rooted.**
  The mode-summary test walks `skills/*/SKILL.md` from a fixed parent, and on the branch the equivalent parent is the branch root.
