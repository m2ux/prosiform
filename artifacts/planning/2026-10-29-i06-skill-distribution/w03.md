**Component:** work-planner (new tree on the `skills` orphan branch)

## Overview

Every citation a procedure carries for a script or a shared document resolves inside the branch, and the branch declares the section contracts the shared checker reads, so the check passes on the tree that readers copy.

## Problem

A procedure cites `skills/work-planner/scripts/x.py` and `skills/scripts/check_skill_files.py`, which are paths from a workspace root. On the branch the first is `work-planner/scripts/x.py` and the second is `scripts/check_skill_files.py`, so every citation has to be re-rooted and none may be left naming a folder above the branch. The checker also reports over a hundred findings against the example, all from the absent `structure.json`.

## Proposal

- **Citations are re-rooted in one pass.**
  A sweep lists every path a document cites, and each becomes its branch-relative form.
- **The shared documents keep their own names.**
  `guidelines.md` and `scripts/check_skill_files.py` sit at the root, so a citation reads `../../guidelines.md` from a mode and `scripts/…` from the root, with no name changing.
- **The branch declares its section contracts.**
  `structure.json` beside the entry point states the sections each directory takes, which is the one thing the checker is missing.
- **The check is the proof.**
  A clean run of the shared checker over the branch is what this task delivers.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Every cited path in the branch, and the checker's findings grouped by the rule they break. |
| Plan | The re-rooting map, and the section contract each directory declares. |
| Implementation | The citations re-rooted and `structure.json` written. |
| Review | No citation naming a path above the branch root. |
| Test | The shared checker reporting no finding, and each cited path resolving to a file. |
