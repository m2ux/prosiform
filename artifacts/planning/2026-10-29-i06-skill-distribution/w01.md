**Component:** work-planner (new tree on the `skills` orphan branch)

## Overview

The interface the branch's root takes, and the first move onto it: every document the example holds, arriving unchanged in content at the path the skill's own citations already name.

## Problem

The skill's documents exist in two variants with no tree that is the skill. The example's are current and reach a script folder it does not carry; the workspace's are older and sit beside scripts a procedure reaches by a workspace-root path.

## Proposal

The branch starts from no history, so its layout is stated once and every later file arrives into it.

- **The root mirrors the workspace's `skills/` folder.**
  `guidelines.md`, `scripts/` and `work-planner/` at the root, because a mode cites `../../guidelines.md` and a procedure cites `skills/scripts/check_skill_files.py` from a workspace root. The branch root is where both resolve.
- **The documents move without a content change.**
  The example's files arrive at their own relative paths under `work-planner/`, so a rule that changes later is separable in history from the move.
- **The branch holds its own record.**
  Its planning folder sits under `artifacts/planning/` at the root, as the engineering branch holds its own.
