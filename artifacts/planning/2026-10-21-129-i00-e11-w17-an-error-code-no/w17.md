**Component:** `checks/tests/test_catalogue.py`

## Overview

Every code of both catalogues is stated by a fixture of the corpus, and one harness check over each severity holds that true.

## Problem

An error code decides a failing run, and a code no manifest names leaves that run to one implementation's own tests.

- **Three error codes are in the catalogue and in no manifest.**
  `E_PUBLICATION_FAILED`, `E_SOURCE_CHANGED` and `E_UNEXPECTED_INTERNAL_ERROR` name a destination that refuses the write, a source that is no longer the source the run read, and a fault that is no source-document defect. Each is a run the contract declares and the corpus says nothing about.

- **The coverage check reads one catalogue.**
  The harness holds the warning catalogue to the corpus and stops there, so an error code added to the design reaches the catalogue and no fixture without anything reporting it.

- **Two of the three runs no source tree can produce.**
  A source that changes during compilation and an unexpected internal error are facts about the run rather than about the documents it reads. A fixture declares a source tree, an invocation and a result, so neither run arises from the declaration alone.

## Proposal

The catalogue reading already covers either severity; what reads it covers one. Closing the gap is a fixture per unreached code and one check over both catalogues.

- **A fixture declares each unreached code.**
  A run told to publish into a directory that does not exist is refused the write and declares `E_PUBLICATION_FAILED` with the publication status the contract names. A run over a source that changes during compilation declares `E_SOURCE_CHANGED`, and a run that fails in itself declares `E_UNEXPECTED_INTERNAL_ERROR`, each stating the status and the diagnostic its clause names.

- **A fixture whose run the declaration cannot produce names the work it awaits.**
  The corpus states the contract in full, so the two fixtures whose runs a source tree cannot state carry `awaiting` and are reported as awaiting that work while the corpus run stays green. The marker is lifted by the change that makes it untrue.

- **The coverage check is one check over each severity.**
  It is parametrized over the catalogues, so a code added to the design under either prefix fails the harness until a fixture states it, and the two statements a catalogue is held to — that it is the design's codes, and that the corpus reaches them — are read together.
