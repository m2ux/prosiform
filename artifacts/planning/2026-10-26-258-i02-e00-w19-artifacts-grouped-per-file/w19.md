**Component:** example/work-planner/artifacts, example/README.md, fixtures/usage-example

## Overview

User ruling: artifacts are grouped at depth 1 with a group heading, so each artifact is one block under `# Artifacts` in a mode bundle, as protocols are under `# Protocols`.

## Problem

- **Artifact sections read as the mode's own.**
  The artifacts declared `group: "artifacts"`, `group-depth: 2` and `group-heading: false`. Every artifact's Operations, Fields and Commands merged into three bundle-wide H2 sections under the entry mode's H1, so 2,850 of the Sync bundle's 3,238 lines read as Sync Mode's own sections.
- **Links jump across the bundle.**
  An operation's link to its own Fields rule crossed about 900 lines, since each artifact's sections were split across three merged sections.

## Proposal

- **Depth 1, heading emitted.**
  Each artifact file declares `group-depth: 1` and drops `group-heading: false`. The group keeps its name `artifacts`, emitted as `# Artifacts`.
- **No link changes.**
  Link destinations in source stay as written; the build resolves them to the new headings.

## Implementation Findings

- **The grouped fixture no longer exercises the overview.**
  At depth 1 no member carries content above the grouping depth, so `every-document-under-a-directory-merged` drops the `Document content above the grouping depth` and `The overview section` clauses and claims `A heading for every member`. Other fixtures still cover both clauses; the uncovered-clause count stays 55.
- **The fixture name is kept.**
  The documents under `artifacts/` still join one declared group. The path is cited by earlier planning records and a parallel task re-records it, so a rename would cost more than the word gains.
- **`example/work-tracker` is out of scope.**
  Its artifacts still declare depth 2 with no group heading; the ruling names the work-planner example.
