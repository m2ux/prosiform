**Component:** example/work-planner/SKILL.md

## Overview

`SKILL.md` is the skill's entry point and is read as written, not compiled. Its Modes list links ten modes, each of which compiles to a bundle carrying every protocol, artifact and reference it reaches. This row tells the reading agent to load each mode through `pf` and removes the rule for reading linked sections by hand.

## Problem

- **Nothing in `SKILL.md` names `pf`.**
  An agent selecting a mode opens the mode file raw and follows its links one by one, so the bundle the example exists to demonstrate is never what the agent reads.

- **A bundle printed to standard output is truncated.**
  Mode bundles run to 200–243 KB, beyond what agent harnesses return from one command.

- **The Linked sections rule describes reading by hand.**
  It instructs how to read heading-linked sections and Prerequisites, which a bundle already resolves and which the tree no longer carries.

## Proposal

- **Mark each mode link with `↳`.**
  A skill-level bootstrap mark the agent acts on; `pf` never sees it, since no mode bundle compiles the Modes list.
- **State the bootstrap in a Bootstrap section before Modes.**
  Run `pf` from the skill's directory on the link's destination, write the bundle to a scratch file, read it whole and follow it.
- **Remove the Linked sections rule.**
- **List Prosiform (`pf`) among the dependencies.**

## Implementation Findings

- **No bundle reaches the changed sections.**
  The only link into `SKILL.md` from the tree is `guidelines.md` to `#conventions`, and no mode reaches it; every mode bundle's line count is unchanged and no usage fixture is re-recorded.
- **The procedure fixture is the bootstrap's output.**
  `pf -o <scratch>/plan.bundle.md modes/plan-mode.md` run from `example/work-planner` writes bytes identical to `a-procedure-and-everything-it-reaches`'s expected output.
