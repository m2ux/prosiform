**Component:** src/prosiform/source.py, src/prosiform/bundle.py, src/prosiform/candidate.py

## Overview

The anchor spellings have one home, and each fence's diagram is read once per parse.

## Problem

Review findings 6 and 7 ([review.md](review.md)): `source.py`, `bundle.py` and `candidate.py` each define `ANCHOR`; a `links` line is JSON-decoded twice per read, and a fence's uses are read about six times per run, by discovery, the budget, the refusals, both emission passes and candidate validation.

## Proposal

- **One spelling.**
  `ANCHOR` and `ENTITY_ANCHOR` are defined in `source.py` alone; `bundle.py` and `candidate.py` import `ANCHOR`. The candidate's `Use` carries no anchor, because it compares resolved destinations (W05).
- **One read per fence.**
  `diagram_links(fence)` reads a fence's links and broken lines once and keeps the result on the fence token's `meta`, so each later caller in the run reads what the first read. A run parses each source once, so each source fence is read once. The bundle's text is parsed apart by candidate validation and by the resource warning, and each of those parses is its own fence.
