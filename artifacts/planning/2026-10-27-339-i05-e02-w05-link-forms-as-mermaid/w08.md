**Component:** fixtures/, checks/render.py

## Overview

Every diagram link form the reader follows is proven end to end: a corpus fixture bundles it, and a render of that fixture's bundle under Mermaid 11.16.0 gives each link one anchor opening its group's heading. The forms out of scope are shown carried as written.

## Problem

The corpus holds fixtures for `click` in a flowchart and a state diagram, the class `link` form and the sequence menus; Gantt, swimlanes, class `click` and the `click` variants across types have none. W04's render ran by hand from its planning record.

## Proposal

- **The matrix.**
  One fixture per diagram type carrying each `click` variant that type's grammar admits, which a probe under Mermaid 11.16.0 decides: flowchart and swimlanes take `href`, no `href`, a tooltip and a target; state takes `href`, and no `href` with a tooltip; class takes `href`, a tooltip and a target; Gantt takes `href` alone. A variant a grammar refuses fails the diagram's parse and is no link to prove.
- **The render check.**
  `checks/render.py` renders each listed fixture's expected bundle with mermaid-cli and holds the rendered anchors to the hrefs the fixture's links take, each naming a heading the bundle carries. The corpus holds the build to that bundle. mermaid-cli and headless Chromium are no dependency of the build, so the check is `make render`, outside `make check`, and `MERMAID_CLI` names the mermaid-cli command line, failing without one.
- **The boundary fixture.**
  One fixture carries a C4 `$link`, a Kanban ticket, an HTML anchor in a node label and a pie chart, each fence carried as written.
