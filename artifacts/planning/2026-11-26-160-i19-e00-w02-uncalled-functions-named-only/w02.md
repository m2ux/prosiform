## Overview

A repository check reads `src/prosiform` and fails on any function or method the package never names and no stated reason reaches from outside it, so a function that loses its last caller reddens the build rather than staying green under its tests.

## Problem

Nothing the repository runs says that a function the package defines has a caller. `ruff` reports only the import a removed test leaves behind, and `mypy` reports nothing, so a module-level function or method with no caller passes every check while its tests keep it upright. The one reading that found such functions was an audit taken for I00:E11:W22's validation record and run nowhere since.

## Proposal

The audit already exists as a procedure: parse each module with `ast`, collect the definitions, and compare them with the names the package writes. Neither `ruff` 0.17.1 nor `mypy` in the locked group carries a rule for an uncalled function, so the reading becomes a check of its own.

- **One standard-library check.** `checks/reachability.py` collects every module-level function and every method under `src/prosiform`, and counts the names the package writes as a `Name`, an `Attribute` or an import alias. A definition is reached when its name is written outside its own body, so recursion alone reaches nothing. `src/tests/` is not read.
- **Reasons read from declarations first.** `[project.scripts]` in `src/pyproject.toml` names the console entry, and a name opening and closing with two underscores is one Python calls. What no declaration states sits in one list in the check, each entry naming what calls it: the two framework hooks the package overrides in `ruamel.yaml`'s scanner and `markdown-it`'s inline parser.
- **The list holds only what it must.** An entry naming a definition the package no longer holds, or one the package already names, fails the check.
- **A target in the set.** `make reachability` joins `CHECKS`, beside a row in `checks.md`'s Python table and `checks/README.md`'s check table.
