**Component:** `src/prosiform/cli.py`

## Overview

A build states the error and warning codes it can emit on its own command surface, and the conformance report holds that set to the one the contract declares. The gap this closes is a build carrying a code the design does not name, or omitting one it does, with no check able to tell.

## Problem

- **A code on an unfixtured path is held to nothing.**
  The harness holds the schema's catalogues to the design's codes and the corpus runner compares each emitted diagnostic's code with its fixture's, so only a code some fixture reaches is observed.
- **A build carrying an undeclared code passes every check.**
  Nothing asks a build which codes it can emit, so the set it carries is never compared with the set the contract declares.
- **A check reading a build's internals would bind that implementation.**
  The corpus and the documented invocation reach the build through configuration and name no module, so a check that imported one would make the contract unmeetable by a second build.

## Proposal

The documented invocation is already held to the build's own help output in both directions, so the command's surface is where a build states what it can produce without a check reading inside it.

- **`--codes` reports the codes a build can emit.**
  An informational run writes every error and warning code the build carries, one per line in sorted order, and returns the success status.
- **Each part of the build owns its own codes.**
  Every module declaring a code publishes it, and the command composes the set it reports, so the reported set is the codes the build holds rather than a list written beside them.
- **The conformance report compares that set with the contract's.**
  The declared-surface listing states, for each code the contract declares, whether the build reports it, and lists each code the build reports that the contract declares nowhere.
- **Both directions are failures.**
  A declared code a build does not report, and a reported code the contract does not declare, each fail the report.
- **The report reads the build the way the corpus does.**
  `PROSIFORM_BUILD` names the build's command line and it is invoked as a subprocess, so the comparison binds every implementation of the contract.
