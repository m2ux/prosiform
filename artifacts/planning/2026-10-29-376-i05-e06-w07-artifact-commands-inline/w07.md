**Component:** example/work-planner/artifacts

## Overview

Every artifact command is an unindented fenced block inside its executing step. Artifacts have no separate Commands section.

## Problem

The W06 authoring scan reports 17 artifact Commands sections and 163 artifact command-placement findings. A caller follows a command name to another section to find its executable form.

## Proposal

Inline each command at every operation step that runs it, carrying the working directory, argument mapping, exit status, output and refusal handling. Preserve the command's behavior, conditions and examples where they clarify the mapping. Retire the separate command sections and update every link to their operation or step. Preserve W06's contract boundaries and the approved placement sample's form.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Inventory artifact command definitions, consumers and authoring findings. |
| Plan | Map each command to its executing step and update links to retired headings. |
| Implementation | Artifact operations and directly affected links; regenerate reached usage-example bundles. |
| Review | Commands visible at each call site, with preserved inputs and refusal handling; independent consumer walkthrough. |
| Test | Zero artifact Commands section and Command placement findings; Inputs/Outputs remain clear; local and bundle anchors; make steps, make links, make corpus and make check. |
