## Overview

The overview refresh rule, which the written page states differently from the protocol that performs it.

## Problem

The architecture overview says a written overview is kept while the protocol rewrites it on every run, so the page and the protocol state different conditions.

The finding is recorded as finding 26 in the [merged-epic review](../../2026-10-31-merged-epic-review/findings.md), with its site and the case that failed.

## Proposal

**The scene.** Each defect above was found by the review of fifteen merged epics, and each has a case that reproduces it. The task repairs one scope area and carries that case, so the defect cannot return unnoticed.

**The design.**

- **The repair follows the finding.** State the condition under which an overview is rewritten, in the page that describes the protocol.
- **The case ships with the fix.** The failing case the finding records becomes a check the repository runs, so a regression fails a target rather than waiting for another review.
- **No other task's area is touched.** Each task repairs one scope and carries its own failing case, so the faults land as separate pull requests.
