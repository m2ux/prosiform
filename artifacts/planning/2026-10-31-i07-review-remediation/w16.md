**Component:** evals/diagram-following/instruction.md

## Overview

The dispatching instructions, which name the sub-agent trace only in the bootstrap form, so a compiled or authored run keeps no sub-agent trace.

## Problem

`instruction-bootstrap.md` tells a dispatched sub-agent to record its states in `trace-<section>.log`, and `instruction.md`, which the compiled and authored forms use, tells it nothing. The runner's `keep()` keeps a trace under that name, so in those forms it keeps nothing, or the sub-agent appends to the dispatching session's `trace.log`. AC16's test passed only because the stub agent writes the sub-agent trace itself.

The finding was raised by the review of the merged I07:E00 work, against AC16 and finding 2 of the [merged-epic review](../../2026-10-31-merged-epic-review/findings.md).

## Proposal

**The scene.** A scored run in the compiled form dispatches a section, and the score reads that section's trace. The trace has to exist because the instruction asked for it, not because a stub wrote it.

**The design.**

- **Every dispatching form states the trace name.** Each instruction a dispatching form uses tells the sub-agent the trace name `keep()` reads.
- **The proof is a real form, not a stub.** The case scores a dispatching scenario in the compiled and the authored form with an agent that writes only what its instruction states.
