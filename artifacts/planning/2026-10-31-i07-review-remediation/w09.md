**Component:** evals/diagram-following/scorer

## Overview

Three outcome faults where a run that did not complete is reported as a result.

## Problem

`sequential_set` passes a record in which the set was split across two messages. A budget-stopped run whose started sessions all errored reports `completed` with a 0% table. `--write-baseline` accepts a run that started nothing and cuts the committed baseline to zero cells.

The finding is recorded as findings 9, 23 and 24 in the [merged-epic review](../../2026-10-31-merged-epic-review/findings.md), with its site and the case that failed.

## Proposal

**The scene.** Each defect above was found by the review of fifteen merged epics, and each has a case that reproduces it. The task repairs one scope area and carries that case, so the defect cannot return unnoticed.

**The design.**

- **The repair follows the finding.** Pass a set only where the opener starts first and every later member starts alongside it; refuse a budget-stopped run whose started sessions all errored; write a baseline only from cells the run measured.
- **The case ships with the fix.** The failing case the finding records becomes a check the repository runs, so a regression fails a target rather than waiting for another review.
- **No other task's area is touched.** Each task repairs one scope and carries its own failing case, so the faults land as separate pull requests.
