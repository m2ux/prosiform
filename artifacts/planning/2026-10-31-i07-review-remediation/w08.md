**Component:** evals/diagram-following/harness

## Overview

The opencode harness, which reports an unobservable question as answered and undercounts a session's spend.

## Problem

The harness returns `done` for every start, so a dispatched question is unobservable and its cell is admitted rather than withheld. The token guard reads only the last step, undercounting a session's spend by all but its final step.

The finding is recorded as findings 6 and 7 in the [merged-epic review](../../2026-10-31-merged-epic-review/findings.md), with its site and the case that failed.

## Proposal

**The scene.** Each defect above was found by the review of fifteen merged epics, and each has a case that reproduces it. The task repairs one scope area and carries that case, so the defect cannot return unnoticed.

**The design.**

- **The repair follows the finding.** Read a state's output text so a question is measurable, and sum every step for a session's spend.
- **The case ships with the fix.** The failing case the finding records becomes a check the repository runs, so a regression fails a target rather than waiting for another review.
- **No other task's area is touched.** Each task repairs one scope and carries its own failing case, so the faults land as separate pull requests.
