## Overview

Two example faults where a mode verifies a criterion twice and the board guard cannot fire.

## Problem

Align Mode calls Record Verified Criteria without the verification evidence it re-runs, verifying one criterion twice in one revision. The board path's evidence-completeness guard can never fire, so a pull request titled without its initiative prefix is invisible.

The finding is recorded as findings 5 and 27 in the [merged-epic review](../../2026-10-31-merged-epic-review/findings.md), with its site and the case that failed.

## Proposal

**The scene.** Each defect above was found by the review of fifteen merged epics, and each has a case that reproduces it. The task repairs one scope area and carries that case, so the defect cannot return unnoticed.

**The design.**

- **The repair follows the finding.** Pass the verification evidence to every operation that requires it, and read a task issue's Development links so a linked pull request absent from the board listing is still an absent record.
- **The case ships with the fix.** The failing case the finding records becomes a check the repository runs, so a regression fails a target rather than waiting for another review.
- **No other task's area is touched.** Each task repairs one scope and carries its own failing case, so the faults land as separate pull requests.

| Part | Description |

| Plan | Settle the repair against the surrounding code, and whether the case belongs in the corpus, the checks or the example, per the scope the disposition table names. |

| Review | Confirm the case fails before the change and passes after, and that no neighbouring behaviour moved. |
| Test | The authoring check's run over that mode passes the evidence; a run over that board treats an unlisted linked pull request as an absent record. |
