**Component:** [`src/prosiform/source.py`](https://github.com/m2ux/prosiform/blob/main/src/prosiform/source.py)

## Overview

Dependency discovery reads an image's alternative content as the run of inline events it is, so a link written there is read where a link written beside the image is.

## Problem

A marked link written inside an image's alternative content reaches the bundle with its mark, and the document it names is not carried.

- **The run that holds the link is never walked.**
  The reference uses of a source are read from the direct children of each inline token. An image holds its alternative content in a run of its own, so a link written there is discovered as no dependency, assigned no destination, and rewritten by nothing.

- **Three statements of the contract are false for this one position.**
  The mark is authoring syntax that never reaches a reader, every local Markdown link in selected content is rewritten to its target's destination, and no published link names a source path. The run publishes the mark as text, names `rules.md` in the bundle, and exits 0.

- **Four readers of one run disagree about what it carries.**
  Discovery, the occurrence count a budget is declared over, the emission's destination list and the candidate comparison each walk an inline run for themselves, and only the emission's own text scan descends into an image. A reading that differs between them is a defect that reaches the bundle or an internal error that stops the run.

## Proposal

An inline token carries a tree of events rather than a list: an image's alternative content is a run of its own, and a use written there is a use its author wrote. The walk that reads a run therefore descends into an image where the image sits, and written order is the order it yields.

- **One walk over a run of inline events.**
  `events` yields each link and image use with the run that carries it and its position in that run, descending into an image's alternative content. The position is what a use opens with, which is where the mark is read, so a nested use is marked on the run it was written in.

- **Every reader of a run reads it through that walk.**
  Discovery takes its destinations and openings from it, the budget counts it, the emission's destination list filters it for marked links, and the candidate comparison builds its own uses from it. One order and one count serve all four, so the destination the emission assigns lands on the span that spells it.

- **An image's own text is what surrounds its uses.**
  The candidate comparison reads an image's alternative content as the text its run shows with each nested link's own text left out, because that text is compared on the nested link's comparison, where the mark the rewrite drops is accounted for.

The fixture `fixtures/reference/a-marked-link-inside-image-alternative-content` already declares the outcome and awaits this row; delivering it lifts that marker.
