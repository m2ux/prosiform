**Component:** main:evals/diagram-following/composition-edges-<harness>.json

## Overview

One live run of the edge workflows per harness carrying a shell, each committed as its own record beside the baseline, so the eval states how agents follow deferred, composed and dispatched bundles.

## Problem

- **The edge scenarios have no committed live measurement.**
  Their build and corpus tests establish the compiled paths; the edge runbook still needs measured results on its selected shell harnesses.

## Proposal

**The scene.** A workflow is a directory under `workflows/`, with `scenarios.toml` naming its inputs, path, sub-agent starts and ordered `pf` runs. A `compiled` session receives the sources, bundle set and build as `pf`, with a shell limited to it. Each scenario passes when its recorded path and commands match that walk.

- **A record of its own.**
  A `run.py` run takes one harness, so each shell harness gets its own run, whose `report.json` is committed as `composition-edges-<harness>.json` and its `report.md` beside it, as `RUNBOOK.md` states (user, 2026-11-03); `baseline.json` and `mvp-proof.json` are untouched.
- **A measurement, not a gate.**
  The run follows the edge runbook in `RUNBOOK.md`. Failing sessions carry the scorer's class and the rubric's disposition; a defect or unclear session stops the run for escalation, and a refused run is not committed.
