**Component:** main:evals/diagram-following/default-matrix-<harness>.json

## Overview

Each harness the eval defines has a committed run of the default matrix from which its sessions' exit statuses are readable, so a crash on any form is a recorded fact rather than an unmeasured possibility.

## Problem

- **One harness's run stands for every harness.**
  The committed baseline was taken on one harness, and the eval's README states that a harness with no committed record has no crash-free evidence of its own.
- **A harness's own confinement decides what it can run.**
  Each harness states the forms it observes, the commands its stream reports and the settings it confines, so one harness's run cannot establish what another does.

## Proposal

**The scene.** A harness states the command a session runs, the forms it observes, the nested starts and commands its stream reports and the settings it confines, and `run.py` takes one harness per run.

- **A run per harness.**
  The default matrix runs on each harness `--harness` accepts, and each run's `report.json` is committed as `default-matrix-<harness>.json` with its `report.md` beside it, as the composition-edge records are, and `baseline.json` untouched.
- **A crash is a recorded exit status.**
  Each session's own exit status is kept in its record, so a run whose sessions all ended without a crash states that from its committed record rather than from a count.
- **A measurement, not a gate.**
  The run follows `RUNBOOK.md`, and each failing session takes the triage rubric's disposition before the record is committed.

| Part | Description |
