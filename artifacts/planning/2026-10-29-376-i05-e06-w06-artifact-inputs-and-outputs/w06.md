**Component:** example/work-planner/artifacts

## Overview

Every artifact operation declares its Inputs and Outputs as one paragraph each of links to the contracts defining those values, or `None`, in the shape of the approved sample `artifacts/placement.md`.

## Problem

117 operations in 30 artifact files carry a prose **Inputs:** line and no **Outputs:** line: 234 findings of the authoring check at `c5056b8b`. An operation's boundary is a sentence to interpret, not a set of values to follow to their definitions. Each operation name also carries emphasis on its verb.

## Proposal

- **Operation names.** Verb first with no emphasis. Stripping the emphasis leaves each heading's anchor as it is; an operation whose words change has every link to it across `example/` updated.
- **Inputs and Outputs.** Each a paragraph of one line after the opening line: comma-separated links, the text naming the value and the target its contract, or `None`.
- **Boundary values only.** A value the operation builds and consumes itself is linked from the step that builds it. Authentication and the workspace path are execution context, not values.
- **Contracts.** A value without a contract gains a `###` under `## Fields` in the file owning its subject; a value another file owns links that file's Fields or Template. Contract prose says what a value is.
- **Conditions.** A condition written into an input's description moves to the step it binds.
- **Fixtures.** Every usage-example bundle the changed files reach is regenerated with the worktree's pf.
