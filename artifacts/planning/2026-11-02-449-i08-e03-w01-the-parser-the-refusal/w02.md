**Component:** main:src/prosiform/cli.py

## Overview

A section entry derives its run's name from the document it names, and the branch that read a referrer goes with the option.

## Problem

One name has two sources, and one of them is the option being removed.

- **`selections` falls back to the referrer.** A reference carrying no path takes the referrer's path, so a run named from a bare fragment got its document from `-f`.
- **`derived_name` and `entered` read the same fallback.** The entry bundle's name and the identity an entry's chain opens on each took the referrer as a base.

## Proposal

**The scene.** `selections` builds each distinct `(path, fragment)` from the requested references, and `run_name` turns each into the name the folder and the entry bundle take.

**The design.**

- **The fallback is removed.** Every entry carries a path, so a selection's path is the reference's own, and `entered` writes each identity against no base.
- **The derived name is unchanged for the spellings that remain.** `guide.md#stop` derives `guide__stop`, the name the same run derives today, so no published folder renames.
- **A run of several sections names them in order.** `pf 'a.md#x' 'a.md#y'` joins the two names with `+`, exactly as two documents do.
