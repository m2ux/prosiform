## Overview

Corpus fixtures built from documents taken unmodified from this workspace's skills.

## Problem

A claim that ordinary Markdown bundles is untested while every fixture is written for the test.

## Proposal

Documents are copied from the workspace's skills into fixtures without alteration, and their expected bundles are recorded. A document needing an edit to bundle is a defect in the build or a gap in the design, not a reason to edit the document.

### The Selection Rule: A Closure of One

A fixture declares the result the contract requires, not the result this build produces. That distinction decides which documents can be fixtures of this family at all.

Recursive bundling traverses every local Markdown link in selected content until the closure is resolved, and a link resolving to nothing fails with `E_TARGET_NOT_FOUND`. Traversal is `I00:E04`. A document carrying a link to a sibling document therefore has two different correct answers: this build publishes a bundle naming a document it does not carry, while the contract either carries that document or refuses the run. An expected bundle written against the first answer is a photograph of an unfinished build, and it would have to be rewritten when `E04` lands.

**A document is eligible for this family when its closure is itself.** That means no local Markdown document reference, and fragment-only references only where the destination the bundle generates is the fragment the source already spells — which holds when the heading the fragment names survives the group's absorption and takes no ordinal. Such a document's expected bundle is the same under this build and under the finished tool, because traversal has nothing to traverse and rewriting has nothing to rewrite.

A document carrying a sibling reference is rejected here and named as waiting on `E04`, not edited, and not declared against today's behaviour.

### How an Expected Bundle Is Justified

An expected bundle produced by running the build and saving the output asserts only that the build does what it does. Three checks are applied to each candidate before it is committed, and each can fail.

- **A complete accounting of the difference from the source.** Whole-document bundling permits exactly seven changes: the leading byte-order mark and frontmatter block removed, the generated entry line and the blank line after it, the generated file heading and the blank line after it, the absorbed title, one level added to each emitted ATX heading, blank runs between document-level blocks normalised to one, and a single terminating newline. The bundle's non-blank lines are compared with the source's non-blank lines globally — in order, each either identical or shifted by one `#` — and every blank run is reported with the content line it follows. A line the seven clauses do not explain is an unaccounted difference and the bundle is refused. This is the check that would catch a dropped reference definition, a reflowed table, a rewritten link or a mangled region, none of which any clause permits.
- **Every destination resolves.** The published bundle is reparsed, its headings walked under the renderer's ordinal rule, and each fragment-only reference in it required to name one of the destinations that walk assigns. No destination may occur twice. The entry line's own link is included in that check, so the line says what the reader finds.
- **A clause-by-clause reading.** The file heading, the escaping, the absorbed title or the shift, the entry line's text and destination, the region boundaries and the frontmatter strip are read against `design.md` for each of the six and recorded in `validation.md` as what was checked rather than that it was checked.

### What the Workspace Does Not Carry

Eight constructs the profile names have no instance anywhere in the eighty-five documents, so no real-source fixture can cover them and the authored fixtures remain their only coverage: double-tilde strikethrough, indented code blocks, thematic breaks, Setext headings, reference-link definitions and reference-style uses, images, ordinary autolinks, and task-list markers outside a code fence. Two more have no instance that is also eligible: a tilde fence occurs in one document only, and that document carries six sibling references; no document combines a shifted group with a heading-like code example. Raw HTML occurs nowhere, so `E_RAW_HTML` has no real-source case, and no document approaches H6, so neither has `E_HEADING_DEPTH_OVERFLOW`.
