**Component:** `checks/runner.py`

## Overview

Two of the contract's failing runs are facts about the run rather than about any document it reads, so no source tree states them and the two fixtures declaring them are marked and unreached. This task gives a manifest a way to name the fault its run meets and the runner a way to perform it, so both fixtures run unmarked against a build that reports each outcome and fail against one that does not.

## Problem

A fixture declares a source tree, an invocation and the expected result, and the runner decides the verdict from those alone.

- **A source that changes during compilation needs something to change it.**
  `E_SOURCE_CHANGED` is raised when the bytes discovery captured are no longer the bytes the path names. A static tree is the same tree at both reads, so the run the contract names never happens.

- **A run that fails in itself is no source-document defect.**
  `E_UNEXPECTED_INTERNAL_ERROR` names the run rather than any document it read, so a source tree provoking one would declare a defect to fix rather than the outcome the contract declares.

- **Two fixtures are marked and nothing runs them.**
  `source-consistency/a-source-that-changes-during-compilation` and `diagnostics/a-run-that-fails-in-itself` carry `awaiting = "I00:E11:W24"`, so the error catalogue's coverage of both codes rests on declarations no run has exercised, and the design's Consistency adversarial family is named by no fixture the corpus runs.

## Proposal

- **The manifest names the fault the run meets.**
  An optional `fault` key names one of the faults the contract declares, so the declaration stays in the fixture beside the result it qualifies rather than in a driver written for one run. A manifest naming none declares a run that meets no fault, which is every other fixture.

- **The runner asks the run for it, as it asks for the root and the diagnostic format.**
  The runner supplies `--fault NAME` beside `--root DIR` and `--diagnostics json`, so one module performs it and nothing else does, and a build is still named by configuration alone.

- **The contract declares the fault, so the corpus stays neutral.**
  `--fault source-changed` writes other bytes to each source the run read, once discovery has read them and before the recheck. `--fault internal` fails the run in itself once the candidate is built and before anything publishes. Both are the run's own, so the detection the fixture observes is the build's real detection rather than a report the corpus asked for.

- **A fixture declaring a fault runs in a copy of itself.**
  A fault that writes to a source tree changes the fixture, so the run happens in a copy and the corpus leaves the repository as it found it.

- **The marker goes with the work, and the family comes with it.**
  Both markers are lifted, and the source-consistency fixture names the Consistency adversarial family among its clauses, which no fixture the corpus runs names today.
