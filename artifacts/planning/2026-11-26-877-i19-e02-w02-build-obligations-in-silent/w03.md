## Overview

The avoided-term rule reads fixture identities beside descriptions, and the fixtures whose identities state an avoided term are renamed.

## Problem

- **Identities state avoided terms.**
  The corpus holds identities such as `the-sibling-once-closure-includes-it`, `a-link-inside-a-contribution-includes-its-target` and `an-html-anchor-*`.
- **An identity is the name a reader meets first.**
  The corpus report and every runner request print it, so it carries the contract's words as much as a description does.

## Proposal

A reader asks the runner for one fixture by its identity.

- **The rule reads identities.**
  Each path segment of a fixture's identity is read as words, and an avoided term among them is reported with the glossary's reason.
- **Offending fixtures are renamed.**
  Each is renamed with the words its description already uses; clause names, which quote the design, stay as they are.
