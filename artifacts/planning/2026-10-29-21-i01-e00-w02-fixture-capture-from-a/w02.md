**Component:** checks/capture.py

## Overview

The capture takes one recorded entry, performs its run over the closure its sources name, and emits the smallest corpus fixture that reproduces the result observed.

## Problem

An entry states a result in words and names the sources the run bundled. A reader reproduces it by hand, so a revision cannot be judged against it, and the skill tree that raised it is too large to be a fixture.

## Proposal

A command under `checks/` reads the entry, materialises the closure from a checkout at the revisions the entry records, and runs the configured build over it. The result of that run is the observed result the reduction is measured against. Each source is then removed in turn and the removal kept only where the run is unchanged, in passes that repeat until one removes nothing, so what the fixture carries is a source set no member of which can go.

The fixture emitted is an ordinary corpus fixture: `source/` holding the reduced tree at its checkout-relative paths, `expected/stdout.md` holding the bytes the observed run produced, and a `manifest.toml` declaring the entry's invocation and that result. The fixture is run through the corpus runner before the directory is put in place, so one that does not reproduce its entry is never emitted. It carries no `awaiting` marker: it enters the corpus with the revision that resolves the entry, which states the result expected in place of the one observed.

Reduction is measured by the suite rather than asserted by the tool: a case runs the emitted fixture through the runner and requires it to pass, and requires the run of each remaining source's removal to differ from the observed result.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | How the entry's closure is materialised at its recorded revisions, and what makes a removal safe |
| Plan | The emitted fixture shape, where the reduction's reference result comes from, and what the manifest declares |
| Implementation | The capture command and the reduction |
| Review | A captured fixture holds no source the result does not need, and no fixture the corpus would carry as failing |
| Test | Reduction tests over recorded entries, each running the emitted fixture through the runner and removing each retained source in turn; the suite under `make harness` |

## Boundaries

AC3 and AC4 only. A tree spanning repositories is refused rather than approximated. The emitted fixture is not placed in `fixtures/`; the session that resolves the entry places it. No build behaviour changes.
