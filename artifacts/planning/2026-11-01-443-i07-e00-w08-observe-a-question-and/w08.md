**Component:** evals/diagram-following/harness.py

## Overview

The opencode harness reads what each sub-agent returned and what every step of a session spent, so a dispatched question is scored as a question and a session's spend is the whole of it.

## Problem

- **A question is unobservable.**
  `Opencode.starts` returns `done` for every start, so a sub-agent that returned a question the session left unanswered reads as answered. A dispatch-question cell is withheld or admitted on a value the harness never read.
- **A session's spend is its last step.**
  `Opencode.result` keeps only the last `step_finish` part, so `tokens` and `cost` report one step of a multi-step session. The run's ledger settles a session for less than it spent, and the budget admits sessions it cannot afford.

## Proposal

**The scene.** opencode 1.19.5 prints a completed `task` call as a `tool_use` part whose `state.output` wraps the sub-agent's final text in `<task id=… state=…>` and `<task_result>` (`<task_error>` on failure). It prints one `step_finish` part per model step, each carrying that step's `tokens` and `cost`.

**The design.**

- **Read the returned text.** A start's return is what the text inside the output's `<task_result>` or `<task_error>` element states, read by the same `said` the other harnesses use. An output with no such element is read whole; a part with no output reads as `done`.
- **Sum the steps.** `Opencode.result` returns one `step_finish` record whose token kinds and cost are each the sum over every step the session printed, so `tokens`, `cost` and the session record carry the session's whole spend unchanged in shape.
