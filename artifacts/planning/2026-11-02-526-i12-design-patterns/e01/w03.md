**Component:** main:docs/patterns/role-interface.md

## Overview

The Role Interface pattern page: an interface shaped around one consumer, rather than a header interface mirroring the whole, realised by section selection and structural ancestors, with a specimen the build compiles and checks.

## Problem

- **The grammar affords it, and nothing names it.**
  Section selection and structural ancestors already behave as an interface shaped around one consumer, but no page tells an author so.
- **An author re-derives it per skill.**
  Without a named pattern, each skill states its own version of the structure as private rules.

## Proposal

**The scene.** The catalogue's template and checks are in place, and the Shared Rule page shows a conforming page and specimen.

**The design.**

- **Paradigm.**
  An interface shaped around one consumer, rather than a header interface mirroring the whole, cited from Fowler, RoleInterface.
- **Grammar.**
  Section selection and structural ancestors, each linked to its documentation section.
- **Specimen.**
  A tree at `docs/patterns/role-interface/`: two consumers, each linking a different section of one shared document.
- **What the bundle shows.**
  Two bundles, each carrying only the section its consumer names, with the ancestors that place it, committed as the specimen's expected bundle set.
- **Principles.**
  The page's `Related` names the SOLID principles it serves: interface segregation.
- **The limit to probe.**
  The page states whether a whole-document link can be flagged where a section link would serve; a limit found is stated under `Limits` and raised as its own issue.
