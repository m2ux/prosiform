## Overview

The Prototype Override pattern page: delegation to a prototype: a new object states how it differs and forwards the rest, realised by section selection, consolidation and placement order, with a specimen the build compiles and checks.

## Problem

- **The grammar affords it, and nothing names it.**
  Section selection, consolidation and placement order already behave as delegation to a prototype, but no page tells an author so.
- **An author re-derives it per skill.**
  Without a named pattern, each skill states its own version of the structure as private rules.

## Proposal

**The scene.** The catalogue's template and checks are in place, and the Shared Rule page shows a conforming page and specimen.

**The design.**

- **Paradigm.**
  Delegation to a prototype: a new object states how it differs and forwards the rest, cited from Lieberman, Using Prototypical Objects to Implement Shared Behavior.
- **Grammar.**
  Section selection, consolidation and placement order, each linked to its documentation section.
- **Specimen.**
  A tree at `docs/patterns/prototype-override/`: a variant writing its own `Verify` section and linking the base's `Prepare` and `Publish` sections.
- **What the bundle shows.**
  The variant's own section and the base sections it links, and not the base's `Verify`, committed as the specimen's expected bundle set.
- **Principles.**
  The page's `Related` names the SOLID principles it serves: open-closed, Liskov substitution.
- **The limit to probe.**
  The page states whether a variant can link every base section it does not override without naming each; a limit found is stated under `Limits` and raised as its own issue.
