## Overview

The Composite Outline pattern page: the composite: parts and wholes treated alike, each whole built from its composed parts, realised by leaves-up placement of each file's `group` pair, and nested grouping, with a specimen the build compiles and checks.

## Problem

- **The grammar affords it, and nothing names it.**
  Leaves-up placement of each file's `group` pair, and nested grouping already behave as the composite, but no page tells an author so.
- **An author re-derives it per skill.**
  Without a named pattern, each skill states its own version of the structure as private rules.

## Proposal

**The scene.** The catalogue's template and checks are in place, and the Shared Rule page shows a conforming page and specimen.

**The design.**

- **Paradigm.**
  The composite: parts and wholes treated alike, each whole built from its composed parts, cited from Gamma et al., Design Patterns (Composite).
- **Grammar.**
  Leaves-up placement of each file's `group` pair, and nested grouping, each linked to its documentation section.
- **Specimen.**
  A tree at `docs/patterns/composite-outline/`: a parent linking a child that links a grandchild, each declaring a `group` pair.
- **What the bundle shows.**
  The grandchild inside the child's result, inside the parent's, committed as the specimen's expected bundle set.
- **Principles.**
  The page's `Related` names the SOLID principles it serves: single responsibility, open-closed.
- **The limit to probe.**
  The page states whether a whole can be selected as a part by one reference; a limit found is stated under `Limits` and raised as its own issue.
