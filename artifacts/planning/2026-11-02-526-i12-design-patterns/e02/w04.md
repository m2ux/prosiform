## Overview

The Hook Section pattern page: the template method: a fixed skeleton whose hook steps a variant fills, realised by a section-keyed `subst`, which takes precedence over a document key, with a specimen the build compiles and checks.

## Problem

- **The grammar affords it, and nothing names it.**
  A section-keyed `subst`, which takes precedence over a document key already behave as the template method, but no page tells an author so.
- **An author re-derives it per skill.**
  Without a named pattern, each skill states its own version of the structure as private rules.

## Proposal

**The scene.** The catalogue's template and checks are in place, and the Shared Rule page shows a conforming page and specimen.

**The design.**

- **Paradigm.**
  The template method: a fixed skeleton whose hook steps a variant fills, cited from Gamma et al., Design Patterns (Template Method).
- **Grammar.**
  A section-keyed `subst`, which takes precedence over a document key, each linked to its documentation section.
- **Specimen.**
  A tree at `docs/patterns/hook-section/`: a base procedure whose steps link hook sections of one document, and a preset redirecting one hook.
- **What the bundle shows.**
  The replacement for the redirected hook and the base's own section for every other, committed as the specimen's expected bundle set.
- **Principles.**
  The page's `Related` names the SOLID principles it serves: open-closed.
- **The limit to probe.**
  The page states whether a base can mark which of its sections are hooks; a limit found is stated under `Limits` and raised as its own issue.
