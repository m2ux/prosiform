## Overview

The Null Object pattern page: a null object: a do-nothing stand-in with the same interface, in place of a conditional, realised by a section-keyed `subst` to a section stating no action, with a specimen the build compiles and checks.

## Problem

- **The grammar affords it, and nothing names it.**
  A section-keyed `subst` to a section stating no action already behave as a null object, but no page tells an author so.
- **An author re-derives it per skill.**
  Without a named pattern, each skill states its own version of the structure as private rules.

## Proposal

**The scene.** The catalogue's template and checks are in place, and the Shared Rule page shows a conforming page and specimen.

**The design.**

- **Paradigm.**
  A null object: a do-nothing stand-in with the same interface, in place of a conditional, cited from Woolf, Null Object.
- **Grammar.**
  A section-keyed `subst` to a section stating no action, each linked to its documentation section.
- **Specimen.**
  A tree at `docs/patterns/null-object/`: a procedure whose audit step links a hook, and a `lite` preset substituting a section that states no audit runs.
- **What the bundle shows.**
  The audit step's link reaching the no-op section, committed as the specimen's expected bundle set.
- **Principles.**
  The page's `Related` names the SOLID principles it serves: Liskov substitution.
- **The limit to probe.**
  The page states whether a stand-in carrying the heading alone is accepted; a limit found is stated under `Limits` and raised as its own issue.
