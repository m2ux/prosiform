## Overview

The Test Double pattern page: a test double installed in place of a real component so a test can run, and the test adapter of ports and adapters, realised by `subst` in a test preset, and the warning that reports each redirect, with a specimen the build compiles and checks.

## Problem

- **The grammar affords it, and nothing names it.**
  `subst` in a test preset, and the warning that reports each redirect already behave as a test double installed in place of a real component so a test can run, but no page tells an author so.
- **An author re-derives it per skill.**
  Without a named pattern, each skill states its own version of the structure as private rules.

## Proposal

**The scene.** The catalogue's template and checks are in place, and the Shared Rule page shows a conforming page and specimen.

**The design.**

- **Paradigm.**
  A test double installed in place of a real component so a test can run, and the test adapter of ports and adapters, cited from Meszaros, xUnit Test Patterns; Fowler, TestDouble.
- **Grammar.**
  `subst` in a test preset, and the warning that reports each redirect, each linked to its documentation section.
- **Specimen.**
  A tree at `docs/patterns/test-double/`: a mode linking a tracker document of side-effecting operations, and a `test` preset substituting a stub tracker.
- **What the bundle shows.**
  The stub in place of the tracker, committed as the specimen's expected bundle set.
- **Principles.**
  The page's `Related` names the SOLID principles it serves: dependency inversion.
- **The limit to probe.**
  The page states whether a run can assert that a redirect happened, as a spy would; a limit found is stated under `Limits` and raised as its own issue.
