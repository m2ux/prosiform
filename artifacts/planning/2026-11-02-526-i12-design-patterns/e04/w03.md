## Overview

The Dispatched Command pattern page: a request reified as a command, and an actor that shares no state and answers only through messages, realised by the dispatch operator, its dispatch sub-section and the Prosiform section, with a specimen the build compiles and checks.

## Problem

- **The grammar affords it, and nothing names it.**
  The dispatch operator, its dispatch sub-section and the Prosiform section already behave as a request reified as a command, but no page tells an author so.
- **An author re-derives it per skill.**
  Without a named pattern, each skill states its own version of the structure as private rules.

## Proposal

**The scene.** The catalogue's template and checks are in place, and the Shared Rule page shows a conforming page and specimen.

**The design.**

- **Paradigm.**
  A request reified as a command, and an actor that shares no state and answers only through messages, cited from Gamma et al., Design Patterns (Command); Hewitt et al., A Universal Modular Actor Formalism.
- **Grammar.**
  The dispatch operator, its dispatch sub-section and the Prosiform section, each linked to its documentation section.
- **Specimen.**
  A tree at `docs/patterns/dispatched-command/`: a mode dispatching a review procedure.
- **What the bundle shows.**
  An entry bundle with a dispatch sub-section naming the review's own bundle, which the set also holds, committed as the specimen's expected bundle set.
- **Principles.**
  The page's `Related` names the SOLID principles it serves: single responsibility, interface segregation.
- **The limit to probe.**
  The page states whether a dispatched bundle can state the report it returns; a limit found is stated under `Limits` and raised as its own issue.
