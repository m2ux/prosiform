**Component:** main:docs/patterns/README.md

## Overview

The catalogue's index: what a pattern page is, the SOLID map from each principle to the grammar that serves it, and one section per family that its epic fills.

## Problem

- **The principles have no grammar map.**
  An author applying single responsibility or dependency inversion to a skill has no page naming the feature that does it.
- **Four families need one entry point.**
  Without an index, pages are found by listing a folder.

## Proposal

**The scene.** The grammar is as the argument-surface and grouping work leaves it: declaration, section selection, consolidation, groups, presets, `subst`, operators, diagram links and section composition.

**The design.**

- **The SOLID map.**
  One subsection per principle, each stating it as Martin's 2020 module form does and naming the grammar features that serve it, each linked to its documentation section.
- **One section per family.**
  Structure and contracts; polymorphism and substitution; composition and reuse; flow, concurrency and staging. Each states its intent; its table of patterns, with a `Principles` column naming the SOLID principles each page serves, is added by its family's work.
- **The map reads both ways.**
  The SOLID map names the grammar features per principle and points at the family tables' `Principles` column for the pages; no family edits the map.
- **The template, stated once.**
  The section names a pattern page carries, linking the page check as their one enforcement.
- **The index declares `prosiform`.**
  So `pf docs/patterns/README.md` compiles it, as the bundle check requires.
