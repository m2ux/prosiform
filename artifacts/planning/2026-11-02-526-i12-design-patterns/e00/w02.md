**Component:** main:checks/pattern-bundles.py

## Overview

The check that compiles every pattern page and every specimen with the build under test, and fails when a specimen's bundle set differs from the one committed beside it.

## Problem

- **A page's claim is a bundle shape.**
  Each pattern shows what a tree compiles to; with no compilation behind it, that claim survives a grammar change that falsifies it.
- **The corpus is the contract, not usage.**
  `make corpus` holds the behavioural contract; a specimen states how an author uses that behaviour and belongs with its page, not among the fixtures.

## Proposal

**The scene.** A specimen is a tree at `docs/patterns/<pattern>/`, its entry named in the page's `Specimen` section, its expected bundle set committed beside it.

**The design.**

- **Every page compiles.**
  `pf` runs on each pattern page, the index included; a refused page fails the check.
- **Every specimen compiles to what is committed.**
  The check runs the specimen's entry into a fresh folder and compares the bundle set file by file; a difference fails, naming the specimen, the file and the first differing line.
- **The build under test is the corpus's.**
  The check uses the build `make corpus` uses, so both read one configuration.
- **Expected bundles are not authored documents.**
  The committed set sits where `make links` and the page check do not read it as a source, or is declared so.
- **An intended build change re-records in one command.**
  A re-record mode writes each specimen's current compilation as its expected set, so a deliberate change to what the build emits updates every specimen at once and the diff shows what moved.
- **One target.**
  `make pattern-bundles` runs it, `make check` runs that, and `checks.md` documents it.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Read how `make corpus` chooses the build and compares outputs; read how `make links` enumerates documents. |
| Plan | Fix the specimen layout, the expected set's location and its exemption from the link check. |
| Implementation | Write the check, its make target, its `make check` entry and its `checks.md` row. |
| Review | An altered expected bundle fails with the specimen, file and line; an unaltered one passes. |
| Test | The check's own tests over a matching and an altered specimen; `make links`; `make check`. |
