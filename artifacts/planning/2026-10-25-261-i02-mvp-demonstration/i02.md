## Overview

The feature set prosiform already delivers is demonstrated end to end on a worked example the size its users write, within three days of this initiative opening. The demonstration is one repeatable run against a tree holding the routing document, the modes, the artifacts and the protocols an agent-engineering skill carries, and the bundle that run publishes resolves every link it emits. The goal the reviews test against is that the repository's own checks pass on the revision demonstrated, and that a reader of the example can repeat the run without the session that produced it.

## Problem

The delivered feature set has no demonstration a reader can observe, and the tree that would carry one is a fraction of the shape its users write.

- **The example is four files and cannot show the constructs that were built.**
  `example/work-tracker` holds one routing document, one mode and two artifacts. Nothing in it reaches a protocol, a second mode, or a folder holding more than two members.

- **The migration is planned beside twenty-six rows of non-demonstration work.**
  The refinement initiative holds findings, specification revision, repository checks, branch configuration and a freeze. Each of those rows stays open while the migration waits behind it, so the example's growth is gated by work no demonstration needs.

- **A demonstration with no fixed revision cannot be repeated.**
  The refinement stage holds no tagged revision until its freeze, so a demonstration pointed at a branch tip is a different run each day.

- **The feature set is proven by a corpus and not by the example.**
  The corpus passes and the example's fixtures are green, but the two are separate instruments. Nothing reads the example as the demonstration it is documented to be.

## Proposal

- **One run demonstrates the set.**
  A bundled entry of the example is the demonstration artifact, and the command that produces it is published beside the example.

- **The tree grows to the shape its users write.**
  The example receives the routing document, the modes, the artifacts, the protocols and the reference those documents already link to, so a bundle of it shows grouped folders and a mode reached from another document.

- **Every file supplies its own conversion settings.**
  Root, group and group depth are declared per file, so a bundle composes the folders rather than leaving their links authored.

- **The example publishes one bundle per mode.**
  The tree exceeds the default output budget as a whole, so each mode is a documented entry and the fixtures record what each produces.

- **The demonstration rests on a fixed revision.**
  The revision demonstrated is tagged, and the corpus run and the checks are read against that revision rather than against whatever the branch holds on the day.

- **What the pass defers is recorded where it lands.**
  Work the demonstration meets but does not need takes a row in a final epic rather than widening the epic in hand or standing loose.

## Acceptance Criteria

- [ ] **AC1.** The example carries a tree of the shape its users write, with a routing document, more than one mode, an artifacts folder and a protocols folder, as a file listing of the example and a bundle of one of its modes show.
- [ ] **AC2.** Every file under the example declares the conversion settings its links resolve under, and no link in a bundle of any mode is left authored, as the bundle of each mode reports.
- [ ] **AC3.** The example's bundles are published and its fixtures record them, as the corpus run reports against the example tree.
- [ ] **AC4.** The revision demonstrated is named, and both the corpus run and the repository's checks pass against it, as the tag and the runs on that revision show.
- [ ] **AC5.** A reader can reproduce the demonstration from the example's own documentation, without the session that produced it, as the documented commands run against the example show.
- [ ] **AC6.** The technical debt this initiative's delivery defers is fixed, as the Done column of its final epic's Work Breakdown shows.

## Non-Goals

- It does not make the skill the example is copied from compatible with the compiler.
- It does not implement a production build.
- It does not add a compiler feature the delivered feature set does not already have.
- It does not settle the specification or freeze it.
- It does not change the corpus contract to accommodate the example; a fixture that changes states a decision.
- It does not protect the repository's branches or configure its platform settings.
- It does not open an issue or a pull request on another project.
