## Overview

A demonstration is only a demonstration if it can be repeated on a named revision. This epic supplies the ground the example's growth does not: one tagged revision, one published command that produces the demonstration artifact, and the repository's checks held green against that revision rather than against a branch that moves.

## Problem

The example's growth makes the tree demonstrable, and nothing yet makes the demonstration repeatable.

- **The tree moves under any run pointed at a branch.**
  The example is edited by the migration itself, so a run read against a branch tip is a different run on each day of the three.

- **The checks and the demonstration are separate instruments.**
  `make check` reads the build, the corpus and the repository's documents. Nothing ties a passing check to the revision the demonstration was actually taken on.

- **A demonstrated command that is not published cannot be reproduced.**
  The example's documentation names the invocations it publishes, and a demonstration of a command those pages do not carry is reproducible only from the session that ran it.

- **A demonstration has no defined success.**
  Without a stated set of constructs the run must show, a bundle that shows fewer of them passes for a demonstration of what was built.

## Proposal

- **The revision demonstrated takes a tag.**
  The example and the build it is bundled by are tagged together, so the demonstration names one revision and the checks are read against that same one.

- **One command produces the demonstration artifact.**
  The documented invocation for the chosen mode is the demonstration, and it is published in the example's documentation beside the tree it reads.

- **The demonstration has a stated content.**
  The constructs the run must show are declared, and the artifact is read against them rather than accepted for being non-empty.

- **The checks and the corpus are read on the tagged revision.**
  A demonstration whose revision fails the repository's checks is not a demonstration of a delivered feature set.

## Acceptance Criteria

- [ ] **AC1.** One tag names the revision demonstrated, and the tag resolves to a commit carrying both the example tree and the build that bundles it, as the tag's commit shows.
- [ ] **AC2.** The demonstration's command is published in the example's documentation with the entry it reads and the output it writes, as the documented command run against the example shows.
- [ ] **AC3.** The published command reproduces the demonstration artifact byte for byte on a second run, as two runs from the published documentation show.
- [ ] **AC4.** The demonstration artifact shows each declared construct, as a read of the artifact against the declared set shows.
- [ ] **AC5.** The repository's checks and the corpus run pass on the tagged revision, as the checks and the corpus run at that tag show.
