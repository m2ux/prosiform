## Overview

A diagram link reads its operator from the text of the element it is drawn on, as a Markdown link reads its operator from its text, and its quoted tooltip is its title alone. An element carries one diagram link.

## Problem

- **A tooltip is both operator and title.**
  The marks opening a `click` or class diagram `link` tooltip state its operator, and the rest of the tooltip is its title, so prose opening with a mark becomes an operator and prose after one becomes preset tags.
- **The reader's text and the compiled operator live apart.**
  The node text a reader sees carries nothing `pf` reads, so an author restates the operator there and the two can disagree.
- **A rendered diagram opens one link per element.**
  Mermaid keeps the last link and tooltip it reads for a node or class, while `pf` follows every `click` line naming it.

## Proposal

- **The element text is the link text.**
  A flowchart node's text is the text its last shape writes, between the shape's brackets or as the `label` of its `@{…}` metadata, quoted text read without its quotes and a Markdown string without its backticks. A class's text is the label its `class` statement declares, as `class Judge["⇉ Judge"]`. The marks opening that text state the link's operator as a Markdown link's text does, the same combinations accepted and refused.
- **Elements drawn without text carry no operator.**
  A node no shape gives text, and a class declaring no label, are drawn with their names, which are identifiers rather than text, so a link on one carries no operator. An element of any other diagram, a Gantt task or a state among them, is read for no text and carries none.
- **The tooltip is the title.**
  The quoted tooltip as written is the title, its tags selecting presets, the pick token among them. It states no operator, so a tooltip tag stating operator marks, as `"⇉"` or the `⇉` of `"⇉, checks"`, fails with `E_UNSUPPORTED_CONSTRUCT` naming the line, its remedy writing the marks at the start of the element's text, rather than compiling silently as a preset name no document declares. A link with no tooltip has no title and selects `default` alone. A deferral carrying no tooltip publishes the run's names as a tooltip of their own after its destination.
- **An element carries one link.**
  A second `click` or class diagram `link` naming an element an earlier line names fails with `E_UNSUPPORTED_CONSTRUCT`, naming its own line as the diagnostic's source and the earlier one in the message, wherever either points.
- **The tooltip operator rule is retired.**
  The tooltip reader in `marks` is removed, its fixtures rework to element text, and the documents and design state the element-text rule alone.

## Settled Question

- **Elements drawn without text.**
  A class diagram `link`, and a `click` in a class diagram, read the class's declared label; a class declaring none carries no operator, its name being the identifier the line names. A flowchart node with no shape text carries none the same way. Shown by `fixtures/reference/a-class-diagram-link-reads-its-class-label-and-a-class-with-none-carries-no-operator`.
