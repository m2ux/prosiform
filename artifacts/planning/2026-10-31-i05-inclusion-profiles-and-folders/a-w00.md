**Component:** artifacts/planning/2026-10-17-prosiform-v1/design.md

## Overview

The clause that makes inclusion a property of the target document, the codes the change retires, and the pin that lets a fixture name the clause.

## Problem

`make conformance` reads the design at the revision [README.md](https://github.com/m2ux/prosiform/blob/main/README.md) pins and refuses a declaration naming no clause it carries. The clause does not exist, and three pieces of the contract currently state the opposite of what this epic delivers.

## Proposal

**The scene.** The pinned design states at *Link classification and resource handling* that a reference is a dependency when it "resolves to a Markdown file under its authoring source's effective root", and at *Conversion metadata* that `prosiform` admits "`root`, `group` and `group-depth`" and "a key outside them fails with `E_INVALID_CONVERSION_METADATA`". Both clauses are read by fixtures across the corpus.

**The design.**

- **One clause, stated where the root's clause stands.** The root's three statements are replaced by one clause: a local Markdown link under the invocation working directory is a dependency when its target declares `prosiform`, a target that declares nothing is text, and a document's boundary is the deepest directory holding every local Markdown path its own links name.
- **The key set narrows rather than widens.** `root` leaves the admitted keys and joins the refused ones, carrying the code the unknown-key refusal already carries. `E_ROOT_NOT_FOUND` leaves the code catalogue; `E_SOURCE_OUTSIDE_ROOT` keeps its row and its meaning is stated as the path forms no grammar admits.
- **The retired code is recorded rather than deleted quietly.** `make conformance` compares the codes the contract declares against the codes the build reports for itself, so a code removed from one and left in the other fails the check; the clause states the retirement so the comparison has a fact to read.
- **`E_TARGET_NOT_FOUND` keeps its row and narrows its reach.** The clause states the two shapes that still reach it — a link an operator marks, and a fragment-only link — so the corpus rows citing it name the clause that still states it.
- **One pin moves for every clause in this initiative.**
  Conformance reads the design at the committed revision `README.md` pins, so a clause has to exist there before a fixture can name it. Seven epics each amending the design and moving the pin would serialise seven pull requests on one commit. This row instead amends the design for itself and is the only row that moves the pin: the other six amendments land beside it, and the pin names the revision carrying all seven. Conformance reads the design at the pinned commit, so the amendment exists on `engineering` before the pin can name it.
