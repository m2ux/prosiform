**Component:** checks/mock_scenarios.py

## Overview

Each scenario `make mock-scenarios` runs states its stand-in as a `path-sub` entry in the copied document that writes the link, and passes no command-line pair.

## Problem

The scenarios rest on the retired option.

- **Each scenario passes `-m`.** The plan-mode artifact stub and the conventions stub are named on the command line, so the scenarios fail once the option is gone.
- **The stubs declare `root`.** `ARTIFACT_STUB` and `CONVENTIONS_STUB` carry `root:`, which [I08:E00](https://github.com/m2ux/prosiform/issues/434) refuses.
- **A pair reaches only its own document's links.** A link to `artifacts/epic.md` or `conventions.md` is written by documents inside the skill, so the stand-in is reached by a preset on each copied document that writes it.

## Proposal

**The scene.** The check copies `example/work-planner` into a temporary directory, writes the stubs beside the copy, and bundles the copied mode.

**The design.**

- **The preset goes into the copy.** For each scenario the check adds a `path-sub` entry to the `default` preset of every copied document that writes the stubbed link. The shipped tree is never edited, which the fingerprint either side of the run already proves.
- **The stubs declare `prosiform` without a root.**
- **The expectation is unchanged.** Each mocked bundle is still held to the unmocked bundle reached in the same copy.
