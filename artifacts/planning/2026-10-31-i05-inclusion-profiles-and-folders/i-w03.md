**Component:** checks/authoring.py

## Overview

The checks that read a declaration read the preset shape, and none reads a retired field.

## Problem

Two checks hold the example tree to fields that no longer exist.

- **`checks/authoring.py` reads a declared root.** `DECLARED_ROOT` parses `  root: "..."` and `link_form` refuses a link resolving from the declared root. Declared Inclusion removed the root reader and left the group reader, which reads the same field this epic rewrites.
- **`checks/smoke.py` writes a root.** Its source carries `prosiform: {root: "."}`, which fails the run that installs the build, so `make smoke` fails the moment the refusal lands.
- **A check reading a retired field passes over a tree it does not understand.** The tree migrates to presets, and a reader expecting `root` finds nothing and reports nothing.
- **The checks are what hold the tree.** If they do not read the shape the tree declares, the migration is unverified by them.

## Proposal

**The scene.** `checks/authoring.py` holds the example tree to its authoring rules, and `checks/smoke.py` bundles a tree it writes itself.

**The design.**

- **`authoring.py` reads the preset shape.** A group is read from a preset's `group-depth` entry, and a tree declaring `group` or `root` is reported by the check rather than by a run.
- **`smoke.py` declares without a root.** Its source carries a `prosiform` block stating inclusion and no field, so the installed command bundles it as it does today.
- **The retired-option assertion is restated.** `smoke.py` asserts that the root option is invalid usage; that assertion follows whatever the option table says rather than naming a field.
- **No check reads a field the build refuses.** A corpus-wide pass over `checks/` confirms it, so a later field removal cannot leave a reader behind.
