**Component:** main:checks/smoke.py

## Overview

The checks that read a declaration read the preset shape, and none reads a retired field.

## Problem

A check reading a retired field passes over a tree it does not understand.

- **`checks/smoke.py` bundles a tree it writes itself.**
  Its source and its retired-option assertion must state the fields the build accepts.
- **The trees migrate to presets.**
  A reader expecting a flat field finds nothing and reports nothing, so the migration is unverified by it.

## Proposal

**The scene.** `checks/smoke.py` installs the build and bundles a tree it writes, and the other checks read frontmatter where they hold a document to a rule.

**The design.**

- **`smoke.py` declares without a setting.**
  Its source carries a `prosiform` block stating inclusion and no field, so the installed command bundles it.
- **The retired-option assertion follows the option table.**
  It asserts what the option table says rather than naming a field.
- **No check reads a field the build refuses.**
  A pass over `checks/` confirms it, so a later field removal cannot leave a reader behind.
