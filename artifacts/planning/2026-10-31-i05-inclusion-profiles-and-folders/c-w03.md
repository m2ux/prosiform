**Component:** src/prosiform/cli.py

## Overview

A folder key that answered a reference at a path the substitute folder does not hold fails the run, and a folder key that answered nothing warns. Both name the key rather than the folder alone.

## Problem

Two outcomes turn on a key's reach.

- **An absent substitute is new.** `Substitution` redirects to a path; with a folder key the path is derived from a reference rather than written by the author, so the run is reading a document nobody named directly and its absence is nobody's obvious mistake.
- **The absence is known where the reference is resolved.** `key` answers the substitute reference and the caller then probes it, so the absence is visible before any source is read and can be refused as the command-line fault it is.
- **A folder key's use is one fact.** The used-key set records a document key when it answers a reference; a folder key answers many, and the set should hold the key once rather than once per reference.

## Proposal

**The scene.** `substitution(options)` folds the pairs; `Substitution` answers lookups; `compiled` reads `W_MOCK_UNUSED` for each key the run never used.

**The design.**

- **The absent substitute is refused where the reference is resolved.** When the folder lookup answers and the probe finds no file at the substitute path, the run fails with `E_TARGET_NOT_FOUND`, exit status `1`, naming three things: the reference as its author wrote it, the folder key, and the path the redirect resolved to.
- **A document key keeps its shape.** A document key naming a path the run does not hold is already compiled and refused where the substitution is applied, so the folder key's message is stated with the three parts and the document key's message is left as it is.
- **The used set holds a folder key once.** It is recorded at the first reference the key answers, so `W_MOCK_UNUSED`'s absence states that the folder was reached and not how often.
- **The warning's wording covers a folder.** `W_MOCK_UNUSED` names a key no reference named; the message states the key in the form the author wrote it, with its separator, so a command line carrying both a document key and a folder key is told which one matched nothing.
- **A folder key matching only text references is unused.** A reference whose target declares nothing is text rather than a dependency, so a folder that redirects only silent documents answers no compiled reference. It warns, and the warning is the fact the author needs.
