## Overview

E09's redirected-referrer criterion is marked superseded and its fixture withdrawn, so that epic records a capability the tool no longer has as history rather than as a claim.

## Problem

A delivered epic asserts what this removal takes away.

- **AC13 is ticked.** It states that a referrer `-f` names is redirected and that a fragment-only entry resolves against the substitute, delivered in PR #438 and covered by `fixtures/mock/a-redirected-referrer-carries-its-entry`.
- **No referrer survives.** With the option removed there is no value to redirect, so the criterion asserts a shape the build cannot express.
- **The fixture tests nothing reachable.** It passes the removed option, so the corpus would fail on it rather than pass over it.
- **E09 already carries superseded criteria.** AC6, AC11 and AC20 are marked for `root`'s retirement, and this is the same pattern for a different capability.

## Proposal

**The scene.** E09's epic body holds a *Supersession* section stating which criteria a later epic voided, and each such criterion carries a note linking to it.

**The design.**

- **AC13 joins the superseded set.** It keeps its tick, because the work that delivered it landed, and gains a note pointing at a paragraph stating why the capability is gone.
- **The paragraph names this epic.** It states that `-f` was removed and that the redirection AC13 describes has no subject.
- **The fixture is withdrawn by this epic's corpus row.** It is not rewritten, because there is no spelling that reaches the same behaviour.
- **The row is not renumbered.** AC13 keeps its number, as AC6, AC11 and AC20 did, so a pull request naming it still resolves.
