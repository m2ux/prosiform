## Overview

The clause that admits a folder pairing in the substitution mapping, its precedence against the exact keys, and its two outcomes.

## Problem

The mapping clause states one pairing shape.

- **A key is an identity.** The substitution clause states that "a key is the identity a reference normalizes to", which states a file and a section and no folder.
- **Two shapes of key would be two rules.** A folder key asks a different question — is this reference under that directory — so the clause has to state the precedence between the two rather than leave it to whichever a reading happens to implement.
- **The two outcomes are stated for one shape only.** An unmatched key warns, and a substitute naming no document is refused. A folder key raises the same two questions with one more: a folder that holds the reference but not the substitute.

## Proposal

**The scene.** The substitution clause states the pairing, the matching rule, the reach and the four refused shapes.

**The design.**

- **One clause, amended where the matching rule stands.** A side ending in a path separator makes its entry a folder pairing, and both sides carry the separator or neither does.
- **The precedence is stated in one sentence.** An exact key answers before a folder key, a section key before either, and of two folder keys holding one reference the longer is the key.
- **The remainder is the identity.** A folder key redirects a reference to the path with the same remainder under the substitute folder, keeping the section the reference named.
- **Two more refused and reported shapes.** A half-folder pairing is invalid usage; a folder key whose substitute path holds no document fails with `E_TARGET_NOT_FOUND`. A folder key no reference touched warns as any unmatched key does.
- **The pin moves after the clause merges.**
