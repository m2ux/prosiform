**Component:** src/prosiform/cli.py

## Overview

The parser declares no referrer, a bare `#section` is refused as a usage error naming the remedy, and `entry` is reached for positional references alone.

## Problem

The option, its refusal and its plumbing sit in one file.

- **The parser declares it.** `cli.parser()` adds `-f` with `dest="referrer"`, and the help output states it.
- **`execute` refuses a bare fragment when it is absent.** A loop over the requested references raises a usage failure naming `-f` whenever a reference carries no path.
- **The referrer is resolved and chained.** `entry(options.referrer)` builds a `Reference` whose chain is seeded, and that value is passed to `selections`, `run_name` and `compiled`.
- **`selections` reads it.** A reference carrying no path falls back to the referrer's path, which is the branch that goes with the option.

## Proposal

**The scene.** `execute` normalises the command line's references through `entry`, resolves the referrer, and passes both to the run.

**The design.**

- **The option is removed.** `parser()` declares no `-f`, and `diagnostic_format` no longer walks its value.
- **A bare `#section` is a usage error naming the remedy.** The refusal states `document#fragment` as the spelling to write, exits `2`, and replaces the current message that names `-f`.
- **`entry` stays and is reached for positions alone.** It already normalises a positional with parent bootstrap permitted and refuses an external or drive path, and none of that changes.
- **No referrer value exists to thread.** `selections`, `run_name` and `compiled` lose the parameter, so the fragment-falls-back-to-referrer branch goes with it.
- **The link form never reaches this file.** A fragment-only link inside a document is resolved by `closure.inside` against the document that carries it, which no command-line option touches.
