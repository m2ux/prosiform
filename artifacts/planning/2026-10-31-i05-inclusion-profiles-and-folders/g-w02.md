**Component:** src/prosiform/limits.py

## Overview

Each ceiling gains a name and loses its option letter. `BUDGETS` stays the one table, so a ceiling's name, default and counting rule are written once.

## Problem

The table holds an option that ceases to exist.

- **`Budget.option` is a letter.** `Budget("-F", "max_files", 256, "distinct source documents opened")` states a spelling the parser renders, and after the collapse there is no letter to render.
- **The counting rule already reads as a name.** "distinct source documents opened" is what `files` states, and the rule is a budget's whole meaning — a byte budget summed once per identity and one summed per reference are different budgets.
- **The default and the rule are unchanged.** Only the spelling changes, so a run naming no ceiling behaves as it does today.
- **`Limits` maps a `Budget` to a figure.** It already does, so nothing about the holding changes.

## Proposal

**The scene.** `BUDGETS` is a tuple of `Budget` values, and `Limits({budget: figure})` holds one figure per object.

**The design.**

- **`Budget.name` replaces `Budget.option`.** `files`, `file-bytes`, `input-bytes`, `output-bytes`, `targets`, `links`, `nesting`, `depth`, each beside its default and its counting rule in one row of the table.
- **The name is resolved once.** A function from a name to a `Budget` answers the parser and any later reader, so the eight admitted names come from the table rather than a second list.
- **Nothing about the holding changes.** `Limits.hold` and `Limits.of` keep their signatures, so no stage that counts a figure changes.
- **The counting rules stay in `limits.py`.** They are the table's third column today and remain so, because a rule written anywhere else would be a second statement of a budget's meaning.
- **`Crossed` names the ceiling by name.** Its message reads "which crosses the `output-bytes` budget of N", so a diagnostic names a word a caller typed rather than a letter they did not.
