**Component:** src/prosiform/dispatch.py

## Overview

A deferred target keeps the profile its own document declares for the run that follows it. Nothing is carried in the bundle, because the deferral names a path and the next run reads the declaration there.

## Problem

A deferral publishes a path, and the path's document declares a profile.

- **The deferred destination is a path, not content.** `rebased` spells the target's working-directory-relative path with its fragment, so the bundle carries a link a later run follows from the same working directory.
- **The later run reads the document whole.** A run naming that path reads the document's frontmatter, so the profile is there to be read. What it lacks is an entry section matching the profile's name when the path carries no fragment.
- **The warning in W04 must not fire.** A deferred document contributes to no bundle, so the used-profile set would not hold its name without an exclusion, and a correct declaration would be reported as inert.
- **A dispatched target is different.** A dispatch compiles its target in this run, so its profile applies here. A deferral does not.

## Proposal

**The scene.** `dispatched_set` compiles each hop as its own entry; `deferred` holds each withheld target, and `rebased` writes its destination.

**The design.**

- **A deferred document's profile is recorded as used.** The traversal yields deferred targets, and each target document's declaration is read by the probe like any other, so the profile names it declares join the used set. W04's exclusion then has a fact to read rather than a special case.
- **A deferred target carrying a fragment names that section.** The deferral's destination keeps the fragment, so the later run names the same section and matches the same profile. No new rule is needed; the clause states it so a later change to the destination does not quietly break it.
- **A dispatched target is compiled under its own profile.** `compiled` is called for the hop, and the hop's entry document declares the profile its own section matches. The entry bundle's profile does not follow it, which W02 states.
- **The deferral states no substitution in this bundle.** Substitution is a resolution rule, so a deferred link carries its authored destination and the redirect happens in the run that follows. The destination the bundle publishes is the path the author wrote, not the substitute's, which is what makes the two runs agree.
