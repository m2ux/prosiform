**Component:** fixtures/runner.py

## Overview

The runner reads a manifest's `fault` field and passes it as `PROSIFORM_FAULT`, so no fixture names a command-line spelling.

## Problem

The runner translates a manifest field into an invocation, and that translation is the seam.

- **The field is already abstract.** A manifest declares `fault = "internal"` and the runner asks the build for `-x internal`, so how the build receives it is one line in one file.
- **The translation is in `arguments` today.** The runner appends the option and its value to the argument list, which is why a fixture's declared invocation carries a flag it did not write.
- **The environment travels with the process.** The runner already controls the working directory and the argument list, so it controls the environment by the same call.
- **A fixture must name no spelling.** A manifest that carried an environment variable's name would bind the corpus to one build, which is what the fixture language exists to avoid.

## Proposal

**The scene.** `runner.py` builds `subprocess.run`'s arguments from `invocation.cwd` and `invocation.arguments`, and compares the result against `expected`.

**The design.**

- **The field passes through the environment.** A manifest's `fault` becomes `PROSIFORM_FAULT` in the child's environment, and no argument is added.
- **A manifest with no fault sets nothing.** The variable is absent rather than empty, so a build reading it sees no fault rather than an unrecognized value.
- **The manifest schema is unchanged.** `fault` keeps its three values and its optional status; only what the runner does with it changes.
- **The fixture language names no spelling.** `fixtures/README.md` states the field as the fault a run performs on itself, and the mechanism behind it is the runner's.
- **The other environment the runner sets is unchanged.** It already passes what a child needs to run the build it was given, and this joins that set.
