**Component:** src/prosiform/dispatch.py

## Overview

A deferred target keeps the preset its own document declares for the run that follows it. Nothing is carried in the bundle, because the deferral names a path and the next run reads the declaration there.

## Problem

A deferral publishes a path, and the path's document declares presets.

- **The deferred destination is a path, not content.** `rebased` spells the target's working-directory-relative path with its fragment, so the bundle carries a link a later run follows from the same working directory.
- **The later run reads the document whole.** A run naming that path reads the frontmatter, so the presets are there to be read; what it lacks is a rule for a path carrying no fragment.
- **A dispatched target is different.** A dispatch compiles its target in this run, so its presets apply here. A deferral does not.
- **The warning in W06 must not fire.** A deferred document contributes to no bundle, so the selected-name set would not hold its names without an exclusion.

## Proposal

**The scene.** `dispatched_set` compiles each hop as its own entry; `deferred` holds each withheld target, and `rebased` writes its destination.

**The design.**

- **A deferred document's presets are recorded as used.** The traversal yields deferred targets, and each target's declaration is read by the probe like any other, so the preset names it declares join the used set. W06's exclusion then has a fact to read.
- **A deferred target carrying a fragment names that section.** The destination keeps the fragment, so the later run names the same section and selects the same preset. A target carrying none selects `default` there, exactly as a whole-document entry does.
- **A dispatched target is compiled under its own preset.** `compiled` is called for the hop, and the hop's entry document selects by its own section. The entry bundle's preset does not follow it.
- **The deferral states no substitution in this bundle.** Substitution is a resolution rule, so a deferred link carries its authored destination and the redirect happens in the run that follows.
