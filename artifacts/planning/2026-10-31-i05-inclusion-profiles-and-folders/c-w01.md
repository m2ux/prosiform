**Component:** src/prosiform/cli.py

## Overview

A mapping side ending in a separator is a folder, and both sides must agree. The grammar reads a side through the reference grammar it already uses and refuses the pairings no rule can honour.

## Problem

`cli.mock` splits on the first `=` and reads each side as a reference.

- **`entry` normalises a trailing segment away.** `closure.normalized` drops an empty segment, so `rules/` and `rules` normalise to one path and the separator that stated the folder is lost before anything can read it.
- **A pairing is validated in one place.** `mock` refuses an absent `=` or an empty side, and `substitution` folds the pairs. Nothing compares the two sides' kinds.
- **A folder is not a document.** `is_markdown` decides whether a path names a document the profile bundles, and `rules/` names none, so the Markdown-suffix test [I05:E09:W10](https://github.com/m2ux/prosiform/issues/432) applies to a folder side would refuse every folder pairing.

## Proposal

**The scene.** `mock(value)` partitions on `SUBSTITUTION_PAIR`, calls `entry` on each side, and returns the pair. `substitution(options)` folds the pairs by `(path, fragment)`.

**The design.**

- **The separator is read before normalisation.** `mock` records whether each side ends in `/`, strips it, and reads the remainder through `entry`. The trailing separator is the folder's marker rather than a path segment, so `rules/` and `rules` remain one identity for matching while stating two different kinds.
- **Both sides agree or the pairing is refused.** One folder side and one document side fails with `E_INVALID_USAGE`, exit status `2`, naming the pair. A folder and a file state different questions and one entry cannot ask both.
- **A folder side is a reference path.** Percent decoding, control-character refusal, `..` normalisation and the drive-path refusal all apply. The Markdown-suffix test applies to the path a reference resolves to under the substitute folder, not to the folder, so a folder key is not refused for naming no document.
- **A folder key carries no fragment.** A side ending in a separator whose text carries `#` is refused, because a folder names no section. A substitute side carrying one is refused on the same ground.
- **`Substitution` holds the two key kinds.** A folder key is stored as a path prefix beside the exact keys, so the lookup in W02 answers both from one value.
