## Overview

The clause that states the fault a run performs on itself as a conformance mechanism rather than an option, and the pin that lets a fixture name it.

## Problem

The contract presents a test affordance as a feature.

- **The CLI contract carries the row.** `-x {source-changed,internal,cleanup-refused}` sits in the option table among `-o` and `-c`, and `make invocation` holds that table to the help output.
- **The variable has nowhere to be stated.** Moving the mechanism out of the options leaves it unstated, and the design states that a run reads Markdown and its own frontmatter — a second input channel belongs in the contract even when it is not an option.
- **Three clauses depend on it.** *Source consistency*, the internal-error exit status and *Publication*'s retention warning each state behaviour no source tree produces, and each is fixtured through a fault.

## Proposal

**The scene.** The CLI contract enumerates each option as a clause; the conformance check lists clauses no fixture reaches.

**The design.**

- **A section of its own.** The design gains *Conformance faults*, stating the variable, its three values, and that a run without it performs no fault.
- **Why it exists.** The section states that some clauses state behaviour no source tree can produce, so a run needs a way to perform the fault a fixture describes without a caller being able to ask for it as an option.
- **The option row is withdrawn.** The CLI contract names no `-x`, and the guide names no fault.
- **An unknown value is invalid usage.** The section states that a value outside the three fails, so a mistyped conformance setting is a fault rather than a silent pass.
- **The pin moves after the clause merges.**
