## Overview

The clause naming `document#fragment` as the one spelling for a section, the retired option, and the pin.

## Problem

The contract states two spellings for one thing.

- **The CLI contract carries the row.** The option table states `-f DOC` as the referrer a fragment-only reference resolves against, and `make invocation` holds that table to the help output in both directions.
- **The positional grammar admits a bare fragment.** `REF` is stated as `document`, `document#fragment`, or `#fragment` with `-f`, so one section has two spellings.
- **A removal needs a clause to be read against.** A build without the option and a design carrying its row disagree, and `make conformance` compares the codes and options the build reports against the ones the contract declares.

## Proposal

**The scene.** The CLI contract enumerates each option as a clause; the reference clause states how a reference is spelled.

**The design.**

- **The row is withdrawn.** The CLI contract names no `-f`, and the reference clause states `document#fragment` as the one spelling a section takes on the command line.
- **The link form is stated separately and unchanged.** A `[Check](#section)` link resolves against the document that carries it, which is ordinary Markdown and no spelling of a command line.
- **The removal is stated rather than implied.** A design that had once carried the option and now does not says so, so a reader of an older revision meets the fact rather than the gap.
- **The pin moves after the clause merges.**
