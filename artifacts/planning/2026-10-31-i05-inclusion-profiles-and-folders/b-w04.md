**Component:** src/prosiform/cli.py

## Overview

An entry naming a whole document matches no preset. The compilation runs under the run's own options, and a preset named for the document's title raises `W_PRESET_UNUSED`.

## Problem

A whole-document entry has no section name, and a preset is chosen by one.

- **The selector is a heading's text.** A preset applies where the section an entry names has a heading whose text matches the preset's name. An entry naming `guide.md` names no section, so the rule selects nothing.
- **A title-matching rule would be a second selector.** Matching the document's title instead invents a naming rule for one case, states no invariant any heading test covers, and gives a document two ways to name one preset.
- **A silent miss reads as a bug.** A caller who declared a preset and named the whole document would find it applied nothing, and nothing would say so.

## Proposal

**The scene.** `compiled` builds one `Profile` per compilation from the entry document's declaration and the section its entry reference names.

**The design.**

- **No section name, no preset.** The compilation uses the run's own options, and the preset set is empty for it.
- **The miss is stated.** `W_PRESET_UNUSED` names the preset and the document, which is the code [I05:E13](https://github.com/m2ux/prosiform/issues/436) already declares for a preset nothing applied. No new code lands.
- **The remedy is a section.** A caller who wants a preset names the section it governs, which is the one selector the design states.
- **A dispatched target is unaffected.** Its entry is the hop's target, and a hop may name a fragment, so a dispatch can select a preset the entry could not.
