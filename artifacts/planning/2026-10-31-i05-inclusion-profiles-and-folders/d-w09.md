**Component:** invocation.md

## Overview

The option's row states the grammar, the two scopes and the level, and the selection page states exclusion as the subtractive half of the same shape.

## Problem

A carve-up is a selection rule, and the pages state selection as an addition.

- **The option table has no row.** `make invocation` holds that table and the help output to each other in both directions, so an option the command offers and no table names fails the check.
- **`docs/selection.md` states consolidation as a union.** It says overlaps union, the larger region wins, and a child selection is satisfied by its parent. An exclusion contradicts none of that and is not mentioned by it, so a reader concludes the selection only grows.
- **The frontmatter's argument keys are stated where the preset is.** [I05:E13](https://github.com/m2ux/prosiform/issues/436) states the two kinds of `prosiform` key, and this epic adds one whose value is a sequence, so that page states the shape beside the others.
- **The two codes belong in the validation page.** `docs/validation.md` lists the input failures a run reports, and two new ones that refuse a carve-up are ones a reader meets only here.

## Proposal

**The scene.** `invocation.md` holds the option table and the bundling rules; `docs/selection.md` states closure, consolidation, placement and structural ancestors; `docs/validation.md` states the codes.

**The design.**

- **The row states three things in one line.** The section's grammar with its optional level, the bare and qualified scopes, and that an exclusion removes the section and everything beneath it.
- **The selection page gains one section.** *Exclusion* states that a name removes what a fragment of the same name would select, that the removal happens before consolidation settles, that a link inside an excluded section is no dependency, and that the two refusals protect a half-applied carve-up.
- **The preset page states the sequence value.** A `prosiform` key naming an argument whose value is a list is stated beside the scalar form, so a reader meets the one exception where the key rule is stated.
- **The validation page gains two rows.** `E_EXCLUDED_CONTENT` and `E_EXCLUDED_ENTRY`, each with what raises it and what the author does instead.
- **The help string is edited with the row.** `cli.parser`'s help text is what the table is compared against, so the two change together and the check holds them.
