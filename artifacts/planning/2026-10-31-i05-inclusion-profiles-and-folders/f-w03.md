**Component:** invocation.md

## Overview

The option table loses its row, the help output loses the flag, and the guide names no fault.

## Problem

The fault is presented to a caller as part of the contract.

- **The table carries a row.** `invocation.md` states `-x {source-changed,internal,cleanup-refused}` with its effect, in the same table as `-o` and `-c`.
- **`make invocation` holds the two together.** The table and the build's help output must name the same options in both directions, so the row and the flag go together or the check fails.
- **The guide lists it.** A caller reading the guide meets an option whose only consumer is the corpus.
- **The contract still states the mechanism.** Moving it off the table must not leave it unstated; the design's own section carries it.

## Proposal

**The scene.** The option table's rows are clauses `make invocation` compares against the build's own help, and the guide is prose.

**The design.**

- **The row is removed.** Six option rows become five, and the table names nothing a caller cannot want.
- **The help string is removed with it.** `cli.parser` declares no `-x`, so the comparison has nothing to hold.
- **The guide states no fault.** Its account of what a run does names no mechanism a caller can invoke.
- **The design states where it went.** The table's prose points at the design's *Conformance faults* section, so a reader who knew the option learns it is a conformance mechanism rather than a feature that vanished.
- **The two-way comparison proves the removal.** An option the build offers and no row names fails, and so does a row naming an option the build lacks.
