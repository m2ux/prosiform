**Component:** src/prosiform/metadata.py

## Overview

The key set opens by rule: a key naming an argument is an argument, a key holding a mapping is a profile, and anything else is a misspelled field. A profile is decoded into the shapes the mapping already holds.

## Problem

`metadata.decode` decides one question per key and refuses every key it does not know.

- **The refusal is total.** `fields` accepts `("root", GROUP, DEPTH)` and raises `E_INVALID_CONVERSION_METADATA` for anything else, so a profile key is refused before its value is read.
- **A profile's entries are the mapping's entries.** A profile holds substitution pairs and budget overrides, and `cli.mock` and `override` already parse those shapes on the command line. Duplicating their grammar in `metadata.py` would put one rule in two parsers.
- **A key's kind is not knowable from its name alone.** `mock` is an argument name and also a plausible profile name; `procedure` is a profile name and no argument. The value decides, which is why the rule is stated as a shape rather than a list.

## Proposal

**The scene.** `decode` iterates the `prosiform` mapping's pairs, refuses a key outside a fixed tuple, checks each field's type, and returns a `Conversion` carrying the three values.

**The design.**

- **Three kinds of key.** A key in the argument-name set carries a scalar and is decoded as that argument is; a key whose value is a mapping is a profile, decoded into the pairs and overrides it holds; any other key is refused with the existing code, naming the key.
- **The argument names come from the grammar.** The set is read from the argument parser's own option table rather than written twice, so an option added to the command is an argument a document may set and one removed stops being settable. `cli` exposes the set the traceback-free way: the parser is built once and its destination names read.
- **A profile's entries are parsed by the command's own parsers.** `Conversion.profiles` holds, per name, the pairs `cli.mock` returns and the overrides `cli.override` returns, so a malformed pair or a non-positive budget is refused with the message the command line carries.
- **An empty profile is refused.** A profile holding nothing states a name that governs nothing, and the run cannot tell it from a misspelling; it fails with `E_INVALID_CONVERSION_METADATA`, naming the profile.
- **A shape the command does not carry is refused.** A profile key holding a scalar, a pair whose sides are not references and a budget naming no option each fail with the code and the location the caller's other metadata faults carry.
