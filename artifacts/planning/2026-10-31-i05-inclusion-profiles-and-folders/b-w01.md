**Component:** src/prosiform/metadata.py

## Overview

`prosiform` holds presets alone. Every key is a preset name whose value is a mapping, and a key whose value is anything else is refused.

## Problem

`prosiform` admits three flat keys and fails every other.

- **The key set is closed.** `metadata.decode` accepts `("root", GROUP, DEPTH)` and raises `E_INVALID_CONVERSION_METADATA` for anything else, so a preset has nowhere to be written.
- **A key's kind is not knowable from its name.** `mock` is an option name and a plausible preset name; `Target` is a preset name and no option. The value decides, which is why the rule is a shape rather than a list.
- **A file-wide setting has no place left.** With the fields moving into presets, any top-level parameter would be a second rule for the same thing, and the one that cannot vary with a selection.

## Proposal

**The scene.** `decode` iterates the `prosiform` mapping's pairs, refuses a key outside a fixed tuple, checks each field's type, and returns a `Conversion`.

**The design.**

- **One kind of key.** Every `prosiform` key is a preset name, and every value is a mapping. A value that is not a mapping fails with `E_INVALID_CONVERSION_METADATA`, naming the key.
- **A reserved name.** `default` is a preset like any other by shape, and the only one whose application is not a heading match: it applies wherever no other name matches.
- **The fields move inside.** `group` and `group-depth` are preset entries now, so the decoder reads them per preset rather than per file. `root` is already gone under [I05:E11](https://github.com/m2ux/prosiform/issues/434).
- **`Conversion` holds presets.** One immutable value per file, mapping a preset name to its settings, and the compilation chooses one.
- **An empty `prosiform` mapping states nothing.** A file with no `prosiform` at all, and one with an empty block, both declare no preset, and a compilation of either runs under the run's own options.
