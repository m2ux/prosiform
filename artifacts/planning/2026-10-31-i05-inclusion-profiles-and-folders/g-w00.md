## Overview

The clause stating the eight budgets as one named set behind one option, and the pin.

## Problem

The contract enumerates eight options of one shape.

- **The CLI contract carries eight rows.** `-F`, `-B`, `-I`, `-O`, `-T`, `-L`, `-N` and `-E` each take a positive integer and each bound a different count, so eight rows state one rule eight times.
- **The letters are unreadable.** Nothing in `-E` says it bounds link hops, and `-O` is one case from the unrelated `-o`.
- **`make invocation` compares both directions.** One row replacing eight changes the table, so the comparison is what proves the collapse complete.
- **The counting rules are the budgets' meaning.** Each ceiling's rule is already written beside its number in `limits.py`, and the clause states them with the names so a reader meets one table.

## Proposal

**The scene.** The CLI contract enumerates each option as a clause; `limits.py` holds one `Budget` per ceiling, naming its option, its default and what it counts.

**The design.**

- **One row, one option, eight names.** `--budget NAME=VALUE`, repeatable, with the eight names and their counting rules stated beneath the row.
- **The names replace the letters.** `files`, `file-bytes`, `input-bytes`, `output-bytes`, `targets`, `links`, `nesting`, `depth`.
- **Validity moves into the value parser.** A name outside the eight, an entry carrying no `=`, and a value that is no positive integer are each invalid usage, and the clause states them together because one parser states them.
- **A name given twice is refused.** The clause states it with the other two refusals.
- **The defaults are unchanged.** Each ceiling stands at the figure it stands at today, so a run naming none behaves exactly as it does now.
- **This row does not move the pin.** [I08:E00:W00](https://github.com/m2ux/prosiform/issues/434) moves it once for every clause in this initiative, so this amendment lands beside that one.
