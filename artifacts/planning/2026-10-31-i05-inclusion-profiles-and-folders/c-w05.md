**Component:** invocation.md

## Overview

The option's row states the folder form beside the document form, and the bundling rules state what a folder key redirects.

## Problem

The documented row states one pairing shape.

- **`invocation.md` states `-m ORIGINAL=ALTERNATIVE`.** Its row names a document and a section, and its bundling paragraph states that a key carrying a fragment redirects that section and takes precedence over a key naming the whole document.
- **`make invocation` compares both directions.** The option table and the help output must name the same options, so the row is rewritten rather than added, and the help string is rewritten with it.
- **The precedence a folder introduces is not stated anywhere a reader looks.** The row states the document-key precedence and would otherwise say nothing about two folder keys, which is the rule a caller writing two of them needs.

## Proposal

**The scene.** The row reads `-m, --mock ORIGINAL=ALTERNATIVE`, and the bundling paragraph states the matching rule.

**The design.**

- **The row states the folder form.** A side ending in a separator names a folder, both sides carry it or neither does, and the pair is a command line the grammar refuses when they disagree.
- **The bundling paragraph states the precedence in one sentence.** An exact key answers before a folder key, and of two folder keys holding one reference the longer is used.
- **The help string states the folder form.** `cli.parser`'s help text is what `make invocation` compares the row against, so the two are edited together and the check holds them.
- **The glossary gains nothing.** A folder key is a key, and the term *substitution mapping* already covers it; the note about the residual `root` exemption remains as [I05:E09](https://github.com/m2ux/prosiform/issues/414) stated it until [Declared Inclusion](epic-a-declared-inclusion.md) reworks that epic's criteria.
