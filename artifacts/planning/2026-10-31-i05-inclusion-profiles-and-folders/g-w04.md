**Component:** invocation.md

## Overview

Eight budget rows become one, and the counting rules move under it.

## Problem

The table states the same rule eight times.

- **The table carries eight budget rows.** Each takes a positive decimal integer and each bounds a different count, so a reader scans eight rows to learn one rule.
- **`make invocation` compares both directions.** The table and the build's help output must name the same options, so eight rows and eight flags go together or the check fails.
- **The names and their rules are the content.** A reader needs the eight names and what each counts, which the rows stated one at a time.
- **The usage examples pass letters.** A worked example carrying `-O` states a command line the build refuses.

## Proposal

**The scene.** The option table's rows are clauses `make invocation` compares against the build's own help.

**The design.**

- **One row states the option.** `--budget NAME=VALUE`, repeatable, with the eight names and their counting rules beneath it in the same cell or a following list.
- **The examples use names.** Every worked example passing a budget passes its name, so the page states no command line the build refuses.
- **The prose naming budgets is rewritten.** Any sentence stating a budget by letter states it by name, so the page has one vocabulary.
- **The comparison proves the collapse.** An option the build offers and no row names fails, and so does a row naming an option the build lacks — which is how eight rows becoming one is shown complete.
- **No other row changes.** The invocation rows and the informational rows keep their wording.
