**Component:** src/prosiform/cli.py

## Overview

A positional entry compiles the document it names, and the run derives its name from that path. No preset substitutes it, because no document writes it.

## Problem

The entry is redirected by a mapping no document states.

- **`cli.entry` ends in `substitution.redirect(found)`.** A command-line pair redirects the entry before any source is read, and the run name follows the substitute.
- **A preset cannot state it.** A `path-sub` pair substitutes links its declaring document writes, and an entry reference is written by none. The entry's own presets govern the links the entry writes, not the entry.
- **A fixture asserts the retired behaviour.** `fixtures/mock/a-redirected-entry-derives-its-name-from-the-substitute` holds [I08:E07](https://github.com/m2ux/prosiform/issues/414) AC2, which is superseded.

## Proposal

**The scene.** `cli.execute` normalises each positional reference through `entry` and derives the run's folder from the selections.

**The design.**

- **`entry` takes no mapping.** It normalises the positional reference and returns it.
- **The name follows the path the caller wrote.** A run's folder and bundle are named for the entry as given, whatever its document's presets state.
- **The fixture is withdrawn.** `a-redirected-entry-derives-its-name-from-the-substitute` goes with the capability, and a fixture asserting the entry compiles as named replaces it.
