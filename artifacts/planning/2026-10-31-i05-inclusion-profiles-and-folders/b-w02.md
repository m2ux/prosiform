**Component:** src/prosiform/metadata.py

## Overview

`group-depth` replaces `group` and holds a list of single-entry mappings, so one document may join several divisions at different depths and the two halves of a pair are never written apart. The division a document joins follows the preset governing the reference that reached it.

## Problem

A file declares one group, and the two halves of the pair sit in separate keys.

- **One division per file.** `Conversion.group` is a single string, and `cli.group_depths` maps one name to the list of files declaring it, so a document cannot be carved into two divisions.
- **The pair is two keys.** `group` holds a string and `group-depth` an integer, paired only by both being present. They can be written apart, and `decode` refuses one without the other as a repair for a rule that a single field removes.
- **The depth check is per group.** `group_depths` compares every member's depth and raises `E_GROUP_DEPTH_CONFLICT` where two disagree, which a list of pairs still needs per name.
- **A document's placement is its own, and it should not be.** The division a document joins is a fact about the bundle it lands in, and the section that asked for it is the one that knows which outline its consumer reads. A per-file declaration states one placement for every consumer.

## Proposal

**The scene.** `decode` reads `group` and `group-depth` as separate nodes, checks their pairing and returns one name and one depth on `Conversion`.

**The design.**

- **One field, a list of pairs.** `group-depth: [{protocols: 1}, {targets: 2}]`. Each entry is a single-entry mapping from a division name to its depth, so a pair is one value.
- **`group` is refused.** A `prosiform` preset carrying it fails with `E_INVALID_CONVERSION_METADATA`, naming the key, so a tree declaring one migrates rather than half-working.
- **The entry shape is strict.** A mapping holding two keys, a non-string key and a depth outside one through six each fail with `E_INVALID_CONVERSION_METADATA` naming the entry. YAML admits all three and none is what an author could mean.
- **A document may join several divisions.** `Conversion` holds a sequence of pairs per preset, and `group_depths` collects members per name across the run, so one document appears in each division a governing preset names.
- **Placement follows the governing preset.** The pairs read for a reference are those of the preset that governed it, so one document reached by two links under two presets is placed twice. Where the governing preset names none, the target's own `default` places it.
- **Depth still agrees per name.** Two members of one division at different depths raise `E_GROUP_DEPTH_CONFLICT`, exactly as one field per file does today.
