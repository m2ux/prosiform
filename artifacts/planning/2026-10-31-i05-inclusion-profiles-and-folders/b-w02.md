**Component:** src/prosiform/metadata.py

## Overview

The settable set is named rather than read from the parser, and every argument value is a list. A document therefore sets what shapes its bundle and nothing that decides where the run writes.

## Problem

Two rules about an argument's value decide what a document can do to a run.

- **The parser's table is the wrong source.** `cli.parser()` declares `-o`, `-c`, `-d` and `-x` beside `-m` and the budgets. Read from that table, a `prosiform` key would set every one, so a document could redirect its own bundle with `-o` or silence the diagnostics that report it.
- **One value, two shapes.** `-m ORIGINAL=ALTERNATIVE` names one pair, and a document sets it as a list so a second pair is written the same way. A frontmatter value that is a scalar in one key and a list in another is two rules a reader has to hold apart.
- **A scalar is ambiguous.** `mock: "rules.md=stub.md"` and `mock: ["rules.md=stub.md"]` would mean the same thing if a scalar were tolerated, and a rule with two spellings is one a reader gets wrong.

## Proposal

**The scene.** `metadata.decode` reads the `prosiform` mapping and admits a key naming an argument, a key holding a mapping and its own fields.

**The design.**

- **The settable set is one tuple.** `mock` and the budgets `-F`, `-B`, `-I`, `-O`, `-T`, `-L`, `-N` and `-E`. Every name in it is an option the parser declares, so one test holds the tuple to the help output and a new option fails until someone places it. A key naming any other option is refused with `E_INVALID_CONVERSION_METADATA`, naming the key. The tuple sits beside the parser, and a test holds it to the options the help output declares, so an option added to the command fails the test until someone decides which side it belongs on.
- **A document states content, not destination.** Every option in the set shapes what the bundle holds or how large it may grow. `-o` decides where a run writes and `-c`, `-d` and `-x` describe the invocation, so none is a document's business.
- **Every argument value is a list.** `mock` holds a list and each entry is read by the option's own parser, so a malformed entry carries the message the command line carries. `exclude` is a preset entry rather than an argument, and its list is the shape [I05:E14](https://github.com/m2ux/prosiform/issues/445) states.
- **A scalar is refused.** `mock: "rules.md=stub.md"` fails with `E_INVALID_CONVERSION_METADATA` naming the key and its location, because one shape is what makes the rule learnable.
- **The argument-name rule is unchanged.** A key in the set is an argument; any other key whose value is a mapping is a preset; anything else is refused as a misspelled field.
