## Overview

The clause stating exclusion as the subtractive half of selection, the two codes it carries, and the pin that lets a fixture name it.

## Problem

The design states a selection that only grows.

- **Consolidation unions.** The design states that overlapping selections are unioned and the larger region wins, so a run carries every region anything reached. There is no clause admitting a region the run removes.
- **An option for it has no row.** The `CLI contract` table enumerates each option as a clause `make conformance` reads, so an option the build offers and the table omits fails `make invocation`.
- **Two refusals need codes.** An exclusion holding selected content and an exclusion emptying its own entry are each a shape the run must refuse, and `-C` and the design's catalogue must agree on each code.

## Proposal

**The scene.** The selection clause states closure, consolidation and placement order; the `CLI contract` table states the options; the code catalogue states each error and warning.

**The design.**

- **One clause, stated where consolidation is.** Exclusion removes a named section from what a document contributes, before consolidation settles the run's regions, so a region removed by one exclusion cannot be restored by a selection that also reached it.
- **The shape is the selection's.** An exclusion names what a fragment names — a document-level heading and everything beneath it — so inclusion and exclusion describe one shape and a reader learns one rule.
- **The two scopes and the level are stated with the grammar.** A bare name applies to every document read, a qualified one to the document it names, and a level selects which heading of a repeated name the exclusion means.
- **Two codes join the catalogue.** `E_EXCLUDED_CONTENT` for an exclusion holding content another reference selected, and `E_EXCLUDED_ENTRY` for a selection emptied by its own exclusions. Both are input failures with exit status `1`.
- **The pin moves after the clause merges**, as every epic in this record does.
