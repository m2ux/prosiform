**Component:** main:Makefile

## Overview

The example tree and every check, target, fixture, script entry and document built on it are removed, after an annotated tag `archive/example-work-planner` is placed on the last commit holding `example/work-planner`, so the tree stays reachable from git history.

## Problem

The example tree is stale, unmaintained, and holds checks to it.

- **It copies a skill that has moved on.**
  `example/work-planner` is a snapshot nobody maintains, so each field rule would need a rewrite of a tree nobody reads.
- **Five targets read it alone.**
  `make steps`, `make authoring`, `make boundary`, `make mock-scenarios` and `make examples` read `example/` and nothing else, and `make check` names the first four.
- **A fixture family reaches it.**
  Every `fixtures/usage-example/` case's `source` is a symbolic link into the tree, and `make test` copies the tree to compile its modes.
- **Documents name it.**
  `README.md`, `invocation.md`, `checks.md`, `checks/README.md` and `fixtures/README.md` describe the tree or link into it.

## Proposal

**The scene.** `make check` runs the authoring, step and boundary guards over `example/work-planner` ahead of `make test` and `make corpus`, which bundle it.

**The design.**

- **The tag comes first.**
  An annotated tag `archive/example-work-planner` names the commit on `main` the removal is cut from, so `git show archive/example-work-planner:example/work-planner/SKILL.md` and the GitHub tree link at the tag read the tree.
- **Everything built on the tree is removed.**
  `example/`, its `scripts/examples.json` entries and the diagrams they render, the `make` targets and the checks behind them, the `usage-example` fixtures, and the tests that copy the tree.
- **No surviving document names the tree.**
  Each page that describes or links it states the repository as it is; the pull request and the planning record name the tag.
- **Nothing is refused in its place.**
  A retired tree is removed, so no check or fixture asserts its absence.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | List every file under `example/`, every check, target, fixture, test, script entry and document that reads or names it. |

| Implementation | Tag the commit, then remove the tree and everything the analysis lists. |
| Review | Search the repository for the tree's paths and names; confirm only the tag reaches it. |
| Test | `make check`. |
