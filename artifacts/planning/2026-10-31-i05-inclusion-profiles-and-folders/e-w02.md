**Component:** src/prosiform/cli.py

## Overview

A section entry derives its run's name from the document it names, and the branch that read a referrer goes with the option.

## Problem

One name has two sources, and one of them is the option being removed.

- **`selections` falls back to the referrer.** A reference carrying no path takes the referrer's path, so a run named from a bare fragment got its document from `-f`.
- **`run_name` reads the selection.** Each selection's name is its working-directory path with separators written as underscores, and a fragment adds `__` and its text.
- **A section entry names its own document now.** `guide.md#stop` carries its path, so the name derives from the reference rather than from a second argument.
- **The output folder's name follows.** The run folder is the joined names plus the suffix, so a changed derivation changes a folder's name.

## Proposal

**The scene.** `selections` builds each distinct `(path, fragment)` from the requested references, and `run_name` turns each into the name the folder and the entry bundle take.

**The design.**

- **The fallback is removed.** Every reference carries a path, so a selection's path is the reference's own.
- **The derived name is unchanged for the spellings that remain.** `guide.md#stop` derives the same name it derives today, so no published folder renames.
- **A run of several sections names them in order.** `pf 'a.md#x' 'a.md#y'` joins the two names with `+`, exactly as two documents do.
- **A section naming no heading still fails.** The heading lookup is unchanged, so `guide.md#nowhere` remains the input failure it is today.
