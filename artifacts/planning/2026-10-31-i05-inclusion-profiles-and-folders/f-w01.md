**Component:** src/prosiform/cli.py

## Overview

The parser declares no fault option, the run reads `PROSIFORM_FAULT` where the option's value was read, and an unrecognized value is invalid usage.

## Problem

The fault arrives through a shipped flag and the run reads it from a `Namespace`.

- **`parser()` declares it.** `-x` takes a choice of the three names with `dest="fault"`, so the grammar admits it like any other option.
- **`execute` reads `options.fault` at three points.** Once before `rewrite_sources`, once to raise `Faulted`, and once as `publication`'s `retained` argument.
- **`diagnostic_format` walks its value.** That function steps over the value of every option that takes one, so an option removed from its set leaves a later `-d` unread.
- **An unknown value has no path.** A choice declared by the grammar cannot fail it; a variable can, and the run has to refuse it.

## Proposal

**The scene.** `main` parses the command line, `execute` runs the compilation, and `publication` takes a `retained` flag.

**The design.**

- **The option is removed.** `parser()` declares no `-x`, and `diagnostic_format` no longer lists it.
- **One read of the environment.** A function reads `PROSIFORM_FAULT` once, before any source is opened, and returns the fault or nothing. The three points that read `options.fault` read that value instead.
- **An unrecognized value is invalid usage.** A name outside the three fails with `E_INVALID_USAGE` and exit status `2`, naming the value and the three admitted, so a mistyped setting is a fault rather than a silent pass.
- **An absent variable is no fault.** Nothing is performed, which is every run a caller starts.
- **The environment is read once, not per stage.** Three reads of one variable could disagree if a caller changed it mid-run, and one value passes to each site as a parameter.
