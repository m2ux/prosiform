**Component:** fixtures/source-consistency

## Overview

All three fault fixtures pass unchanged through the new channel, which is what proves the mechanism moved without the behaviour moving.

## Problem

The three fixtures are the evidence the fault still works.

- **`a-source-that-changes-during-compilation` exercises the recheck.** A run whose sources change between discovery and the recheck fails, and it is the only test of the mechanism that prevents publishing bytes the run no longer reads.
- **`a-run-that-fails-in-itself` exercises exit status `4`.** Nothing in a well-formed tree produces an internal error, so the fault is the only path.
- **`an-earlier-set-the-run-cannot-remove-warns` exercises the retention warning.** A directory the run cannot remove is unreachable from a tree.
- **Their manifests already declare a field, not a flag.** So the change is one of plumbing, and a changed expected result would prove the behaviour moved when only the channel should.

## Proposal

**The scene.** Each manifest declares `fault = "<name>"` and its expected result, and the runner asks the build for that fault.

**The design.**

- **No fixture changes.** The three manifests keep their declarations and their expected results, and none names a mechanism.
- **A diff proves it.** The task's evidence is that these three files are untouched by the epic, so the corpus's expectations are the statement that the behaviour did not move.
- **The recheck keeps its test.** The clause whose only fixture is `a-source-that-changes-during-compilation` stays fixtured, which is the reason the mechanism was kept rather than recorded unfixturable.
- **A fourth fixture names the refusal.** `an-unknown-fault-is-invalid-usage` is new, because a grammar choice could not fail and a variable can.
