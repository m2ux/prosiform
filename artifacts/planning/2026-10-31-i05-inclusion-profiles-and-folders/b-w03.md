**Component:** src/prosiform/closure.py

## Overview

A profile's entries are held to the refusals the command line already states, and an entry restating a `-m` pair is refused rather than ordered. The joined mapping is one value, so precedence is decided once.

## Problem

Two sources of mapping entries meet at one lookup.

- **`Substitution` holds one dictionary.** `closure.Substitution` is built from the pairs `cli.mock` returned, keyed by `(path, fragment)`, and `substitution(options)` builds it before any source is read. A profile's entries join it later, once the entry document's declaration has been read.
- **A duplicate key is already refused.** `cli.main` refuses two pairs normalising to one identity, and a pair whose sides normalise to one identity. A profile's entries need the same two refusals, stated against the same identities.
- **An overlap between the two sources is new.** A profile entry and a `-m` pair naming one identity state the redirection twice, and a dictionary would take whichever was written last, so the run's answer would depend on an order no reader can see.
- **A profile's pairs are parsed before they are validated.** `metadata.decode` returns them as the pairs the command line's parser produced, so an `=` pairing and a reference grammar error are reported where the profile is read.

## Proposal

**The scene.** `cli.substitution(options)` folds the pairs into a `Substitution`. `Substitution.key` answers exact-first, then the document key, and `substitute` returns the reference the mapping names.

**The design.**

- **One joining point.** `Profile` folds the command line's pairs and then the profile's pairs into one `Substitution`, refusing a duplicate as it goes. The refusal names both spellings, so an author who wrote `./rules.md` in one and `rules.md` in the other is told which two collided.
- **A restating entry is refused.** A profile entry naming an identity `-m` already names fails with `E_INVALID_USAGE`, exit status `2`, naming the profile and the pair. The command line is the run's statement of what to substitute; a profile restating it states a second answer for one identity.
- **A profile's refusals carry the profile's location.** A duplicate inside one profile, a self-mock inside one profile and a restating entry are each reported with the profile's key location, so the author is pointed at the document rather than the command line.
- **The document-key rule is unchanged.** A profile entry naming a whole document covers every fragment of it, and one naming a section takes precedence, exactly as `-m` does, because it is the same `Substitution`.
- **A folder key is a key.** [Folder Mocks](epic-c-folder-mocks.md) gives a key a folder form, and a profile entry takes it with no rule of its own, since both reach one `Substitution`.
