**Component:** invocation.md

## Overview

The option table loses its row, and the guide states `document#fragment` as the one spelling for a section.

## Problem

The option is documented in two places and named in a third.

- **The table carries the row.** `invocation.md` states `-f DOC` as the working-directory-relative document for fragment-only references, and `make invocation` holds that table to the help output in both directions.
- **The positional row states three forms.** `REF` is given as `document`, `document#fragment`, or `#fragment with -f`, which is the second spelling the removal retires.
- **The guide names it in prose.** A caller told to select a section is told one form, and the guide must state that one.
- **The usage examples may carry it.** Any example passing `-f` states a command line the build refuses.

## Proposal

**The scene.** The table's rows are clauses `make invocation` compares against the build's own help, and the guide is prose that no check reads.

**The design.**

- **The row is removed.** Five option rows become four invocation rows, and the positional row states `document` and `document#fragment` alone.
- **A bare fragment is stated as refused.** The row says a section is named as `document#fragment`, and that a bare `#fragment` is invalid usage, so a caller meets the rule where the grammar is stated.
- **The guide states one form.** Its account of selecting a section names `document#fragment`, and no example passes the removed option.
- **The help string is edited with the row.** `cli.parser`'s help text is what the table is compared against, so the two change together and the check holds them.
- **The two-way comparison proves the removal.** An option the build offers and no row names fails, and so does a row naming an option the build lacks.
