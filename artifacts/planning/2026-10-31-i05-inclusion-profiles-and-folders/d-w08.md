**Component:** src/prosiform/metadata.py

## Overview

A document's `prosiform` declares its own exclusions, and a preset declares the exclusions its compilation carries. A carve-up is therefore the document's statement rather than only a command line's.

## Problem

An exclusion lives on the command line, and a carve-up belongs to the document.

- **A preset is the natural home.** [I05:E13](https://github.com/m2ux/prosiform/issues/436) admits a key naming an argument and a key holding a preset. An exclusion is an argument, so it has a home without a new rule; what it lacks is a shape a frontmatter value can hold.
- **A list of sections is not a scalar.** `prosiform` values are strings and mappings, and the exclusion is a sequence of references, so the argument's value is a sequence rather than one scalar.
- **Two applications are wanted.** An `exclude` at the top level of `prosiform` describes the document whichever compilation reads it; an `exclude` inside a preset describes the one compilation that preset governs. The distinction is the same one every other argument in a preset has.
- **The value must be read by the option's grammar.** A frontmatter exclusion and a command-line one are one intent, so a malformed one is refused with the message the command line carries rather than a second parser's.

## Proposal

**The scene.** `metadata.decode` reads the `prosiform` mapping, admits an argument name holding a scalar and a preset holding its pairs and overrides, and returns a `Conversion`.

**The design.**

- **The argument's value is a list, as every argument's is.** `exclude` holds a list of sections and each entry is parsed by the option's own parser, so an encoded colon, a level and a query are read exactly as on the command line. [I05:E13](https://github.com/m2ux/prosiform/issues/436) states one shape for every argument, so a scalar `exclude` is refused rather than read as a one-element list.
- **A preset's exclusion joins that compilation's list.** The command line's exclusions and the preset's are one list for the compilation the preset governs, and the collision rule is the mapping's: an exclusion naming what another already names is refused rather than applied twice.
- **A top-level exclusion joins every compilation.** It is folded once, before any compilation starts, exactly as a top-level `mock` is, because the document states it whichever compilation reads it.
- **An absent `exclude` states nothing.** A document declaring none excludes nothing, and no diagnostic accompanies that.
- **An invalid entry is a metadata fault.** A value that is neither a string nor a list of strings fails with `E_INVALID_CONVERSION_METADATA`, naming the key and its location, which is the code the frontmatter's other shape faults carry. A well-formed string that names a malformed section is the option's refusal instead, so one fault is stated once.
