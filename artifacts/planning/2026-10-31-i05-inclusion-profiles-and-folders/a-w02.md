**Component:** src/prosiform/access.py

## Overview

A declaration is answered by reading a target's frontmatter and stopping there. The probe opens the file through the same rooted no-follow walk, delimiters the block and decodes it within the byte budget, and returns whether the file declares.

## Problem

The only read the run has captures a whole source.

- **`access.read_source` reads to a limit or to the end.** `cli.read_document` calls it, counts the bytes against `-I`, decodes the metadata, then keeps the document as a source. A document that declares nothing would be counted, captured and re-checked for a decision that needs its frontmatter alone.
- **The frontmatter span is delimited after capture.** `source.py` finds the opener and closer over the captured text, so the delimiter rule and the BOM tolerance are stated against bytes already in hand.
- **A cited document is not a source.** Nothing in the pipeline distinguishes "read to answer a question" from "read to carry", so a budget over cited material would be spent as though the material were carried.

## Proposal

**The scene.** `cli.required` yields a `Reference`; the traversal calls `read_document` on each new path, which reads the whole file and parses it. `verify_cached` re-opens the file by its authored walk, and `recheck` re-reads every captured source before publication.

**The design.**

- **`access.read_head`.** A function on the existing walk: `access.opened` yields the descriptor, and the read is bounded by `min(-B, a head budget)` — the frontmatter span plus one byte past its closer, whatever the delimiter rule needs to know the block ended. The walk is rooted and no-follow as every other read is, so a probe cannot reach what a capture cannot.
- **The delimiter rule stays in one place.** The probe calls the same span finder the capture uses, over the bytes it read, so an indented delimiter, a trailing space, a `...` closer and a leading BOM answer the same in both. A file holding no opener is undeclared without reading further.
- **The decode is the same decode.** `metadata.decode` is called with the probed bytes and span, so an invalid `prosiform` mapping is refused at the probe as it is at a capture, and a target declaring an unknown key fails the run with the diagnostic it would have failed with as a source.
- **A size boundary is not a declaration.** A file longer than `-B` that carries no frontmatter declares nothing and is text; one carrying frontmatter fails the run, since an invalid declaration is a defect rather than a silent document. The probe reports which of the two it found, so the caller states the distinction.
- **A probe is remembered.** One path is probed once per run, and the answer is held beside the captured sources so a second link to the same target costs no read.
