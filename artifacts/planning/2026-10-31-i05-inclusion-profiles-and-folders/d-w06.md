**Component:** src/prosiform/metadata.py

## Overview

A file's `exclude` is declared in its `prosiform`, either at the top level or inside a preset. The scope is the declaring file, so no entry names a document.

## Problem

An exclusion has two homes and one scope, and the key rule decides how they read.

- **A preset is the natural home.** [I05:E13](https://github.com/m2ux/prosiform/issues/436) admits a key naming an argument and a key holding a preset. An exclusion is an argument, so it has a home without a new rule; what it lacks is the shape a frontmatter value can hold.
- **The value is a list.** Every argument's value is a list under the rule E13 states, so `exclude` holds one or more sections and each entry is an exclusion.
- **Two applications are wanted.** An `exclude` at the top level of `prosiform` governs every compilation of that file; an `exclude` inside a preset governs the compilation that preset was selected for. Either way the file is the scope.
- **The entry must be read by the option's grammar.** A frontmatter exclusion and one written on a command line are one intent, so a malformed one carries the option's message rather than a second parser's.
- **The scope is what makes it file-owned.** Because no entry names a document, an exclusion cannot reach material its declaring file does not contain, and a preset shared across a folder carves each file by what that file says.

## Proposal

**The scene.** `metadata.decode` reads the `prosiform` mapping, admits an argument name holding a list and a preset holding its pairs, overrides and exclusions, and returns a `Conversion`.

**The design.**

- **The value is a list of sections.** Each entry is read by the exclusion grammar W01 states, so a level and an empty section are refused with the message the option carries.
- **A preset's exclusion joins its compilation's list.** The top-level `exclude` and a preset's are both a list of sections for the compilation in force, and the scope each carries is the declaring file.
- **A top-level exclusion joins every compilation.** It is folded once, before any compilation starts, exactly as a top-level `mock` is.
- **An absent `exclude` states nothing.** A file declaring none withholds nothing, and no diagnostic accompanies that.
- **An invalid entry is a metadata fault.** A value that is not a list of strings fails with `E_INVALID_CONVERSION_METADATA`, naming the key and its location. A well-formed string naming a malformed section is the option's refusal instead, so one fault is stated once.
