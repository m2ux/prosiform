**Component:** fixtures/usage-example

## Overview

Every corpus source declares its settings in a preset, and every fixture's expected bundle is unchanged.

## Problem

The corpus carries the same flat fields the tree does.

- **Fixture sources declare `group` and `group-depth` flat.** Each is refused by the field rules the epics before this one land.
- **The `usage-example` family reaches the real tree.** Its sources are symbolic links, so those fixtures follow the tree migration and need no rewrite of their own.
- **The other families write their own trees.** Each source there carries `prosiform` for inclusion and a group only where the fixture is about grouping, so the rewrite is small per fixture and broad in count.
- **An expected bundle changing is a finding.** The migration rewrites a spelling, so a changed expectation means a field moved.

## Proposal

**The scene.** A fixture declares a `source/` tree, an invocation and the bundle the run must write.

**The design.**

- **Each flat pair becomes a `default` preset.** The same rewrite the tree takes, applied to a fixture's own sources.
- **A source declaring only inclusion is unchanged.** A document whose `prosiform` holds no setting already satisfies the shape.
- **No expected bundle changes.** The evidence is that every `expected/` file is untouched by this task.
- **A corpus-wide check states the removal.** No fixture source declares `group` or `root`, so a missed one fails rather than passing over a field the build refuses.
