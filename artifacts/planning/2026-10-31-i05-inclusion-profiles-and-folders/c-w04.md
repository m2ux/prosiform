**Component:** example/work-planner/SKILL.md

## Overview

The example skill's plan mode is compiled against a whole folder of stubs by one mapping entry, and the folder is a real directory in the tree so a reader can see it.

## Problem

The example demonstrates one stand-in at a time.

- **W08 of I05:E09 proves one stub.** `make mock-scenarios` copies the example tree and redirects plan mode's artifact to a stub. A mode's protocols, its artifacts and its references are separate documents, so exercising a mode against stand-ins drawn from the whole tree is a different case and the one the folder pairing exists for.
- **The stub folder has nowhere to live.** A stub tree beside the skill cannot ship with it, and one inside it would be compiled by every run of the skill. The check that copies the tree to a temporary directory is where a stub folder can be written without shipping.

## Proposal

**The scene.** `make mock-scenarios` copies `example/work-planner` into a temporary directory, writes the stubs it needs, and runs `pf` against the copy, with `-o -` so nothing is published into the tree.

**The design.**

- **One folder pair replaces every entry per file.** The run passes `-m protocols/=stubs/protocols/`, the copy's `stubs/` holding a stand-in for each protocol the mode reaches, and the bundle carries each stand-in where the real protocol's heading stood.
- **The stubs declare.** Under [Declared Inclusion](epic-a-declared-inclusion.md) a redirect reaches a document because the substitute declares, so each stub carries `prosiform`, and the check states that as part of what it demonstrates.
- **A stub folder holds only what is redirected.** A protocol the mode does not reach has no stub, and the check states which it wrote, so a run that reached more than the folder holds fails rather than passing over a real document.
- **The check compares the bundle's outline rather than its bytes.** Each protocol's heading is where the stub's heading stands, which is the property [AC6](epic-c-folder-mocks.md) states, and a byte comparison would restate every stub's prose in the check.
