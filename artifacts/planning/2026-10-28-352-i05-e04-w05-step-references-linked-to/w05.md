**Component:** example/work-planner

## Overview

Every reference the example corpus makes to one step of a procedure is a link to that step's sub-section, so the precision the sub-sections give is used where the corpus names a step.

## Problem

- **Steps named in prose link nothing.**
  W02–W04 gave every step a sub-section and an anchor, but 56 prose references across 22 files still name a step by number, such as `step 4`, or by role, such as `the report step`. A later insertion that renumbers a step leaves such a reference naming the wrong step, and nothing reports it.

## Proposal

Plan mode's `record its result as step 4 does` becomes `record its result as [4. Populate the Epics](#4-populate-the-epics) does`.

- **By name, not number.**
  A reference names the step's heading as its link text and links the heading's anchor. A reference to a step in another file links `<file>.md#<anchor>`. `pf`'s unresolved-link check reports a link left naming an old anchor.
- **Wording.**
  - A number reference takes the heading in place of `step N`: `continue at step 6` becomes `continue at [6. Return the Initiative's Findings](#6-return-the-initiatives-findings)`.
  - A role reference takes the heading in place of `the <role> step`: `continue at the report step` becomes `continue at [6. Report](#6-report)`.
  - A possessive role takes `of`: `the confirm step's interview` becomes `the interview of [6. Confirm](#6-confirm)`.
  - A pair links both steps joined by `and`: `repeat steps 2 and 3 once` becomes `repeat [2. Refresh the Evidence](#2-refresh-the-evidence) and [3. Check Readiness](#3-check-readiness) once`; `the sync and read steps` becomes `[2. Sync](#2-sync) and [3. Read the Evidence](#3-read-the-evidence)`.
  - A range links its first and last steps joined by `through`: `Repeat steps 3–9` becomes `Repeat [3. Repair the Format](#3-repair-the-format) through [9. Prepare Delivery Bases](#9-prepare-delivery-bases)`.
  - `align-mode.md`'s `continue at step 10, Re-run` drops the trailing name the link now carries.
  - The README names a step of the file it describes: `its publish step` becomes `its step [6. Publish](work-planner/modes/plan-mode.md#6-publish)`.
- **Left alone.**
  - A reference to several steps that names none: `the following steps`, `the steps below`.
  - A step referring to itself: `this step`, `this selection step`.
  - A reference to a caller's step, which no file can name: `the calling step`.
  - The README's `the step links`, which refers back to the excerpt quoted just above it, after the link that names it.
  - Generic uses: `whatever step it is on`, `a step its procedure names`, `step order`.
  - Text in code blocks and code spans, including the guidelines' `plan-mode.md#6-publish` example.
- **No numbered list.**
  No edit adds a numbered list outside a code block, which W06's step-shape guard rejects.
- **Fixtures.**
  Each usage-example bundle carrying linked prose is regenerated with the worktree's `pf`.
