## Overview

A pull request whose change touches no checked path runs no checks. This task makes that pull request carry a check result stating that its change was not checked, so a merge record says whether its change was verified.

## Problem

- **A skipped run and a passing run read alike.**
  Nothing on a pull request distinguishes a change that was verified from one that was never attempted, so the distinction survives only in a check made afterwards.
- **An absent check reads as pending.**
  A workflow that does not start posts no status, so a reader of the pull request cannot tell a skipped run from one that has not yet reported.

## Proposal

**The scene.** The workflow decides from the changed paths whether `make check` runs. The decision itself is a result a reader needs.

- **The decision is a reported result.**
  Every pull request into a branch carrying the build receives the checks' status. A change touching no checked path reports that the checks did not run and names why, under the same check name a run reports under.
- **One path set decides both.**
  The status reads the path set the trigger reads, so the run and its report cannot disagree about which changes are checked.
