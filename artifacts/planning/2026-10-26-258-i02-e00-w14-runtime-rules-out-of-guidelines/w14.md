## Overview

Guidelines are for revising the skill and are not read in normal practice. A running mode needs only what its bundle carries, so any guidance a mode follows at runtime belongs in `rules.md` or `conventions.md`. This row moves the one such rule, Interview, out of the guidelines.

## Problem

- **Runtime modes defer to the guidelines.**
  `rules.md` Decisions, five modes and the Epic Integration protocol link `[¬ Interview](../guidelines.md#modes)`, so a mode that asks the user a question depends on a document its bundle excludes.
- **The guidelines home every-mode rules in themselves.**
  Modes "Step rules" says a rule that binds every mode is added to that section; Protocols and Artifacts say the same of theirs, and Prose "One home per rule" lists the guideline sections as homes.

## Proposal

- **Decisions states how a question is put.**
  The Interview bullets join the Decisions rule in `rules.md`, beside its allowance and recording sentences; the rule leaves `guidelines.md`.
- **Runtime links point at `rules.md`.**
  Without the `¬` mark, since `rules.md` is bundled with every mode.
- **Guidelines name `rules.md` and `conventions.md` as the home of a rule that binds every run.**
  Their sections keep rules on how each kind of file is written.

## Implementation Findings

- **The plan-mode fixture carries no deferred link.**
  Its three deferred links (plan-mode, `rules.md`, Epic Integration) all named `guidelines.md#modes`; its description and clause list drop the deferral claim, which the `deferral/` fixtures cover.
- **The example README excerpts the plan-mode publish step.**
  Its input and output excerpts and the sentence explaining the deferred link follow the new text.
- **No other runtime guidance sits in the guidelines.**
  The Operations rules on execution location, scripts and bodies restate `conventions.md` as authoring rules for command specifications; no runtime file links them.
