## Overview

One make target names every failing check in one run, and a fixture's verdict tells a run that failed in itself from one whose output moved. Restatement reads that verdict to refuse a failed run, so this task is first on the chain to it.

## Problem

Each of two mechanisms reports part of whether a tree is sound, and each hides the next failure.

- **The first failure is the only one reported.**
  `make check` names its targets in one dependency line and stops at the first that fails, so each further failure costs another run.
- **A crash and a drift are one verdict.**
  The runner's result is false for a fixture whose output moved and for one whose run failed in itself, so a restatement driven from it records the fault as the expectation.

## Proposal

A change breaks two checks at once, and a fixture's run now ends in the contract's internal error.

- **One target reports the set.**
  `make check-all` runs every check `make check` names, whether or not an earlier one failed, then names each that failed and exits nonzero. `make check` keeps stopping at its first failure. One make variable lists the checks, so the two targets cannot name different sets.
- **A verdict has three states.**
  The runner's result carries a public `state`: the run met its manifest, its output moved, or it failed in itself. A run fails in itself when its fixture is not one the schema describes, it does not complete within its timeout, it ends on a signal, or it exits with the contract's internal-error status where its manifest declares another. Only a moved output is drift.
- **The report names the state.**
  A fixture's report opens with its state, so a reader of a red corpus run tells a crash from a drift without reading the differences.
