**Component:** checks/authoring.py

## Overview

A check reads the work-planner example and reports every departure from the authoring rules W01 stated, by file and area. Its first report is the findings scan the rollout rows W06–W09 start from, and W10 later makes it a guard under `make check`.

## Problem

No check reads an operation's Inputs or Outputs line, a Commands section, a command's place or a link's form. The extent of the change is a hand count, and nothing stops a regression.

## Proposal

A reviewer runs `make authoring` from the repository root and reads one report over `example/work-planner/`. It groups findings by area: modes, protocols, artifacts, references and the entry files beside `SKILL.md`.

### Finding Kinds

Each kind is one rule `example/work-planner/guidelines.md` states.

- **Inputs and Outputs.** From Operations › Inputs and Outputs.
  - An operation is a `###` heading under `## Operations`.
  - It is a finding when it has no `**Inputs:**` or no `**Outputs:**` line ahead of its first step.
  - It is a finding when either line is neither `None` nor a comma-separated list of links whose targets carry a fragment, the contract section.
  - It is a finding when either line runs onto a second line.
- **Commands section.** From Operations › Commands in steps, "No file has a Commands section".
  - Any heading titled `Commands`, outside literal content, is a finding.
  - Prose naming the rule, as `guidelines.md` writes it, is not.
- **Command placement.** From Operations › Commands in steps.
  - A command is a fenced block whose info string is `bash`, `sh`, `shell`, `zsh` or `console`.
  - It is a finding when it sits outside a step, or when its fence is indented.
  - A step is a step sub-section (`N. Action`), or an operation or `Procedure` section of one step written with no step heading.
- **File-relative links.** From Prose › File-relative links. A cross-file link is a finding when written:
  - as an absolute path;
  - as a repository blob or tree URL naming a file the checkout holds;
  - or as a path that resolves from the root the file's front matter declares but not from the file.

### Reading

- **Literal content.**
  - Fenced blocks are blanked before headings are read, indented fences included.
  - A fence closes only at a run of the same character at least as long, so a `````markdown` template holding a command fence is one block.
  - Links are read after fenced blocks, indented blocks and code spans are blanked, which is how `checks/links.py` reads them.
- **Size report.** Each file over 20 KB (20,480 bytes) or 8 operations is listed for a reviewer to read for a second subject. The list is not a finding.
- **Exit.**
  - Each finding prints as `path:line — kind: detail` under its area.
  - A table of counts by area and kind follows.
  - The check exits 1 when any finding exists.

### Placement

- **Make target.** `make authoring` runs it under `python3`, since it reads the standard library alone.
- **Outside `make check`.** `make check` leaves it out; W10 adds it once the example passes.
- **Documentation.** `checks/README.md` carries its row, which `make tables` requires of the target.
- **Test file.** The tests are `checks/tests/test_authoring_check.py`. `checks/tests/test_authoring.py` already holds the invocation-guidance audit, and a second module of that name cannot share the suite.
