**Component:** src/prosiform/cli.py

## Overview

A run writes its bundles into `<entry name>.bundles/` under the folder `-o` names, and the swap only ever replaces a folder of that name. An author folder named like the entry — `states/` beside `states.md` — is then never a run folder, so it is neither refused as one nor replaced.

## Problem

- **The run folder can be an author's folder.**
  [`execute`](https://github.com/m2ux/prosiform/blob/f006e0b8d7a3c2fdc23627df67809fe379ffb717/src/prosiform/cli.py#L2123) names the run folder by the entry's stem alone, so `pf states.md` beside `states/` names `states/`. Holding a source the run reads, it is refused and the run needs `-o`; holding none, it is replaced whole.
- **A fixture carries the workaround.**
  `fixtures/rewriting/a-state-diagram-click-in-each-form` runs with `-o ..` only to step around that collision.

## Proposal

From `source/`, `pf states.md` writes `states.bundles/states.bundle.md` and leaves `states/` as it was.

- **The suffix.**
  The run folder is the entry's derived name plus `.bundles`; the bundles in it keep their derived names.
- **Only a run folder is replaced.**
  The swap renames aside and removes only the folder of that name, so nothing an author names without the suffix is touched.
- **The workaround goes.**
  An author folder named like the entry is no run folder, so it meets no refusal and the state-diagram fixture runs without `-o`. A run folder holding a source the run reads — a previous run's bundle linked as a source — is still refused, since the swap would remove it.
- **The contract moves with the build.**
  The design's CLI, Automatic output names and Publication clauses, the pin, `invocation.md`, the glossary and the epic record's Output section state the suffix.
