**Component:** main:checks/reachability.py, main:checks/tests/test_reachability.py

## Overview

The reachability check counts a definition reached where the package calls or references it, not where a local variable, parameter or exception name shares its name.

## Problem

- **Any name counts as a caller.**
  A definition is reached when the package writes its name anywhere, so `cli.Parser.error`, which `argparse` calls, reads as reached through `except OSError as error`.
- **A dead function can hide behind a common name.**
  A function named like a local variable elsewhere in the package passes whatever calls it.

## Proposal

A function loses its last caller and keeps a name a loop variable also uses.

- **Bindings are not references.**
  A name written as an assignment target, a parameter, an exception name or a loop variable binds it and reaches nothing; a load of the name, an attribute or an import reaches the definition.
- **Framework hooks are listed by reason.**
  `cli.Parser.error` joins the written list of hooks, with argparse as its caller.
