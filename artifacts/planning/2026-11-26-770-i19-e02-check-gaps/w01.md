**Component:** main:checks/documents.py, main:checks/tests/test_documents.py

## Overview

The shared reading blanks a fenced block wherever it is indented, so the link check passes over a link form inside a fence written under a list item.

## Problem

- **A fence is found at the left margin alone.**
  The fence reading matches a fence line that opens the line, so a fence indented under a bullet is read as content and its link forms are resolved as references.
- **Two readings decide one kind of question.**
  Indented code blocks are found by the build's CommonMark parser and fenced ones by a pattern, so the two can disagree on one document.

## Proposal

A bullet explaining a command shows the Markdown it writes in an indented fence beneath it.

- **One parser finds every code block.**
  The CommonMark parser that finds indented code blocks also yields fence tokens; the reading blanks the lines of each, and the pattern is removed.
- **Tables keep their reading.**
  The table check reads documents with fences blanked as it does today; its tests confirm no table moves.
