# W09 — Refuse a Run That Could Not Complete

> Work item · Created 2026-11-01

**Component:** evals/diagram-following/scorer

## Overview

The eval's outcome rules — the run's state, the baseline it writes, and the set check — held to what the run observed, so a run that could not complete is refused rather than reported as a result.

## Problem

`sequential_set` passes a record in which the set was split across two messages. A budget-stopped run whose started sessions all errored reports `completed` with a 0% table. `--write-baseline` accepts a run that started nothing and cuts the committed baseline to zero cells.

The finding is recorded as findings 9, 23 and 24 in the [merged-epic review](../2026-10-31-merged-epic-review/findings.md), with its site and the case that failed.

## Analysis

- **The set check counts openers, not messages.** `dispatched` passes a set when exactly one of its members has `together` false. `together` says only that a start shares a message with the start above it, which may be a start the scenario does not expect. A set whose opener shares a message with an unrelated earlier start, and whose second member opens a later message, has one opener and passes; so does a set whose members sit in two messages with an unrelated start opening the second. Starts in one message are contiguous in the record, so a set is one message exactly when no start between its first member and its last opens a message.
- **The refusal requires the whole matrix to have started.** `outcome` returns `completed` whenever a session was not started. A run its budget stopped after starting sessions that all errored therefore reports a table of `errored` failures, the case finding 23 records. The existing test `test_a_run_the_budget_stopped_part_way_is_not_refused` asserts that defect.
- **The baseline write checks the state, not the cells.** `main` refuses `--write-baseline` only for a refused run. A completed run with no session record writes a baseline of zero cells over the committed one.

## Proposal

**The scene.** Each defect above was found by the review of fifteen merged epics, and each has a case that reproduces it. The task repairs the eval's outcome rules and carries each case, so the defect cannot return unnoticed.

**The design.**

- **A set is one message.** A set passes only where its earliest member starts first and no start between it and each later member opens a message, so every later member starts alongside the opener.
- **A run whose started sessions all errored is refused.** The refusal is decided over the sessions the run started, whether or not its budget stopped it, and carries the first errored session's own `result` text. A run that started no session has no agent reason and is not refused by this rule.
- **A baseline is the cells the run measured.** `--write-baseline` writes only where the report holds at least one cell, and names the run's reason when it was refused. One rule covers the refused run, which holds no cell, and the run that started nothing.
- **The case ships with the fix.** Each defect's case is a test the repository runs under `make harness`, and the README states each rule as the eval holds it.
