## Overview

Confinement of every source read to the allowed root by access, and refusal of a source reached through a symbolic link below that root.

## Problem

A path validated as a string and the path an open arrives at are two different paths. Every segment a reference writes can sit inside the root while the file the open reaches sits outside it, because a symbolic link below the root is resolved by the open and by nothing ahead of it. A check on the normalized string alone therefore confines a reference that escapes.

The build reads each source by joining the normalized path to the root and resolving the result, which follows every link in it. An escaping link is then caught by comparing the resolved path with the root — the right refusal under the wrong name, since the run reports a path outside the root rather than the link policy it broke. A link whose target the root holds is followed in silence, so one document is reachable by two paths and a dependency base varies with which alias the closure discovered first.

## Proposal

The allowed root is canonicalized once, and every source is read by descending its root-relative path from that directory one segment at a time, each segment opened against the directory above it under `O_NOFOLLOW`. A segment that is a symbolic link fails with `E_SOURCE_SYMLINK` whatever it points at. The walk is the confinement, so an empty segment, a `.` and a `..` are refused rather than descended, and a path a normalization never produces still cannot leave the root.

### The Component That Holds It

`access.py` is a new module of the package. `closure.py`, which [W01](https://github.com/m2ux/prosiform/pull/62) introduced, reaches no filesystem by design: it says what document a reference names, over one string and a base, and every comparison in the epic compares what it returned. Rooted, no-follow access is the opposite concern — it reaches the filesystem and says nothing about identity — so holding both in one module would give it two reasons to change and would make the normalization untestable without a tree.

The module answers one question: what are the bytes of this root-relative path, read from this root without following a link. It raises one of three refusals and the command names the code and the status each returns. The command's own reading stage shrinks to a call and three handlers.

Rooted, no-follow access is what the policy requires, so the module declares the environment that offers it: a platform without `O_NOFOLLOW` and `O_DIRECTORY` fails at import rather than reading a source through a check that quietly weakened to a string comparison. That is the design's "fail or declare a narrower supported environment", made self-enforcing.

### The Walk

| Step | What the module does |
| --- | --- |
| 1 | Refuses a path carrying an empty, `.` or `..` segment, which no root-relative path the normalization produces holds |
| 2 | Opens the canonicalized root as a directory; a link at or above the root is the caller's own spelling of it and is resolved there |
| 3 | Opens each directory segment against the directory above it, under `O_NOFOLLOW` and `O_DIRECTORY` |
| 4 | Opens the last segment against its directory, under `O_NOFOLLOW` |
| 5 | Requires the opened file to be a regular file, so a directory, a device and a socket each name no document |

A refused open is named from the directory entry itself: `O_NOFOLLOW` reports a link with the error a directory loop also carries, so an `lstat` of the segment the walk declined to follow says which it was. The open is the safeguard; the entry is only how the refusal is worded. A fault that is neither a link nor a missing entry is the operating system's and is raised as it arrived, which the command reports as an unexpected internal error.

### What Each Refusal Returns

| Refusal | What it is | Code | Status |
| --- | --- | --- | --- |
| `Symlinked` | A segment below the root that is a symbolic link | `E_SOURCE_SYMLINK` | 1 |
| `Outside` | A path carrying a segment the walk cannot hold under the root | `E_SOURCE_OUTSIDE_ROOT` | 1 |
| `Absent` | A path under the root naming no regular file | `E_TARGET_NOT_FOUND` | 1 |

No code is added. The catalogue is complete at 21 codes and this row leaves it at 21: `E_SOURCE_SYMLINK` and `E_SOURCE_OUTSIDE_ROOT` are both already in it, and `E_SOURCE_SYMLINK` is the one this row draws for the first time.

The command's resolve-and-compare check goes with it. A normalized path carries no `..` and no leading separator, so the only way the old comparison could fire was a link the walk now refuses first and refuses by name. Leaving it in place would mean two paths enforcing one rule, with the weaker of them deciding which code a run reports.

### Where `E_SOURCE_OUTSIDE_ROOT` Is Drawn

Under no-follow access the two halves of the criterion are drawn by two mechanisms and no case belongs to both. A normalized path leaving the root is refused by the normalization, before anything is opened; a path reaching a source through a link is refused by the access, at the segment carrying the link. There is no third case in which a run opens a file outside the root, because the only way out of the root that a normalized path can take is a link, and the link is refused whatever it points at.

## Criteria

- **AC5.** A reference whose normalized path leaves the allowed root, or reaches a source through a symbolic link below it, fails with its declared error code, as the confinement fixtures show.

## The Fixtures

The corpus states the contract, so the criterion is proved by fixtures rather than by this build's tests. Git records a symbolic link as its own object, so a source tree declares one rather than a file holding a path, and each link's target sits inside the fixture's own directory.

| Fixture | Declares |
| --- | --- |
| `confinement/a-symlinked-source` | A source that is a link to a document outside the root refused with `E_SOURCE_SYMLINK` |
| `confinement/a-symlinked-directory-below-the-root` | A path whose every written segment is inside the root, reaching its source through a directory link, refused |
| `confinement/a-symlink-to-a-document-inside-the-root` | A link refused although the root holds its target, so one document is reached by one path |
| `confinement/a-symlink-chain-below-the-root` | A link to a link refused at the first link, so no chain is walked to a target |
| `confinement/a-parent-segment-above-the-root` | An entry reference walking above the root refused with `E_SOURCE_OUTSIDE_ROOT`, the document outside never read |

Under D36 the boundary and adversarial cases were measured rather than assumed, and none carries `awaiting`. A directory link, a link chain and a link whose target the root holds are each delivered by this row and declared as passing fixtures. A hard link is not a case: it is a second name for one inode and no filesystem call distinguishes it from the file it names, so the policy has nothing to refuse and the unit tests hold it to reading as the document it is. Git stores no hard link either, so a fixture could not declare one.
