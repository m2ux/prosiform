**Component:** `src/prosiform/source.py`

## Overview

Link ownership as the code states it. A position's owning section is read by nobody the product runs, and the one rule ownership used to decide — whether a link was a direct self-reference — is no longer a rule the contract has. The component states what decides a reference's destination, and the three documents describing ownership say that one thing.

## Problem

- **`source.owner` has only its tests.**
  It answers which eligible section a position belongs to. `cli.self_referent()` was the one production caller, and it went with `E_SELF_REFERENCE`. Five unit tests hold the function upright, so the suite is green over a path no run reaches.

- **`limits.defaults()` has nobody at all.**
  Every budget at the number the profile declares, assembled by a function the build never calls and no test names. The command line builds its own `Limits` from the options it parsed.

- **The repository's lint cannot see either.**
  `ruff` reports an unused import and an unused local, not a module-level function with no caller, so both are invisible to every automated check the repository runs.

- **Three documents describe ownership as load-bearing.**
  The design carries a **Link ownership** clause, a **Preamble ownership** clause and an **Ownership stability** invariant; `candidate`'s module prose cites `source.owner` when explaining why that invariant needs no candidate check; and the `ownership` fixtures declare their cases against both clause names. A reader of any one is told a position decides something.

## Proposal

- **Ownership decides nothing, so the function goes.**
  Under position-states-a-dependency a link naming the section it sits in, or an ancestor of it, resolves to that content's destination like any other reference the bundle carries. The destination comes from `cli.destination_map`, which is keyed by the identity a reference resolves to — a path and an optional fragment — and nothing about where the link sits enters that key. Ownership had one consumer, the self-reference classification, and that classification has no caller to answer. `source.owner` and its five tests go, and `limits.defaults()` goes with them as the same fault in another module.

- **The contract states position independence instead.**
  The design's **Link ownership** and **Preamble ownership** clauses become one clause saying that a reference resolves by its target alone wherever it sits, with the preamble's membership of the document node kept because a whole-document selection still carries it. The **Ownership stability** invariant becomes **Destination stability**: a reference's destination is the one its target was assigned, before and after overlap consolidation.

- **One description survives, in three places.**
  `candidate`'s note names the destination map as what holds the invariant, rather than a function that no longer exists; the `ownership` fixtures declare the clause under its new name and describe the case as a destination read from a target; and `source` and `cli` drop the ownership paragraphs that explain a rule neither module applies.

- **The product's remaining unreached functions are named rather than assumed.**
  An audit over the package's definitions is run and recorded, so what the criterion claims is read off a listing. What it leaves is the console-script entry point, an `argparse` hook, three dunders the language calls, and the `delivery` wrapper, which is a public interface with no in-repository caller and is deferred as its own row.
