**Component:** evals/diagram-following/workflows

## Overview

Four dispatch workflows in the diagram-following corpus, each written in the two forms the report compares: the compiled form whose links carry `⇉` and `⫽`, bundled by `pf` into a bundle set, and the authored-protocol form whose state documents write the dispatch protocol as prose. The reader gains the trace a bundle set's walk produces, so a scenario names the sub-agents a correct agent starts, in what order, and what each returned.

## Problem

- **No scenario names a dispatch.**
  The corpus's three workflows walk from an entry state to a terminal one and their `scenarios.toml` names inputs and a path. A scenario has no way to state the trace a dispatching source produces.
- **No form carries a protocol.**
  Every form's entry is bundled with `pf` and the reader asserts the bundle set is one file, so a form that publishes four bundles is a corpus fault rather than a form.
- **The protocol is unmeasured.**
  With no scenario dispatching and no form holding a protocol, nothing separates what `pf` compiles around a dispatching link from the same protocol an author wrote.

## Proposal

The four scenarios join the corpus as their own workflow, `dispatching`, carrying the same `diagram/`, `prose/` and `linked/` forms the existing workflows hold and adding the two dispatch forms beside them.

- **Scenarios.**
  A chain, a parallel set, a set beside a dispatch, and a dispatched target returning a question. Each names its inputs and the trace its bundle set produces: the dispatch, in order, of each state's targets, each with what it returned.
- **The compiled form.**
  `dispatch-sea/` holds the source tree whose links carry `⇉` and `⫽`. Each state document's step dispatches its next hop, so `pf` compiles the state's targets into bundles of their own and emits the Prosiform section and a dispatch sub-section around each. `scenarios.toml` names inputs and a path as it does for every workflow, and a `[[scenario.trace]]` table names the dispatch trace.
- **The authored-protocol form.**
  `dispatch-authored/` holds the same state documents with the dispatch protocol written into each state's section as prose, and only its entry carrying links, so one bundle publishes and the protocol is the author's text rather than `pf`'s.
- **The reader.**
  A form is declared bundled or unbundled and dispatching or not, so `bundle()` returns a bundle set rather than one file and a scenario's trace is read beside its path. The trace's expected value is a walk of the bundle set the source produces.
- **The report.**
  A scenario's trace enters the session record beside its verdict, and the report's per-model, form and scenario table gives each dispatch scenario's pass rate, which is what AC2 asks to see.
