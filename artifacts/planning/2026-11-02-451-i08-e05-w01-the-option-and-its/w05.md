**Component:** main:src/prosiform/limits.py

## Overview

The budget entries the grammar refuses: an unknown name, a malformed entry, a budget named twice and a nesting budget below its floor, each `E_INVALID_USAGE` with exit status `2` before any source is read.

## Problem

A name-keyed option admits faults a lettered one could not.

- **A name can be mistyped.** `--budget key=1` names no budget, and a caller needs the eight admitted to correct it.
- **An entry can be malformed.** An entry with no `=`, an empty name or a value that is no positive decimal integer states no budget and no figure.
- **A budget can be named twice.** Two entries for one ceiling state one thing twice, and only one order would make a run reproducible.
- **A nesting ceiling below 2 bundles nothing.** A `prosiform` declaration is a mapping inside the frontmatter mapping, two YAML collection levels deep, so `nesting=1` refuses every document that declares.

## Proposal

**The scene.** `budget_entry` reads one `NAME=VALUE`, and the `--budget` action collects the entries into one mapping.

**The design.**

- **Each fault is the parser's own error.** The value parser raises `ArgumentTypeError`, so a refusal is `E_INVALID_USAGE`, exit status `2`, naming the entry.
- **An unknown name names the eight.** The message lists the names `NAMED` holds, from the one table.
- **The duplicate is refused where entries are collected.** `BudgetEntries` refuses a budget already in the mapping, naming it.
- **The floor is a budget's own figure.** `Budget.least` is 1 for every budget but `nesting`, whose 2 is the least under which a declaring document can be read, and the parser refuses a figure below it, naming 2.
