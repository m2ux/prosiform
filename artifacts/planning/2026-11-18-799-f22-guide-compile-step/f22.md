## Overview

The guide `pf` prints tells an agent to run `pf` on a link in a bundle as written, without saying which links that covers. A `⇉` or `⫽` dispatch link points at a bundle the run has already compiled, which the agent hands on, so the agent runs no `pf` on it.

## Problem

- **The agent's `pf` step reads as covering every link.**
  Only a later clause of the guide says that a `⇉` link names a bundle given to a sub-agent, so an agent can read the step as telling it to run `pf` on a published `⇉` link.
- **Agents run `pf` on dispatch links.**
  In the dispatch-brief run (#792), two sessions ran `pf` on a published `⇉` link and were scored `overcompiled`.

## Proposal

- **One short clause.**
  The guide's step ends "never on a ⇉ or ⫽ link", and `invocation.md` states the step "though never by the agent on a `⇉` or `⫽` link". No other wording changes, and neither does what `pf` compiles.
