## Overview

The checks that hold the repository's documentation to what the project declares and to the files it points at: a comparison between the README tables that enumerate the project's commands and dependencies and the `Makefile` and `pyproject.toml` that declare them, and a link check that reads every README the repository owns.

## Problem

`prototype/README.md` enumerates the build's dev dependencies and its check commands in tables, the root `README.md` enumerates every check command, and nothing compares either with its source. A dependency added to `prototype/pyproject.toml` and a target added to the `Makefile` both leave a table stating a set the project does not have, and every check passes. Both went stale on the first change that touched them: #40 added `jsonschema` and `make corpus`, and a second pull request was needed to catch the tables up. A reading by hand is what caught it.

A comparison that only reports an omission is half a check. A dependency dropped from the project stays documented forever, and a reader installs what the table names.

The link check reads the root README alone. The repository owns five — the root, `checks/`, `docs/`, `fixtures/` and `prototype/` — and four of them gained links as their tree gained content, so their references resolve only as long as someone reads them. A check that names the documents it reads also has to be edited whenever a tree is added, which is the moment the new tree's README is least likely to have been read.

A reader installs from a README and invokes what it names, so a stale table or a dead link is a wrong instruction rather than an untidy one.

## Proposal

Both checks read the same set of documents — every README git tracks — and `checks/documents.py` is the one place that set is defined. It also holds the fence-aware reading the two checks share: blanking fenced blocks, whose contents are examples rather than content, and parsing pipe tables into a header and its rows.

### The Table Check

`checks/tables.py` runs from `make tables`. It compares two declaration sets with the tables that enumerate them, and fails in both directions, naming the item and the side it is missing from.

- **A table is located by its header, not by its position.** A table whose header carries a cell `Command` enumerates commands; one whose header carries a cell `Declared` enumerates declarations. Nothing names a document, a section or a heading, so a table moved within a README, or a README added later, is read without the check being edited. `fixtures/README.md` carries a `Declared by` column that names error codes, and an exact header match leaves it alone.

- **A row maps to a declared item through one cell.** A `Command` cell names exactly one target, written `make <target>`; a cell that names none fails as a row naming no command. A `Declared` cell reduces to a name — a link becomes its text, a code span its contents — and the `Value` cell beside it holds the version the project pins. A package name is compared normalized, as the packaging ecosystem compares one, and reported as the table writes it.

- **The declaration sets are the project's own.** The commands are every rule the `Makefile` declares. The declarations are `requires-python`, written `Python` in a table, and every entry of `[project] dependencies` and `[dependency-groups] dev` in `prototype/pyproject.toml`, read through `tomllib` from the standard library.

- **There is no exclusion, so there is no escape hatch.** Every target the `Makefile` declares is named by some command table, `make check` among them, which gains a row stating what it runs. The one name the check does not treat as a target is a make special target, which begins with a dot and is a directive rather than a command; the check prints the set of targets it compared, so what it read is visible in a passing run rather than only in its source. Internal targets are a category this `Makefile` does not have, and the check is written so that creating one means documenting it.

- **Both directions are the same comparison.** A declared item no table names and a table row the project does not declare are the two differences of two sets, and a row naming another version than the project pins is the third failure the comparison reports.

### The Link Check Widened

`checks/links.py` reads every README `checks/documents.py` finds, in place of the one it was given by default. The resolution rules are untouched: a fragment against the document's own headings, a repository-relative path against the working tree, a blob or tree URL into this repository against the git ref it names, and any other address over the network, which `--online` turns on and `make links` always passes.

Discovery is `git ls-files` filtered to the name `README.md`, so a document counts when git tracks it — the same rule `checks/layout.py` applies to a tree, and the rule that matters, because an untracked file is invisible to a fresh checkout. A tree added later brings its README into the check by being committed.

### The Documentation the Change Makes Untrue

The root README's command table claims `make links` checks the references this README carries, `checks/README.md` claims the same, and both enumerate a set of checks that is about to grow. Each is corrected with the behaviour it describes.
