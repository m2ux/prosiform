## Overview

Consolidation of overlapping selections into the region that contains them, one arrangement whatever order a run was asked in, and the output check the completed closure makes possible.

## Problem

A section selected directly and again inside a whole-document inclusion is one region, and emitting it twice makes the bundle disagree with its sources. A bundle whose arrangement followed the order its entry references were written in, or the order its dependencies were discovered in, would make the same selection compile to different bytes.

A run can also write its bundle over a source it bundled. The check refusing an `--output` naming an input source reads the entry references, before traversal, so a document reached as a dependency is not covered. Nothing is corrupted — every source is read whole before anything publishes — but the file is overwritten and lost.

## Proposal

A selection contained within a larger selection is represented by the larger region, and the larger region's own references are traversed before compilation completes. Parsed-file caching is kept separate from included-region tracking, and the mapping from every selected target to its consolidated destination is retained so an entry target stays identifiable when its content is subsumed.

The output check moves from the entry references to the completed closure, and locates a source by its root-relative path under the canonicalized root rather than by resolving it.

## What the Base Already Carries

Three of the five behaviours this row plans were measured on the base before anything was built to them, and each already holds. The row's work on them is the corpus evidence the criteria name, not an implementation.

| Behaviour | What the base does | Why |
| --- | --- | --- |
| A child selected, then its whole document | Emits the larger region alone | `selection()` reads a whole-document reference as every region of the document, and a set of region identities carries no duplicate |
| The larger region's own references | Resolves them | `traverse()` recomputes every group's selection each round, so a round that widens a group reads the widened content for marks |
| A subsection named beside its section | Emits the section once | A section's regions are a contiguous run of the document's regions, and a subsection's run sits inside it |
| Entry argument order | Decides nothing | `contributing()` keys groups by the path the normalization produced and sorts them; `group()` derives entries by walking the regions it emits |
| Dependency discovery order | Decides nothing | The same sort, over the closure rather than over the frontier |

The consolidation rule is therefore the set of region identities a group's references select, and the retained target mapping is `Selection.named`: the headings an entry reference resolved to, kept apart from the content so an entry stays identifiable when a larger region subsumes it.

## The Output Check the Closure Completes

The check belongs here because this row walks the completed closure, which is the first point at which the full set of paths a run read is known. It moves from the entry references to that set.

It was found while delivering [W03](https://github.com/m2ux/prosiform/pull/77) and left there deliberately: completing it needs the read paths known after the closure, and W03 was the row that must not reintroduce a path resolution, the symlink hole [W02](https://github.com/m2ux/prosiform/pull/71) had just closed.

**The identity the check compares is a location, not a resolution.** A source is located by joining its root-relative path to the canonicalized root and by nothing further. The read descends that path one segment at a time following no link, so every segment names the directory entry the walk opened and the join is already the file the bytes came from. `sources()` resolved that join, which is what the row removes:

- A resolution crosses a symbolic link the read refuses, so it names a file the run never opens and answers a question about the link rather than about the source.
- Measured on the base: `--output real.md alias.md`, where `alias.md` links to a document outside the root, exited 2 with `E_INVALID_USAGE` — the resolution had claimed the link's target as an input source. It now exits 1 with `E_SOURCE_SYMLINK`, which is the policy the reference meets first.

**The check runs after the closure, so a run whose sources it cannot read reports that instead.** A command line naming both an unresolvable reference and a dangerous output now reports the reference. Nothing is published on either path, so the output file is as safe under the later check as under the earlier one, and the diagnostic names the fault that stopped the run.

## Why AC10 Stays Unticked

A heading-only *structural ancestor* is [I00:E09:W02](https://github.com/m2ux/prosiform/issues/60)'s work and the build emits none: `ancestor` appears nowhere in `src/`, `checks/` or `fixtures/`. AC10 turns on a link to a section **present only as** such an ancestor, and no run on this base can produce that state, so no run can demonstrate the promotion.

Half of the criterion does hold and was measured. A marked link to a section the run has not selected expands closure to that section's body, including a fragment-only link from a descendant back to its own ancestor section. What is missing is the ancestor's heading-only presence beforehand, and the replacement of it.

`ancestor-promotion/a-link-to-a-heading-only-ancestor` declares the whole criterion and carries `awaiting = "I00:E09:W02"`. Its source outline is the design's own structural-ancestor example: two sections, each with a subsection, both subsections selected, one of the two sections reached by a marked link through a second document. The expected bundle carries that section's heading and body, and the other section's heading alone. The run on this base differs from it by exactly the heading-only ancestor, so the marker names work that is real and the fixture lifts it when that work lands.

## What This Row Does Not Do

**It adds no error code and no contract term.** The output check keeps `E_INVALID_USAGE`, which the design already declares for an output path naming an input source, so the catalogue the two branches share is unmoved at 21 codes and the vocabulary check is unmoved at 34 terms.

**It names no group through the filesystem.** Group identity stays the path the normalization produced. The resolution this row removes was the last one `cli.py` performed on a source path.
