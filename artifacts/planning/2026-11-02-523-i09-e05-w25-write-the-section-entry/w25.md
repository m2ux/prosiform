**Component:** main:evals/diagram-following/workflows/section-entry/scenarios.toml

## Overview

A diagram-following workflow compiled from an entry naming one section of its handbook, so the live run measures an agent following a bundle built from a `document#fragment` entry.

## Problem

- **No eval workflow is compiled from a section entry.**
  Every workflow is compiled from its whole entry document, so the eval never measures a bundle that leaves a document's other sections out.
- **The corpus proves the bytes, not the reading.**
  A fixture shows what `pf` emits for a section entry; only a session shows an agent following it.

## Proposal

**The scene.** A workflow is a directory under `workflows/`, its forms beside a `scenarios.toml` naming each scenario's inputs and path. The harness compiles each form from the entry `scenarios.toml` names (W33).

**The design.**

- **A handbook of two sections.**
  `workflow.md` is a handbook: `Onboarding` draws the workflow (Enrol, Equip, Greet) and `Upkeep` links a declared maintainers' note. The note is benign, so a `tree` session reading the whole handbook can still pass.
- **The entry names one section.**
  `scenarios.toml` names `workflow.md#onboarding`, so the bundle carries the Onboarding workflow and its states and none of Upkeep or the note.
- **One scenario.**
  `document-fragment` walks Enrol, Equip, Greet.
- **The diagram form alone.**
  The feature lives in the entry, so the workflow takes `bundle` and `tree`; prose and linked forms would measure nothing the feature adds.
