**Component:** main:evals/diagram-following/workflows/section-composition/scenarios.toml

## Overview

A diagram-following workflow whose steps compose sections beneath their own headings, one scenario per permutation, so the live run measures an agent following a bundle built with composition.

## Problem

- **No eval workflow composes a section.**
  The existing workflows predate composition, so the eval measures bundles that never place one section beneath another.
- **The corpus proves the bytes, not the reading.**
  A fixture shows what `pf` composes; only a session shows an agent following it.

## Proposal

**The scene.** A change workflow: Lodge decides on `inputs/kind.txt` between Configure and Assess, Assess decides on `inputs/scope.txt` between Migrate and Amend, and each reaches Close.

**The design.**

- **Several sources merged under one step.**
  Configure composes `Inputs` from the settings and the schema documents, one destination section holding both contributions. Scenario `merged-sources`.
- **A deferred occurrence later activated.**
  Migrate defers the migration's steps with `[¬→]`, so the bundle carries the `[↳ Steps](reference/migration.md#steps)` line, and `pf reference/migration.md#steps` activates them in a run of its own. The step names that later `pf` run. Scenario `deferred-occurrence`.
- **Nested composition.**
  Amend composes the amendment's checks, whose own directive composes the lint rules beneath that contribution. Scenario `nested-composition`.
- **A path every default cell can follow.**
  Each state's action and transition sit in its own section, so no path depends on composed or activated content. The default harness carries no shell and a bundle session holds no sources, so no default cell can run the activation; `deferred-occurrence` proves the agent completes the path through a deferred occurrence, and the harness test proves the activation.
- **The diagram form alone.**
  The workflow takes `bundle` and `tree`.
