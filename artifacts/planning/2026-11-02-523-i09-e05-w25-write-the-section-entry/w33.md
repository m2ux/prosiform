**Component:** main:evals/diagram-following/workflow.py

## Overview

The harness compiles each workflow from the entry its `scenarios.toml` names, so a workflow can be compiled from one section of its entry document.

## Problem

- **The entry is fixed.**
  The harness runs `pf workflow.md` for every form, so no workflow can be compiled from a `document#fragment` entry, and W25 has no bundle to measure.
- **The entry's bundle name is fixed.**
  The runner and the tests find the entry's bundle at `workflow.bundles/workflow.bundle.md`, which a section entry does not write.

## Proposal

**The scene.** `bundle()` runs `pf` in a form's directory; `prepare()` writes the entry's bundle into the session's workspace as `workflow.md`.

**The design.**

- **An `entry` key.**
  A top-level `entry` in `scenarios.toml` names the reference every form is compiled from, `workflow.md` when absent.
- **The derived bundle name.**
  `entry_bundle()` derives the entry's bundle path as `pf` names it: the path without its suffix, separators as `_`, and `__<fragment>` for a section.
- **Callers take the workflow.**
  `bundle(workflow, form, output)` compiles from the workflow's entry, and the runner names the entry's bundle by `workflow.entry_bundle`, so a section entry's session still reads `workflow.md`.
- **The eval page states it.**
  The README states the `entry` key, the `undeclared/` directory and the default matrix with the feature workflows.
