**Component:** main:src/pyproject.toml

## Overview

A `release/v0.17.0` branch from `main` holds one commit setting the selected version, so the release names the revision this build implements.

## Problem

- **`main` declares a version whose contract it has superseded.**
  `src/pyproject.toml` and `src/uv.lock` name `0.16.0`, and the `0.16.0` corpus fails against the build at `main`.
- **A release carries its bump as its own commit.**
  The previous release is one commit beyond its parent, and the branch stays after the merge.

## Proposal

**The scene.** The release branch carries the commit both tags name.

- **One commit.**
  It sets the version in `src/pyproject.toml` and the `prosiform` entry in `src/uv.lock`, and nothing else.
- **The number is measured.**
  The `0.16.0` declaration is the previous revision, and its corpus fails against this build, so the minor moves once: `0.17.0`.

| Plan | Settle the branch name from the number. |
| Implementation | Cut `release/v0.17.0` from `main` and commit the bump. |
| Review | Confirm the commit changes the two files alone. |
