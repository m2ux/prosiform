**Component:** main:src/pyproject.toml

## Overview

A pull request raises the release branch into `main` with every check passing, for the user to merge.

## Problem

- **The version commit lives on the release branch.**
  `main` reports the superseded version until the branch is merged.

## Proposal

**The scene.** The release branch holds the tagged version commit.

- **One pull request.**
  From `release/v0.17.0` into `main`; merging it is the user's, since `main` requires an approving review this session does not supply.
- **The checks are the branch's own.**
  The pull request's check run is read from the head commit the tags name.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Confirm the branch holds the tagged commit alone beyond `main`. |
| Plan | Settle the pull request's title and body. |
| Implementation | Raise the pull request. |
| Review | Read its checks. |
| Test | Inspect the pull request's head, base and open state; separately record every check's conclusion. |
