**Component:** main:src/pyproject.toml

## Overview

Annotated `contract/v0.17.0` and `python/v0.17.0` tags name the version commit, their messages following the previous pair.

## Problem

- **A release is named by its tags.**
  A production build names a contract revision by its `contract/` tag.
- **The messages are the release's record.**
  Each states what the previous pair's states, for this revision.

## Proposal

**The scene.** `contract/v0.15.0` and `python/v0.15.0` are annotated, with a subject line and a paragraph each.

- **The contract tag.**
  Its subject, profile, corpus count and the previous corpora's results.
- **The build tag.**
  The contract it implements, its profile, its package version and its validation counts.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Read the previous pair's messages and the counts the release build reports. |
| Plan | Draft both messages. |
| Implementation | Tag the version commit and push both tags. |
| Review | Compare each message with its predecessor's shape. |
| Test | `git tag -n` over both tags. |
