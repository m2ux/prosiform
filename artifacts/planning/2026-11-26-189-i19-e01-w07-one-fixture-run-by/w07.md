## Overview

The corpus runner takes the identity of each fixture to run and reports those fixtures' verdicts by the comparison and under the report the corpus run gives. A session delivering a change that moves one fixture's bytes reads that fixture's verdict without a run of every fixture, and without invoking the build by hand outside the runner's comparison.

## Problem

- **The runner takes no fixture to run.**
  `checks/corpus.py` accepts `--awaiting WORK` and nothing else, so a session reads one fixture's verdict from a run of the whole corpus.
- **Reading one fixture by hand is not the check.**
  Invoking the build in a fixture's directory skips the byte comparison, the ordered diagnostics and the undeclared-file reading the runner performs.
- **A result names a fixture outside the default corpus by its absolute path.**
  `runner.run_fixture` reads identity against `fixtures/` whatever corpus the run walks, so a corpus written for a test reports paths rather than identities.

## Proposal

A session has just moved a fixture's bytes and wants to know whether that fixture holds, by the check the corpus run applies.

- **The runner takes identities as positional arguments.**
  `corpus.py identity/whole-document` runs that fixture alone and prints its verdict line, any differences and the count, as the corpus run prints them.
- **Several identities may be named; a family directory names no fixture.**
  Matching an identity whole is the simplest rule that meets the criterion. Several names cost nothing extra and serve restatement, which selects fixtures the same way. A family is left out: a prefix rule widens what a name means and nothing yet asks for it.
- **An identity no fixture carries is refused before anything runs.**
  The request fails, naming each such identity, and nothing is printed to standard output.
- **Selection lives with discovery.**
  `manifests.selected` resolves names against `manifests.fixtures` and raises `UnknownFixture`, so `checks/restate.py` reads the same selection.
- **A result names its fixture under the corpus being run.**
  `run_fixture` and `outcome` take the corpus, so a test corpus reports identities as the real corpus does.
- **A report and a run are exclusive.**
  `--awaiting` and identities form one mutually exclusive group.
