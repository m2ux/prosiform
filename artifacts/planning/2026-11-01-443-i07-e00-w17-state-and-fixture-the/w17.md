**Component:** fixtures/

## Overview

Declares the publication refusal and the title-dispatch refusal in the corpus and its catalogue, and brings the pages describing publication and dispatch to the behaviour the build performs. The build refuses both cases already; until the corpus and the pages state them, a reader of the contract meets neither, and a second build would not be held to them.

## Problem

The build refuses a regular file standing at `<entry>.bundles` with `E_PUBLICATION_FAILED`, and a dispatch in a heading the bundle emits as text alone with `E_UNSUPPORTED_CONSTRUCT`. No fixture runs either case, the catalogue rows for both codes name neither, and `docs/bundles.md` still states that whatever stands at the run folder's path is renamed aside.

## Proposal

A reader of `fixtures/README.md` looks up `E_PUBLICATION_FAILED` and finds the file case; a reader of `docs/bundles.md` learns a file is refused and left in place; a reader of `docs/dispatch.md` learns where a dispatch cannot be written.

- **Publication fixture.** `publication/a-file-at-the-run-folder-s-path-is-refused` stands a file at `guide.bundles` and expects exit 3 with `E_PUBLICATION_FAILED` naming that path. The runner diffs the tree before and after the run, so a run that renamed the file aside and published would fail it.
- **Title-dispatch fixtures.** `dispatch/a-dispatch-in-an-absorbed-member-title-is-refused` and `dispatch/a-dispatch-in-a-title-above-the-selection-is-refused` expect exit 1 with `E_UNSUPPORTED_CONSTRUCT`, the link's reference and source line.
- **Catalogue rows.** The `E_PUBLICATION_FAILED` and `E_UNSUPPORTED_CONSTRUCT` rows name the cases.
- **Pages.** The publication section of `docs/bundles.md` states that an earlier set is renamed aside, a link is replaced, and anything else is refused and left in place. `docs/dispatch.md` states the heading cases and the remedy.
