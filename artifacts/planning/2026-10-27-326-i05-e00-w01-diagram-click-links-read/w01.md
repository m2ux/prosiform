**Component:** src/prosiform/source.py

## Overview

A `click` line in a `mermaid` fence is read as a use, so discovery, resolution and the `-L` budget take a diagram's links as they take any inline link.

## Problem

A use is only what the parser reads as a link. [`uses`](https://github.com/m2ux/prosiform/blob/30636a72aed3c780bd583ea5ed995458032eba7b/src/prosiform/source.py#L526-L556) and [`occurrences`](https://github.com/m2ux/prosiform/blob/30636a72aed3c780bd583ea5ed995458032eba7b/src/prosiform/source.py#L581-L594) walk inline tokens alone, so a fenced block is skipped whole and the document a diagram links to is never opened or counted.

## Proposal

A fence token carries its info string and its content as one string, with the line it opens on in its map. The design reads that content and nothing else.

- **One reader over a fence.**
  A function in `source.py` takes one fence token and yields each click destination it writes, with the line of the document the click sits on and the offset of the quoted destination within that line. Emission and validation read the same function, so every consumer sees one set of diagram uses.
- **What it reads.**
  The info string's first word is `mermaid`. A line is `click <node> href "<destination>"` or `click <node> "<destination>"`, with an optional trailing tooltip and target. A click naming a callback, or a `call` form, yields nothing.
- **Joined to the existing walks.**
  `uses` yields a `Use` for each diagram destination, `resource=False` and with no opening text, since Mermaid gives a click no link text and so no deferral mark. `occurrences` counts each one.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Read how `within` selects fence tokens and how a `Use` line is reported, and the Mermaid click grammar (R1 of the epic). |
| Plan | `clicks(fence)` returns `Click(destination, line, offset)` positions, and `uses` maps each to a `Use`, so emission and validation read positions while discovery reads uses. A fence is a diagram when its info string's first word is `mermaid`. A line matches in full: `click`, a node id, an optional `href`, the quoted destination, an optional quoted tooltip, an optional `_self`, `_blank`, `_parent` or `_top`, and an optional `;`. The offset is the destination's first character inside the quotes, in the line the fence holds. `occurrences` counts `uses`, so the budget and discovery read one walk. |
| Implementation | The fence reader, and its use in `uses` and `occurrences`. |
| Review | No inline-link behaviour moves: the corpus run is unchanged except where a fixture writes a `mermaid` click. |
| Test | `test_source.py` for the `href` form and the short form; end-to-end fixtures under `fixtures/` for a callback and a link-shaped line in a non-`mermaid` fence published as written, and for a run whose diagram links exceed the `-L` budget; `make check` and `make corpus`. |
