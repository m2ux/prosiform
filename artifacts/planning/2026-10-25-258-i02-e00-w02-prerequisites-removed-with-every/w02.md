**Component:** example/work-planner/

## Overview

Thirty-five files under the example open with a list of the documents a reader should reach before following their own procedure. Each list names documents the same file's body already reaches, so the list states a reading order the links below it state again. This row removes every one and holds the copy to the rule that each document a list named is still reachable from the body of the file that wrote it.

## Problem

The example carries a redundant structure the skill it copies will not keep.

- **Thirty-five of forty-nine files open with a Prerequisites section.**
  Each one lists between one and a dozen documents, and every one of those documents is reached again from the file's own Procedure, Operations or Fields. Of the 180 links the 35 lists carry, 108 compile under the root the file declares and 72 name a document the root cannot contain, so those 72 are citations no bundle of the file ever carried.

- **A list restates what the links below it already say.**
  A reader following the body arrives at the same documents, so the list adds reading the reader must discard rather than content to compile.

- **Nothing yet holds the removal to what it was allowed to lose.**
  A section removed carelessly takes an edge with it, and a bundle of that mode then carries a link the run did not follow.

## Proposal

- **Every `## Prerequisites` section leaves the example.**
  The heading, its opening line and its link list are removed, and the rest of the file is untouched.

- **Every document a list named stays reachable from that file's body.**
  The comparison is the list before the removal against the body after it: each target the list named appears somewhere in the file's Procedure, Operations or Fields, and the check runs over the whole tree rather than over a sample. The measure is the edge a bundle follows, so a list link that compiled must still be matched by a link in the body that compiles; a list link the root already refused as a citation carries no edge to keep.

- **A target no body reaches is a finding, not a silent loss.**
  A file whose list named a document its body does not reach keeps that document's link, placed in the body where its procedure first needs it, and the placement is recorded. No file in this tree needs one.

- **The bundle carries no Prerequisites heading afterwards.**
  A bundle of each mode is searched for the heading, and its absence, together with the links it used to introduce still resolving, is the instrument. Every mode bundles with no such heading; a list link naming a document whole had also selected that document's every section, so removing it shortens each mode's bundle and leaves `deliver-mode` one hop deeper than the default budget admits.

- **The skill the example copies loses the same sections.**
  The migration plans the removal on both trees. The skill keeps its own issue; this row's change is the example, and the skill's removal is recorded as the same edit made where the skill lives.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Record the target set of all 35 sections before editing, and read each file's body to confirm which targets it reaches. |
| Plan | Decide, for each target no body reaches, where in the procedure its link belongs. |
| Implementation | Remove each Prerequisites section, and place the link for any target whose body would otherwise lose it. |
| Review | Compare every removed list against its file's body, and confirm no file's content beyond the removed section and any placed link differs from row W01's copy. |
| Test | Search the tree for the heading, bundle each mode, confirm no bundle carries a Prerequisites heading, and confirm every target the lists named still resolves in the mode bundles that reach it. Run `make links`. |
