**Component:** example/work-planner/artifacts/delivery-evidence.md

## Overview

The example's Board Reads states its reads as sequential step sub-sections, since each read takes the result of the one before it and a parallel set has no order. It is the first procedure in the corpus written in the step form the corpus adopts.

## Problem

[Board Reads](https://github.com/m2ux/prosiform/blob/9851615028ea489c48f6b3fa5ddbe0d917438cf2/example/work-planner/artifacts/delivery-evidence.md) is a `⫽` run-set whose nested items wait on their parents: the pull requests are fetched for each repository the board read returned, and their issue links from those records. Under a set with no order, that nesting states nothing.

## Proposal

Read Board Delivery Evidence's first step links Board Reads, whose reads follow as `##### 1. Read Board State`, `##### 2. Fetch Initiative Pull Requests`, `##### 3. Fetch Pull Request Issue Links`, `##### 4. Read Board Configuration` and `##### 5. Read Board Assignee`, each naming the result it takes.

- **Number plus action.**
  Each step heading is its position and its action, one level below Board Reads, as the corpus convention states.
- **No `⫽` link.**
  The step linking Board Reads links it as an ordinary section.
- **Fixtures.**
  Each usage-example fixture whose entry reaches Read Board Delivery Evidence takes the expected bundle the rewrite compiles to.
