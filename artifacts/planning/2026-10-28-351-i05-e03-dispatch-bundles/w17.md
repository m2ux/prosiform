**Component:** checks/conformance.py

## Overview

The conformance report over the clauses this epic changed, so the contract it rewrote is measured rather than assumed.

## Problem

The epic changes the Dispatch, Run-set, Invocation and Publication clauses of the design. Their fixtures prove the build meets them one case at a time, and nothing states whether any clause the epic changed is left unnamed, or whether the build reports a code the design does not declare or lacks one it does.

## Proposal

`make conformance` reads the design against the fixtures and reports the mapping, and this row takes what it reports for the changed clauses.

- **What the report reads.**
  Each fixture's manifest names the design clause it encodes, and the design states that clause. A clause no manifest names is listed as uncovered; a declaration matching no clause fails. A code the design declares that the build reports nowhere, and a code the build reports that the design declares nowhere, each fail.
- **What this row closes.**
  Each uncovered clause among those the epic changed, by a fixture naming it; and any code disagreement in the declared surface, by a diagnostic the build emits or the design states.
- **A clause the epic did not change is not this row's.**
  The report covers the whole contract, and an uncovered clause outside these four areas belongs to the epic that owns it.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Read `make conformance`'s report and separate the changed clauses from the rest. |
| Plan | Take each uncovered changed clause and each code disagreement to the fixture or diagnostic that closes it. |
| Implementation | The fixtures naming each uncovered clause, and the diagnostic or design clause each code disagreement needs. |
| Review | Re-read the report and confirm no changed clause is uncovered and no code disagrees. |
| Test | `make conformance` and `make check`. |
