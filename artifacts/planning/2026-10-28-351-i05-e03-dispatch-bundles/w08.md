**Component:** src/prosiform/cli.py

## Overview

A bare `pf` prints what an agent needs before it compiles anything, so a skill's bootstrap is one instruction: run `pf` and follow it. The example's bootstrap document is retired, and the documentation states the bundle set, the sub-sections and the Prosiform section.

## Problem

- **Every corpus restates how to use pf.**
  The example's [`bootstrap.md`](https://github.com/m2ux/prosiform/blob/9851615028ea489c48f6b3fa5ddbe0d917438cf2/example/work-planner/bootstrap.md) carries the compile command and a symbol table, and [`SKILL.md`](https://github.com/m2ux/prosiform/blob/9851615028ea489c48f6b3fa5ddbe0d917438cf2/example/work-planner/SKILL.md) and `rules.md` link it.
- **The documents describe withheld dispatches and run-sets.**
  `invocation.md`, `docs/glossary.md`, `README.md` and the example's `guidelines.md` and `rules.md` state the operators as the build before this epic had them.

## Proposal

A skill's `SKILL.md` says: run `pf` and follow it.

- **`pf` with no arguments.**
  Prints the guide and exits 0: the compile step (`pf -o <folder> <destination>` from the skill directory; a non-zero exit stops the run and reports diagnostics), the `↳` inline-target rule, and that a bundle opening with a Prosiform section is followed from there. No option prints it; `pf -h` states that a bare `pf` does.
- **The guide is pf's text.**
  It is a constant of the build, and `invocation.md` states the bare invocation.
- **Bootstrap retired.**
  `example/work-planner/bootstrap.md` is removed; `SKILL.md`, `rules.md` and `guidelines.md` link nothing to it and state the one instruction.
- **Documentation.**
  `invocation.md`, `docs/glossary.md` and `README.md` state the output folder, the bundle set, the dispatch sub-sections, the parallel set and the Prosiform section; the design states the bare invocation.
