**Component:** src/prosiform/dispatch.py

## Overview

Each target a `⇉` link names is compiled, transitively, to a bundle of its own, and the link points at a `Dispatch <link text>` sub-section that names that bundle. An agent follows a dispatch by handing a bundle that already exists to a sub-agent, rather than compiling at run time from a symbol table.

## Problem

- **A dispatched target is withheld.**
  A `⇉` link [contributes nothing](https://github.com/m2ux/prosiform/blob/9851615028ea489c48f6b3fa5ddbe0d917438cf2/src/prosiform/cli.py#L1015-L1079) to the bundle and publishes its mark and a source path, so the agent must compile the target itself, as the example's [bootstrap](https://github.com/m2ux/prosiform/blob/9851615028ea489c48f6b3fa5ddbe0d917438cf2/example/work-planner/bootstrap.md) instructs.
- **A target's closure is computed for warnings alone.**
  [`analysed`](https://github.com/m2ux/prosiform/blob/9851615028ea489c48f6b3fa5ddbe0d917438cf2/src/prosiform/dispatch.py#L202-L247) follows each target's would-be closure to report depth and cycles, and publishes nothing from it.

## Proposal

`modes/advance-mode.md` step 2 writes `[⇉ Sync Mode](sync-mode.md)`. The run publishes `modes_advance-mode.bundle.md` and `modes_sync-mode.bundle.md`; in the first, step 2's link reads `[Sync Mode](#dispatch-sync-mode)` and the section ends with `### Dispatch Sync Mode`, whose one line names `modes_sync-mode.bundle.md`.

- **One bundle per distinct target.**
  The run follows dispatches transitively and compiles each distinct document-and-fragment target once, as its own entry, into the output folder; every link naming it points at that bundle.
- **The sub-section.**
  One per target per section, one heading level below the section holding the link, after its own content and before its child sections; a dispatch above the first heading takes that heading's level. Its body is one line dispatching the bundle file, as the Dispatch protocol states.
- **The mark is stripped.**
  The published link text carries no operator.
- **Per-bundle budgets.**
  `-E` counts hops from each bundle's entry; `-F`, `-T`, `-L`, `-I` and `-O` count what each bundle alone opens, reaches and publishes.
- **The contract moves with the build.**
  The design's Dispatch clauses, the pin and the `invocation.md` paragraph state the bundle set, so `make conformance` and `make invocation` hold.
