## Overview

The destination each included document and section takes, and the refusal when a source fragment cannot name one heading.

## Problem

A name derived from heading text alone cannot tell two sections apart once several documents are one document.

- **Heading slugs repeat across files.**
  Two documents can each hold a section called Review, so the slug `review` names both.

- **A renderer numbers them apart and the tool must agree.**
  A renderer reading the bundle gives the first heading to carry a slug that slug and every later one the slug and an ordinal. A destination map that numbers a different list of headings disagrees with the document it describes.

- **Two headings in one source can still coincide.**
  Nothing about the file separates them, so a source fragment naming their shared slug names two headings and selects neither on its own evidence.

## Proposal

A destination is the fragment the declared renderer generates for the heading the bundle emits: that heading's slug under the profile's slugging rules, carrying the ordinal the renderer appends where an earlier bundled heading already took the slug. The ordinal is assigned by walking the headings the bundle emits in bundle order, and nothing is emitted at the destination — the heading the renderer already indexes is the target.

A source fragment carries no ordinal. It is looked up against the slug each heading's own text produces, so it names one heading by what the author wrote. A fragment two headings answer to fails with `E_AMBIGUOUS_SOURCE_HEADING` and the author retitles. Two documents whose paths differ only by Markdown extension head one file group a reader cannot tell apart, and fail with `E_AMBIGUOUS_FILE_GROUP`.

## Every Emitted Heading Takes a Destination

The list a destination's ordinal is computed over is the headings the bundle emits, not the document-level regions alone. A heading a retained container carries reaches the output and a renderer indexes it, so leaving it out of the map makes the two disagree.

Measured against GitHub's own renderer, through the `POST /markdown` endpoint, on a bundle holding a blockquoted `## Run`, a list-item `### Run` and a later document-level `### Run`: the three take `run`, `run-1` and `run-2`. A container contributes a heading to the renderer's index exactly as the document level does, in source order, and the retained container the outline rules keep is therefore part of the numbering.

Raised as [#75](https://github.com/m2ux/prosiform/issues/75) and reproduced on this base: one document carrying `> ## Run` beside another carrying `## Run` publishes an entry line linking `#run`, which the renderer gives to the quoted heading, so the entry line resolves into the blockquote. `Bundle destinations — Uniqueness` holds that the ordinal makes each destination resolve to exactly one heading by construction, and the construction is incomplete while the list is built from document-level regions.

This is the row's own subject rather than an addition to it: deriving the destination each heading takes is what AC1 states.

## A Source Fragment Names One Heading by Its Own Text

`Source-heading resolution` holds that two headings in one source producing the same slug are not numbered apart, that a fragment requiring one of them fails with `E_AMBIGUOUS_SOURCE_HEADING`, and that the author disambiguates by retitling. The base does the opposite: it assigns the renderer's ordinal inside the source heading index, so `#run` silently selects the first of two and `#run-1` silently selects the second.

Two rules follow, and they are the same rule seen from both sides. A source fragment is matched against the slug of each heading's own visible text, with no ordinal anywhere in source resolution: a fragment no heading's text produces names nothing and is reported as the missing target it is, and a fragment two headings' text produces is refused as ambiguous. The renderer's ordinal stays where the design puts it, on a bundle destination, because the tool assigns that ordinal over a document it generated in one pass.

This also settles the order of two refusals. Where one of the two coinciding headings sits inside a container, the ambiguity is reported rather than the nested-target refusal, because the run cannot say which heading the fragment meant and so cannot say that the one it meant roots no section.

## What the Measurement Found

- **AC2's second half is already delivered.** `identity/paths-differing-only-by-suffix` holds against the base and `E_AMBIGUOUS_FILE_GROUP` is raised from the file-heading check. Only the first half is this row's build.
- **Both codes AC2 declares are in the catalogue.** The twenty-three-code schema carries `E_AMBIGUOUS_SOURCE_HEADING` and `E_AMBIGUOUS_FILE_GROUP`, so no code is added and the two-branch hazard is not entered.
- **Structural ancestors are not yet emitted.** `Ordinal assignment` names them beside file headings and selected source headings; they arrive with I00:E09, and the numbering here runs over what the bundle emits, which takes them in when they do.
