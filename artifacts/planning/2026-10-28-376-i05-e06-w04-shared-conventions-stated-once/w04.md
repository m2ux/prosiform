**Component:** example/work-planner/conventions.md

## Overview

How a helper is invoked and how a write is confirmed each have one home in `example/work-planner/conventions.md`. Every operation applying either links that entry, and the guidelines' operation rules link both. The usage-example bundles the changed files reach are regenerated.

## Problem

- **Helper invocation is restated.**
  The guidelines' Local scripts rule restates the conventions' Scripts entry, and Check Dependencies restates where a helper runs and how its files are passed. The 21 helper commands state none of it by link.
- **Write confirmation has no home.**
  Fourteen steps re-read a write, each in its own words, and three repeat the board's lag condition. No file states that only a fresh re-read confirms a write, or what a failed re-read means.
- **Bodies is restated.**
  The guidelines' Bodies rule restates the conventions' Bodies entry and adds that the file holds the exact text.
- **Names outside this repository.**
  The conventions' Bodies example and one Example values line name a project outside this repository.

## Proposal

### The Two Conventions

- **Helper invocation.**
  A helper is a script in `<workspace>`, the checkout holding this skill. It runs from `<workspace>`, or the directory within it that its command names, under the sandbox invoked by its absolute path, `<workspace>/scripts/sbx`. A file kept outside `<workspace>`, such as a body file, is passed by its absolute path.
- **Write confirmation.**
  Only a fresh re-read confirms a write: read the written object again and compare it with the intended state. The write's own output confirms nothing. A re-read that fails, or shows another state, leaves the write uncertain; that uncertainty returns to the caller, and the write is never retried as a different write.

Helper invocation replaces the Scripts entry. Bodies gains commit messages and the exact-text rule, and loses its example. The Example values line names a theme board by role.
