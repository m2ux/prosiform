**Component:** src/prosiform/cli.py

## Overview

The two warnings a substituted run emits, with the three fixtures that show each and the exit status both leave, and the mapping applying under `-c`. A bundle of stand-in material is the same kind of output as a bundle of the material that ships, so a skill rehearsed against stand-ins would otherwise read as a skill validated. The complementary defect is quieter: a fixture whose mapping matched nothing mocks nothing, and whatever it asserts then passes for the wrong reason.

## Problem

A substitution is invisible in its own output. `closure.inside` redirects the reference and every stage that reads it — discovery, emission, candidate validation — sees only the substitute, so nothing downstream can tell a mocked bundle from a real one. Neither warning has a code the contract declares, and `fixtures/manifest.schema.json` refuses a warning code its catalogue does not carry, so a fixture declaring either fails validation before the run starts.

`-c` is the same gap in the mode a mocked check runs in. The mapping is built from the command line before any source is read and publication is the only stage `-c` skips, so the substitution is reported as a publishing run reports it — but nothing states it, and a later change moving the mapping behind the publication branch would quieten every mocked check in CI without failing one.

## Proposal

**The scene.** `Diagnostic` carries a severity, a code, a message and the further fields a defect has values for: `reference`, `resolved`, `source`, `chain`, `remedy`, `location` and `related`. `Reporter` writes them in the format the run asked for. `publication` emits each bundle's warnings once every name and budget check has passed, before it writes the set or does not, so a warning accompanies a publication rather than replacing it and `-c` emits it too. `Substitution.substitute` is the one place that knows a reference was redirected and which key served it.

**The design.**

- **`W_MOCK_SUBSTITUTED`.** One per distinct redirected target, emitted at the first reference that redirects it. `location` is the link's source position, `source` the authored destination, `resolved` the substitute's identity, and the message names the identity the reference would have resolved to.
- **`W_MOCK_UNUSED`.** One per mapping key no reference named, with the key's authored spelling as `source`. It states a fact about the invocation rather than about the sources, so it carries no `location`.
- **Both accompany a published bundle and exit `0`,** which is the rule `W_RESOURCE_PORTABILITY` already follows. An empty mapping raises neither, because neither has a subject.
- **The records are kept where the lookup is read.** The mapping records each hit — the substitute's identity and the authored reference that reached it — and the run reads the record after traversal rather than inferring it from the bundle. A warning naming one target however many links reach it follows from the record being keyed by the substitute's identity.
- **Both codes join the contract and the corpus schema.** A warning is a name the design declares and the schema's `warningCode` catalogue repeats, and `make conformance` holds the two to each other in both directions while a test holds each catalogue to the design's own text. A code in one and not the other fails, so the design's exit-status section gains a sentence for each code beside the other `W_` codes and `fixtures/manifest.schema.json` gains both names; `fixtures/README.md` gains the row a reader looks the code up in.
- **`-c` reports the substitution as a publishing run does,** because the mapping is built before traversal and the warnings are emitted before the publication branch.

## Fixtures

| Fixture | What its source tree and manifest declare |
| --- | --- |
| `fixtures/mock/a-substitution-warns-with-its-target` | `guide.md` links `rules.md` twice, once whole and once by section, and the run is given `-m rules.md=stand-in.md`. Exactly one `W_MOCK_SUBSTITUTED` is emitted, naming the first link's location and the substitute, however many references the key served. |
| `fixtures/mock/an-unused-key-warns-and-publishes` | `guide.md` links `rules.md`, and the run is given `-m unrelated.md=stand-in.md`. Exit status `0`, the bundle is published unchanged, `W_MOCK_SUBSTITUTED` is absent, and `W_MOCK_UNUSED` names the unused key's authored spelling. |
| `fixtures/mock/a-mocked-check-publishes-nothing` | `guide.md` links `rules.md`, and the run is given `-c` with `-m rules.md=stand-in.md`. Exit status `0`, standard output is empty, and the substitution warning `W_MOCK_SUBSTITUTED` is emitted exactly as in a publishing run. No `absent` declaration is needed: the runner invokes every fixture with `-o -`, so no run in the corpus can write a file. |

## Additions from review

| Addition | What it states |
| --- | --- |
| One warning per substitute, keyed by the substitute's identity | The record holds one entry per substitute, so a key serving two references names the target once at the first of them. Keying by the authored identity would emit one warning per key and miss a document key and a section key naming one substitute. |
| The emitted order is the run's, not the mapping's | Substitution warnings follow the order the references were discovered, then the unused keys follow in the order the command line gave them. A fixture declares the order, so the order is a decision rather than whatever a dictionary yields. |
