**Component:** main:checks/documents.py, main:checks/links.py, main:checks/tables.py, main:checks/README.md, main:checks/tests/test_documents.py

## Overview

The checks that read the repository's documents name each Markdown document present in the working tree and untracked as unread, so a run's count no longer reads as coverage of a document it never saw.

## Problem

`documents.py` discovers documents from `git ls-files`. A document written and not yet staged is absent from the set `make links` and `make tables` read, and both exit zero with a count that silently leaves it out.

## Proposal

A contributor writes a new document and runs the checks before staging it. The run reads the tracked documents and closes on a count; nothing says the new document was skipped.

- **Choice: name, not read.** The run names each present and untracked document as unread, one line each, and adds the number to its summary. Reading the working tree was rejected: the checks' subject is the repository's own content, which is what a fresh checkout and continuous integration hold, and a scratch file someone keeps untracked would otherwise become a CI-invisible failure source locally.
- **Report, not fail.** An unread document fails nothing. The criterion asks only that it is named; failing would block every local run carrying a scratch document.
- **Ignored is not present.** Discovery lists untracked paths with `git ls-files --others --exclude-standard`, so a document `.gitignore` excludes is not named.
- **The corpus stays excepted.** A fixture is held out whether or not git tracks its manifest, so a fixture being written is excepted like a committed one. A bundle is excepted as today.
- **Scope.** `documents.unread` owns the rule; `links.py` and `tables.py` print it. `links.py` run on named documents reads only those and reports nothing unread. `strip_indented_blocks`, which W01 changes, is untouched.
