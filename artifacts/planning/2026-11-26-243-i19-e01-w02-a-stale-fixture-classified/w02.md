## Overview

Triage names each stale fixture under one declared drift category, and a category can be selected, so a change accepts the drift it intended and leaves every other category for a reader. The categories are the vocabulary restatement reads: it restates a fixture whose bundles moved by content or name, and refuses one whose run reports something else.

## Problem

A red corpus run names each failing fixture and its differences, and nothing sorts them.

- **A rewrite at fixture scale is unreviewable by hand.**
  A behaviour change can fail many fixtures at once, and reading every diff is what a maintainer does instead of reading the ones that matter.

- **Nothing distinguishes accepting intended drift from accepting all of it.**
  Without a category to select on, a rewrite takes everything a red run names, including fixtures whose exit status or diagnostics moved.

- **The triage script is unreachable.**
  The earlier script sits in a planning record, reads verdicts by its own rules and is named nowhere the corpus maintains itself.

## Proposal

A maintainer has a red `make corpus` run in hand and wants to know which fixtures moved only in their bundle text before restating any of them.

- **Triage reads the corpus's own verdicts.**
  `checks/triage.py` runs the fixtures through `corpus.run_all`, so each verdict is the corpus run's: a passing or awaited fixture is no drift, and a fixture the corpus fails is read by its runner `state`.

- **A run that failed in itself is reported apart.**
  A fixture in `State.FAILED_IN_ITSELF` is named under its own heading, outside every drift category, so neither a reader nor restatement takes its output as an expectation.

- **The runner's result carries what the run wrote.**
  `Result.written` holds each file the run created, so triage reads the produced bundles from the run the verdict came from.

- **Categories classify a moved output, in order.**
  `Drift` in `checks/triage.py` declares them once; the first that applies names the fixture.
  - `status` — the exit status differs from the manifest's. Restatement refuses it.
  - `streams` — the diagnostics or the text on standard output differ. Restatement refuses it.
  - `layout` — the run writes a different number of bundles than the manifest declares, or not into one folder of its own. Restatement refuses it.
  - `names` — the bundles are as many as declared and a name differs. Restatement writes it.
  - `inserted`, `removed`, `rewritten`, `both` — every name matches and the content differs: lines only inserted, only removed, replaced one for one in place, or a mix. Restatement writes them.

  The refusals come first because a fixture refused for one reason is refused whatever else moved. Lines keep their endings, so a newline spelling or a missing final newline reads as a line rewritten in place.

- **A category can be selected.**
  `--only CATEGORY` reports the fixtures in that category alone; identities on the command line limit the run through `manifests.selected`.

- **Triage writes nothing.**
  It prints a report and exits zero; a green tree prints nothing.
