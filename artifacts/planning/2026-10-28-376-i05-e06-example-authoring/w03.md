**Component:** example/work-planner/configuration.md

## Overview

The example's deployment and run values — repository, labels, board fields, limits — are stated in one configuration document and linked wherever they are used.

## Problem

Board fields, labels and limits are written in more than one file, so a value changed in one place leaves a stale copy in another.

## Proposal

The configuration document lists each binding once with its meaning and allowed values; every occurrence elsewhere becomes a link to it.

- **Home.**
  The component path is the recommendation on the epic's configuration-home question and changes with its answer.
- **Limits.**
  A loop or batch limit names the configured value.
- **Helpers.**
  A helper script's command takes each binding as an argument.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Every deployment or run value the example writes, and each file writing it. |
| Plan | One entry per binding, and the link that replaces each occurrence. |
| Implementation | The configuration document, its link from `SKILL.md`, each replaced occurrence, and the usage-example bundles they reach. |
| Review | No binding is written outside the document. |
| Test | `make links`, `make corpus` and `make check`. |
