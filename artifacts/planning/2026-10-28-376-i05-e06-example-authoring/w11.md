**Component:** example/guidelines.md

## Overview

The shared skill guidelines agree with the work-planner example's authoring rules, so a reader of the example meets one rule for commands and rule homes, not two that disagree. Placed from [#378](https://github.com/m2ux/prosiform/issues/378).

## Problem

The shared guidelines at `example/guidelines.md` apply alongside the work-planner example's own guidelines, and still state the shape those guidelines retire.

- **Commands.**
  The shared Commands section places each command specification in a `## Commands` section at the end of the file whose procedure runs it. The work-planner guidelines place each command in an unindented fenced block in the step that runs it.
- **Procedure file sections.**
  The shared Procedure files section lists Commands among a procedure file's top-level sections.
- **One home per rule.**
  The shared rule homes each rule in SKILL.md, the owning mode or a shared guide. The work-planner rule homes it in the contract it constrains, the step it binds or a convention, and every other file links it.

## Proposal

`example/guidelines.md` states commands and rule homes as the work-planner guidelines do.

- **Commands inline.**
  The Commands section, and the Commands entry in Procedure files, state a command inline in the step that runs it, with no Commands section.
- **Rule homes.**
  One home per rule names the homes the work-planner guidelines name.
- **Fixtures.**
  The usage-example bundles that reach the shared guidelines are regenerated.
