**Component:** example/work-planner

## Overview

Each rule of the example has one home that every other file links, and each file holds one subject.

## Problem

Rules are restated across files, sometimes named in code font, and four files exceed 20 KB, so a reader cannot tell which statement of a rule governs or where one subject ends.

## Proposal

- **One home per rule.**
  Each rule lives in the contract it constrains, the step it binds, or a convention; each restatement becomes a link.
- **Splits.**
  Each file the size report names is read for a second subject — operations sharing no contract and applying nothing across the cut — and split along that cut where one is found.
- **Unread rules.**
  A rule, section or operation nothing reads is deleted.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Each rule stated in more than one file, and the subjects of each file the size report names. |
| Plan | Each rule's home, and each split with the links it moves. |
| Implementation | The example files and the usage-example bundles they reach. |
| Review | No rule is stated twice; each split file holds one subject. |
| Test | The authoring check, `make links`, `make corpus` and `make check`. |
