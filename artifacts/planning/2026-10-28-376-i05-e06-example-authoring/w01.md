**Component:** example/work-planner/guidelines.md

## Overview

The example's guidelines state the authoring rules the epic applies, so each later change has one written rule to meet and a reviewer one place to check it against.

## Problem

The guidelines describe operations with a prose Inputs line and a separate Commands section, and say nothing about where a binding, a convention or a rule lives, so the shape the example teaches is the one the epic replaces.

## Proposal

The guidelines' Operations section gains the rules as they will bind every file.

- **Bindings.**
  A deployment or run value is stated once in the configuration document and linked; a helper takes bindings as arguments.
- **Contracts.**
  Inputs and Outputs are one line each of contract links, or `None`; every value has a contract, and conditions sit in the step they bind.
- **Commands.**
  A command sits in an unindented fenced block in the step that runs it; no Commands section.
- **Homes.**
  A shared convention, a rule and a binding each have one home; every other file links it; every cross-file link is file-relative.
- **Files.**
  One subject per file; a file over about 20 KB or 8 operations is reviewed for a second subject. Operations are named verb first with no emphasis.
- **Steps.**
  The `N. Action` sub-section form stays as stated.
- **Title headings.**
  The rule on a file's H1 follows the answer to the epic's open question.
