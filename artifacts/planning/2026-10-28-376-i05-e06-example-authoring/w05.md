**Component:** example/work-planner/artifacts/placement.md

## Overview

One artifact file is brought to every authoring rule, so each structural rule is seen on a real file and approved before it is applied across the example.

## Problem

The rules are new to the example, and applying them across 58 files before one reviewer has seen them at work risks redoing the whole rollout.

## Proposal

`artifacts/placement.md` is the recommended sample: it carries a Commands section, four operations, contracts under Fields and a disposition rule other files restate.

- **Every rule shown.**
  Inputs and Outputs as contract links, commands inline in their steps, bindings and conventions linked, operations named verb first.
- **Approval.**
  The pull request is the approval: a rule changed in review is changed in the guidelines on this row.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The authoring check's findings for the file. |
| Plan | The file's operations, contracts and commands in the new shape. |
| Implementation | `artifacts/placement.md`, any guideline wording review changes, and the usage-example bundles it reaches. |
| Review | The file reads as the guidelines say a file reads. |
| Test | The authoring check over the file, `make links`, `make corpus` and `make check`. |
