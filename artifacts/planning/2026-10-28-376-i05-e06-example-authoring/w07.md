**Component:** example/work-planner/artifacts

## Overview

Every artifact command sits in the step that runs it, and no artifact keeps a separate Commands section.

## Problem

18 artifacts carry a `## Commands` section, so a step names a command it does not show and a reader moves between the step and the section to follow it.

## Proposal

Each command moves into the step that runs it, with where it runs from and which inputs fill which parameters; the next step reads its exit code, output and refusal. A command used by several operations is written in each.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The authoring check's command findings for the artifacts, and each step that names a command. |
| Plan | The step each command moves into, and the steps that read its result. |
| Implementation | The artifacts and the usage-example bundles they reach. |
| Review | No command is named without being shown. |
| Test | The authoring check over `artifacts/`, `make links`, `make corpus` and `make check`. |
