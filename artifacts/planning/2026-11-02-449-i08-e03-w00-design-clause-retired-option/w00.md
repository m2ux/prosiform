## Overview

The design states `document#fragment` as the one command-line spelling for a section and names the retirement of `-f`, and the README pins that revision, so every fixture this epic writes cites a clause the pinned design carries.

## Problem

The pinned design states two spellings for one section.

- **The CLI contract carries the row.**
  The option table states `-f DOC` as the referring document a fragment-only positional reference resolves against, and the usage examples show it.
- **The invalid-usage list explains the option by its absence.**
  It refuses "a fragment-only entry without `-f`", so the form a caller types first fails for want of an option.
- **Other clauses lean on the referrer.**
  *Automatic output names* derives a fragment-only entry's name from `-f`, *Source ownership* and *The substitution mapping* name fragment-only entries and a referring document, and the validation scope and metadata conformance cases list them.
- **A removal needs a clause to be read against.**
  A build without the option and a design carrying its row disagree, and two fixtures cite the row by name.

## Proposal

**The scene.** The CLI contract enumerates each option and the forms it refuses; *Reference normalization and path identity* states how a positional reference is spelled.

**The design.**

- **The row is withdrawn.**
  The option table and the usage examples name no `-f`; *Automatic output names*, *Source ownership*, *The substitution mapping*, the CLI validation scope and the per-file ownership case drop the referrer.
- **One spelling, stated where references are spelled.**
  *Reference normalization and path identity* states `document#fragment` as the one spelling a section takes on the command line, and that a fragment alone names no document.
- **The refusal lives in the CLI contract alone.**
  Its invalid-usage list refuses an entry reference naming a fragment alone, with a diagnostic naming `document#fragment` as the remedy, which is AC1's live behaviour.
- **The link form is stated separately and unchanged.**
  A `[Check](#section)` link resolves against the document that carries it, as *Fragment-only links* states; the normalization clause links there rather than restating it.
- **The removal is stated.**
  The normalization clause says `-f` retires with the form it served, the way `E_ROOT_NOT_FOUND` retires with `root`, so a reader of an older revision meets the fact rather than the gap.
- **The pin moves.**
  I08:E00 and I08:E01 are merged, so this row moves `README.md`'s design link to the engineering commit carrying this amendment.
- **Citations of the withdrawn row go with it.**
  `extraction/a-fragment-alone-selects-from-the-referrer` and `usage-example/a-bare-fragment-and-its-referring-document` each cite `CLI contract — -f DOC`, which the new pin does not carry, so `make conformance` would fail on them. Their citation of that row is removed; the fixtures themselves stay for W03 to withdraw or rewrite.
