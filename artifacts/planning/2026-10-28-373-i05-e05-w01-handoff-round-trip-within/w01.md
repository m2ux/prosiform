**Component:** src/prosiform

## Overview

The handoff round-trip test bundles every mode of the work-planner example well within its 60-second limit per `pf` run, so a Checks run fails on it only for a fault in the change under review. The cost is removed where it lies: in `pf`'s candidate validation, and in the test bundling each mode twice.

## Problem

`test_each_handoff_the_example_publishes_is_followed` timed out on two Checks runs bundling `modes/deliver-mode.md`, which takes about 19 seconds locally. Candidate validation reads each carried region's tokens by scanning the whole reparsed bundle and the whole source document, so its cost grows with regions times tokens, and the test then repeats every mode's run.

## Proposal

A runner several times slower than a developer machine bundles `modes/deliver-mode.md` in well under the limit, and the test says what that limit allows for.

- **Each region's own run of tokens.**
  `source.runs()` maps each document-level region to the tokens from its opening up to the next region's opening. `candidate.validate()` builds it once for the reparsed bundle and once per source document, and each `Side` of a region comparison carries its region's run.
- **A cheaper region filter.**
  `source.within()` tests each token's line against the selected spans in a plain loop, so it builds no generator per token. Its result is unchanged.
- **One run per mode.**
  `Tree.published()` takes the bundle a run produced, so the test reads dispatched bundles and deferred destinations from one run.
- **The limit stated.**
  The test's `LIMIT` constant carries the cost of its costliest entry.
