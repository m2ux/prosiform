## Overview

The design states the guide as the one home of the rules an agent follows a bundle by, before any build row implements it: an instruction for every mark, the returned-question marker, plain terminal text, and a bundle that opens by sending its reader to the guide.

## Problem

- **The guide covers two marks.**
  [Guide](../../2026-10-17-prosiform-v1/design.md#guide) states the compile step, the `↳` inline target and a bundle opening with a Prosiform section. It states nothing for `⇉`, `⫽`, `¬`, an arrow directive, a dispatch list or a returned question.
- **A bundle restates the protocols.**
  [The Prosiform section](../../2026-10-17-prosiform-v1/design.md#link-classification-and-resource-handling) puts the Dispatch and Parallel dispatch paragraphs into every dispatching bundle, and only a dispatched bundle needing a first run tells its reader to run `pf`.
- **A deferred mark leaves no trace in a bundle.**
  *The deferral mark* and *Operators that combine* publish a deferred link with its `¬`, `⇉` and `⫽` marks removed, pointing at a source path. A plain deferred link and a deferred dispatch then read like a citation of a document that declares nothing, and *Run pf first* states that a plain deferred link asks for no run of `pf`. Only an arrow directive's label, kept by *The directive's link*, and the generated `↳` line reach a bundle.
- **No marker names a returned question.**
  The eval reads a return as a question only from its first word, and the CLI's hand-back frame wraps every return ([#637](https://github.com/m2ux/prosiform/issues/637)).

## Proposal

**The scene.** The design states the guide in *Guide*, the Prosiform section and its protocols in *Link classification and resource handling*, and the bundle's opening in *Clean Markdown* and the conformance list's *Prosiform section* entry.

- **The guide states every rule once.**
  *Guide* gives one instruction for each of `⇉`, `⫽`, `¬`, an arrow directive, `↳`, a dispatch sub-section, a `Dispatch in parallel` list and a returned question, and carries the Dispatch and Parallel dispatch protocols the Prosiform section held.
- **Plain terminal text.**
  The guide is command-line text: no Markdown heading, emphasis, link or code fence.
- **One returned-question marker.**
  *Guide* fixes the line a dispatched run opens a returned question with, and the protocol tells the dispatching session to read a return opening with it as a question. The planning recommendation is a first line reading `Question:` with the question, its context and its options below it.
- **Every bundle opens with the run-pf line.**
  Every bundle `pf` writes, whatever it holds, opens its preamble with one fixed line telling its reader to run bare `pf` and follow the guide. The Prosiform section and its protocol paragraphs retire; a dispatch sub-section and a `Dispatch in parallel` list stay, their lines naming no protocol link. *Clean Markdown*, *Generated heading collisions* and the conformance list follow.
- **A deferred link's marks.**
  The clauses state how a deferred link is published, as the epic's open question settles; the recommendation keeps the marks its source wrote, so the guide's instruction for each mark is the one an agent applies.
- **A mixed parallel set is refused.** (User, 2026-11-03.)
  *Operators that combine* and *Parallel dispatch sub-sections* state that a set's members are all deferred or none are: a set mixing `⫽` and `¬⫽` members fails with `E_UNSUPPORTED_CONSTRUCT`, naming the section's set and each member as immediate or deferred, and publishes nothing. The conformance list names the refused fixture.
- **The pin moves.**
  The README's design link moves to the engineering commit carrying the amendment.
