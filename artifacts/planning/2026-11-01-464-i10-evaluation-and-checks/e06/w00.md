## Overview

The design states the guide as the one home of the rules an agent follows a bundle by, and the plain dispatch sections a bundle carries, before any build row implements them; the deferred dispatch marks retire.

## Problem

- **The guide covers one mark.**
  [Guide](../../2026-10-17-prosiform-v1/design.md#guide) states the compile step, the `↳` inline target and a bundle opening with a Prosiform section, and nothing of dispatch or a returned question.
- **A bundle restates the protocols.**
  [The Prosiform section](../../2026-10-17-prosiform-v1/design.md#link-classification-and-resource-handling) puts the Dispatch and Parallel dispatch paragraphs into every dispatching bundle, and *Dispatch sub-sections* name a target's file in a code span, linking the protocol instead.
- **Deferred dispatch is a second way to dispatch.**
  *Operators that combine* admits `¬⇉` and `¬⫽`, published with their marks removed, so a deferred set member falls out of its set.
- **The withheld link's wording.**
  *The deferral mark* says the destination a deferred link publishes "already states that the material is a run of its own", where the link is kept as a link and its target is not bundled.
- **No marker names a returned question.**
  The CLI's hand-back frame wraps every return ([#637](https://github.com/m2ux/prosiform/issues/637)).

## Proposal

**The scene.** *Guide*; *Link classification and resource handling*'s deferral mark, operators, dispatched bundles, dispatch and parallel dispatch sub-sections and Prosiform section; *Clean Markdown*; and the conformance list. (User, 2026-11-03.)

- **Compiled up front, as now.**
  *Dispatched bundles* keeps each distinct `⇉` or `⫽` target compiled once, transitively, into its own file in the run folder, with the up-front refusals, `W_DISPATCH_SELF`, `W_DISPATCH_DEPTH` and `E_DISPATCH_CYCLE`.
- **A single dispatch.**
  The prose link points at a `Dispatch <text>` section whose line links the dispatched file, as in "Give [the crew](loading__crew.bundle.md) to a sub-agent and continue with its answer." A condition stays in the prose, on the link leading there. Instruction text never says "bundle".
- **A parallel set.**
  The set's `⫽` links point at one `In parallel` section, its boundary, listing each member as a link to its compiled file under the instruction: give each to its own sub-agent at the same time, and continue when all have answered. A set of one is published as a single dispatch.
- **No protocol in a bundle.**
  The Prosiform section and its protocol paragraphs retire; every bundle opens its preamble with one fixed run-pf line. *Clean Markdown*, *Generated heading collisions* and the conformance list follow.
- **The guide holds the rules.**
  *Guide* states how to run `pf`, what `↳` means, how a `Dispatch` and an `In parallel` section are followed, the inputs a dispatch carries, waiting for all, failures returned together, and a returned question opening with a first line reading `Question:`, all as plain command-line text.
- **Deferral.**
  `¬→` publishes as its `↳` line, its preset rule unchanged. `[¬ x](x.md)` is a withheld link: kept as a plain link at its rebased path, its content not bundled, which *The deferral mark* states in place of the "run of its own" wording. `¬⇉` and `¬⫽` are refused with `E_UNSUPPORTED_CONSTRUCT`, naming the link. The clause states that this loses no preset behaviour, since a dispatched target already selects its presets by its own heading.
- **The pin moves.**
  The README's design link moves to the engineering commit carrying the amendment.
