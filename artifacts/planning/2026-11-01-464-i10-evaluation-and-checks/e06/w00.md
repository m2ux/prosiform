## Overview

The design states the guide as the one home of the rules an agent follows a bundle by, before any build row implements it: what to do with each mark and dispatch section a bundle carries, the returned-question marker, plain terminal text, a bundle that opens by sending its reader to the guide, and the published forms of a deferred dispatch and a parallel set.

## Problem

- **The guide covers one mark.**
  [Guide](../../2026-10-17-prosiform-v1/design.md#guide) states the compile step, the `↳` inline target and a bundle opening with a Prosiform section. It states nothing for `⇉`, a dispatch section or a returned question.
- **A bundle restates the protocols.**
  [The Prosiform section](../../2026-10-17-prosiform-v1/design.md#link-classification-and-resource-handling) puts the Dispatch and Parallel dispatch paragraphs into every dispatching bundle, and only a dispatched bundle needing a first run tells its reader to run `pf`.
- **A deferred dispatch leaves no trace.**
  *Operators that combine* publishes `[¬⇉ x](path)` with its marks removed, so it reads like a citation.
- **A deferred parallel member falls out of its set.**
  *Parallel dispatch sub-sections* builds a set from its immediate members alone, so `[⫽ a](a.md)` beside `[¬⫽ b](b.md)` publishes `a` as a set of one and `b` as a plain link.
- **No marker names a returned question.**
  The eval reads a return as a question only from its first word, and the CLI's hand-back frame wraps every return ([#637](https://github.com/m2ux/prosiform/issues/637)).

## Proposal

**The scene.** The design states the guide in *Guide*, the Prosiform section, dispatch sub-sections, sets and combined operators in *Link classification and resource handling*, and the bundle's opening in *Clean Markdown* and the conformance list's *Prosiform section* entry.

- **The guide states what a bundle carries.** (User, 2026-11-03.)
  *Guide* states that `[↳ x](path)` is compiled and kept in context, followed inline; that `[⇉ x](path)` is compiled and dispatched to a sub-agent; how a Dispatch sub-section and a `Dispatch in parallel` section are followed, carrying the protocols the Prosiform section held; and the returned-question marker. `⫽` and `¬` never reach a bundle, so the guide does not teach them.
- **Plain terminal text.**
  The guide is command-line text: no Markdown heading, emphasis, link or code fence.
- **One returned-question marker.**
  *Guide* fixes a first line reading `Question:`, with the question, its context and its options below it, and the protocol tells the dispatching session to read a return opening with it as a question.
- **Every bundle opens with the run-pf line.**
  Every bundle `pf` writes opens its preamble with one fixed line telling its reader to run bare `pf` and follow the guide. The Prosiform section and its protocol paragraphs retire; Dispatch sub-sections and `Dispatch in parallel` sections stay, naming no protocol link. *Clean Markdown*, *Generated heading collisions* and the conformance list follow.
- **A deferred dispatch keeps its mark.**
  `[¬⇉ four](four.md#do)` publishes as `[⇉ four](four.md#do)`, its path rebased as *A deferred link's destination* states.
- **A set holds its deferred members.**
  A deferred `⫽` member keeps no `⫽`, and the set is built as an immediate set is: prose links point at `#dispatch-in-parallel`, and the section lists a compiled member as its bundle file and a deferred member as a deferred dispatch, `- [⇉ five](five.md#do)`. The section's rule: compile each `⇉` item first, then dispatch the whole set together; if any compile fails, dispatch none.
- **A set of one is a plain dispatch.**
  A one-member set publishes as a Dispatch sub-section when immediate and as a deferred `[⇉ x]` link when deferred, never a parallel list of one.
- **The pin moves.**
  The README's design link moves to the engineering commit carrying the amendment.
