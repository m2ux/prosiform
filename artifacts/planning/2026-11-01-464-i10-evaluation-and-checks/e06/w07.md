## Overview

The eval's `compiled` form follows a bundle that opens by sending its reader to the guide, and the eval's README states the forms against the new bundles. The row waits on the epic's open question: what the `compiled` form becomes.

## Problem

- **A compiled session cannot run `pf`.**
  The `compiled` form gives a session the bundle set without the build, and a Claude session in it carries no shell, as E04's AC26 holds. A bundle whose first line says to run bare `pf` asks for what the form withholds, and the dispatch rules are in a guide the session cannot read.
- **The README describes the retired section.**
  The `compiled` form's row states the Prosiform section `pf` emits around each bundle.

## Proposal

**The scene.** `harness.py` builds each harness's session per form; `staged` alone carries the build on its path and, for Claude, a shell.

- **The compiled form as the user settles it.**
  The options held for the user include giving a `compiled` session the build and a shell, folding `staged` into `compiled`, and giving a `compiled` session the guide's text with its bundle. The row is planned once the answer is recorded; its component may move with it.
- **The README follows.**
  The forms table and the dispatch text state the run-pf line, the dispatch sections and the guide.
