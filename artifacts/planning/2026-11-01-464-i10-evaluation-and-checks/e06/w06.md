## Overview

The eval's `compiled` form can follow a bundle that sends its reader to the guide, and the eval's README states the forms against the new bundles.

## Problem

- **A compiled session cannot run `pf`.**
  The `compiled` form gives a session the bundle set without the build, and a Claude session in it carries no shell, so a bundle whose first line says to run bare `pf` asks for what the form withholds, and its dispatch protocol is in a guide the session cannot read.
- **The README describes the retired section.**
  The `compiled` form's row states the Prosiform section `pf` emits around each bundle.

## Proposal

**The scene.** `harness.py` builds each harness's session per form; `staged` alone carries the build on its path and, for Claude, a shell.

- **The compiled form reaches the guide.**
  A `compiled` session can run bare `pf` on every harness the default matrix runs, in the way the epic's open question settles; the recommendation gives it the build on its path and a shell, and folds `staged` into it.
- **The README follows.**
  The forms table and the dispatch text state the run-pf line and the guide.
