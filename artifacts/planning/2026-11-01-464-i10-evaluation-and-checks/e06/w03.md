## Overview

A dispatching bundle carries only its own Dispatch sub-sections and `Dispatch in parallel` sections, since the guide holds the rules; a parallel set lists its deferred members beside its compiled ones, and a set of one is a plain dispatch.

## Problem

- **Each dispatching bundle restates the protocols.**
  `dispatch.py` opens a dispatching bundle with `# Prosiform`, `## Run pf first`, `## Dispatch` and `## Parallel dispatch`, each a fixed paragraph, and each dispatch line links `#dispatch`.
- **A deferred member falls out of its set.**
  A set is built from its immediate members alone, so `[⫽ a](a.md)` beside `[¬⫽ b](b.md)` lists `a` as a set of one and publishes `b` as a plain link.

## Proposal

**The scene.** `dispatch.py` holds `PROSIFORM`, `FIRST_RUN`, the protocol paragraphs, `instruction()`, `TOGETHER`, `listing()`, set building and the heading-collision list.

- **The section retires.**
  No bundle carries `# Prosiform` or a protocol sub-section; the first-run line goes, as W02's line covers every bundle.
- **The sections stay, unlinked.**
  A Dispatch sub-section's line and a `Dispatch in parallel` section's lead line carry the wording W00 fixes, linking no protocol.
- **A set lists both kinds.** (User, 2026-11-03.)
  A deferred `⫽` member keeps no `⫽` and joins its section's set: its prose link points at `#dispatch-in-parallel`, and the section lists it as a deferred dispatch, `- [⇉ five](five.md#do)`, at the path W04 rebases, beside each compiled member's ``- `two__do.bundle.md` (two)``.
- **A set of one is a plain dispatch.** (User, 2026-11-03.)
  A one-member set publishes as a Dispatch sub-section when immediate and as W04's deferred `⇉` link when deferred, never a `Dispatch in parallel` section.
- **Collisions shrink.**
  The headings pf emits no longer include `Prosiform` or the protocol headings, so an authored heading of that text publishes.
