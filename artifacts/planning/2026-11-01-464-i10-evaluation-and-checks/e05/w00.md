## Overview

The design work a live run needs, done once before any run: a triage rubric for failing sessions, a runbook for each of I10's live runs, and the model the default matrix runs, so each run is carried out without judgement of its own.

## Problem

- **A run row carries design judgement.**
  Telling an agent's miss from a scenario or harness defect, fixing what a shakedown finds, and setting the budget are decisions each run row makes for itself.
- **A run cannot settle them for itself.**
  A runner that fixes a scenario can tune a real failure away; one that cannot tell a defect from a miss commits a broken measurement.
- **Difficulty depends on the model under test.**
  The corpus is made hard enough to separate its forms, and a scenario that separates them for one model may fail every form on another.

## Proposal

**The scene.** `make eval-diagrams` runs a matrix of models, harnesses and forms over `workflows/` and writes a run record; the scorer gives each failing session a class.

**The design.**

- **The shakedown's model and harness are the user's.**
  The user names the model and harness the proof's shakedown runs on; the runbook records them. The plan names no model, and the default matrix's model is chosen at E00 W01.
- **One rubric, one home.**
  `RUNBOOK.md` holds the triage rubric: for each class the scorer defines and `errored`, the evidence in the session record that marks a failing session an agent miss, a scenario or harness defect, or unclear, and the action a run takes for each. A miss is recorded; a defect or an unclear session stops the run and is escalated. A runner never edits a scenario, the harness or the scorer.
- **A runbook per live run.**
  For the MVP proof (E05 W01), the baseline (E00 W02) and the edge run (E04 W14), `RUNBOOK.md` states the command and its arguments, the model, harnesses and forms, the token budget and cost cap, the stop rules, the files committed and the check each criterion names. The proof's runbook keeps its harness and model asked at the start.
- **The proof's shakedown proves its runbook.**
  The proof's scenarios exist, so the session runs its shakedown on the chosen model, fixes every harness, scenario or plumbing fault it finds in this pull request, and sets its budget from the measured cost. The baseline's and the edge run's runbooks state their matrix and budget formula; E00 W04 and E04 W16 shake them down once their scenarios exist.
- **Each run record carries dispositions.**
  A run record states the rubric's disposition for every failing session, so the runner's reading is checkable.
