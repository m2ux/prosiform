## Overview

A scenario states the `pf` runs a correct session and each of its sub-agents makes, and the corpus declares the `staged` form, so a scenario can say when an agent compiles deferred material.

## Problem

- **A scenario states no compile.**
  `scenarios.toml` names inputs, a path and a dispatch trace; the only compile the eval observes is whether a `bootstrap` session ran `pf` at all.
- **No form hands a session a bundle and the build together.**
  The `compiled` form gives a bundle set with no shell, and `bootstrap` gives sources to compile, so a bundle carrying a `↳` line has no form to run in.

## Proposal

**The scene.** A workflow is a directory under `workflows/`, its forms beside a `scenarios.toml` naming each scenario's inputs, the path a correct session walks, the sub-agents it starts and the `pf` runs it makes. A `staged` session receives the compiled bundle set with the build under test as `pf` on its path; the scenario passes when the session's path is the one its bundle states.

- **Each run is a stated entry.**
  A `[[scenario.compile]]` table names who runs `pf` (the session, or the sub-agent following a section) and its arguments, in the order a correct walk makes them.
- **A stated run names a real document.**
  The corpus test refuses a run whose path names no document of the workflow's sources.
- **`staged` is a shell form.**
  It joins the shell forms beside `bootstrap`, entered at the compiled entry bundle.
