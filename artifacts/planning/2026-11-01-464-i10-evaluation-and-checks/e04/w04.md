**Component:** main:evals/diagram-following/harness.py

## Overview

Each shell harness reports every sub-agent's starts and shell commands, at every dispatch depth, so a scenario can state what a sub-agent three hops down did.

## Problem

- **A sub-agent's commands are unread.**
  `commands` reads the session's shell calls; nothing attributes a call to the sub-agent that made it.
- **The eval reaches two hops.**
  `dispatch-chain` is the deepest workflow, so no harness is shown reading a third hop's start.

## Proposal

**The scene.** A workflow is a directory under `workflows/`, its forms beside a `scenarios.toml` naming each scenario's inputs, the path a correct session walks, the sub-agents it starts and the `pf` runs it makes. A `staged` session receives the compiled bundle set with the build under test as `pf` on its path; the scenario passes when the session's path is the one its bundle states.

- **Commands are attributed.**
  Each shell call is filed under the section its sub-agent followed, as `starts` files a start.
- **Depth is read, not assumed.**
  Whether each harness's stream reports a nested sub-agent's calls is settled from a recorded transcript; a harness that does not is declared so.
