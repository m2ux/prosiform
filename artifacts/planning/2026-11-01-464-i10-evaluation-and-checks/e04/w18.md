## Overview

A `staged` Claude session carries a shell, so the nested-dispatch scenarios reach a harness that reports every start they state.

## Problem

- **The nested scenarios reach no harness.** ([#635](https://github.com/m2ux/prosiform/issues/635))
  `dispatch-depth` and `subagent-first-run`'s `deep-hop-runs` are written in the `staged` form alone. Claude's stream reports each sub-agent's own starts by `parent_tool_use_id`, but its tool allowlist names no shell, so Claude runs no `staged` session; Cursor and opencode carry a shell but report no sub-agent's calls. The edge run therefore gives these scenarios to no harness.

## Proposal

**The scene.** A run gives a `staged` session only where its harness carries a shell; the scorer reads the session's starts and each start's commands.

- **A shell for a staged session.** (User, 2026-11-03.)
  A Claude session given the `staged` form carries the CLI's shell tool, and only that form does; `compiled` and `authored` sessions keep the allowlist that names no shell. `Claude.shell` holds for the staged form, so a run gives Claude `staged` sessions.
- **Each start's commands.**
  The shell calls a session and each of its sub-agents make are read from the stream, attributed to the start whose sub-agent made them, so the scorer holds every `pf` run a nested scenario states.
- **The nested scenarios on Claude.**
  `make eval-diagrams` gives `three-hop-chain`, `three-hop-set`, `three-hop-question` and `deep-hop-runs` to Claude, and the stub agent shows each one scored.
