**Component:** main:evals/diagram-following/workflows/dispatch-depth/scenarios.toml

## Overview

A `staged` workflow dispatching three hops deep, within the depth the run publishes without `W_DISPATCH_DEPTH`, so the eval measures a chain, a set inside it and a question returned from its deepest level.

## Problem

- **The eval stops at two hops.**
  `dispatch-chain` dispatches a section whose step dispatches a second; the design admits three before it warns.

## Proposal

**The scene.** A workflow is a directory under `workflows/`, its forms beside a `scenarios.toml` naming each scenario's inputs, the path a correct session walks, the sub-agents it starts and the `pf` runs it makes. A `staged` session receives the compiled bundle set with the build under test as `pf` on its path; the scenario passes when the session's path is the one its bundle states.

- **A chain.**
  Entry `⇉` A `⇉` B `⇉` C, each following its own bundle and returning before its caller continues.
- **A set at one level.**
  One level dispatches with `⫽`; every member starts together and returns before the chain continues.
- **A question from the deepest level.**
  C returns a question; it is relayed up each level to the user, and the chain is dispatched again with the answers.
