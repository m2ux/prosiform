**Component:** main:evals/diagram-following/run.py

## Overview

The runner gives a `staged` session the compiled bundle set with the build under test on its path, and gives it only to a harness that can run it.

## Problem

- **The build reaches only a bootstrapping session.**
  `place_pf` puts `pf` on the path of a `bootstrap` session alone.
- **A new form would join the default matrix.**
  `--forms` defaults to every form, and the committed baseline measures that matrix.

## Proposal

**The scene.** A workflow is a directory under `workflows/`, its forms beside a `scenarios.toml` naming each scenario's inputs, the path a correct session walks, the sub-agents it starts and the `pf` runs it makes. A `staged` session receives the compiled bundle set with the build under test as `pf` on its path; the scenario passes when the session's path is the one its bundle states.

- **A staged workspace holds the bundles and the build.**
  The run compiles the entry's bundle set as for `compiled`, places it, and puts `pf` on the session's path; the instruction names the entry and says `pf` is available.
- **The default matrix is unchanged.**
  `staged` is outside the default `--forms`, so a run names it, and the baseline's cells are untouched.
- **A harness is given only what it can observe.**
  A harness with no shell gets no `staged` session, and one reporting no sub-agent's commands gets no scenario stating a sub-agent's run.
