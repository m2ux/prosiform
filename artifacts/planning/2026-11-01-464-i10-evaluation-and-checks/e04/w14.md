**Lane:** 2

## Overview

One live run of the edge workflows per harness carrying a shell, each committed as its own record beside the baseline, so the eval states how agents follow deferred, composed and dispatched bundles.

## Problem

- **The edge scenarios have no measurement.**
  The baseline runs the Claude harness, which carries no shell, so no committed run holds a `staged` session.

## Proposal

**The scene.** A workflow is a directory under `workflows/`, its forms beside a `scenarios.toml` naming each scenario's inputs, the path a correct session walks, the sub-agents it starts and the `pf` runs it makes. A `staged` session receives the compiled bundle set with the build under test as `pf` on its path; the scenario passes when the session's path is the one its bundle states.

- **A record of its own.**
  A `run.py` run takes one harness, so each shell harness gets its own run, whose `report.json` is committed as `composition-edges-<harness>.json` and its `report.md` beside it, as `RUNBOOK.md` states (user, 2026-11-03); `baseline.json` and `mvp-proof.json` are untouched.
- **A measurement, not a gate.**
  The run follows the edge run's runbook in `RUNBOOK.md` (E05 W00). Failing sessions are recorded with the class the scorer names and the rubric's disposition; a defect or an unclear session stops the run and is escalated, and a refused run is not committed.
