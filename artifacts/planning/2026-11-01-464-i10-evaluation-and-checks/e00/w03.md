## Overview

The harnesses' own behaviour held to the two criteria the baseline can observe: that no harness crashes on a form the matrix runs, and that a dispatched question counts as answered only where the session produced an answer.

## Problem

- **The criteria name a run against each harness, and one harness has a baseline.**
  AC6 and AC7 are stated over "the committed baseline's run against each harness", and only the `opencode` baseline exists. The `claude` harness has runs in the mvp proof and the shakedowns, but no committed baseline of this matrix.
- **A harness crash is read from a session's exit status.**
  A run whose harness crashes leaves a session with a non-zero exit status and no verdict, so the evidence for AC6 is every session's exit status rather than any class the scorer gives.
- **A question is answered only where the session started the section again.**
  The scorer reads a returned question as answered when a later start names the same section, and as `unrelayed_question` otherwise. AC7 asks that behaviour be what the committed evidence shows rather than what the code intends.

## Proposal

**The scene.** `baseline.json` holds one matrix's cells, and `report.py` writes it from one run. Each harness reaches its own run, and its sessions' exit statuses are its own evidence.

**The design.**

- **Each harness's baseline is read for its exit statuses.**
  A harness crashes on no form when every session of its run records exit status 0. The opencode baseline holds 360 such sessions over six forms.
- **A harness without a committed baseline is reported, not assumed.**
  AC6 is stated over each harness the matrix runs. A harness with no committed baseline has no evidence, and the README says which harnesses the baseline covers rather than treating one result as covering all.
- **The relayed-question reading is held by a test.**
  A returned question followed by a start naming the same section is the one answer; a returned question with no such start is `unrelayed_question`. A test holds both.

## Validation

### T1: No harness crash

The committed baseline's run started 360 sessions and each recorded `exit_status` 0, so the `opencode` harness crashed on no form its run covers. A harness with no committed baseline has no evidence, and that absence is stated rather than passed over.

### T2: A question answered only by an answer

`test_score.py` holds a start returning a question followed by a start naming the same section as answered, and the same return with no such start as `unrelayed_question`.
