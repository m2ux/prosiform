## Overview

The baseline's runbook proven on the hardened corpus: a session shakes it down before the run on the user's model and sets its budget, so the baseline run carries no judgement of its own.

## Problem

- **The baseline's runbook is written before its corpus exists.**
  E05 W00 writes every runbook's text, but the harder scenarios W01 adds arrive later, so the runbook's budget and stop rules are unmeasured.

## Proposal

**The scene.** `RUNBOOK.md` holds the triage rubric and a runbook per live run; a run row follows its runbook and escalates what the rubric marks a defect.

**The design.**

- **A shakedown over the hardened corpus.**
  The session records in `RUNBOOK.md` the model the user chose at W01 for the default matrix, then runs the baseline runbook's shakedown on it, fixes every harness, scenario or plumbing fault it finds in this pull request, and sets the budget and cost cap from the measured cost.
- **The default budgets follow the measured sessions.**
  The proof's shakedown (E05 W00) measured sessions averaging about 120 000 tokens, cache reads included, against the runner's default session cap of 60 000 and an `EVAL_BUDGET_TOKENS` sized from it. The shakedown sets the default session cap, `EVAL_BUDGET_TOKENS` and the README's figure from what it measures.
- **The rubric meets the new scenarios.**
  Every class the shakedown produces has a rubric entry that decides it.
