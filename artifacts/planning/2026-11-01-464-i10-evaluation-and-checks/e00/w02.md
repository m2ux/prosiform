**Component:** main:evals/diagram-following/baseline.json

## Overview

One baseline over the hardened corpus, carrying every form the default matrix runs, the dispatch scenarios' compiled and authored forms among them. It is the first measured pass rate the dispatch scenarios have, and the reference later runs compare against.

## Problem

- **The baseline carries three of the forms the matrix runs.**
  `baseline.json` holds 150 sessions over `bundle`, `tree` and `prose`, so every `linked` cell of a report reads `new`.
- **The dispatch forms have no baseline.**
  The compiled and authored forms are newer than the committed baseline, so a dispatch scenario's pass rate has nothing to be compared with.
- **One file holds one baseline.**
  `report.py` writes the baseline whole, so two runs cannot each commit one: the second replaces the first. Every form and every dispatch scenario therefore share one run.
- **The documented cost is estimated.**
  The README states the cost of a three-form run, and the default matrix runs more forms than that.

## Proposal

**The scene.** `make eval-diagrams` runs the default matrix against paid agent sessions, and `--write-baseline` commits its cells. The run measures the scoring and the harness as they stand, so it follows the corrections to both.

- **Cost first.**
  The run's estimate is put to the user before it starts, and the run starts only on their approval.
- **One run over the default matrix.**
  `make eval-diagrams` over the hardened corpus: every form each workflow is written in, the default models and five repetitions.
- **Review before the baseline is taken.**
  Every failing session is read. A failure caused by an ambiguous scenario or an unclear protocol is a corpus defect, fixed, and the affected cells are re-run before the baseline is written.
- **Record.**
  The baseline file and the run's report are committed, and the eval's README states the measured cost of the matrix the baseline covers.
