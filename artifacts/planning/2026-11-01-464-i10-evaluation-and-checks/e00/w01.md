**Component:** main:evals/diagram-following/workflows

## Overview

The eval's scenarios are easy enough that every cell of the committed baseline is 5 of 5. This task raises the corpus's difficulty until a plausible misreading produces each failure class the scorer defines, so a run's failures say which way an agent departed rather than only that it stumbled.

## Problem

- **Every cell is saturated.**
  The committed baseline holds 30 cells, every one 5 passed of 5, with no recorded failure of any class.
- **The diagram workflows cannot reach every class.**
  `linear`, `branching` and `looping` carry five scenarios. A linear workflow offers nothing to mis-branch at, and a two-round loop is short enough to miscount by luck rather than by error.
- **Nothing tests that a class is reachable.**
  The scorer holds seven classes beside `errored`, and no test asserts each has a scenario that can produce it, so a class can go dead without a failure.

## Proposal

**The scene.** `make harness` bundles every form of every workflow, holds each scenario's path to the walk of its diagram, and scores stub runs against it. A scenario is what makes a mistake possible; the workflow's diagram, prose and linked forms are the product under test.

- **Difficulty comes from the scenarios.**
  Each class gets at least one scenario a plausible misreading fails: a second decision, a longer loop with a counted bound, a state reachable only through a link, and a distractor state no edge leads to.
- **Every class is held reachable.**
  The corpus test asserts that each of the seven classes and `errored` has a scenario able to produce it, and names any class no scenario reaches.
- **The forms stay one statement of the edges.**
  A new scenario's path is the walk of its workflow's diagram from the start state to a terminal one, so the corpus test holds every form to one statement of the edges.
- **A new linked form meets the entry rule.**
  Each linked form's entry document carries what the corpus check allows a linked entry to carry, so the new workflows measure link-following.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Which class each existing scenario can reach, and which classes no scenario reaches |
| Plan | The scenario and workflow each unreachable class needs |
| Implementation | The workflows, their forms, scenarios and inputs, and the reachability assertion in the corpus test |
| Review | Every path is the walk of its diagram; no form drifts from another |
| Test | `make harness` (the corpus tests) and `make check` |
