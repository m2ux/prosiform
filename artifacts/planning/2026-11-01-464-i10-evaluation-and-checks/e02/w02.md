**Component:** evals/diagram-following/harness.py

## Overview

Claude Code reads a managed settings file from a system path on every host, whatever the config directory names, and the preflight does not read it. This task makes the preflight read the host's managed settings file and refuse one declaring a hook before the first session starts.

## Problem

- **Managed settings reach every session.**
  The managed settings file sits at a system path, `/etc/claude-code/managed-settings.json` on Linux, and its `hooks` block reaches a session exactly as one in the config file does. Relocating the config directory leaves it in force.
- **The preflight reads the config directory and the project scopes alone.**
  A hook declared by the host's managed settings therefore reaches every session of every form, and only the injected-context read catches it, after the sessions are paid for.

## Proposal

**The scene.** The preflight, as widened by W01, reads the config directory's `settings.json` and every project-scope settings file before `run()` starts a session.

- **The preflight reads the managed settings file.**
  It reads the managed settings path for the host's platform and refuses the run when that file declares a hook, naming the file and the events it declares in the form the other refusals take. An absent file refuses nothing.
- **The path is injectable.**
  The harness holds the managed settings path as a field beside the config directory's file names, so a stub-agent test plants a file at a temporary path in place of the system one.
- **The remedy is the host's.**
  The file belongs to the host's administrator, so the refusal names it and states that a run on that host cannot be isolated from it.
