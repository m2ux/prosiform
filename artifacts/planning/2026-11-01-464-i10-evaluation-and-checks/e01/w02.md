**Component:** main:checks/links.py

## Overview

The link check resolves a GitHub blob or tree URL into this repository against the branch the URL names, at whatever commit that branch holds when the check runs. This task makes the check name the commit each branch resolved to, so a result is a statement about a revision rather than about a name.

## Problem

- **A branch moves beneath the check.**
  A reference into `engineering` resolves against `origin/engineering` as it stands, so one commit of the repository passes or fails according to what that branch holds at the moment of the run.
- **The output names the branch, not the revision.**
  A failure reads `does not exist on engineering`, and a success names only the reference. Two runs over one commit that disagree are indistinguishable in their output.
- **The design reads are pinned already.**
  The vocabulary, conformance and independence checks read the design at the commit the README's Design link names, and the vocabulary check prints that commit. The link check is the one check whose input moves.

## Proposal

**The scene.** Concurrent delivery writes the engineering branch ahead of the build, so each session's planning commit is visible to the other sessions' link checks before their repository change lands.

- **Each branch is resolved once per run.**
  The check resolves each branch name a reference carries to a commit at the start of its run and resolves every reference into that branch against that commit.
- **The run names what it read.**
  The summary names each branch and the commit it resolved to, and a failure on a reference into a branch names that commit beside the branch.
- **A reference pinned to a commit reads as written.**
  A URL naming a commit resolves against that commit and needs no further statement.
