## Overview

Every session's workspace holds its variant's skill under the root its CLI discovers, and the CLI offers that skill and no other. The task fixes the variant layout every family converts to, and moves the two bootstrap workflows onto it as the first variants.

## Problem

- **One form places a skill.**
  `prepare()` places a skill for `bootstrap` alone, from a `skill/` directory only two workflows hold.
- **The Claude harness disables skills.**
  It passes `--disable-slash-commands` and leaves its skill tool out of `--tools`, so a placed skill is a file the agent can only stumble on.

## Proposal

**The scene.** Each harness already names a `skill_home`: `.claude/skills` for `claude` and `cursor`, `.opencode/skills` for `opencode`.

- **The variant layout.**
  A workflow's variant is its `SKILL.md` text at `skills/<variant>.md` and a material tree: `compiled/` or `diagram/` for the product variant, and the tree a control was written in.
- **Placement.**
  The runner writes the text as `<skill_home>/<workflow>/SKILL.md` and copies the material tree beside it under `sources/`, for every variant on every harness.
- **A workflow with skill texts runs as skills.**
  A workflow holding `skills/` gives sessions in its variants alone; one without keeps its forms until its family converts.
- **The Claude harness offers skills.**
  It drops `--disable-slash-commands`, adds its skill tool to `--tools`, and its preflight refuses a configuration directory holding a `skills/` directory; the isolation table in the README states both.
- **The bootstrap pair moves.**
  `skill/SKILL.md` becomes `skills/compiled.md` and each file under `skill/sources/` moves to `compiled/`, so both workflows run as product variants.
