## Overview

A session opens with its scenario's task in plain words, and the CLI picks the skill from its description. Discovery becomes part of what a session is measured on.

## Problem

- **The prompt is an instruction about files.**
  `instruction()` fills an instruction file with the entry document's name, or, for a skill, tells the agent a skill is there to find.

## Proposal

**The scene.** A scenario's inputs are files under `inputs/` that the workflow's conditions read; its prompt is what the agent is asked to do.

- **A task per workflow.**
  `scenarios.toml` states a top-level `task`, one or two sentences in plain words, with `{<input file>}` placeholders that a run fills from the scenario's inputs.
- **The task is the prompt.**
  The run sends the filled task as the session's only prompt, naming no file, skill or instruction.
- **The tracing duty sits in the skill.**
  How a session records `trace.log`, names a sub-agent's trace and reads `answers.txt` is one paragraph every variant's `SKILL.md` shares, pending the epic's open question.
- **The bootstrap pair states its tasks.**
  `bootstrap-audit` and `inline-bootstrap` gain their `task` and the shared paragraph.
