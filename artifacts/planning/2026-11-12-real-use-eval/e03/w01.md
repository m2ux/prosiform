## Overview

Work Planner becomes a workflow of the eval with a `compiled` and a `tree` skill variant, each taken from a recorded commit of its repository, and its scenarios are captured requests with the inputs each reads.

## Problem

- **No workflow is a skill of real size.**
  Every workflow is written for the eval, and the largest form of any is a few kilobytes.
- **A variant's skill text is the eval's.**
  The variant layout places a `SKILL.md` the corpus writes, and Work Planner's entry point is a file of its own revision.

## Proposal

**The scene.** The variant layout places a workflow's skill under the harness's discovery root and its material beside it, and a scenario's `task` opens the session. Work Planner's cutover settles a revision where every mode compiles and fixes the plain revision it is compared with.

- **Two variants from two commits.**
  `compiled` is the skill's folder at the settled revision and `tree` the folder at the baseline revision; the workflow records the repository and both commits.
- **The skill's own entry point.**
  The runner places each revision's `SKILL.md` and files as they stand, adding no text.
- **Captured requests as scenarios.**
  One scenario per captured Standup, Revise and Understand request: its `task` is the request in plain words and its inputs are the captured sources the request reads.
- **No tracker.**
  A scenario's inputs stand in for the board, pull request or files its request reads, so a session runs with no network.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The settled and baseline commits, the captures each request carries, and what each mode reads from a tracker |
| Plan | How each revision's files reach the eval tree, confirmed by the user; the scenario inputs standing in for tracker reads |
| Implementation | The workflow's commit record and scenarios, the layout and placement admitting a revision's own skill text, the README's workflow table |
| Review | Each placed file matches its recorded commit; no scenario input names a live tracker |
| Test | `make eval-harness`: the corpus test holding both variants to their commits and each scenario to its captured request, and a stub session per variant |
