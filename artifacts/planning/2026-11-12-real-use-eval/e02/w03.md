## Overview

The real-use baseline is run as the runbook states, triaged, and committed as the eval's baseline.

## Problem

- **The eval has no baseline of real use.**
  Its bare-prompt baseline left the eval with the records.

## Proposal

**The scene.** The runbook's real-use baseline section fixes the run's arguments and caps.

- **The run.**
  The section's command on the harness and model the user named, held to its stop rules.
- **The record.**
  Every failing session triaged into `dispositions.json`; `baseline.json` written by `report.py --write-baseline`, the run's `report.md` beside it, and the run's measured cost in the README.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The section's caps and the user's approval of the cost cap |
| Plan | None beyond the runbook |
| Implementation | The run, its triage and the committed record |
| Review | No `untriaged`, `defect` or `unclear` disposition |
| Test | The report's Failing Sessions, and `make eval-harness` reading the new baseline |
