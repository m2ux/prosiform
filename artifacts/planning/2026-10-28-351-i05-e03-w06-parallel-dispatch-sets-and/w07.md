**Component:** example/work-planner/artifacts/delivery-evidence.md

## Overview

The example's Board Reads states its reads as numbered step sub-sections, since each read takes the result of one before it and a parallel set states no order. It is the first procedure in the corpus written in the step form the corpus adopts.

## Problem

[Board Reads](https://github.com/m2ux/prosiform/blob/4fdaf8a2ffb1c46784ef454522e5deb37dfef32a/example/work-planner/artifacts/delivery-evidence.md) is a `⫽` run-set whose nested items wait on their parents: the pull requests are fetched for each repository the board read returned, and their issue links from those records. Under a set with no order, that nesting states nothing, and the `⫽` link would dispatch each read as a bundle of its own.

## Proposal

Read Board Delivery Evidence's first step links Board Reads as an ordinary section, whose reads follow as `##### 1. Read Board State`, `##### 2. Fetch Initiative Pull Requests`, `##### 3. Fetch Pull Request Issue Links`, `##### 4. Read Board Configuration` and `##### 5. Read Board Assignee`, each naming the result it takes.

- **Number plus action.**
  Each step heading is its position and its action, `N. Action`, one level below Board Reads (level 4), so level 5.
- **No `⫽` link.**
  The step linking Board Reads links it as an ordinary section.
- **Fixtures.**
  Each usage-example fixture whose entry reaches Read Board Delivery Evidence takes the expected bundle the rewrite compiles to, and the example README's account of Board Reads states the steps.
