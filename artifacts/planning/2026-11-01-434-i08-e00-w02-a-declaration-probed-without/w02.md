**Component:** src/prosiform/access.py

## Overview

A target's declaration is answered by reading its frontmatter and stopping there. The probe opens the file through the same rooted no-follow walk a capture takes, reads whole lines until the delimiter rule answers, decodes the block within the byte budget, and returns whether the file declares.

## Problem

The only read the run has captures a whole source.

- **`access.read_source` reads to a limit or to the end.** `cli.read_document` calls it, counts the bytes against `-B` and `-I`, decodes the metadata and keeps the document as a source. A question that needs the frontmatter alone is answered by a read that carries the whole file.
- **The frontmatter span is found inside `source.content`.** The opener and closer test is written once, over captured text, and interleaved with the metadata decode and the body strip, so a reader of only the head has no rule to stop by.
- **A size boundary decides a document nobody asked to carry.** A target larger than `-B` fails the run at its capture whether or not it declares, so a cited document that declares nothing still costs the run its budget.

## Proposal

**The scene.** `read_document` captures a document within `min(-B, -I remaining)` and calls `source.content`, which finds the span and calls `metadata.decode`. Every failure the read meets — a link, an absent file, an access fault, an undecodable byte, an invalid or unterminated block — is mapped there to its diagnostic.

**The design.**

- **`access.read_head`.** A read on the existing walk: `access.opened` yields the descriptor, and whole physical lines are read until a supplied predicate answers for the last line, the budget plus one byte is read, or the file ends. The walk is rooted and no-follow as every other read is, so a probe reaches nothing a capture cannot.
- **The delimiter rule stays in `source.py`.** `source.frontmatter` is the span finder `content` calls, and `source.closes_head` answers whether one physical line ends a head from the same `OPENER`, `CLOSERS`, byte-order-mark and `bare` rules: a first line that opens no block ends it, as does a later line that closes one.
- **The decode is the same decode.** `source.declaration` finds the span over the head and calls `metadata.decode` with it, so an invalid `prosiform` mapping is refused at the probe with the diagnostic a capture gives, and an opener the head never closes is `E_UNTERMINATED_FRONTMATTER`.
- **A size boundary is not a declaration.** `cli.probe` reads within `-B`. A head holding no opener declares nothing whatever the file's size, so an oversized silent target is answered without being counted. A head that crosses `-B` before its block closes fails the run with `E_RESOURCE_LIMIT`, since its declaration cannot be read. A declaring target is then captured, and the capture holds `-B` over the whole file.
- **One mapping of read failures.** `read_document` and `probe` share the mapping of walk refusals, undecodable bytes and metadata refusals to diagnostics, so a probe and a capture of one file report one failure alike.
- **What the probe leaves to classification.** No stage calls `probe` yet: the classification task asks it for each cited target, carries its answer on the reference and remembers it per path, which is where a caller exists to read the record. The corpus fixture `fixtures/inclusion/an-oversized-silent-target-is-text` awaits that task.
