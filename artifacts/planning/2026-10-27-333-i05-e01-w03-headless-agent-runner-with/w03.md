**Component:** evals/diagram-following/run.py

## Overview

The runner that gives each workflow form and scenario to real headless agent sessions, and records what each did and cost.

## Problem

Measuring an agent following a workflow needs sessions that act on files, in isolation, many times over, with their cost under control.

## Proposal

One session per model, form, scenario and repetition.

- **Workspace.**
  A fresh temporary directory holding the form's material — the bundle file, or the source tree — and the scenario's `inputs/`, and nothing else.
- **Session.**
  `claude -p --bare --model <model> --output-format stream-json --verbose --allowedTools Read,Write,Edit,Glob,Grep --permission-mode acceptEdits --no-session-persistence --max-budget-usd <per-session cap>`, run with the workspace as its working directory and the shared instruction naming the entry file. `--bare` keeps the user's settings, hooks and project memory out of the session. Confirm each flag against `claude --help` at implementation.
- **Records.**
  Per session: the stream-json transcript, the result's token usage and cost, the workspace's `trace.log` and `actions/`, and the scorer's verdict, under `results/<run-id>/`.
- **Spending cap.**
  `--budget-usd` for the run. Before starting a session the runner checks the recorded cost plus the per-session cap against it; sessions it does not start are reported.
- **Options.**
  Models, repetitions, workflows, forms and parallelism, defaulting to the epic's matrix. The agent command is configurable so the tests run a stub agent that writes scripted traces.

## Work Breakdown

| Part | Description |

| Analysis | Read `claude --help` and the stream-json result message's usage and cost fields. |
| Plan | `run.py` in `evals/diagram-following/`, run as `uv run --project src --frozen python evals/diagram-following/run.py --budget-usd <usd>`. The matrix is model × workflow × scenario × form × repetition, in that order. Forms: `bundle` (the diagram form bundled by `pf`, one file), `tree` (the diagram source tree as it is) and `prose` (the prose form bundled by `pf`); each session's workspace is a fresh temporary directory holding that material with `workflow.md` as its entry, and `inputs/` with each input as its value and a newline. The prompt is `workflow.instruction("workflow.md")`, given on standard input. Session command: `claude -p --bare --model <model> --output-format stream-json --verbose --tools Read,Write,Edit,Glob,Grep --permission-mode acceptEdits --no-session-persistence --max-budget-usd <session cap>`, checked against `claude --help` of CLI 2.1.216: `--tools` limits the toolset, so no Bash tool exists; `--allowedTools` is left out, since it pre-approves and would let Read reach outside the workspace; `--bare` authenticates by `ANTHROPIC_API_KEY` alone, and a run without it fails before starting a session. Records: `results/<run-id>/<model>/<workflow>/<scenario>/<form>/<repetition>/` holds `transcript.jsonl`, `stderr.log` when non-empty, `trace.log`, `actions/` and `session.json` (model, workflow, scenario, form, repetition, command, exit_status, duration_seconds, usage, cost_usd, result — the whole stream-json `result` message — and verdict, W02's record); `results/<run-id>/run.json` holds run_id, options, command, sessions, started, cost_usd and not_started. `results/` is git-ignored. Cap: `--budget-usd` (required) and `--session-budget-usd` (0.50). A session reserves its cap before starting; while recorded cost plus reservations plus its cap exceed the budget it waits for a session in flight to settle, and with none in flight the run stops and lists the rest as not started. A session settles at its `total_cost_usd`, or at its cap when it reports none. Options: `--models` (`claude-haiku-5-5,claude-sonnet-5-5`), `--repetitions` (5), `--workflows` (all), `--forms` (`bundle,tree,prose`), `--parallel` (4), `--agent-command` (`claude`, a command line), `--results`, `--run-id`. Stub agent: `stub_agent.py` recognises its workflow by the state headings in its workspace, walks the diagram for its inputs, writes `trace.log` and `actions/`, and prints a stream-json transcript whose `result` carries usage and a cost; the environment sets its cost, a stop point, a log of what it saw, and silence. Tests in `test_run.py`, run by `make harness`. |
