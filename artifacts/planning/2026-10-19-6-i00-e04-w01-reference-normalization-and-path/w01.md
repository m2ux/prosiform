## Overview

Normalization of a reference into a path identity, and rejection of the forms outside the profile.

## Problem

A link string is not a path: percent escapes, an encoded delimiter, a query and a relative segment each change which file a reference names.

The build reaches a document's identity by splitting an entry reference at the first number sign and joining what precedes it to the allowed source root. That split is performed on the authored text, so an encoded number sign becomes a delimiter and a filename carrying one is unreachable; no escape is decoded, so a reference naming `notes#draft.md` opens nothing; no escape is validated, so a truncated one reaches the filesystem as text; and a query is carried into the path, so `guide.md?view=raw` names a document no root holds and fails as a missing file rather than as the unsupported reference it is.

Every later row of the epic resolves against this identity. Root confinement compares a normalized path with the root, traversal compares two references for the same target, and self-reference classification compares a path and a fragment after resolution. Each of those comparisons is wrong wherever the identity it compares was derived from the authored string.

## Proposal

A reference is normalized to a path identity by one sequence, in the order the design states, and the forms the profile does not admit are refused by name rather than being opened.

A reference is classified as a Markdown document by its suffix: `.md` and `.markdown` are recognized case-insensitively while filesystem spelling and case semantics are preserved, and an explicit entry carrying another suffix fails. Components split before percent-decoding so an encoded delimiter stays a filename character. Escapes validate strictly and decode exactly once as UTF-8. A query on a local Markdown reference fails, as do unsupported schemes, NULs, control characters, decoded path separators, backslash separators, root-relative URL paths, absolute reference paths, protocol-relative URLs and drive paths. Relative segments normalize against the proper base, and the decoded fragment is looked up exactly.

### The Component That Holds It

`closure.py` is a new module of the package, and it is the first of the dependency-closure epic: root confinement, link classification and traversal each extend it. It holds the resolution sequence and nothing else — no filesystem access, no parser and no diagnostic stream — so the identity a reference normalizes to is decided by one function over one string and a base, and every caller that compares two references compares what that function returned.

The module answers one question: what document and what section does this reference name, and is it a reference the profile resolves at all. It raises when the answer is that the reference names nothing the root can contain, and it returns an external classification when the reference carries a scheme or an authority, because such a reference is text rather than a dependency.

### The Sequence

Each step is the design's step of the same number, under `Reference normalization and path identity — Resolution sequence`.

| Step | What the module does | Refusal |
| --- | --- | --- |
| 2 | Splits the fragment at the first number sign and the query at the first question mark before it, on the authored text | |
| 3 | Classifies a reference opening on a scheme or on `//` as external and resolves no further | |
| 4 | Refuses any query component, an explicitly empty one included | `Malformed` |
| 5 | Validates every escape as a percent and two hexadecimal digits, and decodes each path segment and the fragment exactly once as UTF-8 | `Malformed` |
| 6 | Refuses a NUL, a control character, a separator a decoded segment carries, and a backslash the authored path carries | `Malformed` |
| 7 | Normalizes `.` and `..` against the base, and refuses a path the base cannot contain | `OutsideRoot` |
| 9 | Returns an absent and an empty fragment alike as a whole-document reference | |

A path is split into its segments before any of them is decoded, so an escape can never produce a delimiter: a decoded `/` is a character in a filename the root does not hold, which step 6 refuses, rather than a separator the normalization in step 7 would act on. This is the whole reason the order is what it is.

A drive path is read before a scheme, because a scheme of one letter and a drive letter are spelled alike. `C:/notes.md` is a path form the root cannot contain, and reading it as a scheme would emit it as authored.

### What Each Refusal Returns

The module names the kind of refusal and the command names the code and the status, so the sequence states what a reference is and the contract states what a run does about it.

| Refusal | Entry reference | Code | Status |
| --- | --- | --- | --- |
| `Malformed` | A reference the contract's grammar does not admit: a query, an invalid escape, a NUL or control character, a decoded or authored separator | `E_INVALID_USAGE` | 2 |
| `OutsideRoot` | A reference naming a local document the root cannot contain: a normalized `..` escape, a root-relative path, an absolute path, a drive path | `E_SOURCE_OUTSIDE_ROOT` | 1 |
| External | A scheme or an authority, which names no document under the root | `E_SOURCE_OUTSIDE_ROOT` | 1 |

No code is added. `E_INVALID_USAGE` is the CLI contract's code for a command line its grammar does not admit, and an entry reference is part of that grammar; `E_SOURCE_OUTSIDE_ROOT` is the code the design declares for a normalized path the root cannot contain, and the design groups the root-relative, absolute and drive forms with it in one sentence — they each name a local document the root cannot contain. The catalogue is complete at 21 codes and this row leaves it at 21.

An external reference refuses only as an *entry*, where the contract requires a document under the allowed source root. The same reference inside a source is text: step 3 classifies it, and nothing opens, fetches or rewrites it.

## Criteria

- **AC6.** A schemeless reference carrying a query or a path form the root cannot contain fails with its declared error code rather than being opened, while a reference carrying a scheme or an authority is emitted as authored, as the normalization fixtures show.
- **AC8.** Markdown classification recognizes the `.md` and `.markdown` suffixes case-insensitively, and an explicit entry carrying another suffix fails, as the suffix fixtures show.
- **AC14.** A filesystem path written as ordinary prose, rather than as a link, is left as text and resolved as no dependency, as the bare-text fixtures show.

## The Fixtures

The corpus states the contract, so each criterion is proved by a fixture rather than by this build's tests.

| Fixture | Declares | Criterion |
| --- | --- | --- |
| `normalization/query-on-an-entry-reference` | A query component refused by code, the document never opened | AC6 |
| `normalization/root-relative-entry-reference` | A path beginning with a slash refused as one the root cannot contain | AC6 |
| `normalization/a-scheme-and-an-authority-in-selected-content` | A reference carrying a scheme, and one carrying an authority, emitted as authored | AC6 |
| `profile/entry-suffix-outside-the-profile` | An explicit entry carrying another suffix refused — already in the corpus | AC8 |
| `profile/markdown-suffixes-in-mixed-case` | Both Markdown suffixes recognized whatever case they are spelled in | AC8 |
| `normalization/bare-text-paths` | A filesystem path in prose left as text and resolving to nothing | AC14 |

The bare-text fixture writes paths that would each fail normalization if anything resolved them — a parent-relative path and a path carrying a query — so a run that read prose as a reference fails the fixture by its status rather than passing it by accident.

Under D36, the boundary, failure and adversarial cases are declared and carry `awaiting = "I00:E10"`: a double-encoded escape, an encoded path separator, an over-long percent escape, a non-UTF-8 escape sequence, a protocol-relative URL, a drive path, and a `..` sequence normalizing to the root boundary exactly. A marked fixture the build already meets fails the corpus run, so a marker is carried only where the behaviour is genuinely beyond this row and is lifted on the fixture the build satisfies.
