**Component:** `docs/`

## Overview

This task states the epic's rule where a reader meets it. The repository's published documentation says what a reference's position decides — a local Markdown reference under the allowed source root is compiled into the bundle and rewritten to its destination, one resolving outside it is emitted exactly as authored and its target is never opened — and what the mark defers: a marked link is not compiled, the bundle carries its text with the mark as written, its destination names the target from the root, and the target must still exist. The shipped glossary defines the deferral as the contract's own term, which is how the vocabulary check observes the statement.

It matters because seven rows changed what the tool does and the published prose still describes only half of it. The documentation already reads position; it says nothing of the one mark an author writes to override it, so the reader who meets a `¬` in a bundle has nowhere to look it up. The design's *Validation scope* section, meanwhile, still names a rule whose refusal was retired, and a stale clause in the contract reads as current fact.

## Problem

The rule is delivered in the build, declared in the contract and absent from the surfaces a reader reaches first.

- **The published documentation states position and omits the deferral.**
  `README.md`'s architecture list, its How It Works sequence and the paragraph that walks a run each describe a reference as compiled under the root or carried as authored outside it. Neither names the mark, so the third answer position gives — reached in a run of its own — is published only in `example/README.md`, where it reads as a property of that one tree rather than as the rule.

- **The glossary defines no deferral.**
  `docs/glossary.md` is the one place a contract term is defined, and it ships with the build so an installed tool carries the vocabulary its diagnostics use. The deferral is a contract term by D59 and has no entry, so the vocabulary the glossary holds and the vocabulary the contract uses disagree by one term.

- **The rebased destination is stated only in the contract.**
  A reader of a marked link needs three things: that this run does not compile it, that the mark is the author's and is carried, and where the link now points. The design states the rebase; no published document does, so an agent reading a bundle learns the destination's spelling by inspecting one.

- **The design validates a rule with no subject.**
  *Validation scope* lists self-reference among the things validated within the selected dependency closure, and holds that a self-link in an unselected sibling must not fail bundling. A link naming the section it sits in resolves to that content's destination like any other reference the bundle carries, so neither clause describes a refusal the run can make.

## Proposal

The documentation carries the whole of what position decides, the glossary carries the term that names the exception, and the contract stops validating a rule it no longer states.

- **The published documentation states all three answers together.**
  `README.md` gains the deferral beside the classification it qualifies: in the architecture list as a term of its own, in the How It Works sequence at the step that follows dependencies, and in the paragraph that walks a run, where the mark's four properties are stated in the order a reader needs them — not compiled, carried as written, destination rebased to the target's path from the root, target required to exist. The Scope section stands: a deferral withholds a compilation rather than reaching past the root.

- **The glossary defines the deferral once.**
  One row under References: the term, what an author writes, and what the bundle does with the link. The glossary is a definition rather than a procedure, so the row names the mark's character, the carriage of the text and the rebased destination, and leaves the failure to the catalogue that declares it.

- **The vocabulary check is what observes the statement.**
  It holds `docs/glossary.md` to defining every term the design marks and holds every definition to being carried by the design or an epic's acceptance criteria. A definition the contract does not use fails it, so the term entering the glossary is the term the design already uses, and the check passing is the glossary and the contract agreeing on one vocabulary.

- **The design validates what the run refuses.**
  *Validation scope* names link resolution, supported selected syntax and resource rules within the selected dependency closure, and holds that an unrelated broken link in an unselected sibling must not fail bundling. Self-reference leaves both clauses: the behaviour it named is stated in *Self-reference and ancestor-reference behavior*, which describes resolution rather than refusal.

- **The retired codes have no prose left to correct.**
  `E_MARKED_RESOURCE` and `E_SELF_REFERENCE` appear nowhere in the tree, and the error catalogue in `fixtures/README.md` carries neither; `E_SOURCE_OUTSIDE_ROOT` already reads as the entry-reference refusal `W06` confined it to. The grep the row owes is the evidence of that, and it records a clean sweep rather than a correction.
