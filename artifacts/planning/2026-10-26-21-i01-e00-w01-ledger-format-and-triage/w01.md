**Component:** ledger

## Overview

The ledger that holds what use reveals, the triage states an entry takes, and the exposure set of sources that must be bundled before a freeze. A later reader re-runs an entry from its fields alone, and a schema check run by `make check` holds every entry and the exposure set to their declared shape.

## Problem

A surprise met mid-task competes with the task, so without a cheap place to record it the cheapest action is a local workaround. A note that omits the invocation, the working directory or the revision of what was bundled cannot be re-run once the session that met it is gone.

## Proposal

An agent bundling a mode with `pf` meets output it did not expect. It writes one small file under `ledger/entries/`, commits it beside the work, and carries on; a later reader checks out the named revisions, runs the recorded command from the recorded directory, and compares the result with the two results the entry states.

- **Location.** The ledger is the `ledger/` folder at the root of `main`, beside the check under `checks/` that reads it, so one revision carries both.
- **Format.** One TOML file per entry under `ledger/entries/`, validated against `ledger/entry.schema.json` through `jsonschema`, the same reading the fixture manifests take. TOML and `jsonschema` are already the corpus's format and reader, so the check adds no dependency.
- **Entry fields.**
  - `date`: the day the result was observed, `YYYY-MM-DD`.
  - `invocation`: the `pf` command line and the working directory it ran from, relative to the checkout of the first source.
  - `sources`: each source the run bundled, by repository, full revision and path.
  - `observed` and `expected`: the result the run produced and the result the reader expected.
  - `triage`: one state among `design change`, `corpus gap`, `build defect` and `no change`, with a non-blank reason.
  - `run`: optional, the identity of a run record the entry cites. The run record's own schema belongs to the run-record task.
- **Exposure set.** `ledger/exposure.toml` declares the sources that must be bundled before a freeze, in two required halves, validated against `ledger/exposure.schema.json`:
  - `example`: each worked-example mode entry as its documented `pf` invocation and working directory. The check holds the half to every mode file under `example/work-planner/modes/`.
  - `workspace`: each workspace skill agents invoke, named by repository, branch and path on `m2ux/workflow-server` branch `workspace`. Nothing is copied in.
- **Check.** `checks/ledger.py`, run by `make ledger` within `make check`, validates every entry and the exposure set. An empty ledger with a valid exposure set passes.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | What a later reader needs to reproduce an entry without the original session, and which sources agents bundle |
| Plan | The entry fields, the triage states, the exposure-set halves, and TOML read through the corpus's existing `jsonschema` reading |
| Implementation | `ledger/` with its README, entry and exposure schemas and exposure declaration; `checks/ledger.py`; the `make ledger` target listed in `checks/README.md` and `checks.md` |
| Review | An entry confirmed reproducible from its recorded fields alone; the exposure set confirmed against the example's modes and the workspace skills |
| Test | `checks/tests/test_ledger.py` under `make harness`: an entry missing each required field in turn is rejected naming the field, the entry's fields validated by the entry schema; a missing or unknown triage state and a blank reason are rejected; an exposure set missing either half, or omitting an example mode entry, is rejected; the recorded ledger and an empty ledger with a valid exposure set are accepted. `make check` passes |
