**Component:** src/prosiform/closure.py

## Overview

A document's boundary is the deepest directory holding every local Markdown path its own links name, read from the whole document; a document naming none has its own directory. The boundary is derived from the links, so it refuses none of them, and `make boundary` states it for every document of the example tree.

## Problem

After [W03](https://github.com/m2ux/prosiform/pull/493) and [W04](https://github.com/m2ux/prosiform/pull/499), inclusion is decided by the target's declaration, and nothing stated the boundary.

- **The boundary had no value.** The design states a document's derived boundary and AC9 and AC17 cite `make boundary`, but no function derived it and no target reported it.
- **A link above the writing directory had no fixture.** `closure.inside` already resolves `../rules.md` from the writing document's directory, so the case a declared root refused (AC2) was compiled unobserved.
- **Diagnostics named a retired boundary.** The `OutsideRoot` messages for a drive path, a root-relative path and a path normalising above the working directory said "allowed source root".

## Proposal

**The scene.** `closure.named` resolves one link to the local Markdown path it names from the writing document's directory; `source.uses` yields every link and image a run of regions carries.

**The design.**

- **`closure.boundary(document, tokens)`.** Every non-image use of the whole document, resolved by `named` with no substitution, contributes its directory; the boundary is their common path, or the document's own directory where none contributes. A fragment-only link names the document itself. A path the grammar refuses — above the working directory included — names nothing and contributes nothing.
- **Whole document, not the selection.** The links are a property of the file, so one file has one boundary whichever region a run selects.
- **No field on `Source`, no run consumer.** The run decides inclusion by declaration and confines by the working directory; nothing in it reads the boundary, so it is a function the report calls rather than a value every capture carries. The identity recheck already walks each link's own directory: `Capture.directories` records every component the walk crossed.
- **A positional entry keeps bounded bootstrap.** The epic plan's `a-w05.md` proposed refusing an entry above the working directory; the pinned design's *Bounded bootstrap capture* and resolution table authorize `../guide.md` positionally, and `confinement/a-parent-segment-above-the-root` holds it. The entry is unchanged and the proposed `confinement/an-entry-above-the-working-directory` fixture is not added.
- **`OutsideRoot` names the working directory.** Each message states the path is above, or no path under, the invocation working directory.
- **`make boundary`.** `checks/boundary.py` reads every example document from the skill's directory, strips frontmatter without decoding it, prints the boundary the build derives and fails on a link naming a path outside it. It imports the build, so it runs from the locked environment.
