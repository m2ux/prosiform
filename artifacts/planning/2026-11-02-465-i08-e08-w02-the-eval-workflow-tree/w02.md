**Component:** main:evals/diagram-following/test_workflow.py

## Overview

Every document in the diagram-following eval's workflow tree declares `prosiform` as a mapping of presets, every form still bundles, and the harness holds the tree to that declaration.

## Problem

The tree declares by convention alone.

- **The declarations have already landed.**
  I08:E00 gave every one of the 118 workflow documents a `prosiform: {}` block (`039ce9a7`), so no document is left to declare.
- **Nothing holds the tree to them.**
  A document losing its block, or declaring a setting outside a preset, fails only where a bundle happens to lose a state, and a document no link reaches fails nowhere.

## Proposal

**The scene.** `make harness` reads the workflow corpus, bundles each form with the `pf` under test and holds each property to an empty list of faults.

**The design.**

- **Every workflow document declares presets.**
  `declaration_faults` reads each document's declaration block and reports a document declaring no `prosiform`, a `prosiform` that is not a mapping, and a key holding anything but a preset's mapping.
- **The corpus is held to no fault, and a broken copy to one.**
  A copy of `linear` with one state's block removed, made scalar, or declaring `group` outside a preset reports that document.
- **The forms are otherwise untouched.**
  No heading, link or diagram line changes, so each form's bundle is the one its baseline records.
