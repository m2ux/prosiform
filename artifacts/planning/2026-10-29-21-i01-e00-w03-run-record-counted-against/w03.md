**Component:** ledger

## Overview

The record of each bundling run, beside the entries under `ledger/`, counted against the exposure set declared at the start of the stage. A later reader sees which declared sources were exercised, what each run did, and what its bundle measured against reading the same sources whole, so a claim that the tool was used rests on records rather than on the absence of surprises.

## Problem

A ledger holding only surprises cannot show whether the tool was used, so a condition counting recorded findings is satisfied by a ledger nobody wrote in. An entry states a result that differed from the expected one, and says nothing about the runs that produced no surprise, the sources they bundled, or what the bundle cost.
    10|
The exposure set already declares the sources that must be bundled before a freeze, but nothing joins a run to it: "each source has a size pair recorded" has no figure to read, and the declared sources cannot be counted as exercised.

## Proposal

An agent runs `pf` to bundle a mode entry or a workspace skill. Beside the entry it writes when the run surprised it, it records the run itself as one small TOML file under `ledger/runs/`, whether the run published or failed; `make ledger` reads both.

- **Record and identity.** One TOML file per run under `ledger/runs/`, named `<yyyy-mm-dd>-<slug>.toml` for the day the run was taken and a short name of it. The identity a citing entry uses is that name without the extension, validated against `ledger/run.schema.json`.
- **Sources named as the exposure set names them.** The record carries `example` and `workspace` lists whose items are the exposure set's own two shapes — a working directory and `pf` command line, or a repository, branch and path — so one source identity has one spelling and a declared source is counted as bundled when a run names it. At least one of the two is present, since a run that bundled nothing is no bundling run.
- **Outcome.** `published` when the run wrote its bundles and `failed` when it wrote none, so the record covers successful runs as well as failures.
    20|- **Sizes.** `sizes.bundle` is the bytes of the bundle the run published and `sizes.whole` the bytes of the same sources read whole, which is the pair the refinement stage is measured on.
- **Acted on.** `acted_from_bundle` is whether the entry reference's content was acted on from the bundle alone, so a run states what the reader of its bundle needed rather than leaving the question to argument.
- **Counted.** `checks/ledger.py` holds every run record to that schema, refuses an entry citing a run record the ledger does not hold, and prints how many declared sources the runs name, so exposure is read against the records rather than assumed.
