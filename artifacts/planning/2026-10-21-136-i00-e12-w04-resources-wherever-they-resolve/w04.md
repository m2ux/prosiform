**Component:** `src/prosiform/cli.py`

## Overview

This task makes a resource reference text the bundle carries as its author wrote it wherever that reference resolves, the allowed source root included. A resource is anything that is not a local Markdown document, and an image whatever it points at, because image syntax embeds rather than links.

It retires `E_MARKED_RESOURCE`. That code refused a reference that asked for a resource to be bundled, and under [D59](https://github.com/m2ux/prosiform/blob/engineering/artifacts/planning/2026-10-17-prosiform-v1/decisions.md) no reference asks for anything: position states what the bundle carries, and only Markdown documents are bundleable, so the refusal has no subject left.

## Problem

Discovery still reads the mark on a reference it has already classified as a resource, and refuses the run on what it finds there.

- **A refusal survives the request it answered.**
  `cli.marked_resource()` tells an author that a mark asks for a bundled document and a resource cannot be one. Nothing asks for a bundled document any more, so the diagnostic explains a request the author did not make.

- **Position decides everywhere but here.**
  [W01](https://github.com/m2ux/prosiform/pull/138) made where a reference resolves the whole of the question for a Markdown document, and `closure.bundled()` already answers it for every reader. A resource under the root is the one reference whose outcome still turns on its link text.

- **The catalogue is red against the design.**
  `checks/tests/test_catalogue.py` holds the schema's error catalogue to the codes the design declares. The design carries `E_MARKED_RESOURCE` nowhere, the schema still enumerates it, and the check has failed on the epic base since the design changed.

## Proposal

A resource is not a dependency and never was; what changes is that nothing about a resource reference can fail a run. The reference is not resolved further, the file it names is never opened, and the bundle carries its bytes as they were written — the mark among them, where one is there.

- **Discovery passes over a resource.**
  `cli.required()` continues past an image, and past a reference naming no local Markdown document, without reading its link text. `closure.bundled()` already answers the same question for emission, so discovery and emission agree on one classification rather than two.

- **The refusal and its code go.**
  `cli.marked_resource()` and the `MARKED_RESOURCE` constant are removed, and `E_MARKED_RESOURCE` leaves the schema's error catalogue and the corpus's code table, which is what turns the catalogue check green.

- **The warning is unchanged.**
  A bundle whose text names at least one resource still warns once with `W_RESOURCE_PORTABILITY`, and a bundle naming none still warns not at all. Portability is the caller's question, and the run succeeds either way.

- **The corpus states the rule rather than the refusal.**
  The `marked-resource` family asserted three refusals and has no subject; the `resource` family states what a resource is now: one under the root emitted as authored and never bundled, an image naming a Markdown document emitted as authored, and a marked resource carried with its mark.

- **A rule this epic has not delivered keeps the behaviour the build has.**
  `W02` makes the mark defer a compilation, and `W07` rebases a deferred destination. A mark on a resource is carried into the bundle here because a resource is emitted byte-identical, not because the deferral has landed; no fixture of this row asserts what the mark does to a link the bundle compiles.
