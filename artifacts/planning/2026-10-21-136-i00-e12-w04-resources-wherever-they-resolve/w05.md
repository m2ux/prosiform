**Component:** `src/prosiform/cli.py`

## Overview

This task makes a link naming the section it is written in, or an ancestor of that section, resolve to that content's destination in the bundle like any other reference. Identity is decided after the path and the fragment resolve, so a link spelled another way to the same section resolves the same way.

It retires `E_SELF_REFERENCE`. That code refused a link that asked the bundle to carry the very node carrying it, and under [D59](https://github.com/m2ux/prosiform/blob/engineering/artifacts/planning/2026-10-17-prosiform-v1/decisions.md) no link asks the bundle to carry anything: the content is in the bundle either way, so the link names a place that exists and nothing is expanded twice.

## Problem

Discovery compares a reference against the node that owns it and refuses the run when the two are the same.

- **A refusal answers a request that cannot be made.**
  `cli.required()` raises `E_SELF_REFERENCE` for a marked link naming its own section or its own document, and counsels the author to cite it without the mark. The mark no longer selects what is bundled, so the remedy names a distinction the build no longer draws.

- **One link's outcome depends on its text.**
  A link to the section that carries it already resolves to that section's destination when it is unmarked, and fails when it is marked. Two spellings of one reference give two outcomes, which is the rule [W01](https://github.com/m2ux/prosiform/pull/138) removed everywhere else.

- **The catalogue is red against the design.**
  `checks/tests/test_catalogue.py` holds the schema's error catalogue to the codes the design declares. The design carries `E_SELF_REFERENCE` nowhere, the schema still enumerates it, and the check has failed on the epic base since the design changed.

## Proposal

The traversal already terminates on the identity each reference normalizes to, so a reference back to content the run carries adds nothing to the frontier and the fixed point is reached whether the reference points forward or back. A self-reference is that case, and it needs no rule of its own.

- **Discovery yields a self-reference like any other.**
  The ownership comparison and its refusal leave `cli.required()`, which yields the resolved reference. A direct self-reference, an ancestor reference and a preamble link to its own document each resolve to the destination the bundle already holds for that content.

- **The ownership machinery goes with the rule it served.**
  `cli.self_referent()` has no other caller, and the `SELF_REFERENCE` constant no other site. `E_SELF_REFERENCE` leaves the schema's error catalogue and the corpus's code table, which is what turns the catalogue check green.

- **Ownership stability is a property of the resolution, not of a check.**
  A section's link to itself resolved the same way whether the run selected that section or consolidated it into a larger region, and it still does, because identity is read from canonical path and fragment rather than from the region a run chose.

- **The corpus states resolution rather than refusal.**
  The three `self-reference` fixtures and the `ownership` fixture whose subject was the refusal state where each link now resolves. `validation-scope/an-unselected-self-link` is retired: a self-link no longer fails wherever it sits, so an unselected one demonstrates nothing about scope, and `validation-scope/an-unselected-broken-link` carries that statement with a link that does fail.

- **A rule this epic has not delivered keeps the behaviour the build has.**
  `W02` makes the mark defer a compilation and `W07` rebases a deferred destination. The fixtures of this row spell their links without the mark, because what they state is identity and not deferral; what a deferral does to a link naming its own section is `W02`'s to state.
