## Overview

The destination each included document and section takes, and the refusal when two headings would take the same one.

## Problem

A name derived from heading text alone cannot tell two sections apart once several documents are one document.

- **Heading slugs repeat across files.**
  Two documents can each hold a section called Review, so the slug `review` names both.

- **A counter makes a name depend on the whole document.**
  Disambiguating repeats by numbering them ties a destination to how many similar headings precede it, so inserting content elsewhere silently repoints links.

- **Two headings in one source can still coincide.**
  Same ancestors, same slug: nothing about the file or the chain separates them.

## Proposal

A destination is the root-relative document path, then the source-heading slug of each eligible ancestor in order, then the section's own slug. A whole-document destination is the path alone. Path segments keep their separators, so `a/b.md` and `a-b.md` stay distinct.

Two destinations coincide only when the file, the ancestor chain and the slug all coincide, which means two sibling headings with the same slug. Where a link requires one of them, the composition fails with the ambiguity error and the author retitles. Nothing is numbered, so a destination depends only on where its content came from and survives reordering and additions.

Nothing is emitted at the destination. The composite carries Markdown only; the path names a place in it.
