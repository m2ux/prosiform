## Overview

The repository's trees and the README that explains what they are for.

## Problem

The default branch holds a placeholder README and no other file, so the separation the plan assumes between the corpus and the Python build exists only in a decision.

## Proposal

Three trees are created: one for the language-neutral fixture corpus, one for the Python build, and one for the documentation the repository owns. The production build's tree is not created here; the initiative that writes that build creates it. The README states what the tool does, how it is installed, how it is invoked, and links to the design and the planning record on the engineering branch rather than copying them. A layout check asserts the trees exist, and a link check asserts the README's references resolve.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The trees this stage needs and what belongs in each |
| Plan | The layout, the README's sections and the two checks |
| Implementation | The trees, the README and the checks |
| Review | Confirmed that no design or planning content is copied rather than linked, and that no tree is created for a build this stage does not write |
| Test | The layout check fails on a missing tree, and the link check fails on an unresolvable reference |
