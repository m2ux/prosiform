## Overview

The fixture layout and its manifest schema, so a case of the behavioural contract can be declared as data.

## Problem

A behavioural clause has no executable form, and nothing states what a case of it consists of.

## Proposal

A fixture is a directory holding the source tree it composes and one manifest. The manifest names the invocation arguments, the expected standard output, the expected exit status and the expected diagnostics with their error codes. A schema validates every manifest, so a malformed fixture fails as a fixture rather than as a composition.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The expectation kinds the design's failure and success cases require |
| Plan | The directory layout, the manifest fields and their schema |
| Implementation | The schema and a small set of hand-written fixtures exercising each field |
| Review | Each manifest field traced to the design clause requiring it |
| Test | Schema validation accepts the written fixtures and rejects a manifest missing each required field in turn |
