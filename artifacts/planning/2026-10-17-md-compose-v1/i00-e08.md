## Overview

Field deployment makes the prototype the tool agents invoke. It installs with a stable entry point, a wrapper owns the delivery contract so a composite arrives whole or is reported as a delivery failure, and the invocation is documented where the callers that use it live. Without this epic the build is a passing corpus rather than something in use.

## Problem

A validated build nobody can invoke changes nothing, and standard output alone does not establish that a composite arrived.

- **The command runs only from a checkout.**
  Nothing installs it or names an entry point a caller can depend on, so every caller resolves the build's location for itself.

- **Standard output is not an atomic delivery.**
  A transport limit or a broken pipe can truncate a composite that compiled correctly, and Markdown arriving is not evidence that all of it arrived.

- **Success read from output accepts a failure.**
  A caller treating the presence of Markdown as success accepts a failed composition whose diagnostics went to the other stream.

- **An undocumented invocation is used inconsistently.**
  Each caller invents its own arguments, so a composition that fails for one caller is not reproducible for another.

## Proposal

- **The build installs with a stable entry point.**
  One documented command name, resolvable without knowing where the repository sits.

- **A wrapper owns the delivery contract.**
  It checks process status, buffers the composite, enforces the transport's response limit, and returns a delivery failure rather than a truncated success. It never substitutes a summary, a partial document or a reference the caller must follow.

- **Metadata stays out of the composite.**
  Completion metadata, byte counts and warnings belong in the wrapper's structured result, not in the Markdown and not in per-section envelopes.

- **Invocation is documented where callers are.**
  The entry point's options, defaults, exit statuses and profile identifier are documented in the repository, checked against the command's own help output.

- **A failed composition stops the work.**
  There is no supported path by which a caller meeting a failure reads the sources itself instead. Falling back would restore the behaviour composition replaces, and would do it silently, so the failure would teach nothing.

## Acceptance Criteria

- [ ] **AC1.** An installed entry point composes a reference from a source root without the caller knowing the repository's location, as the installation smoke run shows.
- [ ] **AC2.** A composite the transport cannot deliver whole is reported as a delivery failure, with no partial document and no summary in its place, as the delivery fixtures show.
- [ ] **AC3.** A failed composition is reported from the process status rather than from the presence of Markdown on standard output, as the delivery fixtures show.
- [ ] **AC4.** The repository documents the entry point's options, defaults, exit statuses and profile identifier, as the documentation check against the command's own help output shows.
- [ ] **AC5.** The documented invocation states that a failed composition stops the work and that reading the sources instead is unsupported, as the documentation check shows.
