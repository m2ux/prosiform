## Overview

Profile and outline bring the production build to the point where it composes one document correctly: the declared Markdown profile configured explicitly, a compatibility-tested source-heading slugger, eligible section extraction, the group heading shift with title absorption and Setext conversion, and heading-only ancestor scaffolding. The corpus's profile and outline fixtures are what it is measured against.

## Problem

The production build starts with no profile, no slugger and no section model, and each of them changes how existing source is read.

- **A default parser configuration is not the declared profile.**
  Enabling everything available, or accepting defaults, changes whether a construct is a table, a strikethrough, a task marker or ordinary text.

- **A fragment is renderer-defined.**
  The fragment reaching a heading is generated from its visible text and its duplicate numbering, and no slugging component is selected yet.

- **A heading inside a container is still a heading.**
  It must shift with the rest and must not terminate the section that encloses it, which the extraction and shift rules treat as separate facts.

- **Setext headings have no prefix to edit.**
  Shifting one means converting it, which an edit-in-place build must do without disturbing its inline content.

## Proposal

- **Options are set explicitly and pinned with the profile identifier.**
  Pipe tables and strikethrough on, source task markers preserved, typographic substitution off, unsupported extensions off.

- **A slugging component is selected against the compatibility fixtures.**
  The fixtures decide, not the component's documentation, and the chosen version is pinned.

- **The section model comes from the event stream.**
  Eligible roots, boundaries, container nesting and heading ancestry are derived from events with their verified ranges, and heading syntax is edited rather than regenerated.

- **Scaffolds are generated structure.**
  Unselected ancestors are emitted as escaped literal headings, recorded separately from selected content, and not traversed.

## Acceptance Criteria

- [ ] **AC1.** The parser is configured to the declared profile, with typographic substitution absent and source task markers preserved, as the corpus's profile fixtures show.
- [ ] **AC2.** A source heading's fragment equals the one a GitHub renderer generates for it, as the corpus's slug compatibility fixtures show.
- [ ] **AC3.** A fragment selects its eligible section and the blocks up to the next document-level heading of equal or higher level, as the corpus's extraction fixtures show.
- [ ] **AC4.** Each emitted source heading sits exactly one level deeper than in its source with its visible text unchanged, Setext headings included, while a group whose title the file heading absorbs keeps its source levels, as the corpus's shift fixtures show.
- [ ] **AC5.** A selected section's unselected eligible ancestors are emitted as headings carrying no body, sibling or descendant content, as the corpus's scaffold fixtures show.
- [ ] **AC6.** A composition that would place a heading beyond the sixth level fails with its declared error code, as the corpus's depth-overflow fixtures show.
- [ ] **AC7.** One entry composed with and without a cohort selects the same content and differs only in arrangement, and a heading several member documents contribute carries the shortest distinguishing path prefix while one occurring once stays bare, as the corpus's grouping fixtures show.
