## Overview

Fixtures for every adversarial family the design names.

## Problem

A family named in prose that nobody turned into fixtures is a family the next implementation meets for the first time in production.

## Proposal

Each family the design lists gains fixtures: identity, coverage, anchors, references, extraction, boundaries, file hierarchy, partial outlines, wrapper identity, normalization, resources, consistency, validation scope, generated inputs, delivery, parser fidelity, definition inventory, parser exhaustion, validation modes, file-wide safety, profile, frontmatter, command interface and limits. Fixtures existing from earlier epics are counted rather than duplicated.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The families the design names against the fixtures the corpus already holds |
| Plan | The gaps per family and the fixtures that close them |
| Implementation | The additional fixtures and their expected results |
| Review | Each family confirmed represented without duplicating an existing fixture |
| Test | The whole corpus runs and passes, and the family listing reports every named family as present |
