## Overview

Destination identity in the production build names each included document and section by its hierarchy path through the composite, converts resolved reference-style uses to inline form while removing every original definition occurrence, and rebases relative resource references. It is the epic where the definition-occurrence gate's route becomes code.

## Problem

Removing a reference definition requires finding every occurrence of it, which is the capability the first parser gate questions.

- **A later duplicate definition has no map entry.**
  First-definition-wins resolution means the map holds one occurrence per label, while emission must remove them all.

- **An unused definition still occupies source.**
  It resolves nothing and must still be absent from composed content.

- **Labels equivalent under case folding are one label.**
  Occurrence removal that compares labels literally leaves equivalents behind.

- **Fragments collide across files.**
  Two documents can each produce the same fragment, so one composite carrying both needs destinations that distinguish them.

- **A relative resource path is relative to its source.**
  Publishing the content elsewhere changes what that path reaches.

## Proposal

- **Occurrence access follows the recorded route.**
  Whatever route the gate report names is what supplies the occurrence inventory, and removal is driven from that inventory rather than from the resolution map.

- **A destination is a fragment naming a path through the composite.**
  A leading `#`, the root-relative document path without its Markdown extension, the slug of each eligible ancestor in order and the section's own slug form the destination, so two destinations coincide only when the file, the ancestor chain and the slug all coincide.

- **Duplicate siblings are refused.**
  Two sibling headings producing one slug make a destination ambiguous, so the fragment requiring one of them fails and the author retitles.

- **Literal brackets stay literal.**
  Text no source parser resolved as a link cannot acquire a destination from another document's definitions.

- **Resources rebase or fail.**
  A reference that cannot be rebased safely fails rather than acquiring an invented destination.

## Acceptance Criteria

- [ ] **AC1.** Each included document and section is named by a fragment carrying its root-relative path without its Markdown extension, followed by the slug of each eligible ancestor and its own slug, as the corpus's destination fixtures show.
- [ ] **AC2.** Every cross-file and fragment-only link in selected content is rewritten to the destination of the target it resolved to, and two sibling headings producing one slug fail as ambiguous, as the corpus's destination fixtures show.
- [ ] **AC3.** No original reference definition occurrence survives in published content, later duplicates, unused labels, case-fold-equivalent labels, multiline definitions and supported container contexts included, as the corpus's definition-inventory fixtures show.
- [ ] **AC4.** A resolved reference-style use is published inline with its visible content and title preserved, while bracketed text no parser resolved stays literal, as the corpus's reference fixtures show.
- [ ] **AC5.** A relative resource reference is rebased for the selected output destination, or fails with its declared error code when no safe rebasing exists, as the corpus's resource fixtures show.
