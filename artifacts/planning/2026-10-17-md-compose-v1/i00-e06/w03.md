## Overview

Source-change detection before publication, and rejection of a generated document as input.

## Problem

Files are read during discovery and published after validation, so a source edited in between would be published from the bytes discovery captured; and a published composite read back as input would have its generated structure rewritten as source.

## Proposal

Each source's canonical identity and content hash are captured at discovery and rechecked before publication; a changed, removed or relocated source fails with a retry message. A source whose links carry composite destinations, recognized by their path form, is rejected with its declared error code, even when the requested subsection excludes it, while a destination-like path inside code is not detection.

## Work Breakdown

| Part | Description |

| Review | Confirmed that the recheck is described as change detection, not as a filesystem snapshot |
