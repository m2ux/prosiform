## Overview

The source-range adapter is what lets the production build edit a document without rewriting it. It pairs parser events with verified source ranges, maps those ranges back to original bytes through every preprocessing step, and applies non-overlapping edits in place, so untouched content and code examples remain the bytes their authors wrote.

## Problem

An event's range is not the range an edit needs, and the mapping between the parser's view and the original file is not the identity.

- **An enclosing range is not a destination range.**
  A link event carries a span for the construct, so an edit placed from that span replaces more than the destination, or falls outside it.

- **Preprocessing moves every offset.**
  A removed byte-order mark and stripped frontmatter shift the parser's view relative to the file, so a diagnostic or an edit computed in one coordinate space lands wrong in the other.

- **Line endings, tabs and escapes are not one byte each.**
  A range expressed in the parser's view maps to a different extent in the original when carriage returns, expanded tabs, escapes or multi-byte characters sit inside it.

- **Nested constructs produce overlapping edits.**
  An image inside a link has two destinations whose edits overlap, so applying both independently corrupts the construct.

- **A missing span has no safe fallback.**
  Pattern rewriting or regenerating the document through a formatter would change bytes nobody selected.

## Proposal

- **Spans are verified, not assumed.**
  Each construct the design edits has its exact source range established by fixture before it is relied on: headings, link and image uses, and reference definitions.

- **Coordinates map both ways.**
  A range in the parser's view maps to original UTF-8 byte offsets through the recorded preprocessing, and diagnostics report original source coordinates.

- **Nested edits take a parent strategy.**
  A construct containing another is edited as one replacement built from both, rather than as two overlapping edits.

- **An unavailable span fails.**
  A construct whose edit span cannot be established fails the run with a diagnostic. There is no pattern-rewriting or whole-document-formatting path.

- **The crate comes before the adapter.**
  This epic creates the production tree, its workspace, its pinned toolchain and the same documented check commands the prototype carries, so the adapter is written into a build that already runs its own checks. Nothing earlier creates that tree, so it appears when there is a build to put in it.

- **Suppression reaches the compiler.**
  The signal the gate report establishes is wired through the adapter, so a reference lookup an internal limit suppressed is distinguishable from literal bracketed text.

## Acceptance Criteria

- [ ] **AC1.** Each construct the design edits has its exact source range established, as the span-fidelity fixtures covering multiline references, reference-style images, tables, tabs, escapes, Unicode and carriage-return line endings show.
- [ ] **AC2.** A diagnostic reports original source coordinates after byte-order-mark and frontmatter preprocessing, as the coordinate fixtures show.
- [ ] **AC3.** Bytes outside an applied edit, code examples and newline spelling included, are identical to their source, as the preservation fixtures show.
- [ ] **AC4.** A construct containing another is replaced as one edit rather than as overlapping edits, as the nested image-in-link fixtures show.
- [ ] **AC5.** A reference lookup an internal parser limit suppresses fails the run with its declared error code rather than being published as literal text, as the exhaustion fixtures show.
- [ ] **AC6.** The work names the tagged revision of the design and corpus it implements, as the recorded target revision shows.
