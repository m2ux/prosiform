**Component:** main:src/prosiform/cli.py

## Overview

Each group a document joins stands inside the division of the document whose reference placed that group's first member, so a document two references place under different `group` pairs has each group where its own reference was written.

## Problem

- **The second group stands in the wrong division.**
  The build records one placing document for each document, the first reference's, and nests every group the document joins inside that one division. In [#592](https://github.com/m2ux/prosiform/issues/592)'s case Announcements stands inside Alpha although Beta's reference placed the notice in it.
- **Two design clauses can be read either way.**
  *Composition from the leaves up* says a reference reaching a document already placed merges nothing more; *Nested groups* places a group by the reference that placed its first member.
- **No fixture tells the two readings apart.**
  `inclusion/one-document-two-presets` has both references in the entry, so both readings agree.
- **The eval inherits the build's reading.**
  The `group-placement` workflow's `two-presets-one-document` test checks only that Notify appears in two groups.

## Proposal

**The scene.** Placement reads each placed document's links in placement order and records which document placed which; the assembly nests each merged group inside its holder's division.

**The design.**

- **A placing document for each group.**
  Placement records, for each document and each group the pair its reaching reference puts in force names, the document whose link first placed it there. A group an entry places its first member in stays at the top level.
- **A group never holds itself.**
  When the document placing a group's first member stands inside that group, directly or through its holders, the group stands at the top level. Heading levels follow the holder chain wherever the holder falls in placement order.
- **One reading in the design.**
  *Composition from the leaves up* and *Nested groups* state the per-group placement once, and the selection, hierarchy and invocation pages follow.
