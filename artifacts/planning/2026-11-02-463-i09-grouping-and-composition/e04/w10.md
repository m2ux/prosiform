**Component:** main:docs/composition.md

## Overview

A documentation page publishes the reserved composition grammar beside the fixtures that prove it, without assigning the syntax an ontology meaning.

## Problem

- **No page states composition.**
  An author has no page describing the directive, its operator marks, where its target lands, its deferral or its failures.
- **The docs describe operators as exclusive.**
  The glossary says a link states one operator, while `¬⇉` and `¬⫽` are admitted, and the dispatch page quotes an earlier Dispatch protocol wording.

## Proposal

**The scene.** The docs index lists one page per subject; the design's *Section composition* section owns every rule, and the `composition` fixture family proves them.

- **A composition page.**
  `docs/composition.md` outlines recognition, operator marks, the target, destination sections and contributions, composed content (a dispatch in an inline-only contribution taking its own sub-section among it), cycles and self-composition, budgets, presets and `subst`, deferred directives with their `↳` line and activation, and failure. Each part names the design rule it summarises and links every fixture that holds a build to it; each worked example is a fixture's bytes.
- **Placement only.**
  The page describes the label as a placement request and assigns it no meaning about inputs, outputs or invariants. A plain deferred link is described as withholding only.
- **Stale descriptions follow.**
  The docs index, architecture page, README usage, invocation, references and glossary name the page; the glossary's operator entries admit a deferral written before a dispatch; the fixtures README code rows name the composition refusals; the dispatch page quotes the current Dispatch protocol.
