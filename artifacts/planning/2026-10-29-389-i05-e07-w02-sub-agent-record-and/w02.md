**Component:** evals/diagram-following/score.py

## Overview

The scorer's dispatch checks and the sub-agent record they read. A dispatch scenario's bundle set is scored by whether every bundle reached a sub-agent, whether a set's bundles started together, whether every question a sub-agent returned was put to the user, and whether the run completed — each check with a class of its own, so a failing trace is classified by the first check it fails.

## Problem

The scorer reads one trace of states entered and seven classes for a walk that departs from a scenario's path. A dispatch scenario's trace names sub-agent starts, what each returned and whether a set started at once, and the session's transcript is the only place those are recorded. Nothing reads it, so a bundle set handed to an agent is scored as an unfinished walk whether the agent dispatched every bundle or none, and the report cannot separate a bundle left undispatched from a set run in sequence or from a question the sub-agent answered in its own place.

## Proposal

The session transcript is read once, after the session settles, into a record written beside the trace and the session's cost; the scorer reads that record and never the transcript.

- **Sub-agent record.**
  `subagents.json` sits beside `trace.log` and `session.json` in a session's records, holding one entry per sub-agent start: its position in the run, the section it followed, what it returned and whether it started beside the start above it. A start is a `Task` tool call in the transcript, and its return is the result the call carries.
- **Checks.**
  Four, in the order a trace is read: the run completed (the walk's own path and actions), every expected bundle reached a sub-agent, each entry the scenario marks `together` started together, and each return is the scenario's. The first three dispatch checks pass vacuously for a scenario that dispatches nothing, so the three existing workflows score as they did.
- **Classification.**
  `undispatched`, `sequential_set` and `unrelayed_question`, one per dispatch check, taken in that order after the completion check. A run that stopped partway still takes `unfinished`, since the completion check is read first.
- **Stub agent.**
  The stub emits a `Task` start per dispatch its form states, together where the form states a set and returning what the scenario says, so `make check` runs every check and its class without a paid session.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | What a session transcript records of a sub-agent start and of what it returned, and which of those the scenario states rather than the source. |
| Plan | The record's shape beside the trace, the three classes and the order the four checks are read in. |
| Implementation | The transcript reader and the record it writes, the three classes and their checks in `score.py`, the runner's write of the record, the stub agent's starts, and the dispatch session's `Task` tool. |
| Review | Each failing trace classified by the check it fails and not by a later one: a record failing two checks takes the earlier, and a run that stopped takes `unfinished`. |
| Test | AC3: one test per check, one per class, and one holding the order, run by `make check` against the stub agent. |

### Test

AC3 is four checks and a classification duty, so the Test part names one observing row per check and one for the ordering.

| Check | Reading | Test |
| --- | --- | --- |
| Every bundle reached a sub-agent | A record missing an expected start, or naming one out of order, is `undispatched`. | `test_a_bundle_that_reached_no_sub_agent_is_undispatched`, `test_a_dispatch_scenario_passes_on_its_path_and_its_record` |
| A set's bundles started together | A record whose set started one after another is `sequential_set`. | `test_a_set_started_one_after_another_is_sequential_set` |
| Every question was relayed | A record whose return is `done` where the scenario states a question is `unrelayed_question`. | `test_a_question_answered_in_the_sub_agents_place_is_unrelayed` |
| The run completed | A trace short of its path is `unfinished` before any dispatch check is read. | `test_a_run_that_stopped_short_is_unfinished_though_nothing_was_dispatched` |
| Classification order | A record failing two checks takes the earlier; a scenario dispatching nothing passes all three. | `test_the_dispatch_checks_are_read_in_order`, `test_a_scenario_dispatching_nothing_passes_the_dispatch_checks` |
| The record is the transcript's | A start's position, section, return and together flag read from a hand-made transcript, and an absent transcript records none. | `test_a_start_is_read_from_the_transcript_with_its_position_and_return`, `test_an_absent_transcript_records_no_start` |
| The runner writes it beside the trace | A dispatch session's records hold `subagents.json` beside its `trace.log` and the session's cost, and the stub's starts pass. | `test_a_dispatch_session_records_the_sub_agents_its_transcript_states` |
