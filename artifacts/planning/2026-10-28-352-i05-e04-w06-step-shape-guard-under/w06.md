**Component:** checks/steps.py

## Overview

A guard `make check` runs fails when the work-planner example writes a procedure's steps as a numbered list, puts a step heading at the wrong depth, or repeats a step heading within one document, so the step convention E04 applied holds after the epic closes.

## Problem

Nothing observes the step convention. A numbered list added to a procedure reads as valid Markdown and publishes, but it loses the anchor a link needs. A step heading two levels below its procedure renders, but it no longer reads as that procedure's step. A repeated `N. Action` heading in one document takes a suffixed anchor, so a link written to its plain slug opens the first. `pf` states no rule on a target's shape.

## Proposal

A contributor adds `1. Fetch the issue.` to an artifact operation; `make check` fails naming the file and line.

- **What it reads.**
  Every tracked Markdown file under `example/work-planner/`, the skill E04 converted, found through `documents.py` with fenced and indented blocks blanked as the other checks blank them.
- **What fails.** Each failure names the file and line.
  - A line opening a numbered list item, a number and a full stop, at column 0.
  - A step heading, `N. Action`, not exactly one heading level below the nearest heading above it of a lower level.
  - A step heading whose number and action repeat another step heading in the same document.
- **Duplicates per document.** Separate modes legitimately share a step, such as `### 1. Select` in deliver and sync mode, and each is its own bundle entry, so the duplicate rule binds one document.
- **Scope.** `example/my-skill/` is the README's small demo skill, which E04 did not convert and whose `procedure.md` still writes two numbered steps, so the guard reads `example/work-planner/` alone.
- **One target.** `make steps`, in the set `make check` runs and in `.PHONY`, with its row in `checks.md`'s command table and `checks/README.md`'s check table.
