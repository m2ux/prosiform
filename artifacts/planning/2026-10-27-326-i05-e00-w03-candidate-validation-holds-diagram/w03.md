**Component:** src/prosiform/candidate.py

## Overview

Candidate validation holds a bundle's diagram uses to the ones its source wrote, so a click destination the bundle changed or dropped fails the run.

## Problem

[`references`](https://github.com/m2ux/prosiform/blob/30636a72aed3c780bd583ea5ed995458032eba7b/src/prosiform/candidate.py#L931-L967) compares the inline uses of each region. A diagram use the emission rewrote wrongly is published without a finding.

## Proposal

The candidate already compares, region by region, the uses its source intended with the uses it publishes.

- **Diagram uses join the comparison.**
  `references` reads the fence reader on both sides, and holds each published diagram destination to the one `intended` assigns the source's use, with the same count and order rule inline uses take.
- **One finding per fault.**
  A count that differs is `NO_NEW_LINKS`; a destination that differs is `REFERENCE_PRESERVATION`, as for an inline link.
