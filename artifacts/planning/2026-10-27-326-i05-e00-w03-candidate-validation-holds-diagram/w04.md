**Component:** src/prosiform/__init__.py

## Overview

The build reports the profile `skill-markdown-v2`, and the documents that state the profile say a `mermaid` click destination is followed and rewritten.

## Problem

`skill-markdown-v1` states that a fenced block carries no use. Once diagram links are read, that identifier names a grammar the build no longer implements.

## Proposal

The profile identifier is one constant, `PROFILE`, and fourteen files name it.

- **The identifier moves.**
  `PROFILE` is `skill-markdown-v2`, and every file naming `skill-markdown-v1` names the new identifier: the profile module's docstring, the README files, `docs/versioning.md`, the informational-version fixture and the tests that read it.
- **The rules say what is followed.**
  The bundling rules in `invocation.md` state that a `mermaid` click destination is a use, is followed, and is rewritten to the anchor of the group it names, and that a callback, a destination outside the root and a non-Markdown file are carried as written.
- **The design says the same.**
  The Examples rule of the design (`artifacts/planning/2026-10-17-prosiform-v1/design.md`, on `engineering`) excepts `mermaid` click destinations from the fenced code blocks it never follows. That edit is committed on `engineering`.
