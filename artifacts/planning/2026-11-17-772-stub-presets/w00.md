## Overview

A preset holding `stub` binds trial material that the run, rather than each reaching link, selects. One name on the entry puts the stub in force everywhere the run compiles its document, so a trial needs no router file and a live run raises no warning for material it never selects.

## Problem

- **A stub below a dispatch is out of the entry's reach.**
  A preset governs its own document, so with `pf` 0.25.0 an entry tagged `recorded` publishes a dispatched stage declaring that preset against its live reference, and warns `W_PRESET_UNUSED`.
- **A caller reaches it through a router file.**
  A pair redirects a link's target and adds no name to its title, so the caller swaps the file composing its dispatch link.
- **A stub preset warns in every live compile.**
  Nothing but a trial selects it, so every other compile reports it unused.

## Proposal

A trial runs `pf '[Entry](entry.md "recorded")'` over a skill whose dispatched stage declares `recorded: {stub: …, subst: [{review.md: recorded-review.md}]}`.

- **The kind.**
  `stub` is a fourth preset field holding one line; it is refused beside `choice`, in `default`, and as anything but one non-empty line.
- **The run's names.**
  The entry's title names, less `?` and `default`, travel with every source the run reads, in every bundle, so the shared matching rule puts each named stub in force whatever reference reaches its document. A stub in force joins its bundle's preset qualifier.
- **Deferrals.**
  A deferral publishes the run's names its target carries after its authored tags: a Markdown link's title, a reference-style definition's title, a deferring click's tooltip and a deferred directive's `↳` line. A name the target declares as an ordinary preset or alternative is left out.
- **Warnings.**
  An unselected stub raises no `W_PRESET_UNUSED`; a stub's pair is a stand-in, so a link it redirects raises `W_SUBST_USED` once per pair across the run.
