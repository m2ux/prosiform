## Overview

A `staged` workflow whose entry bundle carries a deferred dispatch, `[¬⇉ <text>]`, published as a plain link, so the eval measures an agent that has read the guide compiling it when its path reaches it and dispatching what that run dispatches.

## Problem

- **A deferred dispatch looks like a link.**
  The bundle removes its marks, so only the guide tells the agent that the link is compiled.

## Proposal

**The scene.** A workflow is a directory under `workflows/`, its forms beside a `scenarios.toml` naming each scenario's inputs, the path a correct session walks, the sub-agents it starts and the `pf` runs it makes. A `staged` session receives the compiled bundle set with the build under test as `pf` on its path; the scenario passes when the session's path is the one its bundle states.

- **Compile, then dispatch.**
  `Pack` writes "If `inputs/order.txt` reads `bulk`, the pallet is loaded by [¬⇉ the loading crew](../reference/loading.md#crew)." `pf` publishes it as `[the loading crew](reference/loading.md#crew)`, a path from the workspace. The crew's section dispatches the lift, then the strap, so the run on the link writes a bundle dispatching both.
- **A scenario pair.**
  `deferred-dispatch-compiled`, reading `bulk`, states `pf reference/loading.md#crew` and the trace `reference/crew#lift`, `reference/crew#strap`; `deferred-dispatch-passed`, reading `single`, states neither.
- **The walk reads the plain link.**
  The staged walk compiles a link naming a Markdown path where a step reaches it, as it does a `↳` line, and the dispatch walk follows a reached deferred dispatch to its target's own steps. Each start carries its depth, so the runner gives a shell harness a scenario whose starts are the session's own.
