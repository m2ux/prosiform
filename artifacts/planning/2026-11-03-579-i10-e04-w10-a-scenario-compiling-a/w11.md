## Overview

A `staged` workflow dispatching three hops deep, within the depth the run publishes without `W_DISPATCH_DEPTH`, so the eval measures a chain, a set inside it and a question returned from its deepest level.

## Problem

- **The eval stops at two hops.**
  `dispatch-chain` dispatches a section whose step dispatches a second; the design admits three before it warns.

## Proposal

**The scene.** A workflow is a directory under `workflows/`, its forms beside a `scenarios.toml` naming each scenario's inputs, the path a correct session walks, the sub-agents it starts and the `pf` runs it makes. A `staged` session receives the compiled bundle set with the build under test as `pf` on its path; the scenario passes when the session's path is the one its bundle states.

- **Three paths.**
  `Brief` and `Route` decide on `inputs/shape.txt`, so each scenario walks to the state dispatching its own chain.
- **A chain.**
  `three-hop-chain`: `Relay` dispatches `line/scope#frame`, which dispatches `line/detail#expand`, which dispatches `line/tally#count`, each returning `done` before its caller continues.
- **A set at one level.**
  `three-hop-set`: `Fan` dispatches `fan/divide#portion`, whose first step starts `fan/east#east` and `fan/west#west` as one set at the second hop; both return before its second step starts `fan/join#join`, which starts `fan/seal#seal` at the third.
- **A question from the deepest level.**
  `three-hop-question`: `Query` dispatches `ask/enquiry#pose`, which dispatches `ask/probe#probe`, which dispatches `ask/choice#elect`; the election returns a question, relayed up each level to the user, and `Resume` dispatches the chain again with the answers, as `dispatch-question`'s `Confirm` does, each hop returning `done`.
