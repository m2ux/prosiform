**Component:** evals/diagram-following/run.py

## Overview

The runner that gives each workflow form and scenario to real headless agent sessions, and records what each did and cost.

## Problem

Measuring an agent following a workflow needs sessions that act on files, in isolation, many times over, with their cost under control.

## Proposal

One session per model, form, scenario and repetition.

- **Workspace.**
  A fresh temporary directory holding the form's material — the bundle file, or the source tree — and the scenario's `inputs/`, and nothing else.
- **Session.**
  `claude -p --bare --model <model> --output-format stream-json --verbose --allowedTools Read,Write,Edit,Glob,Grep --permission-mode acceptEdits --no-session-persistence --max-budget-usd <per-session cap>`, run with the workspace as its working directory and the shared instruction naming the entry file. `--bare` keeps the user's settings, hooks and project memory out of the session. Confirm each flag against `claude --help` at implementation.
- **Records.**
  Per session: the stream-json transcript, the result's token usage and cost, the workspace's `trace.log` and `actions/`, and the scorer's verdict, under `results/<run-id>/`.
- **Spending cap.**
  `--budget-usd` for the run. Before starting a session the runner checks the recorded cost plus the per-session cap against it; sessions it does not start are reported.
- **Options.**
  Models, repetitions, workflows, forms and parallelism, defaulting to the epic's matrix. The agent command is configurable so the tests run a stub agent that writes scripted traces.
