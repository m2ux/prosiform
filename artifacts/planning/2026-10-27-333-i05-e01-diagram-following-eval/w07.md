**Component:** evals/diagram-following/score.py, evals/diagram-following/run.py

## Overview

An `errored` class, so a session whose agent was refused or crashed is recorded apart from the failure classes that describe how an agent followed the workflow.

## Problem

A probe run of the linked form returned five sessions that exited 1 in about two and a half seconds at zero cost, each scoring `unfinished` with an empty trace. The transcript's `result` message read `You've hit your weekly limit · resets Oct 31, 7pm`. A spent login was being recorded as a model that walked part way and stopped, which is the opposite of what a pre-flight run exists to say.

## Proposal

- **`Failure.ERRORED`** joins the seven trace classes, documented as taken by a session that entered no state.
- **Classified where the result is read.** `run.start` reads the `result` message and the workspace's trace before scoring. A session whose result sets `is_error`, or one with no result and no trace, takes `errored`.
- **A timeout keeps its trace.** A session ended at its timeout has no `result` message, but it wrote a trace, so it is scored from what it wrote and stays `unfinished`. The committed timeout behaviour is unchanged.
- **The report tolerates a baseline without the class.** `tally` and `difference` read a missing failure key as zero, so the committed baseline, which lacks `errored`, still compares.
- **The budget still holds the cap.** A refused session reports no cost, so the run charges its session cap, as it does for a session in flight.

## Findings

- **The class is drawn on trace evidence, not on exit status alone.** A command exiting 1 having written a trace is a run that stopped (or was cut off), which `unfinished` names. A result message declaring `is_error` is `errored` whatever the trace holds.
- **The refusal was cheap to reproduce.** A single-session run cost nothing and answered in under two seconds, which makes it the right pre-flight check for a corpus change.
- **The defect reached the baseline's column too.** `errored` joins `FAILURES`, so every report table gained a count, and the committed baseline's cells read zero for it.
