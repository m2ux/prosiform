**Component:** evals/diagram-following/baseline.json, evals/diagram-following/report.md, evals/diagram-following/README.md

## Overview

The committed baseline is what every later run is compared against, and it carries the matrix the eval actually runs. This task produces that baseline from the four-form default matrix, so a report reads a comparison for the linked form instead of `new`, and records what a default run costs once it does.

## Problem

- **The baseline predates a form the matrix runs.**
  `baseline.json` holds 150 sessions over `bundle`, `tree` and `prose`, from run `20261028T165414Z`. The default matrix at `92c55bb6` is 200 sessions: the same three forms plus `linked`. Every `linked` cell in a report therefore reads `new`, and the form the epic was extended to measure has no row to be compared with.
- **The documentation and the run record disagree.**
  The report states a default run costs `USD 4.01` over 150 sessions, while `make eval-diagrams` passes `EVAL_BUDGET_USD := 100` for 200. The cost of a four-form run is unmeasured, so the budget's headroom is asserted rather than stated.
- **A refused run is recorded as a completed one.**
  Run `20261029T143428Z` started all 200 sessions and every one was refused by the login's weekly limit. `run.json` records 200 started, `cost_usd` 0.0 and an empty `not_started`, and a report was written and compared against the baseline. A reader cannot tell that run from a matrix of genuinely failing agents without opening a transcript.
- **The baseline separates the forms it carries not at all.**
  Every cell of the committed baseline is 5 of 5 passed, so the instrument detects only a whole-cell regression and cannot say whether the diagram helps over prose. This task produces the figure; acting on it is a change to the corpus.

## Proposal

- **A run refuses a matrix it cannot complete.**
  A run whose every session reports an error is recorded as refused rather than reported: `run.json` carries the reason, and the report names it instead of comparing pass rates. The agent's own words are already in each session's `result` message, and one refused session says the login is spent.
- **The baseline carries every form the matrix runs.**
  The default matrix is run once the login is available, its report reviewed, and its cells written as `baseline.json` with `report.md` beside it, so every form and scenario has a row.
- **The measured cost replaces the estimate.**
  The README's default-matrix section and its `make eval-diagrams` row state the four-form session count, the cost the new baseline records, and the budget that covers it.
- **The form comparison is reported as the baseline shows it.**
  The per-form pass rates are read for what they support. A baseline whose forms all sit at one rate is recorded in the planning record as not separating them, rather than presented as a result.

## Acceptance Criteria

- [ ] **AC1.** A run in which every session reports an error is recorded as refused and its report names that rather than comparing pass rates, as a stub-agent test `make check` runs shows.
- [ ] **AC2.** The committed baseline carries every form the default matrix runs, drawn from a run after 31 October 2026, with its report and its measured cost, as the baseline file and the run record show.

## Open Questions

- **Whether the login is available at the time of the run.**
  The eval's login answered `You've hit your weekly limit · resets Oct 31, 7pm (Europe/Zagreb)` on 2026-10-29, so this task cannot start before then. A second login or an API key for the eval root would lift the wait, at a cost the run's budget would need to cover.
- **Whether a corpus made harder is this task or a further one.**
  A baseline at one pass rate across every cell separates no form. Raising the corpus's difficulty is a change to its scenarios and workflows, so whether it is planned here, as the means of getting a separable baseline, or as a further task with its own criteria, is undecided.

## Findings

- **The cost is unmeasured for four forms.**
  The three-form run recorded USD 4.0068 over 150 sessions, and the per-model means are in [`report.md`](report.md). The linked form's 50 sessions add cost at those means, so the four-form figure is estimated, not recorded, until a run completes.
- **The budget has headroom either way.**
  USD 100 covers 200 sessions at the USD 0.50 cap, and the measured three-form cost is under a twentieth of it, so the budget is not the constraint on a run.
