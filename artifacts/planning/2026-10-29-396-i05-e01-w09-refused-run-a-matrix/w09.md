**Component:** evals/diagram-following/run.py

## Overview

A run whose every session errors is currently recorded as a completed run: `run.json` says 200 started, zero cost, nothing skipped, and a report compares pass rates against a baseline. This task records such a run as refused, quoting the agent's own words as the reason, so a spent login is never read as a matrix of failing agents.

## Problem

- **A refused run is recorded as a completed one.**
  Run `20261029T143428Z` started all 200 sessions and every one was refused by the login's weekly limit. `run.json` records 200 started, `cost_usd` 0.0 and an empty `not_started`, and a report was written and compared against the baseline.
- **The agent's words are discarded.**
  Each session's `result` message carries the refusal, and one refused session says the login is spent, but nothing reads them together to decide the run's state.
- **A report over a refused run reads as a result.**
  Its tables give pass rates and changes against a baseline for a run in which no agent entered a state.

## Proposal

- **A run refuses a matrix it cannot complete.**
  A run whose every session reports an error is recorded as refused rather than reported: `run.json` carries the reason, and the report names it instead of comparing pass rates.
- **The reason is the agent's own.**
  One session's `result` message is quoted, so a reader sees the limit the login reported rather than a count of errors.
- **The state is held by a test.**
  A stub-agent test drives a run in which every session errors, and asserts the refused state, the recorded reason, and that no report compares pass rates.
