**Component:** main:evals/diagram-following/workflows/conditional-composition/scenarios.toml

## Overview

A `staged` workflow composing a state's section with `[→]` beneath a conditional step, so the eval measures whether an agent applies always-present content only where its condition holds.

## Problem

- **Composed content is always present.**
  The bundle carries it whatever the input, and no authoring rule says to defer it, so the reader must apply the condition.

## Proposal

**The scene.** A workflow is a directory under `workflows/`, its forms beside a `scenarios.toml` naming each scenario's inputs, the path a correct session walks, the sub-agents it starts and the `pf` runs it makes. A `staged` session receives the compiled bundle set with the build under test as `pf` on its path; the scenario passes when the session's path is the one its bundle states.

- **A composed state.**
  `Gauge` writes "If `inputs/scope.txt` reads `large`, … [→](convert.md#rows)", composing `Convert`'s action and transition beneath that step. The diagram clicks no `Convert`, so the directive is the only way into it.
- **The walk follows a one-symbol label.**
  The bundle walk enters a state at the heading a directive or footnote mark links, as well as at a link naming the state by its text.
- **A scenario pair.**
  `composed-entered`, reading `large`, walks `Sample`, `Gauge`, `Convert`, `Finish`; `composed-omitted`, reading `small`, walks `Sample`, `Gauge`, `Finish`, though the bundle still carries `Convert` beneath `Gauge`'s step.
