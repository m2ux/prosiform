## Overview

Fixtures for every adversarial family the design names, and every fixture an earlier epic left awaiting this work finished.

**Component:** `fixtures/` — the corpus.

## Problem

A family named in prose that nobody turned into fixtures is a family the next implementation meets for the first time in production.

A fixture states which design clauses it encodes, and the design's adversarial families are clauses like any other, so a family is represented when a fixture names it. Thirty-five manifests name a family that way and they reach ten of the twenty-seven families the design lists, so the corpus carries no listing of which families are represented and which are not. Underneath that, six cases the design names are declared by no fixture at all, and two are declared by nothing a static source tree can state.

## Proposal

- **A family is named by the fixtures that encode it.**
  Each family the design lists is named by at least one manifest's `clauses`, written `Adversarial acceptance fixtures — <Family>` or `Adversarial acceptance fixtures — <Family>, <case>`. The family listing is then read from the corpus and the design rather than from a table beside them.

- **The cases no fixture declares gain one.**
  An outline that skips a level, an empty fragment, tabs and CRLF carried through a rewrite, and a label two definitions spell with different case each gain a fixture.

- **A case a source tree cannot state is declared ahead of the build.**
  A source that changes during compilation, and a parser resource limit suppressing a reference lookup, are each declared as a fixture naming the work that delivers it, so the family is represented in the corpus and the deferral is tracked where the fixture is read.

- **Fixtures already in the corpus are counted rather than duplicated.**
  A family an earlier epic's fixture represents is represented.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The families the design names against the fixtures the corpus already holds |
| Plan | The gaps per family and the fixtures that close them |
| Implementation | The family clauses, the additional fixtures and their expected results |
| Review | Each family confirmed represented without duplicating an existing fixture |
| Test | The whole corpus runs and passes, and the family listing reports every named family as present |
