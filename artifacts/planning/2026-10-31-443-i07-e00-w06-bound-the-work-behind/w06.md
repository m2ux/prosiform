# W06 — Bound the Work Behind the Byte Budget

**Component:** src/prosiform/limits.py

> Work item · I07:E00 · 2026-10-31

## Overview

The declared resource bound and the diagnostic that reports it, so the bound bounds work and the remedy is readable.

## Problem

The declared byte bound does not bound decoder work: a base-prefixed integer costs quadratic time inside the bound. A root-not-found diagnostic reports a bare path segment, with no reference and no remedy.

The finding is recorded as findings 35 and 36 in the [merged-epic review](../2026-10-31-merged-epic-review/findings.md), with its site and the case that failed.

## What the finding missed, and what the repair follows

Both findings are stated as one defect each, and both are one defect at one site. Probing the neighbouring work found that the quadratic cost is not one notation but a family, and that a second notation the finding does not name costs the same:

| Notation | Stage that costs quadratic time | Cost at equal digit counts, before the fix |
| --- | --- | --- |
| `0x` + hex digits | `Decimal(int(value, 16))` | 9.15s at 800,000 digits; 16.1s at 1,048,536 |
| `0o` + octal digits | `Decimal(int(value, 8))`, the same stage | 5.17s at 800,000 digits |
| `1e` + exponent digits | `_finite_float` accumulating `power * 10 ** k` | 4.17s at 800,000 digits |
| decimal digits | none: the literal is its own decimal value | 0.001s at 800,000 digits, linear |
| `1.…` with no exponent | none: read in one pass | 0.21s at the byte budget, linear |

The octal path is the same `Decimal(int(...))` conversion as hex, so it is the same defect with a smaller digit-per-value ratio rather than a second one. The exponent path is genuinely a second site: it is the float branch, and no ceiling on integers reaches it.

A ceiling on integers alone would have left the float notation spending minutes inside the same budget, so the repair bounds the work rather than the spelling that asks for it.

## Proposal

- **Bound the work behind the byte budget as well as the bytes.** A scalar of either costly notation carries at most `SCALAR_DIGITS` characters; a longer one fails with `E_RESOURCE_LIMIT`. Within the ceiling every scalar costs a pass over its own digits, so a source's bytes bound the work the run performs and the byte budget reads as the bound it claims to be.
- **The ceiling is declared, not offered.** It is not a ninth option: it states what a byte budget means rather than a preference an author sets, so it sits in `limits.py` beside the budgets and is documented where the budgets are read.
- **Name the reference that declared the root and the root it named, with a remedy.** The walk reports the segment it refused; the diagnostic now also names the source that declared the root, the root as written and what a reader does about it.
- **The case ships with the fix.** Each failing case becomes a check the repository runs, so a regression fails a target rather than waiting for another review.
- **No other task's area is touched.** `fixtures/` and `checks/` belong to other tasks of the epic, so the cases live in `src/tests` and any corpus case is reported rather than added.

## What the repair changes, and what it deliberately leaves

**Kind resolution is separated from canonicalisation.** `_kind` reads the tag and the implicit rule and builds nothing; `_canonical` reads a scalar already known to be inside the ceiling. That ordering is what lets the ceiling be held before the cost is paid rather than after.

**The decimal notation is untouched.** A decimal literal is already its own decimal value, so it costs one pass over its digits and needs no ceiling. The 5,002- and 20,000-character decimal and float scalars the shipped tests carry keep working exactly as they did.

**The ceiling is a figure, not a timeout.** A timeout would make a run's outcome depend on the machine it ran on, which is the opposite of a deterministic bound. The ceiling is a function of the digits alone, so the same source fails the same way everywhere.
